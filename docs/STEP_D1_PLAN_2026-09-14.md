## 2. 「無い」の種類を、評価が欠けた行・終局の行でどう表すか(**AGENT_PROTOCOL 11.6**)

**値を 0 や `false` で埋めない。** 評価は「値」ではなく「状態 + 値」で持つ。

| 状態 | 記録の形 | 判定 | 表示 |
|---|---|---|---|
| **測った** | `engineReference.baseline` に `scoreCp` か `mate` がある | ― | 値をそのまま |
| **測らないと決めた(終局)** | `engineReference === null` かつ、その行の `sfen` に `isGameOver` が true | 行の `sfen` に本番の関数を当て直す | 「測らない(終局)」 |
| **測らないと決めた(王手中)** | `engineReference === null` かつ `isInCheck(sfen, "sente")` が true | 同上 | 「測らない(王手中)」 |
| **測れなかった** | `engineReference === null` で、終局でも王手中でもない。**または** `baseline` の `scoreCp` と `mate` がどちらも `null` | 同上 | 「測れなかった(例外・時間切れ。記録からは区別できない)」 |
| **測っていない** | ready 行に `engineReference` の欄が無い(T-7 より前の記録) | 欄の有無 | 「測っていない(この記録は評価を持たない)」 |

- **比べる組**: 連続する 2 つの ready 行が**両方とも「測った」で、両方 `scoreCp` のとき**だけ差を取る。**それ以外の組は「比べられなかった組」として理由つきで数える**(黙って飛ばさない ― P-22 の型)
- **`mate` が絡む組**: 差は取らない。**「直前が `scoreCp`、直後が `baseline.mate < 0`(先手が詰まされる読み)」は D-3 で扱いを決める**
- **実戦の続きの窓が棋譜の終わりを越える場合**: その急落候補の「窓の中の王手・詰み」は「**起きなかった**」ではなく「**窓が足りない(記録がここで終わる)**」にする。**終局で終わった棋譜は、終局の手までで窓が閉じるので「足りない」にしない**

**Failure Event の JSONL では、評価の欄を `{ "state": "measured", "scoreCp": 820, "mate": null }` / `{ "state": "notMeasuredInCheck" }` のように書く。** 数字だけの欄を作らない。

## 2. 実装してよい範囲

**A-1(保存の入口。`apps/web`)**: 画面に「保存」の操作を 1 つ足し、押すと現在の対局の棋譜を `scripts/playtest/kifu/` と同じ形式の JSON としてブラウザのダウンロードで書き出す。**方式は 5. の H-1 の人間判断に従う**(推奨: ブラウザのダウンロード。サーバーにファイルを書かせない)。

**A-2(JSON を作る純粋関数。`gameApi.ts` + テスト)**: `buildKifuJson(moveHistory, now)` → `{ id, source, moves }`。
- `id`: `YYYY-MM-DD-live-{手数}moves`(例 `2026-09-11-live-20moves`)。日付は保存した日(ローカル日付)。**機械的な規則で、将棋の判断を含まない。** 同じ日に同じ手数の対局を保存すると `id` とファイル名が衝突する(計画レビューの指摘)。H-1 が (a)(ブラウザのダウンロード)ならブラウザ側が別名で保存するため上書きは起きないが、`scripts/playtest/kifu/` へ人が置くときに気づける必要がある。H-1 が (b)(サーバーが書く)なら衝突時の扱い(拒否する / 連番を足す)を決める必要があるため、H-1 の判断材料として記す。
- `source`: 固定文字列(例 `"apps/web の対局から保存"`)。**文言は 5. の H-2 の人間判断に従う**(ファイルの中身に入る文字列であり、画面には出ない)。
- `moves`: `moveHistory` をそのまま(並び替え・加工をしない)。
- 0 手のときは保存の操作を無効にする(空の棋譜を作らない)。

**A-3(ファイル名)**: `{id}.json`(F-1 の `id` と同じ)。

**A-4(テスト)**: `buildKifuJson` の単体テスト(0 手・奇数手・偶数手、日付の埋め込み、`moves` が入力と同一であること)。既存テスト 82 は変更しない。

**この決定は、既存の人間の線「持ち時間を混ぜない・閾値を使い回さない」を破っていない。** 破っていないことを、説明ではなく**機械で言える形**にしてある ―

**この決定で変わらないもの**: しきい値 30% は**未承認**(別の期間の棋譜での再測の後 ― §4 の段 5)/ 過去棋譜は**全手(投了まで)** / §6 の測っていない 6 件は測っていないまま。

## 1. 「普段」の機械の定義の候補(依頼 §4 の 1)

**3 つとも「本人に聞かない」で成り立つ。** 入力は過去棋譜だけで、自己申告を 1 つも使わない。

共通の前置き: 過去 N 局それぞれの署名を §0.2 の規則で作り、**id ごとに「その id が署名に出た局数」**を数える(1 局で何局面立っても 1)。これを「過去の頻度」と呼ぶ。

### 1.1 候補 A ― 過去の採用頻度のしきい値(**推す**)

> **普段の型の集合 U** = 過去 N 局のうち、その id が署名に出た局が **N の 30% 以上**だった id。
> 今回の局は、**署名が U と 1 つも交わらなければ「普段の型が出ていない局」**。

**しきい値 30% は実測から選んだ。** 25 局を 12 / 13 に無作為に割り、両側で U を作って一致を測った(200 回。道 = §0.1 の全手の出力を割った):

| しきい値 | U の大きさ(平均) | 2 つの U の一致(Jaccard 平均) |
|---|---|---|
| 50% | 1.53 | 0.42 |
| **30%** | **2.80** | **0.82** |
| 20% | 3.35 | 0.78 |
| 10% | 5.24 | 0.50 |

50% は集合が小さすぎて揺れ、10% は 1 回しか出ない長い尾を拾って揺れる。**30% が最も安定した。**

**要求する最小のデータ**: 過去 **30 局以上**(上の測りは 12〜13 局でも 0.82 だったが、12 局は今回の 25 局を割ったものなので、**別の期間の棋譜での再測が要る** ― §4 の段 5)。**全手・平手・分岐なし。持ち時間は問わない**(人間の決定 2026-10-01 ― §0.0)。**いつの**: 直近から数えて N 局(§1.4)。
**言えること**: 「普段の型が出ていない局が K 局あり、その K 局では既存の指標がこうだった」。
**言えないこと**: 「この戦型を普段指さない」(名前は `draft` なので出さない ― 依頼 §3)。

### 1.2 候補 B ― 過去に 1 度も出ていない(厳しい側)

> **U** = 過去 N 局の署名に出た **全部**の id。今回の局の署名が U と交わらなければ「**過去 N 局に無かった型**」。

しきい値を置かないので判断的知識を 1 つも増やさないが、**N を強く要求する。** 真の頻度 p の型が過去 N 局に 1 度も出ない確率(二項。**実測ではなく計算**):

| 真の頻度 p | N=25 | N=50 | N=75 | N=100 |
|---|---|---|---|---|
| 20% | 0.4% | 0.0% | 0.0% | 0.0% |
| 10% | 7.2% | 0.5% | 0.0% | 0.0% |
| **5%** | **27.7%** | **7.7%** | 2.1% | 0.6% |
| 2% | 60.3% | 36.4% | 22.0% | 13.3% |

**読み**: 20 局に 1 度(5%)指す型を「過去に無かった」と誤って言う確率は、**25 局では 27.7%・50 局では 7.7%・100 局では 0.6%**。**N=50 が折れ目で、N=100 で 5% の帯が閉じる。**
**要求する最小のデータ**: 過去 **50 局以上**(100 局あれば 5% の帯まで言える)。他は候補 A と同じ。
**言えること**: 候補 A より強い言い方(「過去 N 局には無かった」)。**ただし「指さない」ではなく「無かった」までで、N を文に書く。**

### 1.3 候補 C ― 順位の差だけを出す(しきい値を置かない)

> 過去と今回で、id ごとの「出た局数の割合」を並べ、**今回だけ上位に出た id** を差として挙げる。

**判断的知識を 1 つも増やさない**(しきい値も「普段/普段でない」の二値も作らない)。代わりに**「普段指さない局」という群ができない**ので、既存の指標を群で割り直せない。**顧客に出せるのは差の並びまで。**
**要求する最小のデータ**: 過去 **30 局以上**(順位が動かなくなる局数は未測 ― §4 の段 5)。
**使いどころ**: 候補 A・B の**前**に 1 回出して、過去と今回で分布がどれだけ違うかを人間が見る材料。

### 1.4 3 つに共通する「最小のデータ」

| 項目 | 決めること | 理由 |
|---|---|---|
| 局数 | 候補 A は 30 以上、候補 B は 50 以上(100 が望ましい) | §1.1・§1.2 の測り |
| 手数 | **全手(投了・切れ負けまで)**。序盤だけは採れない | §0.1 の表(40 手で 11 局の署名が変わる) |
| 形式 | **KIF または CSA** | `lib/kifuImport.ts` が読むのはこの 2 つ |
| 開始局面 | **平手だけ**(駒落ちは `unsupported_start` で落ちる) | 同ファイルの「平手以外の開始局面の変換」の記述 |
| 分岐 | **本譜だけ**(変化は読まない) | 同 |
| 時刻・秒 | **要らない**(署名は秒を 1 つも読まない) | §0.1 の `MeasuredGame` に時間の欄が無い |
| 持ち時間 | **問わない**(人間の決定 2026-10-01 ― §0.0) | 署名が秒を読まないので混ざりが結果に入らず、混ぜていないことを `timeDependent` 0 件で機械で言える |
| 時期 | **直近から数えて N 局**(期間ではなく局数で切る) | 期間で切ると、指した頻度の違いで N が顧客ごとに変わる |
| 勝敗 | **問わない**(署名は結果を読まない) | 同上 |

**取り込みは 100% 通らない。** 3 人目の 20 局では 6 局が 1 文字の成り駒で読めず、直し(`D0-KIFU2`)が要った(`docs/` の記録)。**だから必要数より多めにお願いする**(§3 の文案で「50 局以上」と書くのは、30 局を使うためではなく**落ちる分を見込んでいる**)。

## 2. 2 つのデータセットを比べる口(依頼 §4 の 2)

### 2.1 H-5 との整合 ― 過去棋譜は別の packet。本番の packet に過去の行を混ぜない

**H-5(1 packet = 1 データセット)を動かさない。** 過去棋譜は**それ自身の packet** になる。理由は 2 つ。

1. **母集団が違う数を同じ `aggregates` に並べると、`id` が同じでも分母の出どころが違う行ができる。** これは 5 人目で踏んだ型そのもの(「22 局」と「22 局面」・一致率の分母の取り違え)。
2. **過去の packet はエンジンを持たない。** 時間・分かれ道・崩れ・候補手の欄が空になる。本番の packet の形にその行を混ぜると、「在るはずの欄が無い」と「測っていない」が同じ形になる。

### 2.2 過去の packet の形 ― 既存の契約のまま、埋まる欄が少ないだけ

```
observation-packet v0.1(既存の schema のまま。変更しない)
  customerRef: "c5"          ← 同じ顧客の符号
  facts.games[]              ← 25 → N 局。timeLimitSec は局ごとに実物の値
  facts.moves[]              ← 指し手・駒種(秒は材料が無いので欄を出さない)
  facts.recognition.rows[]   ← ここが本体
  facts.recognition.definitions[]
  facts.engine / branches / collapse / time  ← **空の配列**(エンジンを回していない)
  aggregates[]               ← **時間依存の行を 1 つも持たない**(下の 2.3)
  provenance                 ← 材料は棋譜だけ。thresholds は持たない
```

**`datasetRef` を足すかは司令塔の判断**(この設計案の提案。§4 の段 2 と同じ束)。`customerRef` が同じ 2 つの packet が並ぶので、**どちらが過去でどちらが本番かを機械で言えないと、取り違えが静かに起きる。**

### 2.3 持ち時間の線を使い回さないことを、機械で言える形にする

人間の線「持ち時間を混ぜない・閾値を使い回さない」を、**過去の packet では「時間の行を 0 件にする」で満たす。**

- 署名は秒を 1 つも読まない(§0.1 で測った)。だから**過去の packet に時間の集計行を作る理由が無い。**
- 束 C は既に `aggregates[].timeDependent` を欄名から機械で導いている(`lib/observationAggregates.ts`)。**過去の packet は `timeDependent: true` の行が 0 件、を入口の検査にする。**
- `provenance.thresholds` を**持たせない**(線が無いので、使い回す道が物理的に無い)。

**これで「過去棋譜の持ち時間が違っても閾値を混ぜていない」が、説明ではなく数で言える。**

### 2.4 比べる口 = 第 3 の成果物(新しい契約 1 本)。**どちらの packet も変えない**

| `aggregates[]` | **packet の `AggregateRow` と同じ形**(`id`・`name`・`unit`・`population`・`numerator`/`denominator`・`derivedFrom`・`src`・`recountable`・`timeDependent`) | `population.from` に `"reference"` を 1 つ足す(**この契約の中だけ**。packet の schema の enum は変えない)。`derivedFrom` は**両方の packetId を持つ** |

**`usual: true` の側の行も必ず対で作る。** 片側だけ出すと、分母の無い数が本編に出る(5 人目で踏んだ型)。

### 2.5 代替を機械で止める(§0.3 の読みへの手当て)

`request.json` の問いごとに **`referenceRequired: true`** を立てられるようにし、

- **立っていて `reference-comparison` が無いとき**: 席の `answers[].status` に `partial` を許さない(`unanswerable` か `answered` のみ)。`answered` には `observations[].packetRef` が comparison の行を指すことを要求する。
- **立っていて comparison が在るとき**: 今までどおり。

**席のプロンプトは変えない**(人間が止めている)。**止めるのは検証器の側**(③)。これで「群を代替にした `partial`」が採用候補にならない。**6 行すべてが `partial` だった実測が、この縛りの根拠である。**

## 1. なぜ急ぐか

STEP 5-B で文字入力をなくしたため、**盤をクリックするのが唯一の着手経路**である。移動先の緑が見えないと、初心者は「どこへ動かせるか」が分からないまま指すことになる。縛った初心者の 3 局([PLAYTEST_PERSONA_BEGINNER.md](PLAYTEST_PERSONA_BEGINNER.md))を走らせる前に直す(人間の判断)。

## 2. 現状の実測(修正前)

比はいずれも WCAG 2.1 の相対輝度による。**「何に対する比か」を必ず併記する**(3. の教訓)。

| 移動先の緑 `#bfe3bf` の対比 | 値 | 目安 |
|---|---|---|
| 対 盤の地色 `#f3d9a4` | **1.02:1** | 3:1 に遠く届かない |
| 対 脅威の赤 `#c4574a` | 3.11:1 | 満たす |

色相だけが違って明るさがほぼ同じため、盤と見分けがつかない。

## 3. 総当たりで測って分かったこと(**設計の前提が変わる**)

- **白 `#ffffff` でさえ盤の地色に対して 1.38:1 しかない。** したがって 3:1 を満たす色は**盤より暗い側にしか存在しない**
- **盤 3:1 と黒い駒の字 4.5:1 を同時に満たす緑は 1 色も無い**(脅威の赤との条件を外しても 0 色)。背景色を濃くするなら、**そのマスの駒の字を白にするのが前提**になる
- 盤 3:1 と赤 3:1 を両方満たすには、**赤よりさらに暗い緑**が要る(赤が盤から 3.18:1 の位置にあるため)

## 4. 採用した値(**人間が見本を見て選んだ**)

候補は盤の色の上に並べた見本として提示し、**人間が A-1 を選んだ**。

`.square-destination` の背景 = **`#003900`**、そのマスの駒の字 = **白 `#fff`**。

| `#003900` の対比 | 値 |
|---|---|
| 対 盤の地色 `#f3d9a4` | 9.63:1 |
| 対 脅威の赤 `#c4574a` | 3.03:1 |
| 対 選択中の黄 `#f7ec8f` | 10.94:1 |
| 対 hover `#e9c98a` | 8.32:1 |
| 白い字 `#fff` 対 背景 `#003900` | 13.25:1 |

「はっきり緑に見える」範囲で最も明るい色である。

**赤いマスは変わらない。** `apps/web/src/main.ts:1509` が `threatened ? "square-destination-threatened" : "square-destination"` と**排他的に**クラスを付けるため、白い字の規則は赤いマスに掛からない。

## 5. 確かめ方(**実機では見ていない。明記する**)

**実機確認(ブラウザで対局)は行っていない**(実機の枠も取っていない)。CSS だけの変更で、確かめたいのは**詳細度と適用順**だったため、次の方法で確かめた。

1. `npx vite build` でビルドし、生成 CSS に両方の規則が残ることを確認
2. 生成 CSS の中で `.square-destination .piece-sente, .square-destination .piece-gote{color:#fff}` が `.piece-sente{}`・`.piece-gote{}` より**後**に出ることを確認(詳細度 0,2,0 対 0,1,0 でも勝つので二重に勝つ)
3. その生成 CSS をそのまま埋め、`main.ts` と同じ入れ子(`td > span.piece-*`)の盤マークアップを当てて**実際に描画**し、目で確認した

描画の結果: 移動先(先手駒・後手駒とも)は濃い緑に白い字で読める / 移動先＋脅威は赤に黒い字のまま / 選択中の黄・通常のマスは変化なし。

**実際の対局の中での見え方は、これから走らせる縛った初心者の 3 局で確認される**(人間の判断。追加の実機確認は行わない)。

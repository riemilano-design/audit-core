### 1.3 横断的に見えた設計パターン

以下は、複数サービスに共通して観察できた設計と、本アプリへの適用可能性である。適用可能性はすべて【仮説】。

1. **説明文の語と盤上図示を連動させる**(Chess.com v2、Play Coach、ぴよ将棋)。【仮説】文中の「８八の角」をタップ/ホバーで盤上のその駒が光れば、文章が主役でも盤から目を離さずに読める。
2. **開示の段階化: 問い → 部分ヒント → 答え**(Khan、Chess.com の Retry→Idea→Best、Lichess LFYM)。【仮説】「事実 → 相手の狙いの可能性 → 自分の目的 → 候補手」を操作で開く構造は、現行の5ブロックと順序が一致する。
3. **一度に1つだけ**(Duolingo、Brilliant、Lichess LFYM)。【仮説】毎手すべてのブロックを更新・強調するのではなく、「その手で変わったブロック」だけを強調する。ChessKid の「毎手介入」への反発は反面教師。
4. **問い先行**(Brilliant、Aimchess の二択)。【仮説】既存の実験機能「指す前に目的を申告する」はこのパターンそのもの。申告と盤面の事実の照合を返す形にできる。
5. **警告は「事実」として、危険が生じた瞬間に**(Play Coach の「駒が攻撃されたとき」)。【調査結果】STEP 4-3 で実装済みの「利きが届いている自分の駒」の事実表示は、このパターンと一致する。【仮説】初心者向けには評価値ではなく「どの駒に利きが届いたか」の図示が効く。
6. **数値を離散ラベルに翻訳する**(ウォーズの4段階、Lichess の勝率換算)。【仮説】安全確認の結果を数値で出さない現行方針は妥当。
7. **1行要約 → 展開**(DecodeChess、Lichess Study)。【仮説】各ブロックは1行だけ常時表示し、詳細は展開。相手の手番中(待ち時間)に読める内容をそこに置く。
8. **理由なき分類ラベルは信頼を損なう**(Chess.com フォーラム、ChessKid)。【仮説】「〜の可能性があります」だけでなく「そう言える根拠(盤上の事実)」を必ず添えることで、説明の浅さを事実の提示で補える。
9. **名前は完成した瞬間に出す**(ウォーズ)。【調査結果】CLAUDE.md の「認識が段階に達してから名前を出す」と同じタイミング設計。ウォーズは名前だけで説明がなく、本アプリは「何が完成したか+それが何を意味するか」を添える差別化余地がある。
10. **表記慣習への準拠**(新聞式座標、駒のひらがな切替、移動可能マス表示)。【調査結果】現行UIは筋=算用数字・段=漢数字の新聞式を既に採用している。

### 2.5 情報階層・視線誘導・盤と説明文の関係

- 【調査結果】盤は左、文章は右。文章から盤への参照は「８八の角」「７九のと金」のような座標表記のみで、**盤上に対応する印は出ない**([0] の当たり・[1] の取られた駒・[2] の認識の根拠マスのいずれも盤上表示なし)。盤上に描かれるのは、相手の直前の手(青枠)と候補手(薄い破線矢印)だけ。
- 【調査結果】`docs/PHASES.md` Unit 3 の方針は「盤面上の対象駒 → 移動元を強調 → 移動先を矢印 → その下に『なぜ』」「認識結果についても根拠になったマス・駒を盤上で示せるようにする」だが、実装されているのは候補手の矢印までで、根拠マスの盤上表示はない。【現行仕様】として未実装の範囲。
- 【調査結果】候補手の破線矢印は不透明度 0.55・線幅 1.5px の灰色で、1280×720 のスクリーンショットでは注視しないと見えない(実機検証レポートは「薄い序列は保たれている」と評価しており、意図的な弱さである)。
- 【調査結果】[0]「今すぐ対処が必要なこと」だけが赤い見出し+淡赤の枠で、視覚的に最強。ただし内容は【現行仕様】(STEP 4-3 承認記録 A)「利きが届いているという幾何の事実。取り返しの可否・守りの有無は考慮も言及もしない」である。**見出しは評価語(今すぐ対処が必要)、本文は非評価の事実**という組み合わせになっている。

## 4. デザイン原則(提案)

以下はすべて【提案】。採用・修正・却下は人間の判断。

1. **盤が第一の説明である。** 文章は盤の注釈として書く。[0]〜[4] のどの文も、対応する駒・マスが盤上で示せるなら示す(Unit 3 方針の徹底)。
2. **一手につき、主メッセージは一つ。** その手で変わったブロックだけを強調し、変わらなかったブロックは静かにしておく(ChessKid の反面教師)。
3. **順序を目に見える形にする。** 「起きた → 狙い → 目的 → 理由 → 指す」が上から下・左から右に一続きの導線として見えるよう、番号・接続線・段階的な強弱を使う。
4. **事実と推測を視覚的に分ける。** 事実(取られた・利きがある・完成した)は実線・濃色。認識・推測(〜の可能性)は破線・薄色。文の語尾だけでなく見た目で区別する。
5. **空状態を設計する。** 分からないときは1行で言い、代わりに「今できること」(駒を動かして形を作ると認識が始まる、など)を出す。「分からない」を4回言わない。
6. **要約 → 展開。** 各ブロックは1行の要約を常時表示し、詳細は展開。待ち時間(相手の手番)に読めるものは展開側に置く。
7. **用語はその場で。** 用語が出た場所で短い説明(ツールチップ/脚注)。名前は認識が段階に達してから(CLAUDE.md)。
8. **行動までの距離を最短に。** 「次の一歩」は常に1画面内、盤の近くに置く。操作できることを見て分かるようにする。
9. **断定しないが、曖昧にしない。** 「〜の可能性があります」には必ず根拠(どの駒・どのマス)を添え、盤上で示す。
10. **名前と中身を一致させる。** ブロックの見出しは中身の性質(事実/推測/操作)と一致させる。事実しか言わないブロックに評価語の見出しをつけない。

## 5. デザインコンセプト案

3案と、比較のための「現状維持」を並べる。すべて【提案】。いずれも**5ブロックの情報内容・文言規約・将棋ロジックは変えない**前提で、「見せ方」だけを変える案である。

### 案A「盤が語る」(盤面注釈型)

- **コンセプト**: 盤が主役。[0]〜[4] の各文に対応する印(番号つきマーカー)を盤上に描き、文章パネルはマーカーの「キャプション」になる。文中の駒・マスをタップ/ホバーすると盤上の印が強調される(Chess.com v2 型)。
- **長所**: 思想「盤面で何が起きているかを自然に理解」に最も直結。座標を読めなくても位置が分かる。Unit 3 方針の延長線上。
- **短所**: 盤上に印が増えると混雑する(候補手の矢印・直前の手・当たりが同時に出る局面)。マーカーの語彙(色・形)の設計と凡例が必要。相手の駒の赤と「危険の赤」の衝突。
- **初心者への効果**: 高い。「８八の角」を探さずに済む。
- **将棋盤との相性**: 高い(SVG オーバーレイの仕組みは既にある)。
- **実装難易度**: 中。サーバーは既に座標を返している(当たり・取られた駒・道のりのマス)。フロントのオーバーレイ拡張が中心。
- **将来的な拡張性**: 高い。相手の狙いの根拠マス、利きの範囲、時系列の再生にも同じ語彙を使える。

### 案B「要約と展開」(段階開示型・現行構造の改善)

- **コンセプト**: 現行の5ブロックと3カラムを維持しつつ、各ブロックを「1行要約(常時)+展開(任意)」にし、番号(①〜⑤)と接続線で順序を可視化する。空状態は1行に圧縮。候補手ブロックを盤の直下へ移す。
- **長所**: 変更が最小。DOM の順序と文言はそのまま。1280×720 と スマホの高さ問題を直接解く。
- **短所**: 盤と文の接続(D-問題2)は解けない。要約行の文言を新たに決める必要がある(文言は人間承認事項)。
- **初心者への効果**: 中。読む量は減るが、盤で探す作業は残る。
- **将棋盤との相性**: 中(盤には触れない)。
- **実装難易度**: 低〜中。CSS と折りたたみの追加が中心。
- **将来的な拡張性**: 中。案A・案Cと組み合わせられる土台になる。

### 案C「隣に座るコーチ」(時系列コーチ型)

- **コンセプト**: 一手ごとに「コーチのひとこと」カードを1枚だけ生成し、対局の流れを時系列(縦フィード)で見せる。5ブロックは「その手で変化したもの」だけをカードに含める。Unit 2 の `recognitionTimeline`(本番未接続)をそのまま供給源にできる。
- **長所**: 「今、何が変わったか」だけを見る設計(Duolingo・Lichess LFYM 型)。「相手の狙いが何手目からそう見えるか」の文脈が残る(実機検証Bの「対局全体の文脈が反映されない」に応える)。
- **短所**: 構造の大きな変更。「今の局面の静的な状態」([0] の当たり、[4] の道のり)はフィードと相性が悪く、別枠が必要。過去のカードが積み上がり、現在地を見失う危険。
- **初心者への効果**: 中〜高(理由の連続性は高いが、現在の状態の一覧性は下がる)。
- **将棋盤との相性**: 中。カードから過去局面を再生する仕組みが必要。
- **実装難易度**: 高。フロントの構造と API(時系列の露出は Unit 4 の責務とされている)の両方に及ぶ。
- **将来的な拡張性**: 高。対局後の振り返り・「指す前の目的申告」との照合と自然に接続する。

### 案D「現状維持」(比較用)

- **コンセプト**: 現行の5ブロック・3カラムを維持し、STEP 4-6(重複の削除)・4-7(入力欄・SFEN)で文言・不具合だけを整理する。
- **長所**: 開発中の STEP と衝突しない。文言規約は守られている。
- **短所**: D-問題1・2・3・7・8 が残る。特に「次の行動が最も遠い」「盤と文が接続しない」は思想と直接ぶつかる。
- **初心者への効果**: 低〜中。

## 6. 推奨案

【提案】**案A(盤が語る)を中心に、案B(要約と展開)の情報配置を組み合わせる。案C は将来の拡張(振り返り・目的申告との照合)として、履歴の見せ方に部分的に取り入れる。**

### 6.1 理由

1. 最上位の問い「思想を初心者に最も自然に伝えるUI」に対し、思想の起点(今、盤で何が起きたか)を**盤上で見せる**ことが最も直接的な答えである。文章は補助に回す。
2. 5ブロックの内容・順序・文言規約(断定しない、目的→手→理由)は既に思想と一致している(3.4)。**変えるべきは情報ではなく見せ方**であり、案A+案Bは情報を削らず、盤への接続と配置だけを変える。
3. 進行中の Unit 4(STEP 4-3b〜4-7)は主にサーバーの事実抽出と文言の削除であり、案A+案Bはフロントの見せ方に閉じるため衝突が小さい。むしろ 4-3(当たりの事実)・4-6(重複削除)の成果を盤上表示と要約行がそのまま活かせる。
4. 案Cの利点(文脈の連続性)は、履歴の折りたたみを「認識の変化点だけの時系列」に置き換えることで一部を得られる。全面採用は API と構造に及ぶため、Unit 4 完了後に判断する方が安全である。

### 6.2 推奨案の骨子

- **盤上マーカーの語彙**(案A)。すべて事実/推測の区別(原則4)に従う。
  - 当たっている自分の駒([0]): 実線の赤い輪(事実)。相手の駒の赤と区別するため、駒の色ではなくマスの縁に描く。
  - 直前の手([1]): 現行の青枠(既存)。取られた駒があった場所: 薄い×印。
  - 認識の根拠マス([2]): 淡い塗り(推測=薄色)。完成した形は輪郭線でまとめる。
  - 道のりの目的地([4]): 破線の輪(推測・計画)。候補手: 現行の破線矢印(既存)。
  - 凡例は盤の直下に常時1行。
- **文章パネルの配置**(案B)。
  - 各ブロックは「①〜⑤の番号+1行要約」を常時表示し、展開で現行の全文を出す。要約行の文言は**既存文からの抜粋**を基本にし、新しい文は人間承認を経る。
  - 空状態は1行(例は既存文の短縮案として第8節に記す。確定は人間)。
  - 「次の一歩」(候補手)を盤の直下・操作の隣に置き、ボタンとして描く(操作対象であることが見て分かる)。道のり・分かっていることは展開側へ。
- **相互ハイライト**。文中の座標(「８八の角」)と盤上マーカーを対応づけ、ホバー/タップで互いに強調する(Chess.com v2 型)。
- **用語**。文中の用語に下線+タップで1行説明(データは第8節の課題)。

### 6.3 変えないもの(明示)

- 5ブロックの構成・順序・情報内容。[4] を操作ブロックとして独立させる方針(`docs/PHASES.md`)。
- 文言規約(断定しない、目的→手→理由、draft を断定的に見せない)。
- 将棋ロジック・判定・閾値・対象駒種。
- 相手の駒の赤・回転、座標の新聞式表記。

### 6.4 リスク

- 【仮説】盤上の印が増えると、初心者にはかえって混雑して見える。**同時に出す印の上限**(例: 事実の印は常時、推測の印は該当ブロックを展開したときだけ)を決める必要がある。
- 【仮説】要約行の文言は新しい文になりやすい。既存文からの抜粋で済むかを、実装前に文言案として提示し承認を得る必要がある。
- 【調査結果】相手の駒が赤で描かれているため、「危険=赤」を重ねると意味が衝突する。色相を分ける(例: 当たりは橙系の輪)か、駒の色を変える(慣習を崩す)かの判断が要る。

## 8. 今後のデザイン課題

### 8.1 人間の判断を要するもの

1. **読む順の番号と [0] の位置。** 提案は「起きたこと」を①にし、[0] を②にする。`docs/PHASES.md` の「王手・駒の危機を先頭に」と食い違う。どちらを取るか。
2. **[0] の見出し。** 中身が非評価の事実である以上、「今すぐ対処が必要なこと」という評価語の見出しを変えるか(例: 「相手の利きが届いている駒」)。文言は人間確定事項。
3. **盤上マーカーの色。** 相手の駒の赤と「当たり」の赤の衝突をどう解くか(色相を変える/駒の色を変える)。
4. **要約行・空状態の文言。** 既存文からの抜粋で済むか、新しい文が必要か。新しい文は人間承認。
5. **同時に出す印の上限。** 事実の印は常時、推測の印は展開時のみ、という規則でよいか。

### 8.1 への推奨(2026-09-10 追記。すべて【提案】)

人間の求めに応じ、5論点それぞれに推奨と理由を示す。決める順序は **1 → 3 → 5(構造・視覚)→ 2・4(文言)** を勧める。文言は構造が決まってから一括で承認を取る方が手戻りが少ない。

**論点1(読む順の番号と [0] の位置)― 推奨: [0] は番号を付けない「通知帯」として最上部に残し、①〜④は「起きた → 狙い → 理由 → 指す」に付ける。**
- 理由: [0] は思考の流れ(因果の連鎖)の一部ではなく、いつでも割り込みうる静的な事実である。番号列から外せば、「王手・駒の危機を先頭に」(承認済み)と「読む順は起きたことから」(提案)が両立する。
- 見え方: [0] は内容があるときだけ現れる細い帯。空のときは場所を取らず、①が最上段になる。
- 却下した案: [0] を②にする案は承認済みの優先順位と食い違い、ユーザーが王手を見落とす危険がある。

**論点2([0] の見出し)― 推奨: 見出しを事実ベースにし、王手の行だけを強調する。文言の第一候補は「いま注意する駒」、第二候補は「相手の利きが届いている駒」。**
- 理由: 中身が「利きが届いている」という幾何の事実(STEP 4-3 承認記録 A)である以上、「対処が必要」という評価語は名前と中身のずれを生む(D-問題4)。王手は本当に対処が必要なので、行単位の強調(赤・太字)で差をつける。
- 第一候補を推す理由: 短く、用語(利き)を含まず、王手・当たり・(4-5 以降の)詰みのいずれにも当てはまる。第二候補は正確だが「利き」の説明が要る。
- 補足: 当たりの行の末尾「(次の相手の手で取られる可能性があります)」は初心者向けの補足として残す。

**論点3(盤上マーカーの色)― 推奨: 相手の駒を赤から黒系(#222 程度)に変え、回転だけで先後を区別する。赤は「事実の危険」(王手・当たり)専用にする。**
- 理由: 実物の将棋盤は同色の駒を向きで区別しており、将棋ウォーズ・ぴよ将棋などの主要アプリも同色が既定である(1章)。赤い相手駒は常時「危険」の信号を出し続け、本当の危険の赤と競合する。
- 語彙: 赤=事実の危険(実線の輪) / 青=直前の手(既存の枠) / 緑の淡い塗り=認識の根拠(推測) / 灰の破線=候補(既存)。色だけに頼らず、形(輪・枠・塗り・破線)でも区別する(色覚多様性への配慮)。
- 代替(相手駒の赤を残す場合): 危険の印を橙(#d9a441 系ではなく、より濃い #c96a00 程度)の輪にする。ただし「途中」バッジの琥珀と近くなるため、第二候補とする。
- 注意: 32px のマスで回転だけで先後を読めるかは、実ユーザーテスト(8.3 の 11)で確認する。

**論点4(要約行・空状態の文言)― 推奨: 要約行は「既存文からの抜粋」を原則とし、新しい文は空状態と計算中の表示に限って、一括で承認を取る。**
- 抜粋の規則: [1] は既存の事実文の1文目 / [2] は既存のバッジ文と形の名前 / [3] は「苦手な攻め」の見出し / [4] は候補手の「駒 移動元→移動先」。これらは新しい文を作らない。
- 新しい文が要る箇所(承認候補。いずれも1行):
  - 空状態(①〜③をまとめて1行): 「まだ形も相手の狙いも見えていません。駒を動かすと、ここに分かったことが出ます。」
  - 空状態 [4]: 「形が見え始めたら、ここに次の一歩を出します。」
  - 候補手の計算中: 「次の一歩を確認しています。」
  - 候補手が該当なし: 「今の局面では、出せる次の一歩がありません。」(STEP 4-2 決定4「新しい文言を追加しない」と関係するため、人間の再判断が要る)
- 理由: 現行の「分からない」4文(約200字)を1行にまとめるのは、削除ではなく統合であり、`docs/PHASES.md` の「同じ情報を一回だけ」と整合する。

**論点5(同時に出す印の上限)― 推奨: 「事実の印は常時、推測の印は選んだときだけ、強調は一度に一つ」の3規則にする。**
- 常時出す(事実): 王手・当たりの赤い輪、直前の手の青枠、取られた駒の×印(1手だけ)。
- 選んだときだけ出す(推測・計画): 認識の根拠マスの淡い塗り(②を展開したとき)、道のりの目的地の破線の輪(道のりを展開したとき)。候補手の矢印は現行どおり薄く常時、行を押した1本だけ濃く。
- 強調は一つ: 直前の手で変わったブロックだけを強調する。王手中は候補手の矢印を出さない(STEP 4-5 と整合)。
- 件数の上限: 当たりの輪が4駒以上になる局面では、駒種の固定順(STEP 4-3 の D)で上位3件を描き、残りは文で「ほか N 駒」とする。この数値は暫定であり、実ユーザーテストで見直す。
- 理由: 案Aの最大のリスク(盤の混雑)を、印の「性質」で機械的に制御できる。事実と推測の区別(原則4)とも一致する。

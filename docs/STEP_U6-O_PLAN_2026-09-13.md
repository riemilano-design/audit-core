## 1. この STEP がやること / やらないこと

**やること**: `PvMaterialsResult`(U6-M の出力)を受け取り、**日本語の文を組み立てて返す純粋関数**を作る。決定的で、同じ入力からは常に同じ文を返す。

## 2. 入力 ― 3 種類の「無い」を最初に分ける(規則 11.6)

**司令塔の指示の 1 番。U6-M は「`null` を『無い』と読み替えるのは文を組み立てる段の責任」と明記して渡してきている。** ここで潰すと後から区別できない。

`PvMaterialsResult` は既に 2 状態に分かれている(`kind: "insufficient"` / `"measured"`)。**そのうえで、`measured` の中の各材料について 3 種類を分ける。**

| 入力の姿 | 意味 | 文の組み立てでの扱い |
|---|---|---|
| `kind: "insufficient"` | **読み筋が短くて測れなかった** | **「測っていないから言わない」と分かる文**。「起きなかった」と書いたら誤り |
| `measured` + `truncatedAtPly !== null` | **途中まで測った**(非合法手で打ち切り) | **打ち切り以降については何も言わない。**「最後まで起きなかった」と書いたら誤り |
| `measured` + 材料が `null` + `usablePlies` が十分 | **測って、無かった** | 「まだぶつからない」等、**無かったことを言ってよい** |
| `measured` + 材料が `null` + `usablePlies` が不足 | **測れる長さが無かった** | 上と同じ値だが**意味が違う**。言わない |

**したがって、この関数は `materials` だけを見てはならない。`usablePlies` と `truncatedAtPly` を必ず一緒に見る。** これを**型で強制する**(`materials` だけを受け取る関数を作らない。受け取るのは `PvMaterialsResult` 全体)。

**規則 11.6 の注記(直した直後がいちばん危ない)を踏まえ、実装後に同じ数え直しを行う** ― **この関数が返す値のうち、falsy で「無い」を表すものが何種類の「無い」を背負っているかを、実装した本人がもう一度数える**(6.4)。

### 2.1 出力にも 3 種類を持たせる(入口と出口の両方。規則 11.6)

返り値は文字列ではなく、**状態を持つ直和型**にする。

| 返り値 | 意味 |
|---|---|
| `{ kind: "not_measured", reason }` | **測っていない / 測れなかった**(短い・打ち切り) |
| `{ kind: "no_material" }` | **測ったが、文にする材料が 1 つも立たなかった** |
| `{ kind: "text", sentences: string[] }` | 文が組み立てられた |

**文字列 1 本で返して「空文字列 = 無い」にしない。** 空文字列は 3 種類の「無い」を全部背負う。

## 3. 攻め / 受けの定義(**判断的知識。既定値を置かない**)

司令塔の指示の 2 番。設計書 4.1 の定義:

> **読み筋の中で最初に駒を取ったのがどちらか。** こちらなら「仕掛ける」、相手なら「攻めてくる」。どちらも起きなければ「まだぶつからない」。

**これは判断的知識であり、CLAUDE.md ルール 4 に掛かる。** `PvMaterialRules` と同じ形で**規則として外に出し、既定値を置かない**。

```
export interface SentenceRules {
  /** 攻め/受けをどう決めるか。既定値は置かない(呼び出し側が必ず指定する)。 */
  initiative: "first_capture";
}
```

**既定値を置かないことの意味**: 呼び出し側が指定を忘れると **tsc が止まる**。既定値を置くと、**規則が確定していないのに黙って 1 つの規則で動く**ことになる(U6-F の `directionRule` が「計測用オプションとしてのみ存在し本番から到達できなかった」件と同じ轍を踏まない)。

**確定は測ってから。** 本 STEP では `"first_capture"` の 1 つだけを実装し、**確定していないことを型と文書に残す**。

## 4. 文の組み立て方(設計書 3. と 5. に従う)

**固定した分類には当てはめない**(5.1)。材料の値の**組み合わせ**から、次の 3 つの部品を順に組む。

| 部品 | 材料(`PvMaterials` の欄) | 文の例 |
|---|---|---|
| **(1) 誰が動くか** | `firstCapture`(3. の規則) | 「こちらから仕掛けて」「相手から攻めてくる」「しばらく駒はぶつからず」 |
| **(2) 何が起きるか** | `capturedRoles` / `handDelta` / `firstPromotion` / `firstCheck` / `bishopExchangePly` / `firstDrop` | 「歩を交換する」「角を交換して」「成りが入る」 |
| **(3) そのあとどうなるか** | `kingNeighborDelta` / `advanceRetreat` / `slidingReachDelta` / `kingMovePlies` | 「玉の周りの銀が 1 枚減りそうです」「玉を固めていく流れになりそうです」 |

**規約(実測に基づく。設計書 3.)**:

- **動詞主導で書く。主語は指す人**(Ac が 48.8% の文に出る)。「8 筋で取り合いになります」ではなく「攻めていく手です」
- **場所を言わない**(67.0% が場所に言及しない)。**マスの名前・筋・段・区域表現を出力に一切入れない**
- **未来は仮定の形で短く**(未来 4% / 仮定 9%)。「〜という流れになりそうです」
- **同じ文になってよい**(5.2)。複数の候補が同じ文になったら、そのまま同じ文を出す

**材料が 1 つも立たないとき**は `{ kind: "no_material" }` を返し、**呼び出し側が「測っていないから言わない」と読める文を出す**(5.4)。**「急がないから言わない」と読める文にしない**(P-23 / P-26 の扱いと揃える)。

## 6. どうやって確かめるか(**この STEP の重心**)

### 6.1 測れること(テストにする)

| # | 確かめること | 測り方 |
|---|---|---|
| **T-1** | **同じ材料から常に同じ文が出る**(決定的) | 同じ入力で 2 回呼んで文字列一致 |
| **T-2** | **材料が変わると文が変わる** | 材料を 1 つずつ変えた入力で、出力が変わることを確かめる。**変わらない材料があればそれを列挙する**(「効いていない材料」を静かに持たない) |
| **T-3** | **禁止語が 1 つも出ない** | 出力の全文に「得」「損」「有利」「不利」「互角」が含まれないこと。**`captureSummary.ts` の制約と同じ** |

| **T-7** | **`materials` だけでは呼べない** | 型の話。`PvMaterialsResult` 全体を受け取ることを型で強制する(tsc で確かめる) |

### 6.2 **測れないこと(明記する。S-5 の形)**

- **「文が自然か」は測れない。** 日本語として読めるか、初心者に伝わるか、コーパスの語り口に似ているかは、**この STEP のテストでは一切確かめられない**
- **「材料の組み合わせが将棋として意味のある区別になっているか」も測れない。** 例えば「角交換あり + 玉の周りが減る」を 1 つの文にまとめてよいかは、**将棋の判断であり、テストでは決まらない**
- **したがって、この STEP の完了は「文が良いこと」を意味しない。**「**禁止したものが出ていないこと**」と「**3 種類の無いを混ぜていないこと**」だけである
- **文の質は、(か) U6-Q で画面に出し、実機で人が読んで初めて分かる。** 本 STEP ではそこへ進まない

**「この型の穴はもう無い」と思った回数だけ、まだあった。** 実装を終えたら、**この関数が返す値と受け取る値のうち、falsy で「無い」を表すもの**(`null` / `[]` / `0` / 空文字列 / 欄が無い)を**もう一度列挙し、それぞれが何種類の「無い」を背負っているかを数える**。**2 種類以上あれば分ける。** 数えた結果は、**0 件でも報告に書く**。

### 6.5 集計を出すときは別の統計量も並べる(規則 11.5)

T-2(材料が変わると文が変わる)の結果を数字で出すときは、**「変わった材料の数」だけでなく「試した材料の総数」「変わらなかった材料の一覧」を並べる。** 目当ての数字だけだと、**入力の作り方を間違えていても同じ数字が出る。**

#### 18.7.1 決定 3 を変えた ― 打ち切り時は、材料 3 の片側の言い方を出さない

**前の決定(司令塔。規則 11.9 の形で残す)**: 扱いは変えない。理由は (1) 「こちらが○を取る」は起きたことを言う肯定の文で、事実の食い違いは 0 件 (2) 「相手は取らない」と受け取られうるのは、文が主張していることではなく**読む人の推し量り**で、18.1 の基準(不在を言う文)に当たらない (3) 推し量りはコードでは測れず、(か)と本物の初心者テストで確かめる事柄。

**B の指摘**: `capturedClauses` は、**相手がその駒を取っていないとき(不在の判定)に限って**「こちらが○を取る」を選び、両方が取っていれば「○の取り合いになる」を選ぶ。**文字列は肯定でも、どちらの言い方を選ぶかは不在の判定で決まっている。** 打ち切り時には、その判定を前半 k 手で行う。

**変えた理由(司令塔)**: 「読む人の推し量り」と書いたが、**推し量りの材料を生成器自身が作っていた。** これは 18.1 の基準(不在を言う文は、打ち切りで覆る)の中に入る。**形態素では拾えない否定である** ― 18.2 #4 の文字列リテラルの全数調査では拾えなかった。

**崩れた根拠**: 前の決定の理由 (2)「文が主張していることではない」。**言い方の選び方が、主張の一部だった。**

**新しい決定**: **打ち切り時は、片側の言い方(「こちらが○を取る」「相手が○を取る」)を出さない。「○の取り合いになる」は残す。**

- 「取り合いになる」は、前半 k 手で両方が取ったという**肯定の事実**なので、残りの手で覆らない
- 片側の言い方は「相手は取っていない」という**判定に依る**ので、打ち切りでは覆りうる
- **新しい文言は作らない。節を落とすだけ**

**実装**: `capturedClauses(counts, truncated)` に打ち切りを渡し、打ち切り時は両方が取った駒種の「取り合い」だけを出す。試験を 2 件足した ― (i) 打ち切りで片側の言い方が出ず「歩の取り合いになる」は残る(打ち切りが無ければ片側の言い方も出る、の校正付き) (ii) 母数のどの入力を打ち切りにしても片側の言い方が出ない(母数に片側の言い方がある、の校正付き)。

#### 18.7.2 決定 4 の理由を取り下げた ― 打ち切られていない読み筋の否定の文は、暫定で残す(限界として記録)

**前の理由(司令塔。規則 11.9 の形で残す)**: 「**設計の境目**」― 否定の文は「エンジンの読み筋の全体」に対してだけ言い、読み筋の終わりの先の不在は主張していない。打ち切りは、エンジンが読んだものの一部を再生できなかったこと(情報の欠落)なので外す。打ち切られていない読み筋は、設計が定めた見通しの範囲そのもの。短すぎる読み筋は `canAssertAbsence` で落とす。「しばらく」は、この見通しの範囲を示す控えめな語。

**B の指摘**: 18.1 で外した理由は「**文は範囲を読む人に示さない**」だった。**読み筋の終わりも、読む人には見えない。** 対局は読み筋の終わりで止まらないので、続きはどの読み筋にもある。**違うのはシステムが知っていることで、読む人に見えるものは同じである。**

**取り下げた理由(司令塔)**: 「設計の境目」の理由は、18.1 の理由と噛み合っていない。

**B の模擬の数字**(B の probe による。**実装担当は再計算していない**): 完全に再生できた読み筋の前半 k 手を「**k 手で終わった読み筋**」とみなすと、「しばらく駒はぶつからない」は **13 回中 13 回**、「駒はぶつかりますが、取り合いにはならない」は **172 回中 124 回**が、続きで覆っていた。

- **限界**: 短い前半に寄った模擬である。実際の読み筋の長さ(中央値 17)では、覆る割合はもっと少ない可能性がある
- あわせて、**手数不足の門(`canAssertAbsence`)で変わる読み筋は、記録では 0 本**だった(18.2 #6)。出どころは `u6o-whole-line-probe.ts` の最終行 ― 打ち切られていない読み筋 136 本のうち再生 4 手未満が 1 本、そのうち接触あり・捕獲なしが 0 本。直す前と直した後の出力(`u6o-whole-before.txt`・`u6o-whole-after.txt`)の両方に同じ行がある

**新しい決定: (iii) 限界として記録する。ただし暫定で、門を 2 つ付ける。**

- **門 1**: U6-T の段 A で読み筋の長さの分布(とくに MultiPV 5)が出たら、この露出を見直す。U6-T の予測 E-6 は「読み筋は短くなる」で、そうなると露出は増える
- **門 2**: **(か)で文を画面に出す前に、否定の文をスロット 1 に残すかどうかを必ず決める。決めないまま画面に出さない**
- **理由**: いまの文は画面に出ていない(純粋関数で、どこからも呼ばれていない)。外す (i) と、範囲を見せる文言にする (ii) のどちらを選ぶかは、**露出の量と沈黙の増え方を見てから決める事柄**である

**打ち切られていない読み筋の否定の文は、正しいと確かめたから残しているのではない。決めるための材料がまだ無いから、暫定で残している。** `pvSentence.ts` の `buildSlot1` の doc コメントにも、暫定であることと門 2 つを書いた(門を知らないまま (か) で呼ばれないように)。

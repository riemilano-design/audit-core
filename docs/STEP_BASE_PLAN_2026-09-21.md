# STEP BASE 計画: 全員に共通の基準値を出し、その人が外れている所を候補にする(2026-09-21、司令塔 e3)

人間の決定(2026-09-21「進めて」): 1 人の 20 局の中から条件を探すやり方(D3-COND §13・§15 の下見)は、2 回とも別の人で再現しなかった(D3-COND 計画 §14・§15.2・§16.2)。**向きを逆にする。まず全員に共通の率(基準値)を出し、その人の率が基準値から外れている所を候補にする。**

位置づけ: `scripts/playtest/` の開発補助(対局後診断の側)。本番導線(`apps/`)・`data/`・Gate の値(GATE_VALUES)・承認済みの条件式は**変えない**。この STEP が出すのは**候補(下見)**であって、本人向けの断定ではない。候補を本人に見せる文にするには、§4 の確かめを通す。

## 1. 何を数えるか(新しい物差しは足さない)

- 単位は Gate と同じ「手の組」(`allPairsOf`、軽い値)。**崩れ・分母・分母から外す理由は `lib/gate.ts` の `collapseTallyOf` の数え方をそのまま使う**(直前が優勢・互角で直後が決まる組が分母、1 段以上下がったら崩れ)。
- 組を**あらかじめ決めた枠**に分ける。枠は記録にすでにある欄だけで決まる(D2.6 の `userMoveFacts`・`standingPair`・手数)。**枠はこの計画で固定し、結果を見てから足さない**(409 通りを探した §15 の反省)。

### 1.1 枠(全部で 24。1 つの組は軸ごとに 1 つの枠に入る)

| 軸 | 枠 | 決め方 |
|---|---|---|
| A 直前の形勢(2) | 優勢 / 互角 | `standingPair.before` |
| B 時期(3) | 早い / 中 / 遅い | 組の手数 ÷ その局の総手数を 1/3・2/3 で割る(回す前の手数。`reportData.ts` の `phaseOf` と同じ基準の一方に合わせ、どちらかを明記する) |
| A × B(6) | 優勢・早い … 互角・遅い | 上の掛け合わせ |
| C 手の種類(7) | 打つ手 / 駒を取る手 / 成る手 / 玉を動かす手 / 自玉のそばへ動かす手 / 相手玉のそばへ動かす手 / どれでもない手 | `userMoveFacts` の `drop`・`capturedRole ≠ null`・`promotion`・`kingMove`・`toInOwnKingZone`・`toInOpponentKingZone`。C は重なってよい(打って王手のそば、など)。「どれでもない」は 6 つとも偽 |
| A × C のうち優勢の側(6) | 優勢・打つ手 … 優勢・相手玉のそば | 「どれでもない」を除く |

判定できない組(欄が null・手が欠けた)は、その軸の枠に入れず、件数を別に出す。

## 2. 出すもの

道具 `scripts/playtest/baselineTable.ts`(純粋関数は `lib/baselineTable.ts`)。

```
npx tsx scripts/playtest/baselineTable.ts --person <pN> --material <その人の段 2 の記録 …> --pool <pM>=<記録 …> [--pool <pK>=<…> …] --out <baseline.json>
```

- **基準値の側(pool)**: その人を**除いた**全員の組を合わせた、枠ごとの 崩れ / 分母 と率。人ごとの内訳も出す(1 人が基準値を引っぱっていないかを見るため)。
- **その人の側**: 同じ枠ごとの 崩れ / 分母 と率。
- **外れの印**: 枠ごとに、次の 3 つを**全部**満たすときだけ `candidate: true`。**値は GATE_VALUES の同じ名前の値を読む(新しい数を作らない)**。
  1. その人の分母 ≥ `minTruePairs`(10)、かつ崩れのある局 ≥ `minGames`(3)
  2. 率の比 ≥ `minRateRatio`(2)、かつ差 ≥ `minRateDiffPoints`(10 ポイント)
  3. pool のどの 1 人と比べても、その人の率のほうが高い(1 人だけが低くて基準値が下がっているのではない)
- 逆向き(その人のほうが**低い**)は `lower: true` として同じ基準で出す(「崩れにくい所」も事実として使える)。
- 標準出力は Markdown の表(枠 × その人 / 基準値 / 人ごと)。名前・手・局面は出さない。
- `records/` へ書かない。エンジンを使わない。

## 3. 基準値の材料と限界

- いま使えるのは、2 人目 20 局(`records/real-02`・`real-03`)、1 人目 10 局(`records/real-01`・`real-03` の g3。**g3 の中身は件数だけ**)、公開棋譜の 3 人 × 30 局(gitignore の `out/lishogi-run/`。検証専用)、2 人目の新しい 3 分 14 局・10 分 10 局(gitignore)。
- **持ち時間がそろっていない。** 基準値には持ち時間の欄を付け、そろわない比べには「参考」と書く。持ち時間別の基準値は、データが増えてから。
- 棋力帯も 5 級〜初段で幅がある。人ごとの内訳を必ず出すのはこのため。

## 4. 確かめ方(候補を本人向けの文にする前に)

- **同じ人の次の棋譜で再現するか**を見る。2 人目なら、材料 = 前の 20 局、確かめ = 新しい 3 分 14 局(もう手元にあるが、**組の欄はまだだれも見ていない**)。
- 手順: (1) 材料の側だけで §2 を回す → (2) `candidate` の枠ごとに、確かめの側の 崩れ / 分母 の**予測を先に書いてコミット** → (3) 確かめの側を回す → (4) 照合を記録。
- 「再現した」の基準: 確かめの側でも、その枠の率が基準値の率より高く、かつ分母 ≥ `minTestTruePairs`(3)。**これは Gate の G-4 と同じ考え方を、別の人でなく同じ人の次の棋譜に当てたもの**である。`gate.ts` 自体は変えない(材料と試す側が同じ人だと止まる作りは、そのまま)。
- 再現しなかった候補は、棄却として記録に残す(公開棋譜の人のぶんは件数だけを計画書に)。

## 5. 体制

1. この計画をコミット(docs のみ、司令塔)。
2. 実装は使い捨ての実装担当(worktree)。試験はエンジンを起こさない。合成の組で、枠の振り分け・外れの 3 条件・pool からその人を除くこと・判定できない組の扱い・GATE_VALUES を読んでいること(値を変える変異で落ちる)を見張る。
3. 独立の監査 1 回。GO の後に司令塔がコミット。
4. 司令塔が §4 の手順で 2 人目に当てる(予測 → 実行 → 照合)。公開棋譜の 3 人にも当て、件数だけを記録する。

## 6. やらないこと

- 枠を結果を見てから足す・割り直すこと。足すなら計画を改めて、予測からやり直す。
- 候補を、§4 を通さずに本人向けの文にすること。「癖」「傾向」「弱点」などの語は §4 を通っても使わない(レポートの語の規則のまま。書けるのは「この 20 局では、同じくらいの棋力の比較対象より、この場面で形勢が下がった割合が高かった」まで)。
- 統計の検定を新しく持ち込むこと(いまは Gate と同じ、件数の下限・比・差だけ)。
- Gate の値・承認済みの条件式・`gate.ts` を変えること。

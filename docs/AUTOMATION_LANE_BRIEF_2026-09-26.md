## 0. 何をするレーンか

**冊子 1 冊を作る 9 つの段のうち、席が手でやっている部分を道具に移す。** 出口は「席の時間 5 時間 → 3 時間(堅い線)→ 2 時間(役の型化が当たったとき)」。**人間の時間を減らすためではない**(もともと 1 時間前後で詰まっていない)。**減らすのは席の直列**で、返ってくるのは**同時に受けられる件数と、1 冊が出るまでの日数**。

## 1. 先に頭に入れる 2 つ

**(1) 出力は再現しない。通るか落ちるかは再現する。** 役(LLM)の文は毎回違う。品質は「同じ文が出ること」では担保していない。担保しているのは**門**(写しの白いリスト・仮説の契約 H-1〜H-8・`check_answer.py`・二本立ての照合)で、門は決定的。**この 4 つを通らない経路を作らないこと**が、このレーンの最優先の制約。

**(2) 今日いちばん大きい発見(§10)**: それまで「人間の判断」と記録していたものは、**人間が完成した PDF を外部 LLM に見せて返ってきた講評を中継したもの**だった。効いたのは人間であることではなく**位置**(完成物しか見ていない・作った経緯に未練が無い・規則を渡されていないので「顧客に伝わるか」を見る)。**だから文脈ゼロの批評席として自動化できる。**

1 ページに描ける候補を何件まで載せるか。**人間の意向は「3 か 2」**。司令塔の測定と推し(2026-09-26):

**母集団を必ず併記すること**(納品レーンの指摘。今日いちばん多く踏んだ型 = 族 F-1):

- **描けるものがある 80 局面**だけを分母にすると **中央値 3・平均 3.00**
- **最大 8 はどちらの分母でも同じ**

**上限を決めるのに使うのは後者(80 局面)** ― 上限は「図を出す局面」にだけ効くため。**ただし顧客向けの文で数を書くときは、どちらの分母かを必ず書く。** 上限 2 → はみ出す局面 **43/80(54%)**・落ちる候補 100/240(42%)。上限 3 → **24/80(30%)**・57/240(24%)。**推しは 3**(2 は半分以上の局面で必ず何かを隠すことになる)。**ただし紙面は測っていない** ― 盤の図が 3 つ並んで収まるかは、Phase 2 で最初の 1 ページができた時点で確かめ、収まらなければ 2 に落とす。

**上限だけでは足りない。あと 2 つ決まっていない**: (a) **何を基準に落とすか**(順位の上から 3 つでよいか。順位が信用できないなら「恣意的に 3 つ」になる) (b) **落としたことを顧客に伝えるか**(黙って 24% を捨てると「道具は 3 件と言ったが本当は 8 件あった」という食い違いになる ― 今日の `figure` と同じ型)。**3 つとも閾値なので人間が決める。**

## 4. このレーンが守る縛り

- **やってはいけない自動化**: 役の出力をそのまま冊子に流す / 独立監査を省く / **その場で組んだ確認を門にする**(族 F-3。門は `npx vitest run --root scripts/playtest` と `npm run typecheck:scripts` の **2 本だけ**。`out/` 配下の下書き 10 件の赤は既知 P-84。根で vitest を回すと別の席の写しを拾う P-88)。
- **採否の自動化は種類で分かれる**: **数に触る**指摘は再 PDF で `check_answer` と照合が走るので自動化してよい。**文言・構成・順序**には**決定的な門を置けない**ので、**根拠を書く席が残る**(人間である必要はない)。
- **人間に上げるのは 3 つだけ**: (1) 門が落ちた (2) 批評席の指摘に**数に触るもの**が出た (3) **再 PDF が 2 周を超えた**。
- **試験の件数は絶対値で判定しない。**(2026-09-26、開発・診断レーンの実例。族 F-1 の枝)**共有ツリーでは、他の席が同じ時間帯にコミットした分だけ絶対値が動く** ― P-104 の実装中に `scripts/playtest` の件数が 1765 と 1768 に割れ、差は自動化レーンが別件で足した 3 本だった。**「前 → 後 → 差」を同じ実行で測り、判定には差を使う。**「絶対値が記憶と違う」を不具合と読まない。**監査へ渡す申し送りに先に書く**(読み違えた REVISE は往復 1 回ぶんの無駄になる)。
- **測っていないものは承認しない。** 「直したはず」「通ったはず」で承認しない。
- **他の席の見立てを根拠にしない。実物を自分で測る。**(今日 3 回効いた)
- **コミットはパス指定**(`git add -N` → `git commit -F - -- <paths>`。`git add` は並行セッションでステージが混ざる)。
- **予測は実測の前に書く。** 件数の期待値を先に書いてから回す。

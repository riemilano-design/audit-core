# 役割分担

## 人間(あなた)が判断すべき事項

以下は、AIエージェントに任せず、必ず人間が決める。

- **将棋知識の正しさ**: shapes/openings/intentsの内容が将棋として正確か。特に `confidence_level: low` としてAIが下書きした内容の最終承認。AIは既存スキーマに準拠した新しいレコード(**記述的知識**)を未レビューの下書き(`review_status: draft`)として件数の制限なく追加してよいが、それを `human_reviewed` に上げる判断は人間が行う。スキーマの形式を変える知識(**構造的知識**)、判定結果・優先度・閾値・安全性・ゲーム挙動を変える知識(**判断的知識**)は、人間の承認なしに確定しない。区分の定義は [DATA_MODEL.md](DATA_MODEL.md)
- **スコープの変更**: MVPの対象戦型・目標形を広げる/変える判断([../CLAUDE.md](../CLAUDE.md) の「現在のスコープ」を書き換える判断)
- **Phaseの完了判定**: [PHASES.md](PHASES.md) の各Phaseを「完了」として次に進んでよいかの最終判断
- **`main`ブランチへのマージ**: [GIT_WORKFLOW.md](GIT_WORKFLOW.md) のセルフレビューを経た上での、マージの実行
- **UI・説明文のトーンの最終確認**: 「初心者にとって本当にわかりやすいか」の感覚的な判断
- **予算・外部サービスに関わる意思決定**: LLM APIの利用開始、有料サービスの契約など
- **定跡データの調達方針**: どの書籍・データベース・棋譜を参照するか、有段者によるレビューを挟むかどうか(現時点の判断: shape座標の一次資料確認は**保留中**であり、有段者による確認が取れるまで既存データを `expert_verified` にしない。[DATA_MODEL.md](DATA_MODEL.md))

## AIエージェントが自動化してよい事項

- コードの実装(担当範囲は `.claude/agents/*.md` を参照)
- スキーマに準拠したデータ(記述的知識)の**下書き**作成(`review_status: draft` として件数の制限なし。ただし未レビューの知識を、戦法・陣形・狙いの名前としてユーザーへ断定的に見せない。[DATA_MODEL.md](DATA_MODEL.md))
- テストの作成・実行
- ドキュメント間の整合性チェックと、[CHANGE_MANAGEMENT.md](CHANGE_MANAGEMENT.md) のルールに沿った関連ドキュメントの更新
- 軽微なリファクタリング・バグ修正
- 定型的な進捗確認(Phase完了条件との照合など。ただし完了の確定は人間が行う)

## セッションを分ける場合の考え方

複数のClaude Codeセッション(またはエージェント)を並行させる場合、**担当ディレクトリで分離**し、同じファイルを複数セッションが同時に編集しないようにする。ブランチも担当ごとに分ける([GIT_WORKFLOW.md](GIT_WORKFLOW.md))。

| 担当領域 | 対応する `.claude/agents/` | 主なディレクトリ |
|---|---|---|
| 将棋知識データの下書き | `shogi-content-curator` | `data/` |
| コーチングロジック(形判定・意図推定・経路計画) | `coach-logic-dev` | `apps/server/src/analysis/` |
| 将棋エンジン連携 | `engine-integration` | `apps/server/src/engine/` |
| 画面・UI | `frontend-ui` | `apps/web/` |
| ドキュメント・仕様の整合性維持 | `docs-spec-guardian` | `CLAUDE.md`, `docs/` |

各エージェントの詳細な責任範囲・やって良いこと/悪いことは、このファイルではなく `.claude/agents/*.md` 本体を正とする(重複を避けるため、ここでは表のみ)。

## 責任範囲が曖昧なとき

「これはどのエージェントの担当か分からない」という変更が出てきたら、まず `docs-spec-guardian` に判断させ、必要であれば本ファイルと `.claude/agents/*.md` を更新する。それでも決まらない場合は人間に確認する。

## 3. 指標(本体 §4 の E1〜E5 をこの実験の分母で書く)[提案]

分母の記法: **L** = 根拠ラベルが確定した Claim(層 P 111 + 第 2 便の確定分、層 R 73)。**G(腕)** = その腕が GROUNDED にした Claim ∩ L。

| 指標 | 分子 | 分母 | 「完璧に動いたら」 | 「全部止めたら」 |
|---|---|---|---|---|
| **E2-件数** | G(腕) のうち pointer の (要素, context) の集合がラベルと一致しない Claim | **L**(固定) | 0 | 0(← これを安全と読まないために E1' と同じ表に) |
| **E2-率** | 同上 | **G(腕)** | 0 | 0/0 |
| E1'(根拠まで正しい通過) | G(腕) のうち一致 | L | |L| | 0 |
| E3(誤停止) | L のうち停止(VALUE_MISMATCH / UNVERIFIABLE / POINTER_NOT_FOUND) | L | 0 | |L| |
| E3'(束縛は当たっていた誤停止) | E3 のうち pointer がラベルと一致 | L | 0 | ― |
| 形違い | 対 vs 単一など、ラベルと形が違って一致を判定できない | L | 0 | ― |
| **型 5 露出別** | 上の全部を「同値の他の候補あり(層 P で 53/111)/なし」で層別 | 各層 | ― | ― |

一致の定義: pointer 文字列 `xbrl:<prefix>:<要素>@<context>` を (要素, context) に分解し、ラベルの fact 集合(役割は無視)と**集合として一致**。同値類は**使わない**(第 1 便で 111/111 が厳密一致だったので不要。使うなら別の封)。対の pointer は 2 本とも一致で一致。

## 追記(2026-10-13、**§5 の帯を封じた後**)

**この追記より前の内容の sha256 は `0353ad8206bba266213cc27fd9f2654144a2c19185e0493675905eed6d3c2415`**(`commander_only/prereg_sha256.txt`)。**§1〜§7 は 1 文字も変えていない。** 以下は、既に記録されている main の出力と独立ラベルの突き合わせ([e2_first_measurement_A0_2026-10-13.md](e2_first_measurement_A0_2026-10-13.md))で分かったことによる、**実行前に足すべき欄**の提案である。帯(§5)は変えない。

1. **層を 1 つ増やす**: §3 の全指標を「**値を持つ形**(単一・差・和)」と「**値を持たない形**(符号・方向・率・ポイント差)」で層別する。後者は同じ向きに動く要素対が 45 件あり、根拠の正誤が規約無しでは決まらない。**E2 の主分母は前者**とし、後者は件数だけ出す。層 P の確定ラベル 111 件の内訳は 82 / 29。
2. **pointer の解析規則を §4 に明記する**: `xbrl:<接頭辞>:<要素>@<context>` の接頭辞に**数字とハイフンを含む会社独自要素**(`jpcrp030000-asr_E36539-000`)が在り、対・方向の pointer は **` + ` で連結した複合文字列**(末尾に `builtin:sign(cur-prior)`・`builtin:flow_sign(cur)==direction`・`formula:a-b`)である。採点器はこの 2 つに対応し、**解析できなかったトークンを 0 件と数えず、件数を印字して停止する**。
3. **恒等・変異の検査を §6 のとおり実行前に行う**(ラベル採点器では実施済み: 恒等 117/117・変異 4 本とも検知)。
4. **突き合わせ不能の件数を先に書く**: 確定ラベル 111 件のうち、既存の記録で突き合わせできたのは 79 件。**残り 32 件は GROUNDED だが pointer が記録されていない**ため、2a の engine 実行が必要。これが 2a を行う直接の理由である。
5. **E2 の数は同値類規則の承認で 0 と 2 の間を動く**(GROUNDED 17 件中 2 件が Summary 対)。**§5 の帯の判定は、人間が同値類規則を承認した後に、どちらの定義で判定するかを明記してから行う。**

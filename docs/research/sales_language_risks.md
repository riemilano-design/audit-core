## 1. E1〜E4「判定に AI/LLM を使わない」の検討

### 1.1 Audit Core の実際の処理境界と矛盾しないか

**矛盾しない、と言える範囲**:
- 照合の述語は決定論的。`audit-core/adapters/xbrl/instance.py:facts_for`(要素の完全一致 → 部分一致)、`vocabulary.py:match_value`・`tol_of`、`extract.py:subject_of`(最長一致)はいずれも Python の規則で、LLM を呼ばない(**独自確認: コードを読んだ**)。
- 4 状態への分類も決定論。
- 「数の主張」を抜く経路は正規表現(`xbrl_probe.py` 系の文書に明記)。

**誤解を招きうる点(リスク)**:

| R | リスク | 根拠 |
|---|---|---|
| **R1** | **「判定」の範囲が聞き手に伝わらない。** Audit Core には 2 系統の入口がある ― (a) 正規表現で機械が主張を抜く経路、(b) **LLM が「この数は証拠のどこから」と自己申告した内容を照合する経路**(営業資料 `:50` の「形 B」)。(b) では**どの数を主張として立てるか・どの証拠を指すかを LLM が決めている**。判定そのものに AI は入らないが、**判定の入力の構造化に AI が入る**。この区別を言わないと「AI の誤りは全部機械が捕まえる」と読まれる | 営業資料 `:50`。比較表 §2.1 |
| **R2** | **LLM が申告しなかったものは照合されない。** VERITYGATE は同じ性質を論文の限界として書き、rater 研究で実例を挙げた ― 「the LLM emitted **empty cited fields** and the verifier had nothing to check」(3 名の rater が NO としたのに検証器は YES)。Audit Core でも「数の主張として抜けなかった行」は照合されない | VERITYGATE Appendix A(**論文記載**)。Audit Core 側の既知の型(門が審査していない文が顧客に届く)と同型 |
| **R3** | **語彙の最長一致が「別概念を当たりにする」経路が実測で在る。** S100Z4Q1 の行見出しで、「流動資産合計」「固定資産合計」「無形固定資産合計」「投資その他の資産合計」がいずれも語「資産合計」に当たり、要素名の部分一致(`"Assets" ⊂ "CurrentAssets"` 等)も通る。本番は `exact or loose` なので同じ context に exact が在れば発火しないが、**「決定的」は「正しい」を意味しない** | `edinet_taxonomy_findings.md` §4.4(**独自確認**) |
| **R4** | **「判定に AI を使わない」は、精度の主張として読まれうる。** 決定論であることは**再現性**の主張であって、正しさの主張ではない。VERITYGATE は倫理節でこの区別を運用義務として書いている(§1.3) | VERITYGATE Ethical Considerations(**論文記載**) |

### 1.2 提案する言い換え(案。採用は人間の判断)

- 「判定に AI を使わない」→ **「照合と 4 状態の判定は決定論的な規則だけで行い、LLM を呼びません。したがって同じ入力に同じ答えが返り、理由(契約)が監査証跡として残ります。」**
  - 得るもの: 主張が「再現性と監査証跡」に限定され、精度の主張と混ざらない。
  - 失うもの: 1 文の切れ味。
- 形 B を説明するときは **「LLM が『この数はここから』と申告した内容を照合します。**申告しなかった数は照合の対象になりません**」**の 1 文を添える。
  - 根拠: VERITYGATE が同じ性質を論文の限界として明記しており、**聞かれる前に言った方が強い**。

## 2. E5「3 つ揃いが無い」の検討 ― **今回の調査で最も影響の大きい点**

営業資料 `:113` の空白の主張は 3 本足:
1. 決定的な照合
2. 判定不能を判定不能として出す
3. 判断は人が承認した表から選ぶ

**調査で分かったこと(論文記載)**

| 足 | VeriFin | VERITYGATE | 判定 |
|---|---|---|---|
| 1 決定的な照合 | **ある**(Z3。接地と認可が決まった後は決定論) | **ある**(4 門。「no LLM is involved」) | **2 本とも埋まっている** |
| 2 判定不能を出す | **ある**(Abstain を「明示的な財務統制の決定」と位置づける。XBRLFiling で 1.2%、FinanceBench で 19.4%) | **ある**(permissive emission。落ちた claim を出さない) | **2 本とも埋まっている** |
| 3 人が承認した表から行動を選ぶ | **無い**(修復のため LLM に戻す) | **無い**(修復のため LLM に戻す) | **この足だけが残る** |

> **R5(重い)**: 営業資料 `:113` の根拠説明は「形式手法を持つ AWS は対象が散文から抽出した規則。監査系は決定的だが AI の出力を見ない。評価系は AI の出力を見るが LLM で判定する」だった。
> **VeriFin と VERITYGATE はこの 3 分類のどれにも入らない。** 両者とも **AI の出力を見て・決定的に判定し・判定不能を出す**。
> したがって **「1 と 2 の組み合わせが無い」はもう言えない。** 空白として残るのは **(a) 3 本目の「人が承認した行動の表」と、(b) 領域(日本 EDINET)** である。

**提案(案。採用は人間の判断)**: E5 を次の形に狭める。
- 「今回調査した主要製品では確認できなかった」の形は維持しつつ、**学術研究については『2026 年に同じ 1+2 の組み合わせを持つ研究が 2 件出ている(VeriFin 2026-08、VERITYGATE 2026-09)』を先に言う。**
- 空白として言うのは **3 本目 + 日本の EDINET 対応**に絞る。
- 根拠: E8 が既に「世界初は完全に捨てる」と決めているので方向は一致している。**E5 はその決定が E8 ほど徹底していない箇所**。

## 4. 論文が裏付ける範囲(使える表現)

**使える(論文記載を根拠にできる)**

| 言えること | 根拠 |
|---|---|
| 「LLM に正しい式と接地済みの値を**プロンプトで渡しても、強制にはならない**」 | VeriFin: Judge+Formula が VeriFin と同じ式を受け取って 92 件中 **75 件**の誤りを受理。「providing financial context during prompting as linguistic context is not equivalent to enforcing it」(p.7) |

## 7. まとめ ― 分離した 2 つの範囲

**論文が裏付けるのは「問題が実在し、LLM-as-judge では足りず、決定論的な照合に意味がある」という方向まで。**
**Audit Core の実測が裏付けるのは「実物の EDINET 書類 3 件で 4 状態の照合が回り、21/213 の写し間違いを捕まえた」という事実まで。**
この 2 つの間にある「だから Audit Core が優れている」「誤受理が無い」「世界初」は、**どちらも裏付けていない**。

**人間の判断を仰ぐべき点(本調査では変更していない)**
1. E5「3 つ揃いが無い」を 3 本目 + 領域に狭めるか。
2. E1〜E4 に「判定の入力の構造化には AI が入りうる(形 B)」の 1 文を添えるか。
3. 「合っている」を「提出された XBRL の fact と一致している」に替えるか。
4. 約束の表に「敵対的な誘導の対策ではない」を足すか。

## 3. 問い 3: 型 5 の人手候補と判定者間の不一致

### 3.1 候補の作り方 [事実 + 意見]

- 「同じ値を持つ別の fact」は人手で作る必要が無い。`grounded_binding_check` の method_notes (3) が既にやっている: instance の 863 fact に engine 自身の梯子(`_match_value`: round 半単位 / truncate 0〜1 単位 / abs 版、百万円)を当てて (要素, context) で数える。値を持つ 44 件中 **14 件が 2 件以上**、N219 は 1 件しか無いのに誤り(正しい fact が存在しない型)。
- 推奨する候補集合(機械生成、封じた手順で): Claim ごとに「梯子で一致する fact 全部」から**独立ラベルの正解(同値類込み)を除いたもの**。これが型 5 の候補。加えて VeriFin で観測した 2 型を機械で足す: **×1000 / ×1/1000 の fact**(単位違い)と**符号反転の fact**(当期−前期の向き違い)。
- 人手が要るのは候補ではなく**正解**で、それは §1.2 の構造化(16 行の第 2 読者)と §2.2 の無作為標本のラベルだけ。

### 3.2 不一致の扱い [事実 + 意見]

- 現行の規則(D-012、`independent_truth` の limits)がそのまま使える: **判定不能を正解にしない / 2 巡目は 1 巡目を上書きしない / 席間の一致は記録だけ**。1 巡目 3 席の不一致は「判定不能」に落ちており、多数決はしていない。
- 推奨: 読者 2 席(記憶なし、engine の状態・既存の札・他席の答えを渡さない)。**一致 → ラベル。不一致 → 判定不能(E4)として件数を出す。第 3 席で裁定しない**(第 3 席は 2 席の答えを見るので独立でなくなる)。不一致の行は id と両席の答えを残し、同値類規則の改訂の材料にする(規則の改訂は**次の封**であり、読み直しに遡って当てない)。
- 材料の形は 2 巡目の形(当期側/前期側/差の計算/形)を使い、**率の欄を足す**(limits の 4 点目: 2 巡目の材料に「率」が無く席ごとに扱いが割れた)。T023/T038 型(率 vs 額)はこの欄が無いと必ず割れる。
- 席に渡すファイルの note に伏せた対象の名前を書かない(再監査 A の材料で「真 × VALUE_MISMATCH 33 件」が漏れた)。説明は司令塔側の別ファイルへ。

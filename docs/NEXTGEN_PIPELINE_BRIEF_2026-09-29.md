## 2. 人間に決めてもらうこと(今の規則に触れる所だけ)

1. **分析段階の禁止事項をどこまで外すか。** CLAUDE.md 規則 8 の (3)「手の目的を列挙しない(内部でも)」と (2)「複数 LLM の一致を証拠にしない」は 2026-09-25 の決-A/B/C。構想 ④「自由に分析」は (3) を内部では緩める案に読める。**案**: 内部の分析では目的の言葉を許し、**顧客に出る文では今のまま禁じる**(規則 5 の (1)〜(4) は不変)。(2) は残す。(4)「名前は data/ の認識だけ」は残す(LLM が戦型名を付けない)。
2. **行動の採用の決め方。** 今は「承認済みの表から選ぶ」(規則 5 の (2))。構想 ⑤ は「既存の表にない行動候補」も出す。**案**: LLM の行動候補は「候補」として人間に上げ、人間が表に足したものだけが冊子に出る(表が顧客ごとに育つ)。自動で冊子に入るのは表に在る行動だけ。
3. **読者席の位置づけ。** 構想 F: 席を回すこと自体を品質保証にしない。**案**: RUNBOOK の必須工程から外し、「封の読みで顧客の問いへの答えの場所が機械で確認できた後、回す価値がある場合だけ」に書き換える。

## 3. 順(人間の Phase A〜F。着手は人間の合図の後)

- **A** Observation packet(自動化レーン。既存 JSON の束ね + 顧客の問いの欄 + 局面の実在の索引)。
- **B** LLM 自由分析(API 接続。3 席同一入力・構造化出力。実験席の型を引き継ぐ)。
- **C** 検証・統合(`hypothesisCheck` の拡張 + 統合の整理役)。
- **D** 器への自動配置(スロットの器。器の余裕 0 の直しを先に)。
- **E** PDF 自動監査(今の門 + 「答えの場所」の門 + 組版のコードを見る済みの判定)。
- **F** 席は任意。
- 上位版(重要局面の解説・全局・戦型別・継続比較)は基本版の自動化が閉じてから、同じ packet の上に足す。

## 4. 変えない線
- LLM に数えさせない(数はエンジンと集計)。顧客に出る文は規則 5 の (1)〜(4)。実名を冊子に出さない・本人に聞かない・戦型の名前は承認済みの認識だけ。送るかは人間。

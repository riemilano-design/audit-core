- **L-2 相手の強さ。** 相手は本番の素のエンジン(いまは駒得だけの評価の版。`gameSession.ts:242` の `go({ movetimeMs: 1000 })` 固定)。**B はエンジンに頼らないので、ほぼ一方的に負ける見込み**(予-D1・D4)。優勢が出なければ死因①は測れない。**相手は実質投了しない**(C がソースで確かめた: エンジンの `ResignValue` の既定が 99999)ので、局は詰みか上限まで続く見込み
- **L-3 相手の強さを変えることの扱い。** C がソースで確かめた事実(HEAD `225529b`): `explore.ts` のフラグは `--games`・`--seed`・`--plies`(既定 60)・`--out-dir` だけで、**相手の強さを落とす手段(movetime・nodes・乱択)は相手側に無い**。**エンジンは 1 本(`SHOGI_ENGINE_PATH`)を、相手・先手の E の読み・候補手・`engineReference` が共有する**ので、`SHOGI_ENGINE_PATH` を NNUE 版にすると相手も NNUE 版になり、**相手だけを弱くする経路は無い**。NNUE 版には `NodesLimit`・`DepthLimit` の USI オプションがあるが送る経路が無く、Skill Level の類は無い。`MinimumThinkingTime` の既定は 2000 で、実際の思考時間は確かめていない。`explore.ts` の冒頭は「相手 AI の手加減・強さ調整もしない(相手は本番と同一)」と書いている。**変えるなら本番の挙動ではなく `explore.ts` の相手側の設定として扱い、その冒頭の文も直す**(司令塔の決定。測ってから決める。候補は 6. の Q-6)
- **L-4 再現できない。** 相手の手は movetime で決まるので、同じ種でも同じ局にならない(O-2)。**再現の単位は保存した棋譜 JSON**(`replay.ts` で再生し直す)
- **L-5 千日手・持将棋を判定しない。** `isGameOver` は局面だけから判定し、同じ局面の繰り返しは見ない。**上限(`--plies`)で止まった局は、終局ではなく「上限」と数える**。**B は決定的で相手は投了しないので、繰り返しで 200 手まで伸びる局がありうる。所要(Q-8 の見積もり)はその分だけ上にずれる**(司令塔、2026-09-15)
- **L-6 評価は同じ局面・同じノード数でも揺れる**(P-33)。急落の件数は観測であり判定ではない
- **L-7 群の差は局どうしの揺れと混ざる。** B と B′ は対にならない(L-4)。10 局ずつでは、差が癖によるものか局の揺れによるものかを分けられない。**差は件数として並べるだけで、「B′ の方が多い」とは言わない**(規則 11.5)
- **L-8 D1 の写す欄には、植えた答え(玉を囲わない)を直接表す欄が無い**(予-D9)
- **L-9 記録に評価関数の種類が残らない**(P-43。D0-NNUE 7.1)。`explore.ts` は駒得版、`replay.ts` は NNUE 版で回すので、**どの記録がどちらかを出力先の名前と計画書の実測の節に書く**

## 7. 流れ(実行するときの形。この計画書では実行しない)

```
explore.ts --profile B  --games 10 --seed <s> --plies 200 --out-dir out/d3-b    (本番の既定のエンジン)
```

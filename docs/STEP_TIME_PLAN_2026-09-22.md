# STEP TIME: 消費時間を流れに入れ、本編を 4 ページにし、「考えられること」を数える前に固定する(2026-09-22、司令塔 e3)

2 人目の本人の 44 局版(2026-09-22)は、時計の側の発見(使い切って負けた 6 局は盤上は互角以上・崩れは時間をかけた手に多い)を司令塔が手作りで足した。本人の感想(gitignore の `out/立浪さん_2026-09-22/9_感想_2026-09-22.md`)で、②「時間をかけた手で崩れ」が新しい発見だった、⑦本人が「読み・感覚が間違っている」と自己診断した(3 ページ目の注記「時間をかけたから崩れたとは言えない」は読み飛ばされた)、③「6 局は互角以上」は知っていた、が分かった。この STEP はそれを道具に入れる。

## 1. 決まりとの関係

- 助言は書かない(人間の決定 2026-09-22「1: 人が助言を添える、は無い。2: 次の一歩を事実の形で渡す」)。
- 「考えられること」は発見の種類ごとに人が書いて承認した固定文。局ごとに LLM が考えない。**数える前に書いて固定する**(2026-09-22 人間の合意)。
- 本編 4 ページ + 資料。本編に載せる条件は「今回新しく分かったか/前回のことは今回も起きたか/次の 20 局で何を見れば分かるか」のどれかに答えるもの。
- 「本人が知っていそうなこと」を前に置かない(③の教訓)。感想票に「知っていたのはどれか」を足す。

## 2. 作るもの(概要。細かい設計は実装の前に §6 に書く)

1. **消費時間を流れに入れる**: KIF の 1 手ごとの秒を `kifu-import-check.ts --fixed` の JSON に残し(`moveSeconds`)、`reportData.ts` が「その手にかけた時間 × 崩れ」「残り時間 × 崩れ」「序盤・中盤・終盤の消費」「使い切りで終わった局とその最後の局面の評価」を出す。比較対象(公開棋譜)に秒が無いときは欄を空にして「比べられない」と書く。
2. **本編 4 ページ**: 1 新しく分かったこと(発見ごとに「考えられること」と「次の 20 局で見分けがつくこと」を付ける)/2 前回のことは今回も起きたか(初回は「初回のため無し」)/3 次の 20 局で見るもの/4 数え方。資料(表・付録)は別冊。
3. **「考えられること」の固定文**: 発見の種類ごとに 2〜3 個 + 「どれでもないこともある」を、docs に置いて承認する(§5)。出力は該当する種類の文をそのまま入れる。
4. **感想票**: 「1 ページ目の発見のうち、すでに知っていたものはどれか」を足す。

## 5. 「考えられること」の固定文(2026-09-23 確定。§5.1 を参照)

### 5.1 確定の経緯と、答えの形(2026-09-23)

人間の方針(2026-09-23): **「最終的には『じゃあどうしたらいい?』に、人を介さずできる限り答えていかなければならない。その前提に立って判断し進めて」**。これを受けて司令塔 e3 が、下の固定文を確定した(承認の委任の範囲。根拠はこの節)。2026-09-22 の人間の決定「1(人が助言を添える)はやらない、2(次の一歩を事実の形で渡す)」は変わらない。

**答えの形(発見の種類ごとに 3 段。全部固定文で、局ごとに LLM が考えない)**

1. **考えられること**(2〜3 個。頭に「どれかは分からない。どれでもないこともある」)
2. **次の 20 局で見分けがつくこと**(どの数がどう動けば、どれに寄るか)
3. **試せること**(本人が次に選べる**条件の変え方**: 持ち時間・局数・対局の相手の帯など。**指し手の選び方・読み方・練習の内容は書かない**。条件を変えて同じ物差しで数えると、1 のどれかが分かる、という形)

守る線: 禁止語 0(悪手・弱点・癖・型・傾向・原因・ミス・見落とし・改善・練習・必ず・明らか・あなた・ご自身・いつも・がち・クセ・パターン)。「〜すべき」「〜した方がよい」を書かない。「試せること」は「〜と、(a) と (c) が分かれます」の形で終える。**これ以上(指し手の助言)へ進むかは、人間の判断**。

固定文は docs のこの節が正本。コードの `lib/findingTexts.ts` は写しで、試験が両者の一致を確かめる(作業 3)。文を変えるときは docs → コードの順。

### 5.2 固定文(発見の種類 = `findings[].kind`)

**T1 `timeSpent`: 崩れは、時間をかけた手に多い**
- 考えられること(どれかは分からない。どれでもないこともある): (a) むずかしい局面ほど時間を使い、むずかしい局面ほど崩れる(時間のせいではない) (b) 時間をかけて選んだ手が、候補の中で低いほうだった (c) 残り時間を気にして、読み切る前に指した
- 次の 20 局で見分けがつくこと: (a) は 10 秒以上かけた手の局面で第 1 候補と第 2 候補の差が小さいか、(b) は時間をかけた手が上位 5 つの中の何番目か、(c) は残り 60 秒未満の手の崩れの割合
- 試せること: 持ち時間の長い対局(10 分 + 30 秒など)を 5 局ほど混ぜて同じ数え方で数えると、『残り時間を気にして指した』が残るかどうかが分かれます

**T2 `timeUpLoss`: 使い切って負けた局は、盤上は互角以上だった**
- 考えられること: (a) 中盤で 1 手ずつが長かった (b) 候補が並ぶ局面が続いた (c) 序盤で使いすぎた
- 次の 20 局で見分けがつくこと: 中盤の 1 手あたりの秒(4 秒の線)、候補の差、序盤の消費
- 試せること: 秒読みのある持ち時間(10 分 + 30 秒など)で 5 局ほど指すと、時間で終わる局が消えるか、それでも盤上で下がるかが分かれます

**T4 `aheadLoss`: 優勢になった後に負けた対局があった**
- 考えられること: (a) 優勢の局面で候補が並び、どれを選んでも差が縮んだ (b) 優勢になった後の手に、使える時間が残っていなかった (c) 優勢の局面で 1 手の差が大きい手(分かれ道)が続いた
- 次の 20 局で見分けがつくこと: 優勢の局面での第 1 候補と第 2 候補の差、優勢になった後の残り時間、優勢の局面での分かれ道の数
- 試せること: 持ち時間の長い対局を混ぜると、『使える時間が残っていなかった』かどうかが分かれます。ほかの 2 つは、次の 20 局を同じ数え方で数えると分かれます

**T5 `phase`: 崩れの時期(序盤・中盤・終盤)**(つねに出す。数の文だけ。考えられること・試せることは付けない — 局面の数が段ごとに違うので、回数だけでは比べられない。次の版で「段ごとの局面数あたり」を足してから)

**T3 `none`: 探したが、上に書ける数は無かった**
- 考えられること: (a) 本当に無い (b) 20 局では少なすぎて見えない (c) 比較対象が同じ棋力帯・同じ持ち時間でない
- 次の 20 局で見分けがつくこと: 40 局を合わせて同じ枠を数える。(c) は比較対象を持ち時間でそろえてから
- 試せること: 同じ持ち時間で次の 20 局を指すと、『20 局では少なすぎて見えない』かどうかが分かれます

### 6.1 作業 1 の設計(2026-09-23 未明、司令塔 e3。人間の「君に任せる」による)

**目的**: まとめの冊子の時間の数(§4 の表、序盤・中盤・終盤の消費、使い切りの局)を、手作りの `collect.py` ではなく道具で出す。**新しい数は出さない**(既知の正解で校正する作業)。エンジンは回さない。

**1. 取り込み(`lib/kifuImport.ts`・`kifu-import-check.ts`)**
- KIF の指し手行の `(m:ss/h:mm:ss)` を捨てるだけだった `KIF_TIME` を読み、`moves[i]` に `time: { spentSec, totalSec } | null` を足す(切り捨ての整数。無い行は null、`timeDropped` はそのまま)。CSA は今回読まない(null)。
- `toFixedKifu` が `moveSeconds: Array<{ spentSec; totalSec } | null>` を書く(`moves` と同じ長さ・同じ順。**KIF の手数 = 添字 + 1**)。`alignedFixedKifu` で本人が後手の局を回して 1 手目を畳んでも、`moveSeconds` は **元の手順の順のまま**(`originalMoves` と同じ並び)。読む側は既存の `plyOffsetOf` で合わせる(手作りの `collect.py` が `ply + (後手なら 1)` としたのと同じ)。
- 既存の fixed JSON(44 局 + 90 局)に `moveSeconds` を**後から足す**小さな道具 `kifu-times.ts <fixed.json> <元の KIF>`: 元 KIF を読み直し、`moves`(または `originalMoves`)が一致しなければ書かない。**pipeline の済み判定は mtime なので、fixed JSON を書き換えてもエンジン段(S2〜)が再実行されないことを実測で確かめる**(`--until report` で S2〜S6 が skip と出ること)。再実行される作りなら、pipeline の S1 の済み判定を「moves が同じなら済み」に変えるのではなく、fixed JSON の mtime を元に戻す(`utimes`)。
- 公開棋譜(Lishogi の KIF)は秒が無い、または形式が違うことがある。読めなければ全部 null で「比べられない」。

**2. 数える(`lib/reportData.ts`。純粋関数)**
- `TIME_VALUES` を 1 か所に: `spentBucketsSec = [1, 4, 9]`(0〜1 / 2〜4 / 5〜9 / 10 以上)、`leftBucketsSec = [60, 120]`、`longThinkSec = 10`、`quickSec = 4`(仮説 B の「0〜4 秒」)。値は §4 の表と同じ。
- `PatientTime`(冊子に載せる形。手・値・SFEN は含めない):
  - `available: boolean`(秒の無い局が 1 つでもあれば false、欄は空)

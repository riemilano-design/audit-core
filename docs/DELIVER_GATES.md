# 納品の人間の確認点 ― 書き手への指示書

`deliver.ts`(17 段。[../scripts/playtest/README.md](../scripts/playtest/README.md) の「納品までを 1 コマンドで通す」)が**自動で埋めない 2 か所**と、最後の目視のための手順書。当面この 2 か所は **Claude(司令塔セッション)が書き、人間が読んで直す**(2026-09-23 の人間の決定)。

**正本の関係**: 検査の規則の正本は道具そのもの(`report-pdf/_mid.py`・`check_answer.py`)。この文書はその**使い方**を書いたもので、道具と食い違ったら道具が正。工程の記録は [STEP_DELIVER1_PLAN_2026-09-25.md](STEP_DELIVER1_PLAN_2026-09-25.md) §10・§11。

## 0. 書く前に頭に入れる 4 つ

1. **数を自分で作らない。** 文に出る数は、道具が出した JSON・付録の PDF にあるものだけ。丸めない、足さない、割らない。「〜倍」「〜割」は必ず落ちる。
2. **指し手を自分で書かない。** 本編(§1)はプレースホルダ(`{m}`・`{b}`・`{o}`)で書く。B(§2)は付録 2・付録 3 の PDF に**印字されている手だけ**を引く。
3. **行動は承認済みの表から選ぶだけ。** B の「こうしてみては」は `answer_menu.json` の M1〜M9 のどれかで、`<!-- menu: Mx -->` の印を付ける(§2.4)。新しい行動を発明しない。
4. **断定しない。** 「〜という読みです」「〜の可能性があります」を既定にする([../CLAUDE.md](../CLAUDE.md) の「絶対に守るルール」6 番)。

根拠は CLAUDE.md ルール 5 の拡張(2026-09-23 の人間の決定)。対局後診断では「考えられること」「試せる行動」を組み立ててよいが、**(1) 数・手・読み筋は機械で照合、(2) 行動は承認済みの表から、(3) 断定しない、(4) 指し手はエンジンで答え合わせしたものだけ局面つきで**の 4 つを満たすものだけ。この 4 つは全部、下の道具が機械で見る。**通らないものは書けない**ようになっている。

## 1. 段 `prose-gate` ― 本編の言い換え(`prose.json`)

### 1.1 読むもの

`<work>/report/prose-request.md` **だけ**。必要な事実は全部ここにある(`patient_report_data.json` を読み直さない)。

### 1.2 書くもの

`<work>/report/prose.json`。形は次のとおり(局番号が鍵)。

```json
{
  "4": {
    "summary": "61 手目に優勢になってから、最後まで一度も互角に戻っていません。…",
    "scenes": [
      { "type": "move", "ply": 90, "text": "大きく優勢(+4094)の場面で {m}。エンジンの候補は「{b}」でした。評価は +3246 に下がりましたが、優勢のままです。" }
    ],
    "takeaway": "この一局は、盤の上では最後まで立浪さんの優勢でした。"
  }
}
```

**`prose-request.md` に `## 第 N 局` の節がある局を、全部書く。** 1 つ欠けると `_mid.py` の assert(「言い換えの無い局がある」)で止まる。

### 1.3 機械が見る規則(`_mid.py`。破ると本編 PDF が作られない)

| # | 規則 | 落ちたときのメッセージ |
|---|---|---|
| 1 | **指し手は書かない。** 実戦の手は `{m}`、エンジンの候補は `{b}`、相手の手は `{o}`。同じ文に 2 つ目が要るときは `{m2}`・`{b2}` のように番号を付ける | (置換されずに `{m}` が印字される) |
| 2 | **文に出る数は、その局の「文に使ってよい数」の一覧にあるものだけ。** 一覧は `prose-request.md` の各局の最後の行にある。駒の座標表記(`７六` のような全角数字 + 漢数字)は数として数えられないので安全 | `第 N 局: 文の数 X が事実に無い` |
| 3 | **優勢から負けた局は、`summary` に「優勢」の語を必ず入れる** | `第 N 局: 優勢から負けた局なのに概要に「優勢」が無い` |
| 4 | `scenes[].ply` は `prose-request.md` の「場面」に出ている手数だけ | `第 N 局: X 手目の場面が記録に無い` |
| 5 | **禁止語 15 語**: 悪手・弱点・癖・傾向・原因・ミス・見落とし・改善・練習・必ず・明らか・あなた・ご自身・いつも・がち | `第 N 局: 使わない語「X」` |

### 1.4 文の形(既存の版をまねる。新しい言い方を作らない)

- `summary`: 形勢が動いた手数と評価を時系列で並べ、最後に終局のしかた(投了・持ち時間切れ)。持ち時間が絡む局はそれも書く。
- `scenes[].text`: 「**<区分>(<評価>)の場面で {m}。エンジンの候補は「{b}」でした。評価は <値> に下がりましたが、優勢のままです。**」区分の語は優勢・互角・劣勢・大きく優勢。玉の逃げ道が減った場面は「このあと相手の {o} で、玉の逃げ道が N から M に減りました。」を足す。
- `takeaway`: その 1 局を 1 文で。「この一局は、盤の上では最後まで <表示名> の優勢でした。」のように、事実の言い換えにとどめる。

### 1.5 確かめ方

```bash
npx tsx scripts/playtest/deliver.ts <同じ引数> --from prose-gate
```

段 `pipeline-pdf` が rc=0 なら通った。落ちたら `_mid.py` が理由を 1 行 1 件で出すので、**文を直す**(道具は直さない)。

### 2.5 「こうしてみては」の行の形

```
1. <!-- menu: M4 -->**<行動の文。>** 根拠: <数>。<「〜という読みです」の 1 文>
```

`render_answer.py` が、行動の文(太字)と `根拠:` 以降を 2 つの段落に分けて描く。優先度の高い順に並べる。

### 2.6 どの M が使えるかを、手で数えずに道具に答えさせる

`minN` や条件が成り立つかを**手で計算しない。** 手で導いた数を根拠にすると、後で食い違ったときに原因が追えない(このリポジトリで繰り返し踏んでいる型)。代わりに、**`<!-- menu: Mx -->` の行だけを並べた使い捨ての md** を `check_answer.py` に通す。成り立たない id と理由を道具が名指しで返す。

```markdown
**こうしてみては**
1. <!-- menu: M1 -->**M1 を試す。** 根拠: 道具に判定させるための行です。
2. <!-- menu: M2 -->**M2 を試す。** 根拠: 同じ。
9. <!-- menu: M9 -->**M9 を試す。今回の対局から見つけた読みです。** 根拠: 同じ。
```

引数は本番と同じ一式(`deliver.ts --dry-run` の段 `answer-check` の `args` の先頭を、この md に差し替えるだけ)。

実測(固定材料 44 局、2026-09-23): `4: メニュー M1 の答え合わせの数が下限に届かない(検査 4)` の 1 行だけが返り、**M2〜M9 は成立**した。使えない id とその理由が、この形で 1 行 1 件で分かる。

**注意**: `--direct`・`--time-cause` の材料は段 `appendix3-*`・`appendix4-*` が作るので、**全部の id を判定できるのは `pipeline-pdf` より先に進んでから**である。それ以前は `--patient` 系だけなので、時間の M(M1・M2・M9)と否定の M(M3・M8)までしか見当が付かない。

落ちた行と理由が `<行番号>: <理由>: <文の先頭 100 字>` で出る。**文を直す。道具を直して通さない。**
`render_answer.py` は**ページ数の上限 8**で、超えると止まる(その場合は削る)。

## 3. 段 `check-delivery` のあと ― PDF の目視

`check_delivery.py` が機械で見るので、**目で探さなくてよいもの**: 禁止語 18 語・`@`・`/Users/`・「水匠」・`--forbid` で渡した語。

## 4. やってはいけないこと

- **道具を直して検査を通す。** 落ちたのは文の側。文を書く側は `_mid.py`・`check_answer.py`・`render_*.py`・`lib/` を触らない(DELIVER-1 は凍結。[STEP_DELIVER1_PLAN_2026-09-25.md](STEP_DELIVER1_PLAN_2026-09-25.md) §11.1)。**ただし道具そのものの不具合(落ち方が文の内容と関係ない、型エラー等)に当たったときは、自分で直さず、落ち方・原因の見立て・当たったデータを添えて道具の持ち主(司令塔セッション)へ回す。** 2026-09-23 に実例が 1 件出た(`_mid.py` の null ガード)。
- **数を丸める・足す・割る。** 「約 4 割」「2 倍」は書けない。
- **付録に無い手を書く。** 局面つきで示せない手は出さない。
- **メニューに無い行動を書く。** 表を増やすのは人間の承認。
- **断定する。** 「原因」「傾向」「型」は語そのものが禁止。
- **前の版の主張をそのまま引き継ぐ。** 機械が埋めた事実の箇条書きにも、基準版から引き継いだ「読み」の一文が混ざっている場所がある(問題 1 の 4 本目の末尾。§11.2 の決定で数が動いたので言い方を確かめる)。**数が動いたら、その数に付いている読みも読み直す。**

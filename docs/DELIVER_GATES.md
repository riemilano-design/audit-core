# 納品の人間の確認点 ― 書き手への指示書

`deliver.ts`(17 段。[../scripts/playtest/README.md](../scripts/playtest/README.md) の「納品までを 1 コマンドで通す」)が**自動で埋めない 2 か所**と、最後の目視のための手順書。当面この 2 か所は **Claude(司令塔セッション)が書き、人間が読んで直す**(2026-09-23 の人間の決定)。

**正本の関係**: 検査の規則の正本は道具そのもの(`report-pdf/_mid.py`・`check_answer.py`)。この文書はその**使い方**を書いたもので、道具と食い違ったら道具が正。工程の記録は [STEP_DELIVER1_PLAN_2026-09-25.md](STEP_DELIVER1_PLAN_2026-09-25.md) §10・§11。

## 0. 書く前に頭に入れる 4 つ

1. **数を自分で作らない。** 文に出る数は、道具が出した JSON・付録の PDF にあるものだけ。丸めない、足さない、割らない。「〜倍」「〜割」は必ず落ちる。
2. **指し手を自分で書かない。** 本編(§1)はプレースホルダ(`{m}`・`{b}`・`{o}`)で書く。B(§2)は付録 2・付録 3 の PDF に**印字されている手だけ**を引く。
3. **行動は承認済みの表から選ぶだけ。** B の「こうしてみては」は `answer_menu.json` の M1〜M9 のどれかで、`<!-- menu: Mx -->` の印を付ける(§2.4)。新しい行動を発明しない。
4. **断定しない。** 「〜という読みです」「〜の可能性があります」を既定にする([../CLAUDE.md](../CLAUDE.md) の「絶対に守るルール」6 番)。

根拠は CLAUDE.md ルール 5 の拡張(2026-09-23 の人間の決定)。対局後診断では「考えられること」「試せる行動」を組み立ててよいが、**(1) 数・手・読み筋は機械で照合、(2) 行動は承認済みの表から、(3) 断定しない、(4) 指し手はエンジンで答え合わせしたものだけ局面つきで**の 4 つを満たすものだけ。この 4 つは全部、下の道具が機械で見る。**通らないものは書けない**ようになっている。

### 2.2a 主題と見出しの選び方(2026-09-24 の人間の決定「同じミスがおきないように」)

2 人目の顧客で、前の顧客の主題(時間で負ける)が先頭に来て「時間の処方は出しません」で終わり、その人の最大の事実(優勢 14 局のうち 6 局を負け・守りの場面で守ったのは 19 / 52)が後ろに埋もれた。同じことを繰り返さないための書き手の規則。閾値は置かない。

1. **#2「ひとことで」の先頭は、その人の数の中でいちばん大きな事実から書く。** 前の顧客・前の版の主題を先頭に持ち込まない。「大きい」は閾値で決めず、次の順で選ぶ: 事実の箇条書きに出ている数のうち、**分母が大きく、処方(§2.4 の M)が付くもの**。付かない事実は主題にしない。
2. **「こうしてみては」の処方が 0 本になった問題は、節を後ろへ回す**(節は消さない。「この冊子では処方を出しません」と書き、理由を数で添える)。「時間負けが n 局以下なら省く」のような閾値で決めない ― 出た結果(処方の本数)で決める。
3. **見出し(太字の見出し・「ひとことで」の 1 行)に割合の主張を置くなら、分子と分母を同じ行に書く。** 分子が 1 件増減したときの割合を頭で計算し、比べる相手と重なるなら主張の柱にしない(数で言う)。例: 「長く考えた手のほうが崩れる割合が高い(3 / 27 対 14 / 340)」は分子 3 で、1 件動くと 7〜15% に振れて 4% と重なる → 見出しにしない。「長く考えた手の崩れは 3 / 27、速く指した手は 14 / 340」と数で書く。**この規則は書き手が書く行に当てる。**本編の「ひとことで」は道具が書く行で(`findingTexts.ts` の `oneLine` → `render_front.py`)、承認済みの門(`reportData.ts` の `FINDING_VALUES`: 分母 20 以上・崩れの割合が 2 倍以上)を通ったときだけ出て、数はその次の行に印字される。上の例の 3 / 27 対 14 / 340 はこの門を通る(27 ≥ 20・2.7 倍)ため本編には出る ― 書き手が消すのではなく、**門を変えるなら人間の判断**(閾値 = 判断的知識。CLAUDE.md ルール 4)。
4. **因果に読める言い方を見出しに置かない**(「長く考えると崩れる」)。CLAUDE.md ルール 6。
5. **機械が埋めた事実の箇条書きは数だけ**(§2.1)。比較・解釈を足すなら、書き手がその数を見て、**比べる基準を同じ行に置いて**書く(§4 の否定の規則と同じ)。

### 2.5 「こうしてみては」の行の形

```
1. <!-- menu: M4 -->**<行動の文。>** 根拠: <数>。<「〜という読みです」の 1 文>
```

`render_answer.py` が、行動の文(太字)と `根拠:` 以降を 2 つの段落に分けて描く。優先度の高い順に並べる。

**`M4`・`M6` のような記号を、読者に見える文に書かない。** 記号は上の `<!-- menu: M4 -->` の中だけに置く(コメントなので描画されない)。2026-09-23 の納品では、答え合わせの表と「例」の節に `(M4)`・「上の M6 は」と**本文として**書かれ、冊子に内部記号が出た。**顧客はこの記号を知らない。**行動を指すときは行動の文そのもの(「攻めと守りを 1 つずつ並べて比べる」)で指す。

### 2.6 どの M が使えるかを、手で数えずに道具に答えさせる

`minN` や条件が成り立つかを**手で計算しない。** 手で導いた数を根拠にすると、後で食い違ったときに原因が追えない(このリポジトリで繰り返し踏んでいる型)。代わりに、**`<!-- menu: Mx -->` の行だけを並べた使い捨ての md** を `check_answer.py` に通す。成り立たない id と理由を道具が名指しで返す。

```markdown
**こうしてみては**
1. <!-- menu: M1 -->**M1 を試す。** 根拠: 道具に判定させるための行です。
2. <!-- menu: M2 -->**M2 を試す。** 根拠: 同じ。
9. <!-- menu: M9 -->**M9 を試す。今回の対局から見つけた読みです。** 根拠: 同じ。
```

引数は本番と同じ一式(`deliver.ts --dry-run` の段 `answer-check` の `args` の先頭を、この md に差し替えるだけ)。

この方法が効くことの実測(2026-09-23): 固定材料 44 局で `4: メニュー M1 の答え合わせの数が下限に届かない(検査 4)` の 1 行だけが返った。使えない id とその理由が、この形で 1 行 1 件で分かる。

**この「M1 だけ不成立」という結果を、別の顧客に持ち込まない。** 成否は材料で変わる(時間切れ負けの局数・分かれ道の数・`read/` の有無などが違えば並びが変わる)。**必ずその顧客の材料で回し、返った行だけを根拠にする。** 上の数字は「方法が効くことの例」であって、どの M が使えるかの答えではない。

**注意**: `--direct`・`--time-cause` の材料は段 `appendix3-*`・`appendix4-*` が作るので、**全部の id を判定できるのは `pipeline-pdf` より先に進んでから**である。それ以前は `--patient` 系だけなので、時間の M(M1・M2・M9)と否定の M(M3・M8)までしか見当が付かない。

## 3. 段 `check-delivery` のあと ― PDF の目視

`check_delivery.py` が機械で見るので、**目で探さなくてよいもの**: 禁止語 18 語・`@`・`/Users/`・「水匠」・`--forbid` で渡した語。

**目で見るもの**:

- 表が紙幅からはみ出していないか、行が途中で切れていないか
- 盤面の向きと駒の字(付録 2・付録 3)
- 冊子の順番と名前が揃っているか(`1_まとめ` → `2_付録1` → `3_付録2` → `5_付録3` → `6_付録4` → `8_B`)
- B が 8 ページ以内に収まって読み通せるか
- **まとめの 1 ページ目の表示名が、顧客に見せる名前になっているか**(`--name` に渡した値がそのまま出る)。2026-09-23 の納品では `〇〇さん` のまま出た。**道具はこれを判定できない** ― 匿名で渡したいのか、埋め忘れなのかは渡した人しか知らないため、機械の検査は置かず、ここで目で見る

`--forbid` には**相手の名前など「出てはいけない語」**を渡す。**顧客自身の表示名を渡すと必ず落ちる**(本人の冊子に本人の名前が出るのは正しい。実測で 42 件)。

**`--forbid` に渡す語の種類(2026-09-23 に 20 局の納品で実際に使った 4 種類・計 44 語。語そのものは記録に残さない)**

| 種類 | 件数 | 何を渡すか | なぜ要るか |
|---|---|---|---|
| 対局 ID | 20 | 棋譜のファイル名から機械で取り出した、外部サービスの対局 ID | 付録 4 が `kifuId` を印字する。ID が残ると公開棋譜から本人と相手が特定できる |
| 名前 | 17 | 棋譜のヘッダ(`先手：`/`後手：`)の値から段位を落とした部分。本人・相手の両方。「匿名」も 1 件 | 相手の名前を記録にも冊子にも残さない |
| 段位 | 5 | 同じヘッダから取り出した段位の語 | 本人の強さが分かる |
| サイト名 | 2 | 大文字・小文字の両方 | 棋譜の出どころが分かる |

**一覧は機械で組む**(ファイル名とヘッダから取り出すだけ。手で並べない)。作った一覧は作業用のフォルダに置き、**成果物フォルダに入れない**。`deliver_log.jsonl` は `stage`・`startedAt`・`finishedAt`・`rc`・`humanGate` の 5 つだけで**引数を記録しない**ので、`--forbid` の語が成果物に残る経路は無い(司令塔が `lib/deliver.ts` の `DeliverLogEntry` を読んで確認)。

**運用の注意 2 つ(実際に踏んだもの)**

- **段位の語は、当たりが出るまで外さない。** 盤の段の言い方(「三段目」など)に部分一致する恐れはあるが、**「誤検出するはず」と予測して先に外すのは誤り**である(20 局では当たり 0 件で、外す判断をする場面自体が生じなかった)。当たったら中身を見てから決める。
- **件数は局数と合わないのが普通。** 同じ相手と複数回当たっている局があるため(20 局で名前 17 件)。**合わないことを異常と読まない。**

**付録 4 だけは棋譜の `kifuId`(= `--kifu-dir` のファイル名から作られる)を冊子に印字する。** ファイル名に日付や外部サービスの対局 ID が入っていると、(1) 付録 4 の数の照合で必ず落ち(許す数はその局の局番号・総手数と `{1,2,3,4,5,9,10,300}` だけ)、(2) 通したとしても印字されて個人が特定できる。**これは文の側では直せない。書き始めずに道具の持ち主(司令塔セッション)へ回す**(§4 の 1 つ目と同じ扱い)。安全な付け方は局番号だけの `g01-sente.kif` … `g20-gote.kif`。2026-09-23 に実例が 1 件出た(規約は scripts/playtest/README.md の `--kifu-dir` の項)。

## 4. やってはいけないこと

- **道具を直して検査を通す。** 落ちたのは文の側。文を書く側は `_mid.py`・`check_answer.py`・`render_*.py`・`lib/` を触らない(DELIVER-1 は凍結。[STEP_DELIVER1_PLAN_2026-09-25.md](STEP_DELIVER1_PLAN_2026-09-25.md) §11.1)。**ただし道具そのものの不具合(落ち方が文の内容と関係ない、型エラー等)に当たったときは、自分で直さず、落ち方・原因の見立て・当たったデータを添えて道具の持ち主(司令塔セッション)へ回す。** 2026-09-23 に実例が 1 件出た(`_mid.py` の null ガード)。
- **事実から「〜とは言えません」と否定するのに、比べる基準を並べない。** 割合を 1 つ出して否定するのは、比べる相手が無ければ成り立たない。2026-09-23 の納品に実例がある ― 「長考 47 回のうち分かれ道に当たったのは 27 回(27 / 47)。=「選択肢が多い局面で長考している」とは言えません」と書かれたが、**27 / 47 は 57%** で、分かれ道の全体の割合(238 / 683 手 = 約 35%)と並べると**むしろ当たりやすい**。数の照合は通る(数字は実在する)が、**結論が事実と逆**だった。**否定を書くなら、比べる基準の数を同じ行に置く。置けないなら結論を書かない。**
- **数を丸める・足す・割る。** 「約 4 割」「2 倍」は書けない。
- **付録に無い手を書く。** 局面つきで示せない手は出さない。
- **「付録で確かめられる」と書いて、宣言を付けない。** 「n 局目 m 手目の盤は付録 N にあります」のように、**付録に盤があると本文が指す行**には `<!-- pos: n/m 付録N -->` を置く(§2.3 の検査 7)。2 人目の顧客で、本文が指した局面 2 つが付録に無いまま検査を通った(数の照合は 5 と 59 がどこかにあれば通る)。**宣言が無い参照は機械が見ない**ので、書いたら必ず宣言する。手数を数として言うだけの行(「61 手目に優勢になってから」)は pos の対象ではない(検査 1 が見る)。
- **メニューに無い行動を書く。** 表を増やすのは人間の承認。
- **断定する。** 「原因」「傾向」「型」は語そのものが禁止。
- **前の版の主張をそのまま引き継ぐ。** 2026-09-24 までは、機械が埋めた事実の箇条書きにも基準版から引き継いだ「読み」の一文が混ざっていた(問題 1 の 4 本目の末尾など、7 本の箇条書きと見出し 2 つ)。同日の人間の決定で、**機械は数だけ書く形に直した**(計画 §11.6)。それでも書き手の側で、**数が動いたら、その数に付いている読みも読み直す。** 主題と見出しの選び方は §2.2a。

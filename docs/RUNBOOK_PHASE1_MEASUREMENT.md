# Phase 1 の物差し ― 次の 1 冊で何をどう測るか(自動化レーン。2026-09-26)

[AUTOMATION_STATUS_2026-09-26.md](AUTOMATION_STATUS_2026-09-26.md) §11 の Phase 1 で取ると決めた数の**測り方**を、
**棋譜が来る前に**固めたもの。中身(封をした読み・所要の数)は空で、**Phase 1 を回しながら埋める。**

**なぜ先に作るか**: **封をした読みは、PDF ができてから手順を決めると成立しない**(H-8 の値打ちは「測る前に書かれていた」という
順序だけなので、PDF を見たあとに手順を作れば封の意味が消える)。所要も、**棋譜が来てから様式を考えると最初の段が終わっている。**
**後からでは正しくやれないものだけを先に作る**(司令塔の判定基準)。

**この runbook に入れないもの**(Phase 2 の道具): 組版・PDF の機械監査・批評席の実装。
**見分け方: その道具は、冊子を手で組んでも役に立つか。** 役に立つなら Phase 1 の物差し。
**自動組版があって初めて意味を持つなら Phase 2。**

## 0. Phase 1 の指示は「余計なことをしない」

**次の 1 件は現行方式で最後まで通す。** 道具を足さない・工程を変えない。**測るだけ。**
変えたくなったら、それは Phase 2 以降の材料としてこの runbook の §6 に書き留める(**その場で直さない**)。

## 1. 記録の置き場(3 ファイル)

| ファイル | 誰が書くか | いつ |
|---|---|---|
| `docs/PHASE1_MEASUREMENT_LOG.md` | 各段を回した席 | **その段を始める時と終える時**(後から思い出して書かない) |
| `docs/PHASE1_SEALED_READING.md` | **司令塔だけ** | **PDF を批評席へ渡す前。渡す前にコミットする** |
| `docs/PHASE1_CRITIQUE_TALLY.md` | **自動化レーン長(私)** | 批評が 3 席ぶん返ったあと |

**3 つとも git に入れる。** 封は**コミットの時刻が順序の証拠**になるので、**コミットしてからでないと PDF を出さない。**

## 2. 段ごとの所要(様式)

**いまの「席 5 時間」は 1 標本・自己申告・内訳なし。** Phase 1 で内訳を取る。

`docs/PHASE1_MEASUREMENT_LOG.md` に、段ごとに 1 行ずつ**追記**する。

**時計を始める場所(司令塔と確認済み)**: **段 1 は、司令塔が入口を通すところから。入口も席の時間である。**
棋譜を受け取って局数を数え、連結を割り、名前を付け替える作業を「**準備**」として計測の外に置かない
(置くと、いちばん手のかかる段が消えて 5 時間の内訳が歪む)。

| 列 | 中身 | 注意 |
|---|---|---|
| 段 | 1〜9(`AUTOMATION_STATUS` §2 の番号) | |
| 席 | 回した席の名前 | |
| 開始 / 終了 | **その場で `date -u "+%Y-%m-%dT%H:%M:%SZ"` を実行して、出力を貼る** | **思い出して書かない。** 貼り忘れたら「**取り逃した**」と書く |
| 待ちか席か | `待ち`(機械が回っていて誰も見ていなくてよい)/ `席`(席が手を動かした) | **並行していたら `席(並行)`** |
| やり直し | その段を作り直した回数(0 から) | **門で落ちた回数は別列** |
| 門で落ちた | 回数と、どの門か | 落ちた内容は 1 行 |
| 止まった理由 | 1 行 | 無ければ空 |

**壁時計しか測らない。** 「実際に手を動かしていた時間」は測れないので**測ったふりをしない** ―
並行を `席(並行)` で印だけ付け、**合計は「壁時計の合計」と「並行を除いた直列の合計」の 2 つを出す。**
**今日の「5 時間」がどちらなのか分からないのが、そもそもの穴である。**

## 3. 比較実験(§10 の 5 つの数)

同じ PDF に **3 席**を当てる。**(a) は私が立てる。(b)(c) は人間が掛ける。**

| 席 | 誰が回すか | 渡すもの |
|---|---|---|
| (a) 文脈ゼロの身内の新席 | 私が立てる | **PDF だけ。** リポジトリ・履歴・組んだ会話・規則の一覧を渡さない |
| (b) GPT | 人間 | 同上 |
| (c) Gemini | 人間 | 同上 |

**固定の問い(3 席に同じ文で渡す。採点させない)**

**下の枠の中をそのまま渡す。** PDF 1 個と、この文だけ。**(b)(c) には人間が貼るので、人間にもこの枠ごと渡す。**
**3 席に同じ文を使う** ― **問いが違えば、出てくる指摘の数は比べられない**(分母の話と同じ)。

> **この PDF は、ある人の将棋の対局を分析した冊子です。私はこの冊子を作った側ではなく、内容の背景も知りません。読者として答えてください。**
>
> 1. **弱いのはどこですか。** 箇所を名指しで、3 点まで。
> 2. **最初の 1 ページで、あなたは何を受け取りましたか。** 1〜3 文で。
> 3. **ここで提案されている行動について、なぜそれが提案され、なぜ他のものが提案されなかったかが読み取れますか。** 読み取れないなら、どこで途切れていますか。
>
> **良し悪しの採点はしないでください。読んで受け取ったものを、そのまま書いてください。**

(この文は司令塔が書いた。**問い 3 の「なぜ他のものが提案されなかったか」は私の版に無かった** ―
**選ばなかったものが読めるか**は、行動を 2 つに絞っている冊子では効く問いなので採った。)

**局数を枠から外した(2026-09-27、渡す前に自動化レーン長が直した)**: 元の文は「対局 **20 局**を分析した冊子です」だった。
**今回の材料は 25 局なので、そのまま渡すと私たちが偽の事実を 1 つ混ぜることになる。**
批評席が「20 局と書いてあるが冊子は 25 局」と指摘したら、それは**⑤(観測事実に反する指摘)ではなく私たちの誤り**で、
**⑤ の数が汚れる。** 局数は PDF 自身に書いてあるので、枠から外すのが正しい(顧客ごとに直す手も要らなくなる)。

### 数え方(これを決めておかないと 3 席の数が比べられない)

- **1 件の指摘** = **1 つの直し先**。同じ箇所への言い換え・言い方の違いは **1 件に畳む**。別の箇所なら別件。
- **① 共通の指摘** = **同じ箇所** かつ **同じ向き**(直す方向が同じ)。箇所が同じで向きが逆なら**共通に数えず、両方を別件**にする。
- **② その席だけが出した指摘** = 他の 2 席に同じ箇所の指摘が無いもの。
- **③ 採用された指摘** = 司令塔が直すと決めたもの。**採用の根拠を 1 行書く**(§7 の規則)。
- **④ 司令塔の読みを覆した指摘** = **`PHASE1_SEALED_READING.md` の封と食い違ったもの**。
  **判定は私がやる。司令塔にさせない**(批評される側が批評を採点する形になる)。
- **⑤ 観測事実に反する指摘** = **写し・事実の表と機械で突き合わせて、実在しない数・手・読み筋を含むもの。**
  「同意できない」は⑤ではない。

**④ が 0 のまま続いたら、その批評席はもう echo。**(§10 の判定。**0 だったと書くことが結果である。**)

## 4. 封をした読み(器だけ。中身は司令塔)

`docs/PHASE1_SEALED_READING.md` に、**PDF を批評席へ渡す前に**司令塔が書く。**私は中身を書かない**
(依頼者が予測も書いて採点もする形になるため)。

```markdown
# Phase 1 の封をした読み(司令塔。PDF を渡す前に書いた)

- 対象の PDF: <ファイル名> / 作った時点のコミット: <hash>
- 書いた時刻: <date -u の出力>

## 1. 弱いのはどこか
（3 点まで。箇所を名指しする）

## 2. 顧客が最初の 1 ページで受け取るもの
（1〜3 文）
```

**手順(順序が証拠なので崩さない)**
1. 司令塔が上を書く → **コミットする**(パス指定)。
2. **そのコミットのハッシュを、批評席へ渡す依頼文に書く**(= PDF を出す前に封があったことの証拠)。
3. 批評が返ってから、私が封と突き合わせて ④ を数える。**封は書き換えない**(直したくなったら追記し、追記だと分かるようにする)。

## 5. 再 PDF の周回数

**1 周 = 批評席の指摘を受けて PDF を作り直した 1 回。** `PHASE1_MEASUREMENT_LOG.md` に周ごとに 1 行。

- **2 周を超えたら人間へ上げる**(収束していない = 設計の問題。`AUTOMATION_STATUS` §11 の「人間に上がる条件」3 番)。
- 各周で**何を直したか**を 1 行(数に触る直しか、文言だけかを分ける。**数に触るものは人間へ上げる条件 2 番**)。

## 2. 作るもの

### 2.1 `scripts/playtest/report-pdf/check_answer.py`(python。fitz で付録 2 の印字を読むため)
入力: B の markdown、`patient_report_data.json`(findings・time・overview・games)、`whatif_report_data.json`、READ の summary(24 局分の jsonl の summary 行を合算した数。当面は司令塔が作った `read-combined.json` でよい)、`type-combined/summary.json`、`whatif.pdf`(付録 2)、メニュー(§3 を JSON にした `answer_menu.json`)。出力: rc=0 なら通過、rc=1 なら**落ちた文と理由の一覧**。

検査(すべて機械):
1. **数の照合**: 単位つきの数(局・回・手・秒・ポイント・%・ノード・/ の分数)は、許す集合になければ落とす。許す集合 = 上の JSON にある値 + JSON の分数から計算した割合(四捨五入の整数 %)+ 分数「a / b」は (a, b) が同じ JSON の同じ組であること。単位の無い小さな数(「2 つ」「3 段」「1 行」「(a)」)は対象外。**「〜倍」「〜割」は許さない**(書くなら元の 2 つの数を並べる)。
2. **手の答え合わせ**: 「▲」「△」で始まる指し手の表記は、付録 2(`whatif.pdf`)の印字に**同じ文字列**が無ければ落とす。「第 1 候補は ▲X」の形は、その手が付録 2 の該当局の候補の 1 番目でなければ落とす(局と手数が文に書いてあること: 「n 局目 m 手目」の形を要求)。
3. **禁止語と断定**: 禁止語 18 + 「すべき」「した方がよい」「すれば直る」「間違いなく」。
4. **行動のメニュー**: 「こうしてみては」の各項目は `<!-- menu: M1 -->` の印を持ち、M1 が `answer_menu.json` にあり、**その条件(§3 の「出す条件」)が今回の JSON で成り立つ**こと。成り立たなければ落とす。印の無い行動の項目は落とす。
5. **数が足りなければ言わない**: メニューの各行動に `minN`(根拠の数の分母の下限)。下回れば落とす。
6. **戦法・陣形の名前**: `data/` のレビュー済みの形の名前の一覧(`review_status` が reviewed のもの)に無い戦法名(「〜戦法」「〜囲い」「〜飛車」「〜銀」の語)は、「〜のような形」の後ろに付いていなければ落とす。

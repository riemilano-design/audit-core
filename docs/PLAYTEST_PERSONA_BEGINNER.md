# 縛った初心者(Claude が演じる検証者)の設定(2026-09-11)

> **位置づけ**: 提案。正本ではない。対局ハーネス(機械)と本物の初心者テスト(人間)の間に置く、**粗取り用の検証者の設定**である。Claude がこの設定で対局した記録は **観測** であり([AGENT_PROTOCOL.md](AGENT_PROTOCOL.md) 11.)、既知事項・仕様には自動で進まない。本物の初心者テストを代替しない([LONG_TERM_VISION.md](LONG_TERM_VISION.md) 8.、[COVERAGE_AND_OUTCOME_PROPOSAL.md](COVERAGE_AND_OUTCOME_PROPOSAL.md) 3.)。
>
> 前身は [PLAYTEST_RANKED_2026-09-10.md](PLAYTEST_RANKED_2026-09-10.md) の「A: 初心者」。あのときの定義は「素直に従う」程度に緩く、演じる側の将棋知識が漏れた可能性がある。本文書はその穴を塞ぐために、**知っていること・知らないこと・読み方・決め方・止まり方・記録の形**を先に固定する。

---

## 1. なぜ縛るか

Claude は将棋を知っている。「知らない」を演じることはできても「分からない」を感じることはできない。縛らずに演じると、文を全部読み、意図を汲み、先を読んで指す。それでは本物の初心者が出す違和感の半分しか出ない。だから、**画面に書いてあることだけを根拠に、決められた読み方と決め方で指す**。演じ方が固定されていれば、記録は再現でき、本物との差も測れる。

---

## 2. 人物像(固定)

| 項目 | 設定 |
|---|---|
| 将棋歴 | ルールを覚えて数局。人と指したことはほぼ無い |
| 動機 | 負けたくない。駒を取られたくない。できれば攻めたい |
| 目標 | 「囲い」という言葉は知らない。「玉を安全に」くらいの感覚はある |
| 集中 | 一手に使う時間は 30 秒相当。文章は上から読み、**要約行と最初の 2 行**まで。本文は「分からない」と思ったときだけ開く |
| 画面の読み方 | 盤 → 帯(赤いところ)→ 読む列を上から → 操作する列。凡例は最初の 1 回だけ読む |
| 操作 | **盤の駒を押して指す**(指し手を文字で入力する欄は使わない。2026-09-11 の人間の決定により今後なくすため。実装は別 STEP)。折りたたみは「分からない」ときだけ開く。「参考になる囲い」は 1 局に 1 回だけ開く |
| 態度 | 書いてあることを**そのまま**受け取る。意図を汲まない。行間を読まない。矛盾があれば「どっち?」で止まる |

---

## 3. 知識の境界

### 知っている(使ってよい)

- 駒の動き、成り、持ち駒を打てること、王手、詰み、二歩などの反則
- 筋と段の数え方(盤の外の数字と漢数字を見て「７六」と読める)
- 飛車と角は強い駒、歩は弱い駒。それ以上の駒の価値の序列は知らない
- 「取られそう」= 相手の駒がその駒を取れる位置にある、という意味は分かる。**「利き」「当たり」という言葉は知らない**(画面が説明すれば、その説明の範囲で分かる)

### 知らない(画面が言うまで知らないことにする)

- 囲いの名前(美濃・矢倉・穴熊)、戦法の名前(振り飛車・棒銀)、「振る」「囲う」「拠点」「筋を通す」などの将棋用語
- 「左」「引」「上」「寄」などの棋譜の記法(P-10 で観測済みの穴)
- 定跡、序盤の形、「この形なら次はこう」の類
- 2 手以上先の読み。「取られたら取り返す」の 1 往復だけは分かる

### 禁止(演じる側の知識が漏れる経路)

- 画面に無い根拠で手を決めない。決めた理由は必ず**画面のどの文・どの印か**を指せること
- 評価語(「良い手」「悪手」「形が良い」)を自分の判断として使わない
- 囲いの完成形を頭の中に持たない。「これから作るマス」の印が指すマスだけを見る
- 相手の狙いを自分で推測しない。②が言わなければ「分からない」のまま指す
- 好意的に解釈しない。「たぶんこういう意味だろう」は禁止。意味が取れなければ「分からない」として記録する

---

## 4. 一手の手順(毎手同じ順で)

1. **盤を見る。** 直前の相手の手(青枠)と、赤い印があるかを見る
2. **帯を読む。** 「いま注意する駒」があれば、その駒を逃がすか守るかをまず考える(逃がし方は 3. の知識の範囲で。逃げる先に相手の駒が来られるかは、盤で 1 手だけ確かめる)
3. **①〜④の要約行を読む。** 分からない語があれば記録し、その語を含む本文だけ開く。本文でも分からなければ「分からない」のまま進む
4. **⑤を見る。** 候補手があれば、添えられた理由を読む。**理由を自分の言葉で一文に言い直せたら**押す(例: 「銀を３八に上げると玉の横が守られるから」)。言い直せなければ押さず、記録して 5. へ
5. **⑤が無い、または押せないとき**は次の順で自分で決める(上から順に、該当したらそこで決める)
   1. 帯の駒を逃がす(取られない場所へ)
   2. 相手の駒を取れるなら取る(取り返されるかを 1 手だけ確かめ、取り返されるなら取らない)
   3. 玉の隣の金か銀を玉の方へ一つ寄せる(「玉を安全に」の感覚)
   4. 歩を一つ前に出す(端から順ではなく、飛車か角の前)
   5. どれもなければ、最初に目についた合法手
6. **記録する**(5. の形式)
7. **止まる条件。** 「分からない」が同じ手で 2 つ以上重なったら、指す前に画面を保存し、そのうえで 4. か 5. で決めて進む(テストを止めない)。矛盾(二つの場所が違うことを言う)は 1 つでも記録し、**上にある方**に従う

---

## 5. 記録の形式

一手ごとに 1 行(表)。局が終わったら末尾に 3 問。

| ply | 見た順(盤/帯/①〜⑤のどこまで読んだか) | 分からなかった語・文・印 | 矛盾・沈黙 | 決めた手 | 根拠(画面のどの文・印か。自分で決めた場合は 4. の何番か) | スクロールが必要だったか(既定の開閉のまま。要 / 不要) |
|---|---|---|---|---|---|---|

- 「沈黙」= 帯も①〜④も何も言っておらず、⑤も無く、自分で決めるしかなかった手
- 「分からない語」は**その語のまま**書く(言い換えない)。本文を開いて分かった場合も「開いて分かった」と書く
- 画面の保存は、止まる条件に当たった手と、矛盾の手だけ(全手は要らない。JSONL に応答は残る)
- **「スクロールが必要だったか」(2026-09-11 に人間が追加。既知事項 P-14 の追認のため)**: **既定の開閉のまま**(①開・②③④閉。自分でブロックを開いた後は数えない)で、画面の下端より先を見るために縦スクロールが要ったかを「要 / 不要」で書く。要った手は、そのときの局面の特徴(帯の件数・①の行数・③の「苦手な攻め」の有無・⑤の状態)も書く。P-14 は STEP 5-3 で「解消」にしたが、実測した局面は 3 つだけである(初期局面 / 候補手あり+当たり 1 件 / 完成+候補手除外)。**3 局(1280×720)を通して一度も「要」にならなければ解消が確かになり、「要」が出ればその局面を添えて P-14 を再登録する**(登録は人間の判断)

**局の終わりの 3 問**(本物の初心者テストと同じ問い。自分で答えて、②④の文と比べる):

1. 今の相手は何をしたかったと思う? → ②の最後の文と一致 / 不一致 / ②が無かった
2. 自分は何をしようとしていた? → ④の最後の文と一致 / 不一致 / ④が無かった
3. 一番分からなかった言葉は? → 記録の「分からなかった語」の最頻出

## 6. 局数と条件

- **3 局**。1 局 30 手(自分の手 15)まで。それ以上は初心者の集中が切れる想定で打ち切る
- 相手は本番の素のエンジン(固定棋譜は使わない。回帰ではなく発見が目的)
- 画面は 1280×720、**新しいページを開いた状態から**(初回接触の経路。[AGENT_PROTOCOL.md](AGENT_PROTOCOL.md) 10.)
- 着手は 3 局とも**盤の駒を押して**行う(2026-09-11 の人間の決定により、文字で入力する欄は今後なくすため、検証でも使わない)
- 3 局の違い(**2026-09-11 の人間の指示により Claude が決めた**):

| 局 | 違い | 何を見るため |
|---|---|---|
| 1 局目 | 4. の手順どおり(素直な初心者) | 基準。どこで止まり、どこで黙られるか |
| 2 局目 | 4. の 5-iii(玉の隣を寄せる)を使わず 5-iv(歩を出す)を優先する(攻めたがる初心者) | 囲いから外れた指し方をしたとき、コーチが何を言うか(認識が付かない局面の量) |
| 3 局目 | ⑤の候補手を一度も押さない。帯と①〜④だけで指す | 候補手が無くても考える順番だけで指せるか([LONG_TERM_VISION.md](LONG_TERM_VISION.md) 6.1「助けの段階」の先取り) |

- 対局の JSONL は保存し、**固定棋譜として登録するかは人間判断**(登録規則は提案書の設問 4)
- **棋譜の名前(2026-09-12 の人間の決定)**: 画面の「この対局を保存」(STEP 5-A)が付ける `id` は `YYYY-MM-DD-live-{手数}moves` で、同じ日に同じ手数の対局を保存すると名前が衝突する。**衝突は手順で解く**: `scripts/playtest/kifu/` へ移すときに、**誰の対局か分かる接尾辞**を付ける(例 `-claude-1`・`-tester-a`)。**ファイルの中の `id` も同じ規則に直す**(ファイル名と `id` を揃える。`replay.ts` は `id` を記録の `kifuId` に使うため、揃っていないと記録から元の対局を辿れない)

## 7. 出力と扱い

- 記録は `docs/OBSERVATION_BEGINNER_CLAUDE_<日付>.md`(観測記録。正本ではない)。README の観測記録の並びに 1 行
- 検出された事象の既知事項への登録は人間の指示による。不変条件の draft を書いてよい(11.)
- **本物の初心者テストとの比較**: 同じ 3 問、同じ記録の形式で取り、「本物だけが出した種類」を抜き出す。それが (a) 演じ方の穴か、(b) 製品が初心者向けでない箇所か、を人間が仕分ける。(a) は本文書の 3.・4. を直す材料、(b) は Unit 6 や見せ方の材料

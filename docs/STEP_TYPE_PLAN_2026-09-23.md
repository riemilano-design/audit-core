# STEP TYPE 計画(2026-09-23、司令塔 e3): 分かれ道の「タイプ」を印の組み合わせで定義し、繰り返しを数える

Phase 2 の入口([DIAGNOSIS_ROADMAP_2026-09-23.md](DIAGNOSIS_ROADMAP_2026-09-23.md) §3 の 2)。**2026-09-23 夜の方針(ROADMAP §2.5)の後の位置づけ**: これは B(「どうしたら」の冊子)の足場になる数。B の「問題 2: 考えた手で崩れる」に、どのタイプが繰り返されているかを足す。「同じタイプの局面が複数局で繰り返される」の**タイプ**を、すでにある印の組み合わせで定義し、本人の 24 局で数える。**予測を先に書く。数を見て定義を変えない。**

## 1. 決まりとの関係
- 事実と件数だけ。タイプに名前(「攻め急ぎ」等)を付けない。付けるのは印の組み合わせそのもの。
- 「本人だけに多い」は pool の持ち時間がそろうまで書かない。今回は本人 24 局の中での「繰り返し」だけ。
- 顧客に伝わるか: タイプは冊子に出す前に、1 行で言えるものだけに絞る(§4)。

## 2. 材料(全部ある)
- whatif-v2: 分かれ道 152、第 1 候補と実戦の手の 攻め/守り/両方/なし、`bothFound`、`sideGapCp`。
- READ: 分かれ道 152 の `firstVisibleNodes`(null = 100 万でも 600 未満)、印 7 つ(drop/capture/retreat/declinesPromotion/sacrifice/kingMove/givesCheck)を第 1 候補と実戦の手に、`materialLook`、`opponentReplyMatchesPv`。
- time: 分かれ道の手にかけた秒、残り時間。
- 局の結果・段(優勢/互角/劣勢)・時期(序中終)。

## 3. タイプの定義候補(印の組み合わせ。先に固定)
分かれ道 152 を、次の 3 軸で分ける。
- 軸 A 大きさ: `firstVisibleNodes` が null(600 未満)/ 2000〜10000(浅い探索で分かる)/ 50000 以上(深い)
- 軸 B 側: 第 1 候補が攻め・実戦が守り / 第 1 候補が守り・実戦が攻め / 同じ側 / どちらかがなし
- 軸 C 性質: 実戦の手が 引く(retreat)/ 捨て駒でない駒得の見た目(materialLook > 0 で sacrifice でない)/ 打つ(drop)/ それ以外
「繰り返し」= 同じ (A, B, C) の組が **3 局以上**に出ること(1 局 1 回で数える)。

## 4. 予測(数を見る前に固定)
| # | 何を | 予測 |
|---|---|---|
| T1 | 3 局以上に出る組の数 | 5 以上 |
| T2 | いちばん多い組 | (null, 同じ側, それ以外)。理由: 600 未満が 100/152、側の一致 61% |
| T3 | 600 以上(A ≠ null)の 52 の中で 3 局以上に出る組 | 2 以下(52 を 3 軸で割ると薄い) |
| T4 | 「第 1 候補が攻め・実戦が守り」の分かれ道の秒の中央値 | 「同じ側」より長い |
| T5 | 「引く手」の分かれ道(16)が出る局 | 8 局以上(1 局に集中しない) |

## 5. 冊子に出す条件(伝わるか)
- 3 局以上に出て、1 行で言える組だけ(例: 「エンジンが攻めの手を選んだ場面で、守りの手を指した。3 局で 5 回」)。
- 「考えられること」「試せること」は数えた後に書かず、**種類 T6 として先に固定**(次の版で): 考えられること (a) その形の局面が多かっただけ (b) 攻め/守りの切り替えの場面で時間が短かった (c) 候補が並んでいた。試せること: 持ち時間の長い対局を混ぜる(秒で分かれる)。

## 6. 作り方
- `type.ts`(純粋関数 + CLI)。whatif-v2・read・time の jsonl を id で結合、(A,B,C) を付け、局ごとに集計、3 局以上の組を出す。試験は合成の 3 局。エンジンは回さない。独立監査 1 回。

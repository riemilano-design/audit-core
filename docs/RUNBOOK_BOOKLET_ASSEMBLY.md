2. **別々に取った最大値を並べた行**(P-95)。「そのまま数えた値 0.8 より数え直した値 1 のほうが高い」のような行。**同じ冊子の「数え方」の節と矛盾する。**

## 4. 手で **足すもの**

- **冒頭の総括「この診断で分かったこと」**。2 つの行動を名指しして「次の 20 局で確かめます」で閉じる。**開いて最初に目に入る場所に置く。**これが無いと、研究資料に見える。
- **数の条件**。「12 局」のような数には「**局を通していちばんそろった時点で見ると**」のような範囲を、同じ文か直前の文に(族 F-1)。
- **数 → 読み → 行動をつなぐ一文**。行動の直前に「この 18 局では〜がありました。そこで〜を試します」。**行動だけ置くと、なぜその行動なのかが飛ぶ。**
- **図の説明文**。**図に出る母集団が本文の表と違うなら、違うと書く**(2026-09-26 は 259 行と 161 行で違った)。

## 5. 組んだ後に必ず数えること

```
for w in ["12 局","局を通して","53 / 92","形に名前を付けて","数え直した値との並び"]:
    print(w, html.count(w))
```

**落としたはずのものが 0 件であることを、機械で確かめる。**目で消したつもりが残る。

そのうえで:
- **盤は自分で並べ直す。**sfen を手で展開し、要る升に何がいるか・駒の枚数が合うかを数える。**2026-09-26 は「角が 2 枚あるから成立しない」と止めて、取って打った結果だと分かった**(私の読み違い)。それでも**並べ直したこと自体は正しい手順**で、駒数の検査が実装に入る契機になった。
- **行動の文は表からそのまま引く。手で打たない。**2026-09-26 の送付済みの冊子で、`M4` の「自玉側」を手で打って「守りの手」に変えてしまった(DELIVER_GATES §2.5 の型)。

## 7. 既知の不具合(直していない)

**Chrome が出す PDF は、文字の層に `ActualText` の注釈を付ける。**注釈と字形の両方を読む取り出し方をすると、文字が二重に見える(「行⾏」)。**紙として見るぶんには正しい。**字形の側は康熙部首に対応づけられているので、**注釈を剥がすと二重でなく「よく似た別の文字」に静かに化ける ― 剥がしてはいけない。**フォント・`lang`・Chrome の旗のどれを変えても消えなかった。**送付済みの冊子にも 194 件ある(新しい不具合ではない)。**
**対策**: PDF はそのまま出し、**テキストで読む人にはテキスト版を添える。**

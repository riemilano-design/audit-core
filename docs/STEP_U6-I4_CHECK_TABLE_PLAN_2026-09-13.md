## 3. 例外と exit code の衝突(**D-1。司令塔の決定: (a) を条件付きで承認**)

**決定: lib の `buildIntentStatementReport` が例外を受け止め、その入力の行を「数えられなかった」として表に出す。受け止めても消さない。exit code は 0 のまま。**

- **受け止めるのは `IntentStatementCountMismatchError` に限らない。** 実装の誤りによる別の例外も来うる。**どの例外でも、表の行に加えて、例外の種類(`constructor.name`)と `message` をそのまま 1 行で出す**(司令塔の条件)
- **合計**: 数えられなかった入力が 1 件でもあれば、**合計の行は「出さない(数えられなかった入力が n 件)」と書き、数字を出さない**(一部を除いた合計を、全体の合計と並べて読ませない)
- 採らなかった案: (b) `check.ts` の `main()` で try/catch(試験を置けない)/ (c) 例外をそのまま通す(exit code が 0 以外になり、人間承認事項に触れる)

## 7. この STEP で分からないこと・限界

- **L-1 ソース照合は片側にしか壊れない**(U6-R 計画書 7. の Y08〜Y10b と同じ形)。**子プロセスの試験で V-3・V-4 は捕まる予測だが、子プロセスの試験も「表の数字」しか見ない。** 数字を変えずに表の意味を変える書き換え(例: 列の見出しの入れ替え)は捕まらない

## 1. 目的と範囲

### 1.1 上位構想(§7.3)からの位置づけ

§7.3 は、有段者の目利きを「機械で測定できる事実 / 事実から条件式で導ける死因候補 / 反事実によって検証できる差 / 機械的に確定できない人間の判断」の 4 つに分け、**D2 はその 3 つ目**にあたる。§7.3 の文をそのまま引く:

- 「実戦の続きと第一候補の続きを同じ尺度(駒得損・王手・玉の安全・逃げ道・攻撃駒・守備駒・利き・速度)で比べ、差分を事実として提示する。**これが D2 の中心になる。**」
- 「『○○が正解』『攻め急ぎで悪い』とは書かず、**事実 → 比較 → 気づき**の順にする。」
- 「ここでは『良い・悪い』『見落とした』などの解釈を行わない。」(§7.3 の 1.)
- 「LLM は『将棋を判断する脳』ではなく、『機械が確定した診断材料を人間に伝える言語インターフェース』である(CLAUDE.md 5 番の言い換えに限る、と同じ)。」

**D2 の範囲は、§7.3 の 1. の「既実装」の尺度で、実戦の続きと第一候補の続きを比べ、差分を事実として出すことに絞る。**

### 1.2 §7.2「調査価値」の数の基準に、D2 の出力がどう材料になるか

§7.2 の基準は「同じ発症条件(§7.3 の 2. の名前つきの死因候補)に該当する急落が 3 件以上」「そのうち 2 件以上で本人が『指したとき危ないと思っていなかった』と答える」「その局を実際に落としたか、5 手以内に自玉へ王手か詰みを受けている」の 3 つである。**D2 は 3 つのどれも判定しない。**D2 が出すのは、§7.3 の 2. の条件式が読む**入力の事実**である。例えば §7.3 の例「攻め急ぎ(仮) = 自分の攻撃駒が減少 かつ 自玉の逃げ道が減少 かつ 第一候補の続きでは上記の変化が起きない」のうち、「自玉の逃げ道(の減少)」は D2 の `kingEscapesRoot` と `kingEscapesEnd`(根からの変化)で、「第一候補の続きでは起きない」は読み筋の側の同じ欄と `diff` で読める(「攻撃駒」は D2 の範囲外 ― 1.1)。条件式の定義と該当件数の集計は D3・D4、本人への質問は D4 の計画で決める(§7.3 の「進め方」)。3 つ目の「5 手以内に自玉へ王手か詰み」は D1 の `consequences`(実戦の続き)が既に数えており、D2 はそれを変えない。

### 2.1 並べる 2 本

- **根(root)**: 直前の ready 行(`fromReadyPly`)の `sfen`。先手番で、次の手が分岐点の手(`branchPly`)
- **実戦**: 記録の手順の `moves[branchPly − 1]` から(`actualContinuation` と同じ手順)。**根は読み筋と同じ直前の行の `sfen` に揃える。**`initialSfen` から `branchPly − 1` 手を並べた局面が行の `sfen` と一致することを先に照合し、**一致しなければ状態 `actualRootMismatch`**(R-3。回した記録で平手から並べる誤りをここで捕まえる)

### 2.4 差(`diff`)

- **向きは「読み筋 − 実戦」に固定する**(名前にも書く: `pvMinusActual`)
- **数の欄だけ差を取る**: `capturedRoles.us` と `capturedRoles.opponent` の駒種ごとの差(0 の駒種は書かない)・`kingSurroundingsEnd.own` の差・`kingEscapesEnd` の差(`count` 同士)。**どちらかが数えられない(null・`noKing`・`opponentInCheck`)なら差も null**(0 にしない)。**根からの変化**(実戦・読み筋それぞれの `kingEscapesEnd − kingEscapesRoot`)も同じ規則で持つ(R-4)
- **王手と詰みは差を取らない**(並べるだけ。ply の並びの「差」は定義しない)
- **差の合計・駒の価値・「どちらが良い」は作らない**(0.5)

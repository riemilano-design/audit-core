# 読者理解ログ ― 冊子ごとに同じ欄で残す(2026-09-30 人間の指示で新設)

**目的**: 「分析 → 本編 → 読者の理解」の最後の変換を、冊子ごとに同じ欄で記録し、次回から機械的に比べられるようにする。読者テスト(席 (a)(b)(c))は「何が伝わったか・伝わらなかったか」を見る。この記録は**本人の感想**から「意味は取れたか・読むコストはどうだったか・どんな意味に変換されたか」を取る。次世代パイプラインでは「どんな分析表現なら読者が正しく意味を取れるか」の評価データになる(エンジン事実 → 各席の分析 → 採用された解釈 → 本編 → 実際の読者理解、を蓄積する)。

**規則**: 本人の言葉は要約せず原文を別ファイルに残し、ここには要点だけ書く。読者の強い解釈を、冊子の断定に格上げする根拠にしない。本人に追加で聞かない(記録が薄くても「無い」と書く)。

## 欄(固定。冊子ごとに 1 記録)

| 欄 | 中身 | 値の種別 |
|---|---|---|
| `booklet` | 顧客符号・版・封の符号・送付日 | ― |
| `source` | 感想の原文の場所 | パス |
| `reached` | 届いたもの | `known`(既知の実感と一致)/ `new`(未知の発見)/ `question`(顧客の問いとの一致)/ `action`(行動の意味が取れた) |
| `not_reached` | 届かなかったもの | `term`(用語)/ `navigation`(導線)/ `action_choice`(どの行動を試すか)/ `other` |
| `reinterpreted` | 冊子の表現 → 読者の言葉。冊子の断定の強さと読者の強さの差 | 対 |
| `slot` | その行が本編のどの slot に当たるか(設計案 `NEXTGEN_CONNECTION_DESIGN_2026-09-30.md` §3.1.2 の id)。印を持つ冊子では `slot_map.json` から機械で、持たない冊子では人が対応させたと注記 | slot id |
| `next_demand` | 読者から出た次の需要 | 自由 |
| `decisions` | この記録から人間が固定したこと | 参照 |
| `do_not` | この記録を根拠にしてはいけないこと | 自由 |

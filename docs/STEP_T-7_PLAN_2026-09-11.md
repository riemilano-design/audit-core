## 2. 実装してよい範囲

### A. エンジンの参考評価を記録に残す(ハーネス)

**A-1(`scripts/playtest/lib/engineReference.ts`(新規)+ test)**: 純粋関数 + エンジン呼び出しの薄い関数。
- `passSfen(sfen)`: 手番を `b`→`w` に入れ替えた SFEN を返す(文字列操作のみ。将棋の判断なし)。
- `measureEngineReference(sfen, engine, nodes)`: (1) 現局面(先手番)を `goMultiPv`(MultiPV 1、`nodes` 固定)で読み、`baseline = { scoreCp, bestmove }`(先手視点)。(2) `passSfen(sfen)`(後手番)を同じ条件で読み、`afterPass = { scoreCp(後手視点), bestmove }`。(3) `afterPass.bestmove` の移動先(`toSquareOf`)に**先手の駒がある**なら `captureSquare` にそのマス、無ければ null(`parsePosition(sfen).board` を読むだけ)。(4) `dropCp = baseline.scoreCp − (−afterPass.scoreCp)`(先手視点の落ち幅)。score が `mate` のときは cp を null にし、`mate` の符号だけ残す(比較はしない)。
- **測らない場合**(null を記録): 先手が王手中(`isInCheck(sfen, "sente")`。パスが成立しない)、終局、エンジン失敗・タイムアウト(例外は握りつぶして null。推測しない)。
- 探索量は `--nodes`(既定 4,000,000。T-6)と同じ値を使う(決定的)。`Threads=1` は replay.ts が既に設定。**探索モード(explore.ts)でも参考評価だけは同じ固定条件で測る**(相手の手は本番条件のまま。参考評価はハーネスの観測であって本番の判断ではない)。

**A-2(`recorder.ts`・`replay.ts`・`explore.ts`)**: ready 行に `engineReference: EngineReference | null` を追加(`invariants/types.ts` の `RecordLine` に optional で追加。immediate 行には付けない)。`buildReadyRecord` に `referenceNodes` を渡し、`safeComputeReachablePlan` の後に測る。`--reference-nodes <N>`(既定 = `--nodes` の値。explore は既定 4,000,000)。`compare.ts` の正規化では **除かない**(固定条件なら一致するはず。一致しなければ観測として報告)。meta に `referenceNodes` を記録。

# STEP CUSTOMER-EXIT ― 顧客向け出口を `deliver.ts` の段にする(2026-09-28・人間の決定)

**担当**: 自動化レーン(実装)・独立監査(GO/REVISE)・司令塔(正本の固定・仕様の承認)。**記録は `docs/LANE_AUTOMATION_LOG_2026-09.md`。**

## 0. なぜこの STEP があるか(1 段落。ここを読めば残りの理由が分かる)

承認済みの納品の形 ― **本編 3 ページ + 対応表、付録 1 冊 20 ページ前後、合計 30 ページ前後**([DELIVER_GATES.md](DELIVER_GATES.md) §3a)― は、
**2026-09-24 に 4 者が 6 冊 113 ページの納品を「顧客に価値が薄い」と却下した結果**として作られ、**「次のモニター 5 名にも使う」と書かれた。**
ところがその形を作った道具は `scripts/playtest/out/_deliver1_handoff/reedit/`(**gitignore の試作**)にしかなく、**`deliver.ts` は却下された 6 冊の形を出す。**
2026-09-28、司令塔は `deliver.ts` を通して**却下された形(6 冊 129 ページ)を 5 人目に対して再現した**。3 席の批評と人間の読みが出した結論
(「研究ノートを顧客に見せている」「本人の像が無い」)は、**9 月 24 日に既に出ていた結論だった。**
**原因は、分析パイプラインに「顧客向け出口」が無いこと。** 人間の決定: **手で 30 ページに戻して終わりにしない。出口そのものを `deliver.ts` の段にする。**
**それを Phase 2 の自動組版の一部として扱う。**

## 1. 順番(人間が決めた 7 段。動かさない)

| # | 何を | 誰が | 出るもの |
|---|---|---|---|
| 1 | **承認済み 30 ページ版を正本(golden master)として固定** | 司令塔 | [GOLDEN_MASTER_CUSTOMER_EXIT.md](GOLDEN_MASTER_CUSTOMER_EXIT.md)(構造・実物 2 件の指紋・試作の指紋) |
| 2 | **今回の 6 冊 129 ページを材料庫として扱い、30 ページ版に要る材料を対応付ける** | レーン(**測るだけ**) | 対応表: 正本の各ページ ↔ 6 冊のどのページ / どの JSON の鍵。**無いものは「無い」と書く** |
| 3 | **30 ページ版を生成する仕様を決める** | レーン案 → 司令塔承認 | §2 の線引きに沿った段の設計(入力・出力・止まる場所・検査) |
| 4 | **`deliver.ts` に「顧客向け出口」の段として実装** | レーン → 独立監査 GO → コミット | 段の追加。**既存 17 段は変えない** |
| 5 | **1 冊生成**(5 人目) | 道具 | 本人用・見本用 |
| 6 | **正本と構造比較**(§3 の 8 項目) | 道具 + レーン | 8 項目の ○/× と差 |
| 7 | **門を通してから納品** | 道具 → 司令塔 → 人間 | `check_answer` / `check_delivery` / 構造比較 すべて通過 |

**1 と 2 は同時に走ってよい**(2 は正本の構造が §3a.2 に既にあるので待たなくてよい)。**3 は 2 の対応表が出てから。4 は 3 の承認の後。**

## 1b. 1 セットの範囲(人間の追加・2026-09-28)― **30 ページ版を作ることと、批評席に読ませることまでを 1 セットにする**

人間の言葉: **「30 ページ版を作る → 文脈ゼロの読者席 + Gemini に同条件で読ませる、までを 1 セットにする。これが本来の Phase 2。」**
そして今回の本当の問題は **「129 ページ版を批評席に通す前に『これは器が違う』と検出できなかったこと」** ― だから **器の検査(§3 の構造比較)は批評の前に置く。**

| # | 段 | 決定的か |
|---|---|---|
| 5 | 生成(本人用・見本用) | 機械 |
| 6 | **器の検査** = §3 の構造比較 8 項目。**落ちたら批評に回さない**(器が違う PDF を批評しても、9 月 24 日の結論を取り直すだけ) | **門(通る/落ちるが再現)** |
| 6b | **司令塔の封**(`PHASE1_SEALED_READING.md` の形: 弱い 3 点・1 ページ目で受け取るもの)を**コミット** | 順序が証拠 |
| 6c | **批評席**: 文脈ゼロの身内の席 + 外の席(当面は人間が掛ける。Phase 2 で API 連携)。**渡すのは完成 PDF と固定の 3 問だけ**(`RUNBOOK_PHASE1_MEASUREMENT.md` §3) | 門ではない |
| 6d | **集計**(自動化レーン長): 共通 / 片方だけ / 封と一致 / 封に無かった / 観測事実に反する / 好み・表現差 の **6 分類**(人間の列挙。⑤の「観測事実に反する」は機械で照合) | 分類は機械・採否は司令塔 |
| 6e | 採用する直しを決め(根拠 1 行)、必要なら **5 へ戻る**(再 PDF の周回数を数える。2 周を超えたら人間へ) | 司令塔 |
| 7 | 最終の門(`check_answer` / `check_delivery` / 器) | 門 |
| 8 | **人間が「この顧客に送る」を決める** | 人間 |

**これで初めて「30 ページに戻したことで顧客価値が戻ったのか」を検証できる**(人間)。**制作過程を知っている席が「ここはこういう意図」と補って読んだら意味が無い** ― だから批評席には背景を渡さない。

## 2. 何を機械にし、何を書き手に残すか(2026-09-24 の判断を引き継ぐ)

§3a.5 の判断 ―「**本編の中身(主題の選び方・どの盤を 2 つ選ぶか・どの行動を出すか)は書き手が数を見て決めるので、道具にできるのは組版だけ**」― は**引き継ぐ**。
**ただし「候補を機械が出し、書き手は選ぶだけ」は道具にしてよい**(P-101 で決めた形と同じ)。

| 層 | 機械 | 書き手(段は `prose-gate`・`answer-gate` と同型の確認点で止まる) |
|---|---|---|
| P1 数 3 つ | **候補を出す**: `findings` の `shown` なもの + `overview` の主要な数を、**分母つき**で並べる(上限は置かない。並べるだけ) | **3 つを選ぶ・並び順・「ひとことで」の 1 行** |
| P2 盤 2 つ | **候補を出す**: 付録 2・3 に盤が印字されている局面から、`<!-- pos: -->` の形で一覧 | **2 つを選ぶ・各盤の 2 行** |
| P3 試せること | **候補を出す**: `answer_menu.json` のうち **`minN` を通った項目だけ**(通らなかった項目は**「今回は出さない・数 n < minN」と列挙**して、書き手にも読者にも見える形で残す) | **出す本数(§3a.2 は 2 つ)と根拠の 1 行** |
| P3 答え合わせの表・数え方 | **機械が書く**(数と分母は JSON から。§2.2b の 3・4) | 触らない |
| 対応表 | **機械が書く** | 触らない |
| 見本用 | **機械が作る**(対応表のページを抜く) | 触らない |
| 付録 1 冊 | **機械が抜く**: 本編が `<!-- pos: -->` と「付録 N の M ページ」で指すページだけ | 触らない |
| 商品の範囲の 1 段落 | **固定文**(§3a.2 の「免責ではなく、商品の範囲を書く」) | 触らない |

**書き手の席の時間は測る**(§5)。**これが §3a.5 が「測ってから決める」と言っていた原価③である。**

## 3. 正本との構造比較(人間が挙げた 8 項目。**文章の似方ではなく構造**)

| # | 項目 | 機械で比べる方法(仕様で確定させる) |
|---|---|---|
| 1 | ページ構成 | 各ページの先頭見出しが、正本の順(数 3 つ → 盤 → 試せること → 数え方 → 対応表)か |
| 2 | ページ数 | 本編 ≤ 5、付録 ≤ 25、合計 30 前後(正本の実物: 4 人目 5 + 17 = 22) |
| 3 | 数 3 つ | P1 に**分母つきの数が 3 つ**あり、それぞれ `patient_report_data.json` / `audit_metrics.json` に**実在**する |
| 4 | 局面 2 つ | P2 に `<!-- pos: -->` が**ちょうど 2 つ**、どちらも付録に盤がある(検査 7) |
| 5 | 行動 | `<!-- menu: -->` の印が付き、**minN を通った項目だけ**、本数は §3a.2 のとおり |
| 6 | 答え合わせ | 表があり、行数 = 行動の本数、「今の値」列が JSON の数と一致 |
| 7 | 対応表 | 本人用にあり、見本用に**無い** |
| 8 | 付録の扱い | 付録のページ数 = 本編が指すページの数(**指していないページが混ざっていない**) |

**8 項目とも、通る/落ちるが再現する形(決定的な門)にする。** 「顧客に伝わるか」は門にできない(§11 の区別)ので、**それは批評席の仕事のまま。**

## 4. 制約(既存の規則で、この STEP に効くもの)

- **新しい数・手・局面を作らない**(§3a.1)。出口は**選んで並べるだけ**。
- **既存 17 段は変えない。段を足すだけ。** `--out` の安全装置・`--from` の再開・`deliver_log.jsonl` はそのまま。
- **凍結の例外として扱う**(DELIVER-1 は凍結中)。**動きを変えるので独立監査 GO 無しにコミットしない。**
- **本人用と見本用の 2 通り。** 出品ページの約束「PDF 2 冊・30 ページ前後」。
- **`check_answer.py`・`check_delivery.py` を通す**(§3a.4)。構造比較(§3)を**新しい検査として足す**。
- **DELIVER_GATES §4「やってはいけないこと」を全部読む。** 特に「検査を通すために中身を選ばない」。
- **試作 `build.py` をそのまま `scripts/` に移して段にしない。** 読んで、使える部分(盤の SVG・md→PDF・ページ抜き)は**既存の `report-pdf/` の道具と重ならないかを先に数える**(重なっていれば既存を使う)。
- **予測を先に書く**(落ちる件数・ページ数・付録に抜かれるページ数)。**測ってから直す。**

## 5. 測ること(Phase 1 の続き。`docs/PHASE1_MEASUREMENT_LOG.md` に追記)

- 段の所要(壁時計)・**書き手の席の時間(候補から選ぶのに何分か)**・再 PDF の周回数。
- **129 ページ → 30 ページで、捨てられた材料は何か**(§1 の 2 の対応表から数える。**「分析を捨てるのではなく、出口だけを戻す」を数で示す**)。

## 6. やらないこと

- **129 ページ版の中身をこれ以上磨かない。** A(付録 3 の題)・B(手数)の直しは**材料の誤り**なので済ませる。C〜I は**材料に効くものだけ**(D の分母・E の版名)。
- **「再現」層(同じ型が何局で起きたか)の設計** ― 別の判断(`PHASE1_MEASUREMENT_LOG.md` の司令塔の見立て)。**この STEP に混ぜない。**
- **昇格の基準の節** ― §2 の P3 の「minN で落ちた項目の列挙」で**自然に入る**。別の節は作らない。

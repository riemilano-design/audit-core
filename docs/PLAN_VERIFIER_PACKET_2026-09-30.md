## 0. 顧客の PDF にどう出るか(先に書く)

**今は何も変わらない。**冊子の文も数も同じまま出る。
この束が足すのは、**顧客に出る文が「packet の数を指している」ことを機械で確かめる道**である。

いまの冊子は、数が合っているかを「材料のどこかに同じ整数が在れば通る」(`check_answer` の検査 1)で見ている。
**同じ数が別の意味で在っても通る** ― これが P-178(同じ 22 が「局」と「局面」の 2 つの意味で出た)の根であった。
この束の後は、本編の数に `<!-- agg: id -->` の印を付ければ、**その数が packet のどの集計行から来たか**を
機械が突き合わせられる。**印を書く段(⑥ の器づくり)は別の束**で、この束は**印が在れば見る側**を作る。

顧客が受け取る冊子の見え方が変わるのは、その後に「答えの場所」の門(⑧(a))と器づくりが入ってからである。

## 2. V-1(H-9): packetRef の実在と値の一致

**やること**: `observations[].packetRef.path` を packet の中で**解決**し、(a) 在ること、(b) `observations[].value` と
**同じ値**であることを見る。`provenanceId` が在れば `provenance.sources[].id` に在ることも見る。

- **path の文法は import する**(`lib/packetRef.ts`。実験席の module)。**この束で正規表現を書かない。**
- **解決器はこちら側**(packet を読むのはレーンの仕事): `resolvePacketPath(packet, path)` を
  `lib/observationPacket.ts` に足す。`aggregates.<id>` は**集計の行**を指し、
  `facts.<列>[n].<欄>` は**事実の行の欄**を指す。**解決できない path は「在らない」と言う**(黙って通さない)。
- `aggregates.<id>` が指す「値」は 1 つに決まらない(分数の行は分子と分母がある)。
  **規則**: `aggregates.<id>` 単独は**単独の数の行(`value`)だけ**を指し、分数の行は
  `aggregates.<id>.numerator` / `.denominator` まで書かせる。書かれていなければ **H-9 が落とす**
  (「どの数を指しているか決まらない」)。**これは私が決める点**なので §8 で司令塔に上げる。
- **版**: `hypothesis.v0.4` に `observations[].packetRef` が入る(実験席の計画 §2.2)。
  **schema の版上げは実験席の側**。H-9 は「欄が在れば見る」(無い行は H-9 を飛ばす ― v0.3 の行がそのまま通る)。

## 3. V-2(H-10): 語彙

**やること**: 文(`statement`・`counterEvidence.items[].text`)に出た**形・戦法の名前**が、
その顧客の packet の認識に在るかを見る。

**やり方(測って決めた)**: 名前を「文から見つける」には候補の一覧が要る。**一覧は packet の定義の名前**
(`facts.recognition.definitions[].name` / `nameKana` / `id`。実物で 114 × 3)を使い、**字面で照合する**。
- **(α) 定義に在るか**: 一覧から探すので、見つかったものは必ず定義に在る(接続設計案の言う H-10 はここ)。
  **ただしこれだけでは緩い** ― 定義 114 は `data/` の全部で、**その顧客の局で認識されていない名前も通る。**
- **(β) その顧客の局で認識されたか**: `facts.recognition.rows[].names`(実物で 16 種)に在るか。
  **無ければ落とす。****私の判断で (β) を H-10 の本体にする**(理由: (α) は素通しに近く、
  「この顧客の盤から生じたものだけを述べる」という上位原則に効くのは (β))。**§8 で司令塔に上げる。**
- **捕まえられないもの**(正直に書く): **定義の一覧にも無い名前**(誰も承認していない造語・別名)は、
  字面の一覧に無いので**この検査では見つからない**。そこは禁止語の側(`check_answer.BANNED_WORDS`。いまは空)と
  人の目に残る。**「H-10 を入れたから名前は安全」とは書かない。**

## 4. V-3: 分母・母集団の数え直し

`packetRef` が `aggregates.<id>` を指す行は、**その集計行を束 D の数え直しに通す**
(`recountProblems` を 1 行に絞る口 `recountRowProblems(packet, id)` を足す)。

- **数え直せない行**(`recountable: false` の時間の 2 行)は**対象外**で、
  その代わり**「数え直せない行を根拠にしている」ことを検査の結果に書く**(落とさない。印だけ)。
  理由: その 2 行は材料の秒が中盤の手だけで数え直せないと既に記録済み(束 C・人間の了承)。
- **呼び方**: 検証器は TS なので**関数を呼ぶ**(`--verify` の CLI を子プロセスで起こさない)。
  CLI の `--verify` は**人と CI が packet 単体を見るための入口**として残す(束 D)。
  `deliver.ts` の段からは呼ばない(段を増やさない)。

## 5. V-4: 本編の数の id 照合(⑧(c))

`report-pdf/exit_gate.py` に検査 **(x)** を足す。

- 印の形は既存の家族にそろえる: `<!-- agg: <id> -->`(既存は `<!-- pos: … -->`・`<!-- menu: … -->`・`<!-- sec: … -->`)。
  正規表現は `check_answer.py` の `POS_TAG_RE`・`MENU_TAG_RE` の隣に `AGG_TAG_RE` を置く
  (**印の文法は 1 か所**。P-185 の教訓)。
- 見るもの: (1) 印の `id` が packet の `aggregates` に**在る**。(2) **印が付いた行に出る整数**が、
  その集計行の数(`value`・`numerator`・`denominator`)の**いずれかと一致**する。
  (3) 印が 1 つも無ければ**「0 件」と報告して落とさない**(印を書く段はまだ無い)。
- **既存の検査 1 は残す**(「材料のどこかに同じ整数が在れば通る」)。(x) は**その上に重ねる**。
- **packet の場所**: `exit_gate.py` に `--packet <path>` を足す。**渡されなければ (x) を飛ばし、
  「packet が渡されていないので id の照合をしていない」と報告する**(黙って飛ばさない)。

## 6. 試験(何が固定されるか)

1. **H-9**: 合成の packet と行で、(a) 在る path・値一致 → 0 件、(b) 在らない path → 落ちる、
   (c) 値がずれる → 落ちる、(d) 分数の行を `.numerator` 無しで指す → 落ちる、
   (e) `packetRef` の無い行(v0.3)→ H-9 は飛ぶ(既存の行が落ちない)。
2. **H-10**: (a) 認識に在る名前 → 0 件、(b) 定義に在るがその顧客の認識に無い名前 → 落ちる、
   (c) 定義にも無い造語 → **落ちない**(捕まえられないことを試験で固定する ― 後から「守れている」と誤読しないため)。
3. **V-3**: 集計行を指す行で、packet の数を 1 ずらす → 落ちる。`recountable: false` の行を指す → 落ちないが印が出る。
4. **V-4**(python): 印の id が無い・数が合わない・印が 0 件・packet が渡されない、の 4 通り。
   **`check_answer.py` は触らない**(`AGG_TAG_RE` は印の文法の 1 か所として置くだけ ― 既存の検査は変えない)。
5. **実データで測る**(門では読まない): (i) 席の出力(`out/c5/experiment-llm-25/`)に H-9・H-10 を当てて、
   **落ちる本数と理由の内訳**を記録する(実験 1 の「束に無い数 約 25 か所・うち 2 つ誤り」が
   **機械で何本落ちるか**の初回の測り)。(ii) 本編 md の**写しに印を入れて** (x) が噛むことを確かめる。
6. **門は今までどおり 2 本**(`npx vitest run --root scripts/playtest`・`npm run typecheck:scripts`)。
   python の試験は既存の `reportPdfPythonTests.test.ts` が拾う(`exit_gate_test.py` が在れば足す)。
7. **変異は予測を先に書く。**合成材料は「壊したときに数が動く」ことまで確かめる
   (束 C・D で同じ型を 4 回踏んだ ― 値を全部並べて同じ値の組を機械に出させる)。

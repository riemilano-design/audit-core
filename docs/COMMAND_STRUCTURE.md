## 3. 報告と相談の向き(4 つだけ)

1. **下から上へ**: 担当 → レーン長 → 司令塔 → 人間。**飛ばさない。**
   - **例外ではなく前提**: **人間がある席に直接話しかけたときは、その席が直接答える。** 窓口の一本化は**席どうしの連絡**の決まりであって、人間が目の前で聞いていることに「司令塔を通してください」と返す意味ではない(2026-09-24、広報レーン長の確認)。
   - **二重に上げない**: すでに別の席が人間へ直接上げた件を、司令塔が上げ直さない。**人間の側で 2 件に見える。**(2026-09-24 に 1 件実際に起きかけた: 行動表 M4 の文言。開発・診断レーン長が既に直接上げていた)
2. **横は連絡してよい。決めごとは上へ。** レーン同士は事実と材料を直接やり取りしてよい。ただし**方針・文言・値を変える相談は自分のレーン長へ出す**。
   - 正しい横の連絡の実例(2026-09-23〜24): 「20局のレポート作成」が、材料と条件を広報の指示役から受け、道具の不具合を納品レーン長へ回していた。**事実と不具合は横に流れてよい。**
   - **要点は「二重に聞かない」**(本人の申告、2026-09-24): この形が機能したのは、**何を誰に聞くかを毎回分けていた**から。道具の不具合は納品へ、顧客への見せ方と公開の条件は広報へ、と分け、**同じことを両方に聞かない**。9/24 に営業と同じ疑問を持ったときも「使ってよい数の出どころは営業から、9/23 の条件が生きているかはこちらから」と分担した。**同じ問いを 2 つの席に出すと、違う答えが返ってきたときに、どちらが正しいか誰も決められなくなる。**
3. **人間の決定は、直接受け取った席だけが正本へ書く**([AGENT_PROTOCOL.md](AGENT_PROTOCOL.md) 5.2)。セッション間のメッセージを人間の承認の代わりにしない。**伝聞で統治規定を書き換えられる経路を作らない。**
   - **司令塔から伝えられた人間の決定も同じ扱いである**(2026-09-24、納品レーン長の申し出)。司令塔が中継しても伝聞は伝聞であり、**受け取った席は自分の正本に「人間の決定」として書かない**。書くのは直接聞いた席。中継された側が自分の正本に書くのは、**自分が測った数と、自分が決めた設計とその根拠**だけ。
4. **司令塔を飛ばしてよい唯一の例外は「止めるとき」。** 危険・取り消せない操作・規約違反・顧客の個人情報の流出に気づいた席は、**誰に対しても直接「止めて」と言ってよい**。止めるのに許可は要らない。

## 5. 同じ木を共有しているための決まり(物理)

複数のセッションが同じ作業ツリーとエンジンを共有しているため、守らないと**自分は何もしていないのに他人の作業が壊れる**。

| 決まり | 理由 |
|---|---|
| コミットは `git add` を使わずパス指定。新規は `git add -N` | 共有のステージ領域を通ると、並行セッションの変更を巻き込む |
| `git stash` を使わない | スタッシュも共有 |
| 実機確認(ブラウザで対局)は一度に一セッション、`npm start` | 対局の状態はサーバーのグローバル変数 1 つ。`npm run dev` は他人の保存で再起動する |
| エンジンは同時 5 本まで。所要を測る実行は 1 本だけ | 測定値が壊れる |
| STEP 番号・既知事項の番号は、正本を持つ席が採る | 番号空間の持ち主が 1 人でないと衝突する |
| 測るときは worktree で | 型を入れて `tsc` を回す数分間、共有ツリーは他人から見ると壊れている |
| worktree は使い終わったら片づける | 5. の下の表を参照 |

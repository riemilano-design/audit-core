### 4b. 封は 3 つの数で掛ける(sha256 では掛からない。P-145)

**`reportlab` は PDF に `/CreationDate` を埋めるので、入力とコードが同一でも毎回バイト列が変わる。**
したがって **sha256 は「組み直せる PDF」の封には使えない** ― 破れても改変の証拠にならず、一致しないこと以外に何も測れない。

封は `compare_render.py --seal <json> <PDF>…` / `--verify <json>` で掛ける。**3 つの数** ― **ページ数 / ページごとの本文の指紋 / ベクタの本数と署名**。sha256 は参考として併記するだけで、不一致でも赤にしない。
**校正 3 通り**: 組み直しに耐える(rc=0)/ 本文の 1 文字で赤(rc=1)/ ベクタの変更で赤(rc=1)。

## 追補(2026-09-28・司令塔承認)― 索引は 2 層・鍵の形は付録ごと・束ねるのは `exit-render`

§3 の 2(局面 → 付録のページの索引)を、実物を測った結果に合わせて具体化する。

### なぜ追補が要ったか(実物が要求していた)

**実物は `<!-- pos: -->` だけでなく「節」も指している。** 4 人目の本人用 p2 の 1 行目は
「**付録 3 の 8 ページ**に、この局面の盤と第 1 候補からの読み筋があります」。
② の表で 4 人目の付録に入ったページは、**局面で引けるページ**と、**節のページ**(「形勢の流れ」「読み方」等)の両方。
**局面だけの索引では、本編が指すページを機械で決められない。**

### 決めたこと

**1. 索引は 2 層**: `positions`(局面 → ページ)と `sections`(節 → ページ)。**どちらも置いた経路が書く。**
本編の側は `<!-- pos: 局/手 付録N [組] -->` か **`<!-- sec: 付録N/節名 -->`** で指し、
**検査 8「本編が指すページだけ」はこの 2 種の合計で数える。**(`<!-- sec: -->` の検査は未実装 ― `exit-render` と同じ段で入れる。)

**2. 鍵の形は新しく作らない** ― **付録ごとに `check_answer.py` の検査 7 がその付録について受ける形そのまま**:

| 付録 | `positions` の鍵 | 理由 |
|---|---|---|
| **付録 1**(`_mid.py`) | `局/手` | `prose.json` の `scenes[].ply`。組を持たない |
| **付録 3**(`render_direct.py`) | **`組 → 局/手`**(入れ子) | **局番号は組ごとに 1 から振られ、組をまたいで衝突する**(2026-09-25 の凍結の例外 7b)。本編の印も `<!-- pos: 局/手 付録3 組 -->` |

**平らな鍵に組を混ぜる形(`"C7/5/59"`)は採らない** ― **組の有無が辞書の中で見えなくなる。**

**3. 節の鍵は印字される文字ではなく固定の名前。** 印字は「25 局の形勢の流れ」のように**顧客ごとに局数が入る**ため、
文字を鍵にすると顧客をまたいで引けない。**固定名の正本は `report-pdf/exit_index.py` の `APPENDIX_SECTIONS`**
(組版と門が同じ定数を見る。片方に文字列を写さない)。

**4. 組版は自分の索引だけを書き、`exit-render` が付録ごとの入れ子に束ねる。**
各組版は PDF の隣に `<PDF 名>_page_index.json` を書く。`exit-render` が読んで統合版を作る:

  "付録3": { "positions": { "3 分": { "5/59": 8 } }, "sections": { "分かれ道": 6 } }

**5. 範囲は付録 1 と 3 だけ。** 付録 2(`render_whatif.py`)のページは**両実物とも 0 枚**なので触らない。

### 実装で分かったこと(2026-09-28・コミット `68410d1`)

- **reportlab はページ番号を組んだ後にしか知らない。** 局面は流し込みで連続して並ぶ(`PageBreak` は 3〜4 か所だけ)。
  だから `doc.afterFlowable` で **`doc.page` を読むだけ**にする。**flowable は 1 つも足さない。**
- **出力が変わっていないことは、バイトでは測れない。** `invariant` を立てている場所は 0 件なので、
  **無変更で 2 回作っても 64 バイト(0.028%)違う**(`/CreationDate`・`/ModDate`・`/ID`)。
  **比べ方は (1) ページ数 (2) ページごとの文字 (3) `get_drawings()` のベクタの形。**
  **`get_images()` は使えない** ― 盤は埋め込み画像ではないので 0 を返す(実測)。
- **`KeepTogether` は `afterFlowable` に渡らない**(`wrap()` が常に分割を強制する)。記録されるのは中身の表。

### ① の制約 ― **実物での確認は門にできない**(2026-09-28・司令塔承認)

**合成材料の試験が門。実物での確認は記録。**

**理由**: 実物の確認を門にするには、**顧客の棋譜と診断データをリポジトリに置く**ことになる。
置けない(`records/` の実棋譜はコミットしない・相手の名前は出さない、が既に決まっている)。

**だから扱いを分ける**:

| | どこで | 何が根拠になるか |
|---|---|---|
| **門** | `report-pdf/*_test.py`(合成材料・一時フォルダ) | **これだけが門。**変異で落ちることと、門の行が 1 本ずつ覆われていることを測る |
| **実物での確認** | 納品ごとに `deliver_log.jsonl` に**記録する段** | **門ではない。**何を・何件・一致したかを残す(例: 2026-09-28 の実測「索引の 4 件すべてで、抜いたページにその局面・節があった」) |

**これは自動化の限界そのもの**: **組版と検査を機械にしても、実物で合っているかの確認は人の手に残る。**
`AUTOMATION_STATUS` §10 の「残る人間の判断」に、**判断ではない作業**として数える(進行の監視と同じ棚)。

### §5 付録の表紙(2026-09-29 実装。正本 §8 の 4 要素を道具にした)

**表は「節」単位で 3 行**(束ねるのが付録 1 + 付録 3 のため)。
正本 §8 の説明「束ねた付録ごとに 1 行」は司令塔の書き誤りで、**同じ表のデータ(実測)が正**
― 実物 2 件はどちらも 4 行で、**付録 3 が 2 行**を出していた(自動化レーンが fitz で読んで指摘、司令塔が訂正)。

| 要素 | どこから来るか |
|---|---|
| 見出し・段落・末尾(枠) | **4 人目の実物**(`kori/deliver1_送付用/2_付録_数の出どころ.pdf` p1、mtime `2026-09-25T07:06`)。`exit_index.py` の定数に出どころを書いて固定。**3 人目からは写さない**(廃止済みの免責 2 文・顧客の名前が入っている) |
| 表の「節」の列 | `exit_index.COVER_SECTIONS` × `SECTION_TITLES`。**組版と同じ定数**(`_mid.py`・`render_direct.py` が import) |
| 表の「中身」の列 | `COVER_CONTENT` の型 + **材料からの数**。**語はすべて道具に実在する行から採る** |
| 表の「本編との対応」 | 印(`<!-- sec: -->`)の逆引き。**実物より粗い** ― 節の中の順番や仮説番号は印から出せないので作らない |

**写す前の参照先は 2 つある**(表紙で分かったこと):

| 写すもの | 根拠 | 理由 |
|---|---|---|
| **中身の欄**(本編の言い方) | **道具に実在すること** | 実物にしか無い語は「写し」ではなく**新しい文** ― 4 人目の「時計で終わった」は道具に 0 件、3 人目の「時間切れ」は 09-27 に廃止した語 |
| **枠**(見出し・段落・末尾) | **実物**(fitz で読む) | **表紙を作る道具がこれまで無かった**ので、道具に 0 件なのは当然。ここで道具を根拠にすると枠ごと落ちる |

**実在の検査は、参照先に自分を含めない。** 型の置き場(`exit_index.py`・`exit_cover.py`)を数に入れると**循環**し、
**型に書いたどんな新語でも「道具にある」ことになる**(実測: 「盤つき」を 1 件と数えたが、その 1 件は自分の型だった)。

**`hasCover` は検査 8 で必須。** 抜けると顧客は「この冊子に入っているもの」の案内を失い、本編から付録を辿れない。
変異 2 本(偽を書く・鍵ごと無い)で赤になることを測った。

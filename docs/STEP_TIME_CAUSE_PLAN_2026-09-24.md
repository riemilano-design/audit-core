# STEP TIME-CAUSE 計画(2026-09-24、司令塔 e3): 時間負けの要因を、機械で測れる候補に分解する

**人間の指摘(2026-09-24、外部の読み手の意見を人間が採用)**: 「時間が無い → 10 分で指す」は条件変更であって対策ではない。「時間が無い → なぜ無いのかを機械的に分解する」。原因候補を最初から処方にせず、**全部を候補として測り、数字が出たものだけ B に上げる**(「中盤 1 手 4 秒」を捨てたのと同じ挙動を、時間負けの要因に対して行う)。「数」という言い方は伝わりにくい(B では「分かっている事実」に言い換える)。

位置づけ: Phase 2 の新しい分析軸(TYPE と別)。[DIAGNOSIS_ROADMAP_2026-09-23.md](DIAGNOSIS_ROADMAP_2026-09-23.md) §2.6 の「B の仮説を個人化する追加材料」。B v5 の問題 1 の節はこの結果で書き直す。

## 1. いま分かっていること(A の事実)
3 分切れ負け 34 局のうち時間で負けた 3 局は、盤上では大きく優勢(+2806・3 手詰み・+2346)。消費の中央値は序盤 25 秒・中盤 84 秒・終盤 42 秒。中盤の 1 手あたりの速さでは他の局と分かれない(4 秒超 7 局のうち時間負け 1、[STEP_ANSWER_PLAN_2026-09-23.md](STEP_ANSWER_PLAN_2026-09-23.md) §7.6)。時間負けの 3 局は中盤の消費の合計が他の局の中央値(14 秒・39 秒)を大きく超える(84・77・84)。**ここまで**。「なぜ中盤で時間が消えたか」は分解していない。

## 2. 原因候補と、KIF から測れるか(人間の表を写し、測り方を付けた)

| # | 原因候補 | 測れるか | 測り方(既存の値だけ。新しい閾値を置かない) |
|---|---|---|---|
| C1 | 序盤で時間を使っている | ○ | `phaseSpent.perGame.early`(§7 で足した `perGame` に早・終の秒も足す) |
| C2 | 中盤で時間を使っている | ○ | `perGame.midSec`(済み) |
| C3 | 長考(10 秒以上 = `TIME_VALUES.longThinkSec`)が多い | ○ | 局ごと・時期ごとの長考の回数 |
| C4 | 1 回の長考が長い | ○ | 局ごとの最長の 1 手の秒と、その手目 |
| C5 | 長考が連続する | ○ | 本人の連続する 2 手がともに 10 秒以上の回数 |
| C6 | 中考(5〜9 秒 = `spentBucketsSec` の 4 超〜9)の積み重なり | ○ | 局ごと・時期ごとの 5〜9 秒の手の回数と合計秒 |
| C7 | 特定の局面タイプ(分かれ道か/攻め・守りの側)で時間を使う | ○ | 長考の手を whatif-v2 の position 行と `ply` で結合: 長考が分かれ道に当たる割合、長考の手の側の一致(TYPE §7.1 の T4 は「攻め→守り」の分かれ道の秒の中央値 2 秒 < 同じ側 4 秒、n=11) |
| C8 | 攻め・守りの判断で時間を使う | ○ | C7 と同じ結合で「10 秒以上 × 側が逆」の数 / 10 秒以上の分かれ道 |
| C9 | 特定の戦法で時間を使う | △→○ | 戦法の名前は付けない(ルール 4)。**機械で取れる形の印**で分ける: 序盤の終わり(`phaseOf` の 1/3。新しい定義を置かない)の局面で、本人の飛車の筋(初期の筋のまま/左へ動いた)、相手の飛車の筋。この 2×2 で局を分け、序・中の消費と長考の数を比べる |
| C10 | 序盤を速く指せた局ほど中盤に時間を残せたか | ○ | 局ごとの `early` と `midSec`・残り時間(`byLeft` の材料)の関係。34 局の散布を表にする(相関の値は出さない。並べるだけ) |
| C11 | 何を考えていたか | △ | 自己申告(感想票)。測らない |
| C12 | 読みが浅かったから時間を使った | △ | 定義が要る。今回は測らない |

**「何手目までを序盤とするか」は新しく決めない**: 既存の `phaseOf`(局の手数の 1/3・2/3)を使う。局ごとの手数で境が動くので、B には「その対局の前 1/3」と書く。人間が固定の手数(20 手・30 手)を望むなら、それは判断的知識として人間承認。

## 3. 出すもの
- `lib/timeCause.ts`(純粋関数)+ `timeCause.ts`(CLI): 固定棋譜(秒)・whatif-v2・patient から C1〜C10 を局ごとに計算し、`time_cause.json`(局ごとの表 + 組ごとの集計 + 時間負けの局と他の局の比較)を書く。エンジンは回さない。
- 付録 4「時間の使い方」(`render_time_cause.py`): 局ごとの表(序・中・終の秒、長考の回数・最長・連続、5〜9 秒の回数、飛車の筋の印、時間負けか)と、時間負けの 3 局の**中盤の手ごとの秒の帯**(何手目でいくら使ったか、分かれ道の印つき)。
- B v5 の問題 1: 「分かっている事実」→ C1〜C10 のうち数字が出たものだけ → 「試すこと」(メニュー M10 以降は §5 の予測と結果を見てから docs → 監査で足す。**処方を先に決めない**)。

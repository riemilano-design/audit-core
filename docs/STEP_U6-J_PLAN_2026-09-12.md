## 1. なぜこの STEP なのか(形の線が一周した)

2026-09-12 に、形の認識をいじる方向の実験を 3 つ行った。**結果を並べると、全部が同じ一点に戻る。**

| STEP | やったこと | 結果 |

**その一点は `apps/server/src/analysis/shapeFormationAnalyzer.ts:94-101` の `resolveStatus` である。** 実物は次のとおり(2026-09-12 に確認した)。

```ts
function resolveStatus(shapeMatch: ShapeDetectionResult, formationEvidence: ShapeFormationEvidenceEntry[]): ShapeStatus {
  if (shapeMatch.matchedSquares.length > 0 && shapeMatch.missingSquares.length === 0) {
    return "completed";
  }
  if (shapeMatch.matchedSquares.length > 0 && formationEvidence.length > 0) {
    return "forming";   // ← :98。一致 1 件以上 + 指し手で作られた証拠 1 件以上
  }
  return "none";
}
```

**3 つの症状はすべてこの 1 行から出ている**(2026-09-12 の人間の整理):

- **増やすと壊れる**のは、**1 手で複数の形が forming になる**から(`resolveRecognizedDirection` は `status === "forming"` の形を集めて方向を決める。`apps/server/src/api/stateResponse.ts:604`)。
- **誤認が出る**のは、**玉が動いていないのに forming と言う**から(証拠 1 件が他の駒でも forming になる)。
- **盤の緑と破線が消えて困る**のも、**その印が根拠の薄い forming にぶら下がっている**から(13.13 の実測)。

そして [PHASES.md](PHASES.md) の H-3 に書いた順番は最初からこうだった ―「**(i) 誤認を測れるようにする → (ii) 量だけ増やす → (iii) 同じ 4 局で再測定 → (iv) それから閾値を判断**」。**(i)(ii)(iii) は終わった。(iv) の番である。**

## 3. 案(**測る前に、案どうしが本当に違うかを確かめる**)

**U6-F では 4 案を測ったつもりで、区別できた挙動は 2 つだけだった**(10.9 (5))。同じことを繰り返さないため、**測定の前に静的な事前確認を行う**(4. )。

| 案 | forming の条件 | 狙い |
|---|---|---|
| `current`(既定) | `matched >= 1 && evidence >= 1` | 校正用。**既測値と一致しなければ配線が壊れている** |
| 案J1 `evidenceMin2` | `matched >= 1 && evidence >= 2` | 「証拠 1 件で名乗る」をやめる |

**案J2 は判断的知識に触れる可能性がある**(「囲いは玉の位置が要である」は将棋の判断)。**この案を採るかどうかは人間が決める。** 本 STEP で行うのは**測ることだけ**である。

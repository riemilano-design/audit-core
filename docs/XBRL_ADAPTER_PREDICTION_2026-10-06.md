| 項目 | 値 |
|---|---|

## 1. 仕様 v0.2 に対する予測(ここが本題)

| 数 | 予測 | 外れたときの読み |
|---|---|---|
| 層の数 | **4 のまま**(Claim / Evidence Pointer / Contract / Result) | 増えたら v0.2 は「将棋の門を整理した表」でしかない |
| scheme の数 | **+2 まで**(`xbrl:` = 要素名 + contextRef、`filing:` = 提出書類の meta: 提出日・会社・期) | +3 以上なら scheme の設計が将棋の形に寄っている |
| form | **+0**(4 つで足りる) | 足りなければ、財務の主張には将棋に無い形がある |
| modifier | **+0**(3 つで足りる)。ただし **`time_range` が初めて使われる**(「当期」「前年同期」「第 2 四半期累計」の解決) | `time_range` の定義(基準日 + 範囲)が足りなければ、修飾の契約を直す |
| 契約の欄で初めて使われるもの | **`tolerance`**(「約 15%」・百万円単位の丸め)と **`time_range`** | 使われなければ、将棋と同型すぎて 2 つ目の意味が薄い |
| Core 変更の分類(v0.1 §12) | **登録追加のみ**(scheme +2・正規化の規則 +N・鍵の約束 +1)。インターフェース拡張 0・意味変更 0 | 意味変更が 1 本でも出たら、将棋が Core に漏れていた証拠 |
| 鍵の約束の問題(F-2 の再来) | **再来する。** 将棋の `ply` の 1 ずれに当たるのが XBRL の **contextRef**(同じ要素名が期・連結/個別・時点/期間で複数の値を持つ)。結合は contextRef の正規化なしには一致しない | 再来しなければ、F-2 は将棋固有 |
| 正規化の規則(F-3 の再来) | **再来する。** 単位(百万円 ↔ 円)・符号(損失の負号)・連結/個別・「約」。盤の主張の 4 重と同じく 1 つの数に複数重なる | ― |

## 2. 4 つの例の Claim の表現可能性(v0.1 と同じ 3 値。A 充足 / B 不充足 / C 表現不能)

| 例 | 予測 | form / pointer |
|---|---|---|
| 「売上高は 1,280 百万円」 | **A** | `direct_value`、`xbrl:NetSales@当期連結`、normalization = 単位 |
| 「前年同期比 15% 増」 | **A**(tolerance が要る) | `derived_value`、式 (当期 − 前期) / 前期、`time_range` で前期を解決、tolerance = 丸め(人が承認した幅。無ければ **B**) |
| 「今期は堅調に推移した」 | **B** | `threshold` だが線が無い(「堅調」の登録簿は無い)→ UNVERIFIABLE |
| 「来期は増収を見込む」 | **C**(descriptive の登録として台帳に置ける。PREDICTIVE にはならない: 比較子と値が無い) | 予測台帳 |

## 3. 調査そのものについての予測(実物で確かめる前の記憶)

| 項目 | 予測 |
|---|---|
| EDINET API | 鍵(API キー)の登録が要る。無料 |
| 書類の取得 | 書類一覧 API(日付指定)と書類取得 API(ZIP)。ZIP の中に XBRL インスタンスとタクソノミ |
| 財務の数 | インスタンスの要素(`jppfs_cor:NetSales` のような名)に contextRef と unitRef(JPY)が付く |
| 文章 | 経営者の分析(MD&A)などの文章も XBRL に **textBlock** として入っている(人が書いた「前年同期比 x% 増」が構造化データの横に在る) |
| 利用条件 | 利用規約があり、商用利用の可否は規約を読むまで分からない(**ここは予測を置かない**。読んで書く) |
| 会社の文章の数字の丸め | 百万円単位・「約」・小数 1 桁の % が普通で、再計算と完全一致しない(tolerance の出番) |

## 4. 採用の判定(調べた後に、この表で決める)

| 条件 | 満たせば |
|---|---|
| §1 の層 4・scheme ≤ +2・意味変更 0 | v0.2 を「将棋の門の整理」でなく仕様候補として扱ってよい |
| §2 の例 1・2 が A | 「構造化データ → AI レポート」の実演の材料になる |
| 利用条件が実演を許す | 2 つ目の Adapter として採用の提案を人間に上げる(作るのは別の GO) |
| どれかが外れる | 外れを記録し、XBRL を見送るか仕様を直すかを人間が決める |

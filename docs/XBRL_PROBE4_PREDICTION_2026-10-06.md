## 3. 変更 A と変更 B の定義(封じる)

### 3.1 A: 語彙に「セグメント利益 → `OperatingIncome`」を 1 行足す

- 主語表の**先頭**に `("セグメント利益", ["OperatingIncome"])` を足す(先頭なので P-3 の同位置・同長の比較でも優先)。
- 効き方は凍結の規則のまま: 主語が決まる → `facts_for(["OperatingIncome"], …, member)` → member が決まっていれば member の context、無ければ連結の context。
- **A は語彙の登録追加だけ。** 母集団の規則は 3 本目のまま(文単位)。

### 3.2 B: 母集団の印を Claim 単位で、直前方向に見て決める

3 本目の「文に事業名がちょうど 1 つ → member、2 つ以上 → `ambiguous(member)`」を、**Claim ごと**に次の規則で置き換える(P-3 の「いちばん右の主語」と同じ考え方)。

1. Claim の位置より前の同じ文(head)の中で、**母集団の印**を探す。印は (a) 登録簿の事業名(Run L でラベルから引いた 5 語)、(b) **「全社」**。「連結」は印にしない(「当連結会計年度」が業績文のほぼ全部に在るため)。
2. head の中で**いちばん右の印**を取る。
   - それが「全社」 → **連結**(member 無しの context。2 本目と同じ母集団)。
   - それが事業名 → その事業名から後ろ向きに、**列挙の接続語だけ**(「、」「及び」「および」「と」「や」「・」と空白)で繋がっている事業名を集めて 1 つの列挙とみなす。列挙が 1 語 → その member。**2 語以上 → `ambiguous(member)` で未束縛**(連結とも member とも比べない)。
3. head に印が無い → 3 本目の文単位の規則(文に 1 つ → member、引き継ぎ 5 文以内、2 つ以上 → ambiguous)に落とす。
4. 印が決まった Claim の候補 fact は、3 本目と同じく**置き換え**(連結と member を合わせない)。前期比は両期に同じ母集団を要求する。

これを文 17 に当てると: T010「BS サロン運営事業及びキャリアデザイン事業が前期に比べ減少」→ 列挙 2 語 → 未束縛。T008「直営サロン運営事業、ヘアメイク事業、美容室支援事業が…増収」→ 列挙 3 語 → 未束縛。T009「全社としても増収」→ いちばん右の印が「全社」→ 連結。文 20 の N004 → 直前の印は「BS サロン運営事業及びヘアメイク事業」の列挙 2 語 → 未束縛。

- **B は構造の規則(会社に依らない)+ 印の語「全社」1 つ。** 事業名の対応は Run L のまま。
- 「複数の母集団それぞれで増」(T008 の型)は `aggregate` form の候補だが、**4 本目では扱わない**(記録だけ)。

## 4. 3 つの Run と 2 段の byte freeze gate

| Run | 構成 | 出力 |
|---|---|---|
| **Run A** | 3 本目 Run L + A だけ | `probe4A_S100Z4B6.json` |
| **Run B** | 3 本目 Run L + B だけ | `probe4B_S100Z4B6.json` |
| **Run AB** | 3 本目 Run L + A + B | `probe4AB_S100Z4B6.json` |

各 Run は **1 回だけ**。順序は A → B → AB。差は文で分かれる(A は 31/38/42/47/50 が主、B は 17/20/115 が主)ので、`AB − L = (A − L) + (B − L)` が Claim 単位で成り立つかを帰属の検査にする。

| 門 | 条件 | 合格 |
|---|---|---|
| **Gate 1** | `PROBE_MEMBER=1`・`PROBE_RUN3=L`・4 本目の新規フラグ(A・B)を**全部 OFF** | 出力が `probe3L_S100Z4B6.json`(sha `168edc63…`)と **byte 一致** |
| **Gate 2** | `PROBE_MEMBER=0`(新規フラグも OFF) | 出力が `probe2B_S100Z4B6.json`(sha `73f413f2…`)と **byte 一致** |

**片方でも一致しなければ Run A / B / AB を開始しない。** 差分は (1) 主語表の先頭への 1 行の注入(A)、(2) Claim 単位の母集団の解決(B)、(3) 切替の配管、に限る。

## 6. 外れたときの読み方

- Run A で業績文以外の「セグメント利益」が 3 件以上束縛される、または GROUNDED になる: 語彙の 1 行が母集団の規則を越えて効いている。false pass なら A は採らない。
- Run B で T009 が復帰しない: 「全社」の位置が head に入っていない(語の切れ方)か、連結の context の選び方が置き換えで消えている。規則を直さず記録する。
- Run B で文 17・20・115 以外が動く: 印の規則が業績文の中の列挙(「スタジオ、ブライダル、メディア各部門」は事業名でないので当たらないはず)に反応した。どの語かを書く。
- `AB − L ≠ (A − L) + (B − L)`: A と B が同じ Claim に当たった。その ID を書く。
- false pass が 1 件でも出る: 値の層か証拠の層かを書き、4 本目の採否は人間が決める。
- 層・form・modifier・scheme のどれかが増える: 増えたものを Core に入れずに記録する。

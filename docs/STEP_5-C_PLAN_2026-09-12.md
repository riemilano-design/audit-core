## 2. 実装してよい範囲(`apps/web/` のみ)

**A-1(選択の状態)**: `window.confirm` をやめ、**選択を保留する状態**をモジュール変数に持つ(例 `pendingPromotionChoice: { candidates: string[]; toSquare: string } | null`)。`handleBoardMoveClick` は、`candidates` が 2 件なら着手せずこの状態を立てて再描画する。1 件のときは従来どおり即座に着手する(**強制成りの判定は増やさない**)。

**A-2(画面に出す)**: 保留中は、選ぶための小さなまとまりを画面に出す。**置き場所は盤の直下、`#boardLegend` の前**(人間決定 H-2 (a))。中身は次のとおりで、**文言は 5. の表のとおり一字も変えない**(人間承認済み。[PHASES.md](PHASES.md)「STEP 5-C の文言の承認記録」が正本)。

- 説明の 2 文目(駒種で出し分け): 歩・香・桂・銀は「成ると、金と同じ動き方に変わります。」、角・飛は「成ると、今の動きはそのままで、まわりの一マスへも動けるようになります。」
- ボタン 3 つ: 「成る」「成らない」「この手をやめる」
「成る」「成らない」を押すと対応する USI で `playMove` を呼び、保留を解除する。**2 文目の出し分けは、人間承認済みの文言の表を引くだけであり、将棋の判定ではない**(A-5b)。どちらかを既定にして目立たせない。

### 決定に至った経緯(記録)

以下は、人間の判断の前に司令塔が提示した選択肢の記録である(**採用されたのは H-1 の別案・H-2 (a)・H-3 (a)**)。文言の正本は上の 5. と [PHASES.md](PHASES.md) の承認記録であり、**この節の文案を実装に使わない**。

- **H-1 文言(3 つ)**。新しい文言のため、一字単位で人間が決める。司令塔の案(計画レビュー 1 回目の REVISE を受けた改訂版):
  - 説明の一行: 「**この駒は、ここで成る(裏返す)ことができます。成ると、動けるマスが増えたり変わったりします。どちらで指すかを選んでください。**」
  - 選ぶボタン 1: 「**成る**」
  - 選ぶボタン 2: 「**成らない**」
  - 補足: 「成る」の説明を一行に含めた(ルール 2)。どちらが良いかは述べない(ルール 6)。駒ごとに何がどう変わるか(例: 角 → 馬)までは書かない案にしている(駒名の変化を出すなら別の表と承認が要る)。
  - **改訂の理由(事実)**: 初案「裏返して働きを変える」・別案「成ると裏返って、動ける向きが変わります」は、**角・飛には当てはまらない**。角・飛は成っても元の動き(斜め・縦横)を一つも失わず、そこへ一マスの動きが**加わるだけ**である。一方、歩・香・桂・銀は成ると動き方が金と同じものに**置き換わる**(香の長い動き・桂の跳ぶ動きは失われる)。全 6 駒種に共通して正しい言い方は「増えたり変わったりする」であり、改訂案はこれに合わせた。
  - **別案(駒種で言い分ける)**: 角・飛のときだけ「**成ると、今の動きはそのままで、まわりの一マスへも動けるようになります。**」、歩・香・桂・銀のときは「**成ると、金と同じ動き方に変わります。**」と出し分ける。正確さは上がるが、web 側に駒種ごとの文言の対応表を持つことになる(将棋の判定ではなく文字列の対応表だが、範囲が増える)。採るなら A-2 に対応表を足す。
- **H-2 置き場所**。(a) **推奨**: 盤の直下(凡例の前)。(b) 盤に重ねる(押したマスの近く)。(c) 操作する列の⑤の上。
- **H-3 やめ方**。(a) **推奨**: 「やめる」のボタンを 1 つ置く(文言も H-1 と同じく承認が要る)。(b) 盤の他のマスを押したら自動でやめる(ボタンを増やさないが、やめられることが画面から分からない)。(c) 両方。
- 提示のみ(実装上の選択): 保留中は盤の他のクリックを受けないこと(A-4)。強制成りの局面は従来どおり選択を出さないこと。

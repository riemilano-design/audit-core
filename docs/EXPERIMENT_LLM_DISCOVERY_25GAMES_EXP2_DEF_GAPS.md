## 3. 「定義に無い名前の候補」の欄(分類・比較には使わない。知識レーンが下書きを起こすかどうかの材料に限る ― 指示書 §13.3)

- A2: 50 行すべて「―」(名前を付けていない)。
- B2: 50 行すべて「—」(名前を付けていない)。
- C2: 50 行すべてに名前を書いた。出た名前(重複を除く): 角換わり・矢倉・相掛かり・横歩取り・ゴキゲン中飛車。**側の行にも同じ名前**(本人・相手で同じ)。実験席はこれを分類・比較に使っていない。data/ に同名の定義があるかは知識レーンの判断(例: yagura_senpo・aigakari・kakugawari・gokigen_nakabisha・yokofudori は id として存在する)。

## 4. 機械の判定との関係(実験席の実測、LOG §6.3)

- 機械(`openingDetector.ts` → `shapeFormationAnalyzer`)の completed は「pattern の全駒が同時に盤上の to に居る(+ 動いた証拠)」。order_hint は読まない。実験席の検査器(同時に盤上)は機械の rows と 253/253 で一致。
- 席の「完全」は多くが「着いた手が 1 回以上ある」の読みで、同時に盤上という条件より緩い(A2 160 のうち 134、C2 50 のうち 30、B2 217 のうち 145 が機械と同じ判定でも成立)。**G1〜G4 の指摘は、機械の判定にもそのまま当てはまる**(機械も 1 手 pattern・手数の窓なし・取る手・経由で completed にする)。

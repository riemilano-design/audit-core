## 6.5 この STEP で直さない、実機で見つけたこと

**`SHOGI_ENGINE_PATH` が存在しないパスを指していると、サーバープロセスごと落ちる。**

- `UsiEngine.start()` が `spawn` した子プロセスに `'error'` のハンドラが付いていないため、`ENOENT` が**未処理の `'error'` イベント**として投げられ、Node がプロセスを終了させる
- `runBackgroundPlanAnalysis` の `try/catch` では捕まえられない(Promise の reject ではなくイベントのため)
- **結果として「エンジンの設定を間違えた」が「解析が失敗する」ではなく「サーバーが死ぬ」になる。** 画面からは `502` と「初期状態の取得に失敗しました」しか見えない

**P-26 の範囲外であり、この STEP では直さない。** 既知事項への登録は人間・司令塔の判断。**なお `apps/server/src/engine/usiEngine.ts` は現在別セッションが編集中である(2026-09-13 時点の `git status`)。**

## 6.6 数え方の誤り(手順として残す)

エンジンのプロセスを数えるときに **2 通りの誤り**を踏んだ。**どちらも「本数」という数字を静かに間違える。**

| 誤り | 何が起きたか |
|---|---|
| `ps -A -o command \| grep -c '[Y]aneuraOu'` | **自分のコマンドラインに `YaneuraOu` の文字列が別の場所(`pgrep -f YaneuraOu` 等)で入っていると、自分自身を数える。** 実際には 0 本のときに **2 本**と出た |
| `ps -A -o comm= \| grep -cx 'YaneuraOu-by-gcc'` | macOS の `comm` は**フルパス**を出すため、`-x`(行全体一致)が決して一致しない。実際には 1 本立っているときに **0 本**と出た |

**確実なのは、`ps -A -o pid=,ppid=,comm=` を取り、文字列の一致を自分のシェルの外(スクリプト内)で行うこと。** 本数は**過大にも過小にも**間違える。

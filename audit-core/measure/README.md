# audit-core/measure ― 測定用の道具

検出率を測るために、**誤りの型と場所が分かっている文書**を作る道具。
人間の決定 [CLAIM_DECOMPOSITION_DETECTION_DECISIONS_2_2026-10-08.md](../docs/CLAIM_DECOMPOSITION_DETECTION_DECISIONS_2_2026-10-08.md)
の §穴 3 の実装である。

## 測る対象の外にある

この階層は **`audit_core` も `adapters` も import しない。**
XBRL の ZIP 読みも HTML 剥がしも標準ライブラリで書き直してある。
抽出器のコードを共有すると、**抽出器に見えない誤りは注入器にも見えず**、測定が循環する
(第 2 便 §穴 2 (3))。

- **判定の核 (`core/py/audit_core`)・接続部分・抽出器 (`adapters/`)・照合器
  (`scripts/playtest/lib/decompositionCompare.ts`) には 1 行も触れていない。**
- 不変量の確認対象は**判定の核・接続部分・抽出器の 22 ファイルのコミット済みの値**
  (束ねた sha `950ebc91…0cda`)。照合器は本線が修正中のため対象外(人間の決定 2026-10-08)。

## 3 つの規則はコードが守る(心がけではない)

| | 規則 | 破ったときに何が起きるか |
|---|---|---|
| 1 | **種は実行前に封じる** ― `--seed-file` は git に追跡され、コミット内容と一致していなければ `SealError` で停止 | 結果を見てから種を選べなくなる |
| 2 | **混入の記録はリポジトリの外** ― 既定 `~/.audit-core-measure/injection-records/`。repo に戻るのは sha256 だけ | 採点前に分解側が記録を読めない。sha256 は後からの書き換えを検出する |
| 3 | **毎回 round-trip を検査** ― 記録だけで元の文書に戻せなければ、何も書かずに停止 | span のずれた記録で採点することがなくなる |

## 誤りの型 ― 機械が作る 4 つ

| 型 | 名前 | 機械が保証すること | 狙う判定 |
|---|---|---|---|
| `T1_VALUE` | 数字の置換 | 置換値が**参照用の数の一覧のどこにも無い** | `VALUE_MISMATCH` |
| `T2_UNIT` | 単位のずれ | **桁は 1 文字も変えず**、単位だけを同じ族で入れ替え(円/千円/百万円、手/局/局面) | `scale` の事故と同じ形 |
| `T3_ABSENT` | 原文に無い数 | 主語も値も**元データに無い**ことを確かめてから 1 文を挿入 | `POINTER_NOT_FOUND` |
| `T5_COINCIDENT` | 値が偶然一致して参照先が違う | 置換値が**別の事実の真の値**。値だけ探す照合は通る | **既知の一番の穴** |

`T1` と `T5` の違いは**置換値が一覧に在るか無いか**の一点だけで、
そこが「ただの値の不一致」と「一番の穴」を分ける。だから試験は件数ではなく
その 2 つの保証を直接当てている。

### 1 つの数には 1 つの誤りだけ

値の置換と単位のずれは span が重ならないので同時に成立してしまうが、
**両方当てると、止まったときどちらの型のおかげか言えなくなる。**
`select()` は数のトークンを 1 回しか使わない(実測: 入れる前は `107 局面` が `65 手` になった)。

## どの文書でどの型を作るか(人間の決定 2026-10-08)

| 文書 | 機械で作る型 | 作らない型 |
|---|---|---|
| 将棋の冊子 | **型 1・型 2・型 3・型 5** | ― |
| 有価証券報告書 | **型 2・型 3** | **型 1・型 5 は人に回す** |

**型 5(既知の一番の穴)は将棋だけで測る。** 有価証券報告書は
**「機械で作れず未測定」**と書く ― **測った 0 ではない。**

理由は構造的で、歯止めを緩めれば件数は増えるが、増えた分は全部でたらめになる。

1. 本文の金額は和数字の混在(`394億1千9百万円`)。読むのは**抽出器の仕事**(`AMOUNT_JP_RE`)で、この階層は使えない
2. fact は `円`、本文は `億/千/百万円`。**換算は Adapter の仕事**
3. 要素名が英語なので、ラベルによる裏取りができない

**ただし穴は実在する。** 60 件の盲検確認で**人が 3 件見つけている**
(`T008` `T022` `T031` = 3/22。`material/xbrl/observed_t5.json`)。
**機械で作れないことと、穴が無いことは別である。**

## 機械で作れない 2 つ ― 人に回す

**期間の入れ替え・母集団の入れ替え(別の文のものへの付け替え)。**
どの期間・母集団を文が引き継いでいるかの判断は**測る対象そのもの**で、
機械が決めれば自分の答えを自分で書くことになる。

`<doc>.human_tasks.json` に候補を出す(文・語・その語の span・文書内にある入れ替え先)。
人がそこから作り、同じ形で混入の記録に足す。

**今回は扱っていない(人間の決定 2026-10-08)。候補 344 件・参照先が決まらない数 86 件は、
1 件も作っていないので未測定である。** 検出率も誤停止率も存在しない。

## 参照用の数の一覧 ― 正解集合ではない

`prepare_material.py` が出す `<doc>.reference_numbers.json` は
**「参照用の数の一覧」**であり、採点に使わない。
元データが教えるのは「何が事実か」で、「その文が何を主張しているか」ではない
(第 2 便 §穴 2)。この一覧は**混入する値を選ぶためだけ**に使う。

採点に使うのは **混入の記録**(検出率)と **人の 60 件**(誤停止率)だけ。

## 結果に必ず添える一文

> **機械で混ぜた誤りは、実際の AI の誤りとは性質が違う。**

実際の AI の誤りは契約の穴に沿って出る(母集団の昇格のような形)。
ここで作るのは型と場所が分かっている誤りで、同じものではない。

## 使い方

```sh
# 1. 材料をつくる(文書の文 + 参照用の数の一覧)
# shogi の --booklet / --packet は顧客のデータなので既定でリポジトリの外
# (~/.audit-core-measure/material/shogi/)を読む。指定を省略してよい:
python3 prepare_material.py shogi --doc shogi-c5 --out out/material
python3 prepare_material.py xbrl --zip ~/.cache/audit-core/edinet/S100YMFV.zip \
    --doc S100YMFV --out out/material

# 2. 候補の文書を見る(「見ていない」の 2 つの読みを両方出す)
python3 select_documents.py --repo /path/to/sgogi-coach   # out/ があるチェックアウト

# 3. 種をコミットしてから混ぜる(コミット前は停止する)
python3 inject.py --doc shogi-c5 --kind shogi --material out/material \
    --seed-file SEED.json --count 12 --out out/documents

# 4. 自己試験
python3 -m unittest discover -s tests

# 5. 接続部分の開発に使っていない提出書類を取る(鍵は操作する人が置く)
export EDINET_API_KEY=...
python3 fetch_material.py --list --from 2026-09-01 --to 2026-09-30
python3 fetch_material.py --pick 2 --from 2026-09-01 --to 2026-09-30 \
    --seed-file SEED.json --out out/material
```

`fetch_material.py` は **EDINET API v2 の鍵が要る**(API 自体は無料)。
鍵の値はこの道具が読み書き・表示・保存することはなく、要求にそのまま渡すだけである。
接続部分の開発に使った 3 件(`S100Z4Q1` `S100Z4B6` `S100YMFV`)は選ばれない。
選ぶのは**封じた種**で、手で選ばない。

`out/` は生成物。

## 将棋の冊子と packet はリポジトリに入れない(2026-10-08 人間の決定 + 司令塔の判断で拡張)

**`c5_observation_packet.json`(1.6MB)と `c5_round5_booklet.md` は顧客のデータであり、
main の履歴に入れない。** 人間が名指ししたのは packet だけだが、**理由は「顧客のデータだから」
であり、冊子は顧客の診断報告の本文そのものなので同じ理由が当たる** ― この拡張は司令塔の判断。

- 実物は **`~/.audit-core-measure/material/shogi/`**(混入の記録と同じ、
  `~/.audit-core-measure/` の下。正確なサブパスは本書が正本)に置く。
- リポジトリに残るのは **`material/shogi/SOURCE.sha256`** だけ(確認方法はファイルの先頭に書いてある)。
- `prepare_material.py shogi` の `--booklet` / `--packet` は**既定でこの外部の場所を読む**
  (`prepare_material.DEFAULT_SHOGI_BOOKLET` / `DEFAULT_SHOGI_PACKET`)。
  **材料が無ければ(他の場所から手で置いていなければ)`FileNotFoundError` で落ちる ― skip にしない。**
- 履歴からの除去(すでにコミットされている内容を消す `git filter-repo` 等)は**この道具の範囲外**。
  司令塔が別途行う。

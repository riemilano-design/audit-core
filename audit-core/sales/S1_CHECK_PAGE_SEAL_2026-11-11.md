## 1. 何を作るか・なぜ

- 1 枚の HTML。入れる物は 2 つ: **日本語の決算短信の XBRL の ZIP**(TDnet に出す物)と **英文の決算短信の PDF**。
- 2 つとも、読むのは利用者のブラウザの中だけ。file はどこにも送らない(通信するのは部品 2 つを読み込むときだけ)。
- なぜブラウザの中か: 公表前の決算の数字は外に出せない。「出す前の点検」を外の者が請けるには、相手の手元で動く形でないと頼めない(司令塔の読み。相手に聞いて確かめたことではない)。
- 当て方は 50 本の照合と同じ(日本語の ixbrl の数の fact の列を、英文 PDF の数の列に並びで当てる。符号の候補と、値の 1 対 1 の置き換えの候補)。engine(`core/`・`adapters/`)は使わない・変えない。置き場は `sales/en_check/`。

## 2. 部品(ブラウザが読み込む物)

- PDF の字を読む部品 pdf.js 3.11.174、ZIP を開く部品 JSZip 3.10.1。どちらも cdnjs の版を固定した URL を script で読む。
- 手元に file として保存する物は増やさない。新しく取ってくる短信は無い(確かめには、封 72e5e357 で取った 50 本の組をそのまま使う)。
- 並びを当てる部分は Python の difflib の SequenceMatcher(autojunk なし)を JavaScript に写す。

## 3. 確かめ方(50 本に当てる)

母集団: [EN_TANSHIN_50_RESULT_2026-11-10.md](EN_TANSHIN_50_RESULT_2026-11-10.md) の 50 本の組(日本語の ZIP 50・英文の PDF 50)。正解: 同じ結果の文書で司令塔(AI)が画像と足し算で確かめた本物の食い違い 3 本・19 欄。

数えるもの:

- **(a) 拾い**: 本物の 19 欄のうち、ページが候補として出した欄の数(日本語の値と英文の値の組が一致する候補が在れば「拾った」)。
- **(b) 字の読み取り**: 英文 PDF 50 本のうち、ページが読めた数の個数が、Python の script(PyMuPDF)が読んだ個数の半分に届かない本数。

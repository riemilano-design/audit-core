# 売り方の「形」を変えて金にする案 ― SaaS・ブログ・アプリ・その他(2026-11-10)

人間の指示(2026-11-10):「別の収益の形とは、システムの拡張で他分野への進出ではなく、SaaS やブログやアプリや他の何かでマネタイズできないかということ」「できれば君が自動でできるものがよい」。

前の調べ([MONETIZE_ALTERNATIVES_2026-11-10.md](MONETIZE_ALTERNATIVES_2026-11-10.md))は「別の客・別の分野」に寄っていた。この紙は **engine はいまのまま、出し方だけを変える** 案を並べる。
**司令塔の考えで、測った事実ではない。** どの形も、払う人が居るかは 1 件も測っていない。見込みの額・率は書かない。【確】= この場で確かめた、【推測】= 根拠なしの読み。

## 0. 先に確かめた事実(形を選ぶ土台)

- engine(`core/`・`adapters/`)が読み込む部品は Python の標準の部品だけ(import の行を数えた。外の library は 0)。code は約 43 万 byte。【確】 → ブラウザの中で動く Python(Pyodide)に載せられる見込み。**まだ動かしていない。**
- GitHub の置き場 `riemilano-design/audit-core` は **公開**(visibility PUBLIC)で、license の file は無い。【確】 → code は既に誰でも読める。「公開すると譲渡の値が下がる」の心配は半分済んでいる。license が無いので、他人は読めるが使う権利は無い状態。
- 原本(有報の ZIP)は 1 社 0.6〜2.9 MB(手元の 3 件)。日本語の科目名に使う標準ラベルは約 10 MB で、手順は「利用者が EDINET から自分で取る」(README)。こちらから配ってよいかは確かめていない。
- 過去に自分で開いた窓口の記録(将棋の診断。2026-09-24 実測): ココナラ 閲覧 31・相談 0・販売 0、ブログ 1 本目 13、X フォロワー 13。 → **窓口を開くだけでは人は来なかった。** いちばん重い未知は今回も集客。

## 2. 司令塔の読み

1. **「置けば勝手に金が入る」形は、この中に無い。** S3 だけは 1 冊売れればそれが収益だが、額は小さい。ほかは全部、人を連れて来る仕掛けか、既に客が居る所に置く物。
2. **それでも形を変える意味は大きい。** いまの道(資料を送る → 文を 3 本もらう → 2 営業日で返す)は、相手に手間と待ちがある。S1 が在ると「ZIP と文を落とすだけ・1 分・文は外に出ない」に変わる。下書き D・E・F の 1 行目にも、記事の末尾にも、同じ URL を置ける。
3. **S1 は SaaS の 0 段目でもある。** 置き場も運用も課金も持たないので、費用も運用の責任も生まれない(その代わり、計測を入れない限り「何人が使ったか」は数えられない)。使う人が出たら、有料の段(まとめて点検・API・設置)を足す。
4. **S5 は見た目がいちばん「自動で稼ぐ」に近いが、推さない。** 先行と同じ土俵で、集客に時間がかかり、費用と法の確認が先に出る。yomitoka の下見では、カード形式の文は engine が結べた数が 122 のうち 16 だった(文の形を自分で決めれば上がる見込みだが、測っていない)。

## 3. 推す組み合わせ

**S1 を芯に、S2 で人を送り、S3 を 1 回だけ作る。**

| 順 | する事 | 司令塔が 1 人でできる範囲 | 人間の手が要る所 |
|---|---|---|---|
| 1 | S1 の試作(手元でブラウザの中の Python に engine を載せ、同梱の公開の有報 1 件 + 文 1 本で、CLI と同じ報告が出るかを照らす) | 全部。0 USD | Pyodide(ブラウザ用の Python。公開の部品)を取ってくる OK |
| 2 | S1 を公開する | 頁と手順を作る | GitHub Pages を入にする(置き場の設定の変更)・license をどうするかの決定 |
| 3 | S2 の 1 本目〜3 本目の下書き(同梱の公開の有報と、実験で作った AI の文から) | 全部。0 USD | 置き場(note・Zenn・自前の頁のどれか)と公開の OK |
| 4 | S3 の原稿 | 全部。0 USD | 売り場の account・値付け・公開 |
| 5 | S2 を週ごとに回す | 下書きを毎週自動で作る予約まで | 予約を入れる OK・公開の OK |

**できない所を先に言う。** 司令塔は作る・書く・点検するまでは 1 人で回せる。公開する・account を作る・金の受け口を作る・規約に同意するは、1 件ずつ人間の手か OK が要る(まとめての OK は可)。「全部自動」にはならない。

## 4. 引き返す印

- S1 の試作で、ブラウザの中の報告が CLI の報告と一致しなければ、S1 は「手元で動かす配布物」に下げる。
- S1・S2 を出して、決めた期間に問い合わせ・無償診断の申し込みが 0 なら、形ではなく相手の型を疑う(計画 §6 と同じ)。期間は人間と決める。

## 5. 確かめていないこと

- Pyodide で engine が動くか(標準の部品だけ、は確かめた。動かしてはいない)。
- 標準ラベルを頁に同梱してよいか(EDINET の利用規約)。だめなら、報告の科目名は要素名のままか、利用者が自分でラベルを落とす形になる。
- note・Zenn・Kindle の規約と手数料、GitHub Pages の商用の扱い。
- S5 の法の扱い(司令塔は判断しない。専門家の確認が要る)。

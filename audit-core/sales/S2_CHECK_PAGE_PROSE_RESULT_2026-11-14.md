## 何を作ったか

いまの点検ページの写しに、2 つめの一覧「文章の中の数(試作)」を足した 1 枚の HTML。入れる物はいまと同じ 2 つ(日本語の決算短信の XBRL の ZIP・英文の決算短信の PDF)で、表の点検はいまのまま。足した一覧は、英文の「概況」の文に出てくる金額・率・ポイントのうち、日本語の「概況」の文に同じ数が見つからなかった物を、英文の頁と前後の字を付けて出す。英文か日本語の「概況」を切り出せなかったときは、一覧を出さずに「この短信の文章は点検できませんでした。」と、切り出せなかった側を出す。

切り出し・数の読み方・「同じ」の決め方は、文章の便の script(封 9c9cd6ec。sha256 の頭 `859d7a42`)を JavaScript に写した。規則は足していない・引いていない。違うのは PDF の字を読む部品だけ(script は PyMuPDF、ページは pdf.js 3.11.174)。文章の便の数(何件見つかった・何割で取れた)は、ページの字に書いていない。

## 確かめ方の中身(封に書いていないこと・封と違うこと)

- **写しの下確かめ(封の予測には無い。当てる前に行った)。** JavaScript に写した規則に、script と同じ PyMuPDF の行を node で読ませたら、script の出力と全部同じになった(切り出し 214 / 214・行の集まり 乙 119 / 119・丙 95 / 95・確かめた数 8,303 と 4,582・「無い」行 30 と 8・候補 24 / 24)。だから上の表の違い(2 組・4 組・確かめた数の 6 個)は、PDF の字を読む部品の違いから来ている。日本語の側(ZIP の中の HTML から字を取り出す所)は node では通していない。Chrome で当てた 3 回で通した。
- **試験の仕掛け。** ページの写しから「どこにも接続できない」設定の 1 行を外し、手元の file を順に読ませる数行を足した物を、画面なしの Chrome(157)で開いた。350 組を 25 組ずつ 14 回に分けた。木に置いたページは設定を入れたまま。

- **比べる道具が動くことの確かめ。** 3 回目の出力の「無い」行を 3 行だけ「同じ」に書き換えた物を比べる道具に通すと、(b) は 22 件・(c) は 35 件・(d) は 207 組に変わった。

## 言えること・言えないこと

- 言えること: **乙 200 組・丙 150 組で、試作のページは script と同じ「見つからなかった」行を出した**(38 件・候補 24 件を含む)。封の §4 のとおり、ここまで。
- 「見つからなかった」行は誤りとは限らない。38 件のうち AI の席が「数が違う候補」とした 24 件も、人はまだ紙面で読んでいない(文章の便の結果 c0f10815 のまま)。
- 測っていない: 新しい短信での働き・Chrome のほかのブラウザ・人が画面で file を選ぶ道(設定の 1 行を入れたままの木の版は、仕掛けでは開いていない)・1 本ごとの時間(仕掛けの時計は当てにならない)。
- 道具の読み違い・書き方の違いの型を外す規則は足していない(封の §4)。足すなら新しい短信で測る別の便(案の §4 の 4・5)。
- 案の §5 のとおり、人間が確かめ表で紙面を読むまで、文章の便の数は外に出す紙(営業資料・記事・メール・公開のページ)に書かない。試作を公開する・相手に見せるのは人間が決める。

## 2. やること

- (a) **分解器**: `original_text` を受け取り、`claim-decomposition.v0.1` の形の doc を返す。
      出力は `checkClaimDecomposition` を通す。schema で落ちたら**理由を渡して再試行**(上限つき)。
      再試行の理由は**累積して渡す**(直前の分だけでは往復する)。
- (b) **下見**: API を呼ばずに**本番と同じ配線を通す**経路。相対の道・cwd・費用の記録の器まで含める。
- (c) **本番の実行は司令塔が 1 回だけ行う。** 実装担当・監査担当は API 鍵を使わない。
- (d) 出力を照合器に通し、**gold 4 本それぞれと合計**を記録する。

## 3. 報告の規律(D-2b-0 の申し送り)

- **span 一致を単独で引用しない。** 必ず `actualOnly`(過剰生成)と `expectedOnly`(見落とし)を併記する。
- **uncovered は value / form とセットで読む。** 貪欲に claim を作れば uncovered は常に 0 に落ちる。
- 比べる相手は**基準線**(2 回目)である。

| 指標 | 基準線(規則ベース) |
|---|---|
| span 交わり | 32 / 37 |
| span 実測のみ(過剰生成) | 21 |
| span 正解のみ(見落とし) | 5 |
| value 一致 | 8 / 37 |
| form 一致 | 3 / 37(direct 3/3・derived 0/9・aggregate 0/17・threshold 0/3) |
| uncovered 交わり | 0 / 18 |

# 顧客向け PoC 第 1 便 ― **一般 LLM と Audit Core を同じ 35 件で比べる**封

2026-10-17。**正解集合を作るより先・採点より先・C を走らせるより先に commit する。**
人間の決定(2026-10-16 / 10-17)に従う。

> 人間が手作業で照合する比較ではなく、**一般的な LLM に同じ作業をさせ、Audit Core が
> それに対して何を追加できるのか**を検証する。売ろうとしているのは照合サービスそのもの
> ではなく、**普通の LLM では担保しにくい証拠の追跡・接続・誤りの抑制**だからです。
>
> ただし、別の LLM に作業させれば、それだけで独立した正解が得られるわけではありません。
> **比較対象と正解基準は分けて設計します。**
>
> * **値の一意性と参照先の正しさを分離する。** 値が 1 セルなら「値の候補が一意」、
>   2 件以上なら「値だけでは曖昧」、0 件なら「値が不一致」。
>   **この段階では正解と断定しない。**
> * **独立した正解が確定する条件を定める。** 行・列・階層など、報告文の主張と参照先を
>   結び付ける根拠が、**Core の規則に依存せず**確認できる場合に限って正解集合に入れる。
>   独立して確認できないものは別枠にする。
> * **A と B の採点対象を揃える。** 35 件すべてについて、接続の正誤、保留、判定不能を
>   別々に記録する。**正解不明の件数も隠さず報告する。**
> * **会計名の二重採点を維持する。** 印字名・正本名の両方を認める主採点と、
>   印字名のみの厳格採点を併記する。**主採点だけを性能の結論に使って
>   厳格採点を埋もれさせない。**
> * **C の約 0.5 USD は見積もりとして扱い、実測費用とは区別する。**
> * 一般 LLM が十分な正確性と根拠の追跡可能性を実現しているなら、
>   **Core の価値は再検討が必要。**逆に Core が優れていても、
>   **今回の 35 件だけで汎用的な優位性までは主張しない。**

## §1 比較する 3 方式

| 方式 | 入力 | 走らせるもの | 費用 |
|---|---|---|---|
| **A** 一般 LLM 単体 | 同じ主張 35 件・同じ抜粋(76 行 / 値のセル 176) | **既に凍結済み** ― 段 11 の盲検 2 席(`m11_answers_seat1/seat2`。commit `a5f6dc6`) | **0 USD** |
| **B** Audit Core | 同じ主張・同じ資料。既定の索引・証拠規則 | **既に凍結済み** ― 段 11 の `m11_binds`(commit `2b8767d`) | **0 USD** |
| **C** 一般 LLM + Core の証拠情報 | **A と同じ入力に、Core が出す証拠情報だけを足す** | **新しく 2 席**(A と同じ 2 モデル・同じ順序) | **見積もり 0.5 USD(実測ではない)** |

### §1-1 **一般 LLM をわざと弱い条件で比較しない**(人間の指示)

- **A は同じ入力・同じ利用可能資料で答えている。**しかも A に渡した問いは
  **6 欄の書き方の規則と「判定不能 / 根拠なし」の選択肢を明示している** ―
  **これは A に有利な条件である。**弱めていないことを、問いの字で確かめられる。
- **A の答えはこの封より先に commit されている。**
  **席は正解基準の存在を知らずに答えた**(§10 の門が commit の順で確かめる)。
- **C は A と同じモデル・同じ順序で、入力の差は「Core の証拠情報を足した」1 点だけ。**
  モデル名・設定・プロンプト・使ったトークン数を記録する。
- **結果を見てから採点条件を変えない。**

## §2 正解基準 ― **2 段構え。値の一意性だけで正解を確定しない**

### §2-1 第 1 段: **値の分類**(ここでは正解と断定しない)

抜粋は印字された 76 行で、**報告文はこの表だけを根拠に書かれた**(材料の作り方で保証)。
各主張の金額について、**抜粋の中でその値を持つセルを数える。**

| 分類 | 条件 |
|---|---|
| **値の候補が一意** | 値を持つセルが**ちょうど 1 件** |
| **値だけでは曖昧** | **2 件以上** |
| **値が不一致** | **0 件**(報告文の誤記・符号・丸め) |

**「値の候補が一意」は、そのセルが参照先であることを意味しない。**
**この段では正解集合を作らない。**

### §2-2 第 2 段: **独立した確認**(これを満たしたものだけが正解集合)

**Core の規則(索引・別名表・親の絞り・6 欄の鍵・値の照合)を一切使わない。**
使うのは「**主張の文にその字がそのまま出るか**」だけである。

| 記号 | 条件 |
|---|---|
| **G-独立-1** | 第 1 段が「**値の候補が一意**」であること |
| **G-独立-2** | そのセルの **科目名**が、主張の文に**そのまま**出ること |
| **G-独立-3** | そのセルの **親の成分(款名 / 項名)のいずれか**、または **会計名(印字形または正本形)**が、同じ文に**そのまま**出ること |
| **G-独立-4** | そのセルの **列**が、同じ文に出ること(§2-4 の表層形を許す) |

**4 つすべてを満たしたものだけを正解集合に入れる。**
**1 つでも欠けたら別枠にし、「どの条件が欠けたか」を件ごとに記録する。**

### §2-3 共有している部分と、していない部分(**開示する**)

| | |
|---|---|
| **共有している** | 帳簿を**読む・解析する**部分(`sheet_m1_read` / `sheet_m2_structure`)と、**抜粋を行に開く**部分。**主張の文を読むこと自体**も共有している |
| **共有していない** | **接続の規則・別名表・親の絞り・6 欄の鍵・値の照合・保留の規則** ― Core の判定は 1 つも使わない |

**だから「完全に独立した正解」ではない。**
**独立しているのは「Core の判定規則から」である。**この限定を結果の文にも書く。

### §2-4 列の表層形(**盲検ではない。開示する**)

| 抜粋の見出し | 文に出てよい字 |
|---|---|
| `予算現額` | `予算現額` ・ `予算現在額` ・ `計` |
| `支出済額` | `支出済額` |
| `不用額` | `不用額` |
| `補正予算額` | `補正予算額` |

**`予算現在額` を入れたのは、私がすでに報告文を読んでいるからである。**
**盲検ではない。**だから **G-独立-4 を表層形なしで厳格にした数も併記する。**
**この表は結果を見てから書き換えない。**

## §3 会計の欄の二重採点(**両方を同じ表に並べる**)

抜粋は `東京都と場会計`、Core は正本 `と場会計` を出す。
**片側だけ畳むのは段 8 の欠陥の再現である。**

| | 採り方 |
|---|---|
| **主採点(寛容)** | 会計の欄は**印字の字でも正本の字でもどちらでも正解**。**A にも B にも同じ寛容さを当てる** |
| **併記(厳格)** | **印字の字のみ正解**。**主採点と同じ表に並べる。埋もれさせない** |

**どちらか一方だけを性能の結論に使わない**(人間の指示)。

## §4 指標(**分母を字で固定する**)

| 記号 | 中身 | 分母 |
|---|---|---|
| **M-1 誤接続率** | 正解と違う行・列・値に接続した割合 | **正解集合**(別枠を含まない) |
| **M-2 正しい接続の回収率** | 正解を正しく接続できた割合。**M-1 と必ず並べる** | **正解集合** |
| **M-3 根拠の再現性** | 出力された住所から原資料の同じ数に到達できた割合 | **各方式が接続した件** |
| **M-4 失敗時の挙動** | **別枠**の主張で、推測して答えたか / 保留したか | **別枠**(3 分類ごと) |
| **M-5 追加価値** | C − A の差(M-1〜M-4 を同じ分母で) | A と同じ |

### §4-1 M-3 は**両方式に同じ関数**で測る

6 欄 → 原資料のセルへの引き当ては**1 つの関数**で行い、**A にも B にも C にも同じものを当てる**
(記憶 `normalize-both-sides-of-a-comparison`。**今日で 6 回目の型**)。
到達できた = **一意のセルが見つかり、その値が主張の金額と一致**すること。
**B が自分で出した pointer との照合は B だけの併記**にする(A には pointer が無いので、
**pointer の有無を M-3 の分母にしない** ― それは A を弱い条件で比べることになる)。

### §4-2 **35 件すべてを 1 行ずつ記録する**(人間の指示)

件ごとに **正解の状態**(正解集合 / 別枠 + 欠けた条件)と、
**A・B・C それぞれの** 接続 / 保留 / 判定不能 と**正誤**を別々に書く。
**正解不明の件数を隠さない。**

## §7 結果の解釈(**人間が先に決めた 4 分岐をそのまま使う**)

結果が出たら、**最初にこの 3 点を見る**(人間の指示):

1. **一般 LLM と Core のどちらが、独立に正解を確認できる主張を多く正しく接続したか。**
2. **どちらが誤接続をしたか。保留によって誤接続を避けた件数はどれだけか。**
3. **正解不明の主張が何件残り、結論をどこまで制限するか。**

| 結果 | 書くこと |
|---|---|
| 一般 LLM 単体で同等の正確性・根拠の再現性 | **Core の差別化は弱い。売り方か製品設計を見直す** |
| Core は慎重だが正しい接続が少ない | **保留を増やすだけでは価値にならない可能性** |
| 一般 LLM + Core で誤接続を抑えつつ接続・再現性が改善 | **証拠検証レイヤーとしての価値を示す有力な結果** |
| 改善が内部試験に限られ別の文書で再現しない | **汎用的な資産価値はまだ主張しない** |

**差が出なければ「差が出なかった」と書く。**
**「普通の LLM で十分」と判明したら、それも重要な結論として書く。**
**差が出ないのに開発を続ける理由を作らない。**

## §8 示せないこと(限界。**先に書く**)

1. **1 文書・1 報告文・35 件。**汎用的な優位性は主張しない(人間の指示)。
2. **正解集合は「Core の判定規則から独立」であって「完全に独立」ではない**(§2-3)。
3. **列の表層形の表は盲検でない**(§2-4)。だから厳格な数も必ず出す。
4. **A の問いは 6 欄の書き方と保留の選択肢を教えている** ― **A に有利な条件**である。
   「一般 LLM に実務の文脈だけ渡した場合」は測っていない。
5. **工数(時間)は測らない。**人間の作業時間を主要指標にする案は撤回された。
   測るのは**要確認件数**と**誤りの検出**である。
6. **別枠の主張については、どちらが正しいかを決めない。**「正解不明」として数える。
7. **顧客が買うかどうかは測れない。**これは材料であって商談の結果ではない。

## §9 手順(**この順。前の段を commit してから次へ**)

1. **この封を commit する。**(正解集合より先・採点より先・C より先)
2. 正解基準を**機械で**作る(§2 の 2 段)。**採点より先に commit する。**

4. 人間に報告し、**C を走らせる許可を得る。**
5. 許可が出たら C を**1 回だけ**走らせ、凍結して採点する。**実測費用を記録する。**
6. 結果を書く。**差が出なければ出なかったと書く。**

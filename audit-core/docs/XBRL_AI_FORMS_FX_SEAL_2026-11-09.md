## §3 言えないこと

1. 書き手は Claude の 2 model のまま(「Claude 以外」は案 A)。形 4 はこちらが決めた型で、客の文の分布ではない。
2. 20 社は 2026 年提出の有報に偏る。札は同じ系統の model の席(人の目なし)、2 席目は 32 本だけ。
3. F8 の「百万円」は短信の書き方に寄せたが、短信の文の構文(セグメント・定義の違う数)は再現しない。
4. X-5 の窓の外の数は「PB が縛れない前期の数の数」であって、その数が誤って当期に結ばれる率は T9 の F9 の行でしか測れない。
5. 費用の見積りは前の便の実測の平均で、model の単価が変われば外れる(実費は usage から記録)。

## §4 作法

1. 封を先に commit(文書だけ。fresh_seal・facts・boundary の門)→ 駆動 script と門(step-implementer、worktree。前の便の 4 本と F5 の駆動 script は不変)→ 変異 → 独立監査 GO → commit(パス指定)→ `--dry-run`(見積り 2 つ・本数)→ 生成(司令塔。鍵は前の便と同じ渡し方。席には渡さない)→ 判定・注入(0 USD)→ 札(席 160 + 32)→ labels・tally → 結果 `docs/XBRL_AI_FORMS_FX_RESULT_2026-11-09.md` → 門 → 独立監査 GO → commit → 台帳・README。

3. 順序: 規則 T の便(封 eb281f1)と TS の便(封 5bba61e8)の実装・監査が先。この便の生成は両方の commit の後に走らせる(P33E が在れば並べるため)。

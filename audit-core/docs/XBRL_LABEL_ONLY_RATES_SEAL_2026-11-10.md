人間の決定 2026-11-09「それで任せるから進めて」の戦略案の「札の無い行を外した率を全結果に並べる」。engine は変えない。新しい生成・新しい札付けはしない(既存の札だけを使う)。

## §0 材料と決めごと

### §0-1 測った事実(この封を書く前に、読むだけの調べの席が記録から数えた。司令塔は見た。だから下の L-1・L-2 は予測ではなく照合)【門なし】

1. **札の出どころ**: 札は盲検の LLM の席(subagent。1 本 1 席の 1 席目)が `kind == num` の claim にだけ付けた読み(封 `docs/XBRL_AI_FORMS_SEAL_2026-11-03.md`。人は札を付けていない)。真 / 偽 / 判定不能。記録 `fixtures/xbrl/aiforms/labels_2026-11-03.json`(F1〜F4 の 160 本)と `f5_labels_2026-11-03.json`(F5 の 40 本)。

3. **公開している数の分母**: 結果の文書と台帳は P29E 以降の GROUNDED を「数 / 16,588」で並べている(P29E 11,137・P30E 11,260・P32E 11,259・P33E 11,625)。分母に札の無い行 6,231 が入っている。
4. **調べの席の足し引き**(記録の欄そのものではない): 札のある行の GROUNDED は P28E 6,597・P29E 6,586・P30E 6,696・P32E 6,695・P33E 6,979。札の無い行だけだと P33E 4,646 / 6,231。
5. **札ごとの率**(札 真の行の GROUNDED の率・札 偽の行を通した率・判定不能の行の GROUNDED の率)を P29E 以降で出した文書は無い。司令塔はこの封を書く時点でこれを数えていない。

### §0-2 司令塔の決定

1. 材料は AI の文 200 本(F1〜F5)の数の claim(`kind == num`)だけ。文の claim(`kind == text`)は札が無い作りなので母集団に入れない。
2. profile は P28E・P29E・P30E・P32E・P33E の 5 つ。各 profile で 200 本に `verify_document` を 1 回ずつ新しく走らせ(0 USD・手元の cache だけ)、行ごとの state を記録に残す。
3. 札は P28E の (本, claim の id) で結ぶ(札の記録 `本[].札` の id と、今回の P28E の走りの数の claim の id)。P29E 以降の行と P28E の行の対応は、数の読み取り N の便の定義の字のまま: 数の claim の鍵は `(文の番号, 文の中の位置)` で、P29E 以降の数の claim と同じ鍵の P28E の数の claim が在れば「既存の行」、無ければ「新しい行」(`measure/xbrl_numfix_2026-11-04.py` の docstring。関数として切り出されていないので定義の字を新しい script に書き、門で N の便の記録の「既存の行」の数と一致することを確かめる)。既存の行は、同じ鍵の P28E の行の札を持つ。新しい行は「札なし」。
4. 「通した」= GROUNDED。「止めた」= GROUNDED 以外の 3 つ。札 偽の行を通した率は「偽の行の GROUNDED ÷ 偽の行」。
5. 新しい記録は `fixtures/xbrl/labelonly/rates_2026-11-10.json` の 1 つ(行ごとに 本の id・形・profile・state・札(真 / 偽 / 判定不能 / なし)・既存か新か。文・要素名・会社名・pointer の字を持たない)。
6. 判定(採用 / 不採用)は無い便。

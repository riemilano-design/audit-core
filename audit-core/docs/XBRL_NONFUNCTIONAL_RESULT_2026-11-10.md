## §3 記録から読んだこと(門は縛らない)

1. **claim の数が多い書類ほど時間が長い。** 97 書類 × P27 の全部の回(291 回)で、1 回の時間と claim の数の相関係数(Pearson)は 0.81。最大の時間(1.138 秒)は claim の数が最大の書類(279)の回。封 §0-1 の 3 は先頭 5 書類から「時間は claim の数にほとんど比例しない」と読んだが、97 書類ではその読みは当たらなかった(封は書き換えない。この行が補足)。ただし原点を通る比例ではない: 同じ 291 回に最小二乗の直線を当てると切片 0.305 秒(中央値 0.640 秒の 47.6%)・傾き 3.01 ms / claim で、claim の数に依らない固定の部分が約半分ある。相関と直線は司令塔が記録から計算した数で、291 回は書類あたり 3 回の貼り合わせ(独立な書類は 97)。時間の模型ではない。【門なし】
2. **1 claim あたりの時間は profile の間で比べられない。** AI の文 200 本の claim の数(回 1)は P27 14,533 本・P33E 20,750 本(数の claim は 10,371 本・16,588 本)。分母が違うので、P33E の 1 claim あたりの中央値が P27 より小さいのは速くなったことを意味しない。claim の数が違う理由はこの便で測っていない。97 書類の claim の数は P27 11,722 本・P33E 11,724 本。【門なし】
3. **メモリ。** 呼び出しの前の子 process の ru_maxrss の中央値は材料 × profile の 4 群で 9.4〜10.3 MB、呼び出しの後は 99.3〜117.5 MB(§2 の表)。後 − 前の中央値 89.9〜107.2 MB は 1 回の呼び出しで増えた子 process の最大の常駐の量で、fork の親と共有する頁の数え方は OS に依る(§5 の 4)。【門なし】
4. **CPU 時間。** 行ごとの (CPU 時間 ÷ 1 回の時間) の中央値は 4 群で 98.6〜98.8%(書類 P27 の CPU 時間の中央値 0.631 秒・1 回の時間の中央値 0.640 秒)。この区間の時間のほとんどは CPU で使われている(待ちの内訳は測っていない)。【門なし】
5. **import の時間。** 新しい python で `import adapters.xbrl.verify_document` を 5 回: 0.297〜0.330 秒(中央値 0.309 秒)。親が先に engine を読み込んだ後(pyc が在る状態)の数で、pyc が無い最初の 1 回は測っていない。【門なし】

## §4 封に無い決め(実装の報告から写した。12 件。監査は c179f6b2 で「封の字と矛盾なし・予測に寄せた決めなし」)

1. 順は (回, 材料の種類, 本, profile)。回 → 97 書類 → AI の文 200 本。本ごとに P27 → P33E(封 §0-2 の 3 の「材料」を「本」と読んだ。下見と同じ)。【門なし】
2. MB = 2 の 20 乗 byte(下見と同じ)。ru_maxrss は macOS は byte、他の OS は KB を 1024 倍して byte で記録する。【門なし】
3. 判定は丸めない値で幅と比べる。表の桁は 秒 3 桁・ms 2 桁・MB 1 桁・比 3 桁・% 1 桁。値が無い欄(分母 0・材料の穴)は外れ。
4. N-4 = 行ごとの (時間 ÷ claim の数 × 1000) の中央値(claim 0 の行が 1 つでもあれば値なし = 外れ)。N-7 = 同じ (材料の種類, 本, profile) の回の (最大 − 最小) ÷ 中央値を全部の群で出し、その中央値(中央値 0 の群があれば値なし)。N-2 = 97 書類の P33E の中央値 ÷ P27 の中央値。【門なし】
5. N-9 は回 1 の行だけを足す。97 書類は `out["claims"]` の長さ(原文は全部が数の claim)、AI の文は kind が num の数。
6. 入力の byte 数は 2 欄(zip の byte 数・文の byte 数。書類は文なしで null)。
7. import の時間 = 親が新しい python を 5 回起こし、起動の直前から終わりまでの perf_counter の差。主の測定の前に測る(pyc が在る状態。§3 の 5)。
8. 本番の記録は `--only` なし・`--reps` 3 のときだけ書く(それ以外は `--out` 必須)。
9. 記録を書くとき、この便の封の path(32 字以上の英数字の連なりとして鍵の検査に当たる)を除く版の鍵の検査を with の中だけ当てる(PB の関数 `key_check_pb` は変えていない)。
10. 記録の機械が封 §0-1 の 1 と違えば門が赤(結果の数はこの 1 台のもの)。
11. 触らない file の範囲は `adapters`・`core`・`measure` 全部・`fixtures/xbrl` 全部(この便の script と記録だけ新しい file を許す)。

## §5 言えないこと

1. 数はこの 1 台の、この日の 1 回の走り。他の機械・OS・python・負荷では測っていない。
2. 並行の処理(何書類を同時に回せるか・throughput)は測っていない。1 process ずつ直列で測った。
3. 材料は手元の 97 書類と AI の文 200 本だけ。claim が 279 本より多い書類・PDF・他の形式は測っていない。§3 の 1 の相関から大きい書類の時間を推すことはしない。【門なし】
4. ru_maxrss は子 process の最大の常駐の量で、呼び出し 1 回だけのメモリを切り出した量ではない。
5. 有料の API・通信は使っていない。LLM の席の時間・費用は含まない。
6. 時間の数は門で測り直さない(封 §0-2 の 4)。門が縛るのは「文書の表が記録と同じ」だけ。

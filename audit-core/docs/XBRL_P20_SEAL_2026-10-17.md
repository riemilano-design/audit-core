# 封 ― **profile を P20 にして測る。目的は原因仮説の検証であり、性能の証明ではない**

2026-10-17。人間の決定(「P20 への切り替えを、新しい封として実施する。ただし、目的は
性能改善の証明ではなく、原因仮説の検証である」)。

**この封は実測より先に commit する。**順序は門で確かめる
(`tests/measure/test_xbrl_p20_seal.py`)。

---

## §0 目的と、目的でないもの

**目的**: 仮説 A(`docs/XBRL_BRANCH_A_2026-10-17.md` §5)の検証。
**既存の機能(`with_nonconsolidated_fallback`)を正しい設定で使うと何が起きるかを測る。**

**目的でないもの。**

1. **性能改善の証明ではない。**特定が増えても「Core が良くなった」とは書かない。
2. **製品価値の実証ではない。**「LLM + Core が LLM 単体より正確か」(A 対 C′)は
   **別の問いであり、この封では測り直さない。**人間の指示でこの 2 つは分ける。
3. **fallback の適用条件の変更ではない。**条件を変えるかどうかは、この結果を見てから
   人間が判断する。**この便では engine のコードを 1 行も変えない。**

## §1 変える 1 つだけ

| | |
|---|---|
| **変えるもの** | **profile。`P16` → `P20`**(`vocabulary.DEFAULT_PROFILE` は `P20`) |
| 変えないもの | 材料(同じ 8 書類・同じ seed・同じ 24 行)・注入・採点の関数・`norm_pointer`・席の答え(凍結済み)・engine のコード |
| 席 | **呼ばない。費用 0 USD**(通信は EDINET の cache も使わず、既に取得した zip を読む) |

`P16` と `P20` の差は **`nonconsolidated_fallback` の 1 つだけ**である
(`P20 = dataclasses.replace(P16, name="P20", nonconsolidated_fallback=True)`)。
**この 1 行を門で確かめる** ― 2 つの profile の他の欄が違っていたら、1 変数ではない。

## §3 判定 ― **既に commit した予測との照合**

予測は `fixtures/xbrl/cd8/branch_a_predictions_2026-10-17.json`(commit `cf4f5c9`)。
**この file を編集しない。**門が sha256 を固定する。

- **欄ごとに当たり・外れを数える。**外れは外れとして書き、予測を書き換えない。
- **「特定が増えた」だけでは成功と書かない。**M-3(誤認定)を同じ表に並べる。
- **M-4 が 1 行でも動いたら、仮説 A の条件の読みが違う。**その場合は
  「fallback の条件の読み方が誤っていた」と書く(結果に合わせて予測を直さない)。
- **P16 の再現が封の記録と違ったら止める。**同じ入力で `material_2026-10-17.json` の
  Core 欄が再現しなければ、比較の土台が無い。

## §4 失敗条件(**先に書く**)

1. P16 の再現が材料の記録と食い違う → **止めて報告する。**測り直さない。
2. 2 つの profile の差が `nonconsolidated_fallback` 以外にも在る → **1 変数でないので止める。**
3. 材料の sha256 が封の記録と違う → **止める。**
4. 席の答えを読み替える・採点関数を書き換える → **やらない。**
   (A 対 C′ の数はこの封では作らない)

---

## §5 やらないこと

- **engine のコードを変えない**(sha を門で固定)。
- **fallback の適用条件を変えない。**
- **語彙・主語(仮説 B)に触らない。**P20 でも 7 行は誤認定になると予測している。
- **席を呼ばない。**0 USD。
- **A 対 C′ を測り直さない。**製品価値の実証は別の封で行う。

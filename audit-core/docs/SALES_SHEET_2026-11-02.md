# Audit Core ― 外向けの 1 枚(測った数だけ)― 2026-11-02

Audit Core は、文の中の数が**原資料のどの値から来たか**を指し、値が合うかを比べる道具です。有価証券報告書(EDINET の XBRL)が主な領域で、AI が書いた要約の数を 1 つずつ、一致(GROUNDED)・値違い(VALUE_MISMATCH)・参照先なし(POINTER_NOT_FOUND)・判定不能(UNVERIFIABLE)の 4 つで返します。言語 model を呼びません。数は全部、repo の記録(`fixtures/**/*.json`)に在り、台帳 `docs/FACTS_FOR_BUYERS_2026-10-20.md` の行番号で引けます。この 1 枚の数は門 `tests/measure/test_sales_sheet.py` が台帳の同じ行と照らします(門は、同じ行の欄に在る別の数への差し替えまでは見分けません)。

## 4. 作法(買い手が自分で確かめられる)

- 文書の数は門が記録に縛る。台帳の印は `python3 measure/facts_check_2026-10-20.py --check` で 1 行ずつ OK / NG が出る。

## 5. 言わないこと

- 当たる率を約束しない。測った数と、その分母・材料を示す。
- 一般の LLM との優劣を言わない。1 節の数をそのまま示す。
- 材料は少ない。AI の文は 10 社〔台帳 D-21〕と 1 書類〔台帳 L-51〕で、1 つの model の文体。

## 6. 提供の形

- **最初の 1 本は無償。** 相手の AI の文 1 本(と元の書類)を engine にかけ、claim ごとの判定(4 つの状態・指した fact・止めた理由)を返す。
- **有償の PoC。** 相手が選ぶ文と書類で、封(対象・予測)→ 記録 → 結果の報告(この台帳と同じ形)を納める。着手時に一部、納品と検収の後に残り。納めるのは判定と記録で、当たる率の約束ではない。
- **その後は年額の利用と保守。** EDINET の taxonomy の年次更新への追随と不具合の対応を含む。利用の件数と独占の有無で段を分ける。source は渡さない(API か実行 file)。
- **売却は相談。** 記録・台帳・文書の一切と引き継ぎを含む形で、別に話す。
- 受け取った文と書類は `sha256` を記録に残し、保管の期間を先に決める。

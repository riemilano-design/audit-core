# 2 種類のレポートを分ける(設計の決め。2026-11-24)

人間の指示(2026-11-24): 「監査レポートは開発者のためのもの。点検レポートは顧客のためのもの。この区別を今、プロジェクトの設計に明確に入れるべき」。

| | 内部監査レポート | 製品の点検レポート |
|---|---|---|
| 読者 | 開発者・監査の担当 | 資料を作った人・使う人(顧客・第三者) |
| 目的 | 実験(便)の正しさ・再現できること | 資料の問題を分かって直すこと |
| 中身 | 封・集計・script・commit・監査の指摘・指紋 | 問題の箇所・理由・重さ・どうすればよいか・確かめ済みの所 |
| 置き場 | 便の folder の `AUDIT.md`(組んだ形は `AUDIT.html`。`explore/audit_html.py`) | 製品の出力。資料ができた後に、7 段の 7 → 5 の照合から作る |
| 形 | 区分ごとの件数 → 指摘と直し → 確かめられなかった → 合った(いまの形のまま) | 点検結果 → 要確認事項 → 人の判断が必要 → 確認済み → 点検していない数 |

## 製品の点検レポートの決まり

- 読む人に、**どの数が・なぜ・どう確かめればよいか**が分かる字で書く。照合の符号(S1〜S9・GROUNDED など)・commit・指紋は出さない。
- **点検していないものを「確認済み」と書かない。** 確認済みの行には、確かめたこと(元の数との一致・出どころ・期・単位・範囲・人が画面で決めたこと)をその行ごとに書く。照合の規則の外の数は「点検していない数」に分けて出す。
- 見本の診断レポート(`sales/sample_report.html`。XBRL の書類の文を点検したもの)は、この製品の点検レポートの先の形。区分の名は利用者に分かる言葉(確認済み・要確認・人の判断が必要)に寄せる。

## いまの在りか

- 内部監査レポート: 便 RD2・AQ0 から(`explore/rd2/AUDIT.md`・`explore/aq0/AUDIT.md`)。
- 製品の点検レポート: 便 TR0(`explore/tr0/`)で、1〜7 段を通してできた資料に対して初めて作る。

## §1 `audit_core.verify` が見るもの(コードから)

`core/py/audit_core/verify.py` の順序はこれだけである。

1. `recipe.unverifiable_reason` が在れば **UNVERIFIABLE**
2. `recipe.not_found_reason` が在れば **POINTER_NOT_FOUND**
3. **各 pointer を resolver で解く。解けなければ POINTER_NOT_FOUND**(`unresolved:…`)
4. **contract の comparator で比べる。合えば GROUNDED、合わなければ VALUE_MISMATCH**

state は **4 つだけ**(GROUNDED, VALUE_MISMATCH, POINTER_NOT_FOUND, UNVERIFIABLE)。
**comparator が読む欄は `evidence[0].value` と `contract.params` である。**
`evidence[0].unit` は読まない。**リンクベース(`calculation`/`presentation`/
`definition`)を読む場所はコードに無い。**

## §2 人工の探り ― **値を同じにして属性を 1 つだけ変える**

**止めなければ「その属性は検査されていない」**という機械の証拠になる。

| 探り | 何を試しているか | 結果 | |
|---|---|---|---|
| 0 **対照**: すべて一致 | **探りの器が動いているか**(GROUNDED にならなければ、下の 6 件は何も示さない) | `GROUNDED` | **対照(通すのが正しい)** |
| 1 実在しない参照先 | 要素・context の実在 | `POINTER_NOT_FOUND` | **止めた** |
| 2 値が違う | 値の一致 | `VALUE_MISMATCH` | **止めた** |
| 3 値は同じ・**単位が違う(USD)** | fact の単位(`unitRef`)を見るか | `GROUNDED` | **通した → 検査していない** |
| 4 値は同じ・**期間が違う(前期)** | context の期間を主張の期と照らすか | `GROUNDED` | **通した → 検査していない** |
| 5 値は同じ・**次元が違う(単体 member)** | 連結区分・次元を見るか | `GROUNDED` | **通した → 検査していない** |
| 6 同じ鍵の fact が 2 件(値が違う) | 重複を判定に使うか(meta には出る) | `GROUNDED` | **通した → 検査していない** |

**止めたのは 2 件、通したのは 4 件である。**

- **第 1 層(物理)で今できるのは 2 つだけ** ― **参照先の実在**と**値の一致**。
- **できていないのは 4 つ** ― **単位・期間・次元(連結区分)・重複**。
  材料(`unitRef`・context の `instant`/`start`/`end`・`explicitMember`・同鍵の件数)は
  **instance に読み込まれている。**比較していないだけである。
- **第 2 層(意味)は材料そのものが無い。**リンクベースを読んでいないので、
  「XBRL の定義や関係情報が主張を支持するか」は**今は 1 件も機械で確かめられない。**

### §2-2 私の探りの欠陥(**先に対照を入れていなかった**)

最初の実行では **6 件すべてが POINTER_NOT_FOUND** になり、
「Core は単位も期間も次元も見て止めている」と読めてしまった。
原因は**私の探りの参照先に接頭辞(`jppfs_cor:`)が無く、1 件も解けていなかった**ことである。
**対照(すべて一致 → GROUNDED になるべき探り)を入れていなかったので気付くのが遅れた。**
いまは対照を 0 番に置き、**対照が GROUNDED でなければ script が止まる。**

## §3 実物での発火 ― **席が名指した参照先を差し替えて `verify` を呼ぶ**

**正解とは照合していない**(どちらが正しいかは盲検比較の封で測る)。

| | 件 |
|---|---|
| **Core に主張が無い(検証できない)** | 12 |
| **contract が参照先 2 本を要る(1 本渡しでは検証できない)** | 7 |
| **contract が無い(検証できない)** | 24 |
| state GROUNDED | 10 |
| state VALUE_MISMATCH | 32 |
| 席が名指さなかった行 | 107 |
| 席が名指した行 | 85 |
| 検証できた行 | 42 |

**席が名指した 85 行のうち、今の Core で検証できたのは 42 行だけである。**

検証できない理由は 3 つで、**どれも「参照先が悪い」ではない。**

| 理由 | 行 | 中身 |
|---|---|---|
| **contract が無い** | 24 | Core がその主張を束縛できていない。比べる規則が作られていない |
| **Core に主張が無い** | 12 | その行の文を Core が主張として切り出していない |
| **contract が参照先 2 本を要る** | 7 | `pct_change`・`diff(a-b)` 等。**1 本渡しでは定義されない** |

通った 42 行の内訳は **GROUNDED 10 / VALUE_MISMATCH 32** である。

## §4 役割を替える設計に対して、この棚卸しが言うこと

1. **「実証する」側の能力は、今は第 1 層の 2 項目だけである。**
   LLM が選んだ参照先について、**実在と値は独立に確かめられる。**
   **単位・期間・次元は確かめていない** ― だから
   「値が合うから実証済み」と返すと、**期間や連結区分の違いを通す。**
   §2 の探り 4・5 がその実例である(値が同じなら前期でも単体でも GROUNDED)。
2. **第 2 層(意味的実証)は、今は「実証不能」しか返せない。**
   リンクベースを読んでいないので、機械で支持できる根拠が無い。
   **ここを「実証済み」にしてはいけない**(人間の指示の §3)。
3. **検証の入口が半分しか無い。**席が名指した 85 行のうち 42 行。
   残りは **Core 側に比べる規則(contract)が無い**ために検証が始まらない。
   **役割を替えるなら、ここが最初の仕事になる** ―
   「主張を束縛できなかった行でも、外から渡された参照先に対して contract を作れるか」。
4. **複数参照先の主張は、1 本渡しの設計に乗らない**(7 行)。
   差分・率の主張は「LLM が 2 本渡す」形にしないと検証できない。

## §5 言えないこと

1. **これは棚卸しであり、精度の測定ではない。**正解と照合していない。
2. **第 1 部は人工の 1 件ずつである。**実物の分布を代表しない。
3. **「できない」は今のコードについてである。**材料は instance に在るので、
   **検査を足せないという意味ではない。**
4. **engine は 1 行も変えていない。**足すかどうかは人間が決める。
5. **第 2 部の 42 行が「正しく検証できた」とは言っていない。**
   state を数えただけである。

## §6 次に人間が決めること

1. **第 1 層に 3 つ足すか**(単位・期間・次元)。材料は在り、比較は小さい。
   **足せば「値が合うだけで通す」ことは無くなるが、新しい拒否が増える**
   ― 増え方は測るまで分からない。
2. **contract が無い行をどうするか**(24 行)。
   外から渡された参照先に対して contract を作る設計は、**今は無い。**
3. **第 2 層をやるか**(リンクベースを読む)。これは新しい材料の取得である。
4. **盲検比較(A: LLM 単独 / B: LLM + 新しい Core / C: 正解で監査)をいつ始めるか。**
   **4 つの評価軸は人間が定めたものを使う**(誤った参照先を実証済みにした割合 /
   正しい参照先を誤って拒否した割合 / 実証不能として止めた割合 / 最終判定の差)。

## 六 限界

- 「違う」が正しい文に出る率は、報告の形では減らない。既定 P22 の「違う」の件数は報告の前後で同じで、P25 明示で減るのは P24・P25 の engine の直しの効き目であり、この封の効き目ではない。
- `no_same_value` が名指した当期の値は `Claim.provenance` に在るが、`verify_document` の出力の JSON には欄が無い。この封は `verify_document.py` を触らないので、報告に「当期の値は X」は出さない。理由の一行だけ出す。
- 語の主張(増加・減少)の出典の値は、文に単位が無いので円で出る。`report.py` 末尾の「率・差は文と同じ単位」は、差については実物と違う(差も円)。`report.py` は触らないので、この一行をここに書く。
- 「出典の値の単位が文と同じ」は claim の単位に対する値で、文の字の単位ではない。文が百万円・千円・億円・兆円と書いていても claim の単位が円の行では、「文の値」の列が円で出る(独立監査の指摘)。概数(span の字から数えた): P25 で違う 86・要確認 466・一致 924・判断しない 24(P22 で違う 375・要確認 220・一致 881・判断しない 24)。
- 「対象外」「判断しない」の線は reason 単位で、混在の reason(`no_element` 等)は全部「要確認」に入る(安全側)。
- 標準ラベルは repo の外(2026-10-08 の人間の決定)。無ければ要素名のまま出る。`--labels` の dir の sha256 は module では照合しない(照合はこの測定の起動時と `instance.py`)。
- 報告の日本語の字が客に伝わるかは門で縛れない。縛るのは節の振り分け・件数・単位・網羅・バイト列の同一だけである。
- module の変異の実測(理由を一つ消す・節の振り分けを変える・単位の倍率を落とす・節の順を入れ替える・report の `fmt_num` を差し替える等)は、実装席が手で走らせた一回限りの手の実測で、門では縛れない。毎回縛るのは `tests/adapters/xbrl/test_report_customer.py` の網羅・単位・節の順・golden で、これらは壊した標本で赤くなることを同じ試験の中で確かめている。

- 封 §3 は標準ラベルの無い行を「六十七書類で四十八行」と書いたが、この測定の数え方(「違う」と「一致」の行のうち、標準ラベルの無い要素を持つ行。名前空間別)の値は、上の「検査の数」の表のとおりで、封の数とは一致しない。数え方の違いか封の数の誤りかは、封の数の出どころ(試作の手元の数)が repo に無いので決められない。封は直さず、表の値を正本にする。

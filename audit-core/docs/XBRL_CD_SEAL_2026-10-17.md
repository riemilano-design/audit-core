## §4 腕(**同じ入力・同じ生成結果を共有する**)

| 記号 | 中身 | LLM |
|---|---|---|
| **A** | 席そのまま | 1 回 |
| **B** | Core 単体(**参考群**) | 0 |
| **C′** | **席の申告 + Core。申告を上書きしない** | A と同じ生成 |
| **D′** | **席の申告 + 単純な値検索。申告を上書きしない** | A と同じ生成 |
| **D″** | **D′ + 単位の倍率換算 + 最小桁 ±1 の帯**(**値検索を強くした版**) | A と同じ生成 |

**A・C′・D′・D″ は 1 回の生成を共有する。入力の差はゼロである。**
**席は 1 席。**2 席にしない理由は、**軸3 の正解が構成上決まる**ので
席の一致を正解の作り方に使わないからである(複数の LLM の一致を証拠に数えない)。

### §4-1 **D′ の定義(限定して書く。弱く作らないための項目も書く)**

| 項目 | 字 |
|---|---|
| 検索対象 | **その書類の `refs` 全部**(instance の全 fact。TextBlock を除く。同じ `Element@context` は 1 件) |
| 比較 | 文中の数の値と ref の `value` を **`round(x, 6)` で一致**を見る |
| 正規化 | 数の字面は `prepare_material` が通した `normalize_digits` のまま。**単位の倍率換算をしない**・**丸めの帯を持たない**・符号は字面のまま |
| 意味的選別 | **しない**(element の名前・context の期間・連結/個別・member を見ない) |
| 返す物 | **一致した fact を全部**。0 件 → `原資料と一致しない` / 1 件 → `確認済み(その fact を参照先として出す)` / 2 件以上 → `一意でない(参照先を出さない)` |

### §4-2 **D″ の定義(弱く見せないための強い版)**

D′ に次の 2 つだけ足す。**element・context の意味的選別は足さない。**

- **単位の倍率**: `×1`・`×1,000`・`×1,000,000`・`÷1,000`・`÷1,000,000` を試す。
- **丸めの帯**: 文中の数の最小桁で **±1**(四捨五入・切り捨ての両方を許す)。

**Core の丸め規約(`profile.doc_rounding`)は使わない**(使うと Core を D″ に持ち込む)。

### §4-3 **合成の規則(申告を上書きしない)**

1. **席が「誤りが在る」と言ったら、その申告はそのまま残る。**
   照合器が `確認済み` を返しても**消さない**(2026-10-17 に私が壊した所)。
2. **席が「判定できない」「黙っている」ときだけ、照合器の結果を足す。**
3. **種類は席の申告をそのまま採る。**照合器は種類を言わない。
4. **参照先は、照合器が 1 通りに決めたときだけ出す。**
   C′ は Core の pointer、D′・D″ は一致した 1 件。**2 件以上なら出さない。**

## §5 採点(**5 つを独立に数える。分母を必ず書く**)

| 記号 | 分母 | 数えるもの |
|---|---|---|
| **検出** | 注入した件 | 「誤りが在る」と言った件 |
| **見落とし** | 注入した件 | 「確認済み」と言った件(**誤りを通した**) |
| **保留** | 注入した件 | 「判定できない」と言った件 |
| **偽警報** | **無改変の件** | 「誤りが在る」と言った件 |
| **種類** | 注入した件のうち検出した件 | 固定語彙で**正しい型**を言った件 |

**排他**(検出 / 見落とし / 保留 は 1 件につき 1 つ)。

### §5-1 **参照先は 2 つの率に分ける(分母が違う。人間の条件)**

| 記号 | 定義 | 分母 |
|---|---|---|
| **P-特定率** | **正しい参照先**を出せた件 ÷ **正解が構成上決まっている件** | **T5 の件数**(`true_ref_key` が在る) |
| **P-誤認定率** | **誤った参照先を「確認済み」として採った件** ÷ **参照先を出した件** | **参照先を出した件数**(腕ごと) |

**この 2 つを 1 つの率にまとめない。**
「参照先を出せない」と「誤った参照先を確信して採る」は**顧客にとって別の損害**である。

**誤認定に数えるもの(機械で決まる。読みで選ばない)**

- **T5**: 参照先が `coincident_ref_key` だった(= 値は合うが**対象が違う**)。
- **T3**: 参照先を名指した(**原資料に対象が無い**ので何を指しても誤り)。
- **T1**: 「確認済み」と言った(**値がどこにも無い**ので参照先に関わらず誤り)。

### §5-2 **正解の基準**

- **`(element の局所名, context)` の集合として厳密一致。**
  `measure/grounds_eval.py` の `canon` / `fact_set` / `parse_pointer` を使う。
- **値の一致は正解にしない。**
- **`unit` は別の欄として一致を要求する**(T2 を正しく扱うため)。
- **同値類 v0 は併記するが判定には使わない**(厳密が判定)。

### §5-3 **層(どこまでが安価に代替できる範囲か)**

注入した値について、**同じ値を持つ fact の数 `n`** で層に分ける
(`candidate_ref_count` と `refs` から機械で出す)。

| 層 | 意味 |
|---|---|
| **n = 1** | 値が一意。**D′ でも解ける見込みの層** |
| **n = 2〜5** | 値が重なる |
| **n ≥ 6** | 値が多数に重なる。**Core でなければ難しい見込みの層** |

**層ごとに C′ と D′・D″ を並べる。**全体の 1 つの数で結論しない。

## §10 示せないこと

1. **既存製品(Google・NVIDIA 等)との比較は、この試験では実証できない。**
2. **誤りを示唆する問いの下での検出である。**通常の読みでの検出率ではない。

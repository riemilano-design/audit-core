## 1. 指示 1 前半の答え ― EDINET タクソノミに日本語の標準ラベルは**含まれている**

**証拠は手元のファイルの中にある**(ダウンロードしていない)。
書類自身の `.xsd`(`XBRL/PublicDoc/jpcrp030000-asr-001_….xsd`)が、次の `linkbaseRef` を持つ。

```
http://disclosure.edinet-fsa.go.jp/taxonomy/jppfs/2025-11-01/label/jppfs_2025-11-01_lab.xml      ← 日本語
http://disclosure.edinet-fsa.go.jp/taxonomy/jppfs/2025-11-01/label/jppfs_2025-11-01_lab-en.xml   ← 英語
http://disclosure.edinet-fsa.go.jp/taxonomy/jppfs/2025-11-01/label/jppfs_2025-11-01_gla.xml      ← 冗長ラベル
http://disclosure.edinet-fsa.go.jp/taxonomy/jpcrp/2025-11-01/label/jpcrp_2025-11-01_lab.xml      ← 日本語
(jpcrp の lab-en / gla、jpdei の 3 本も同様)
```

`_lab.xml` が日本語・`_lab-en.xml` が英語という付け方は、**書類の中に入っている会社拡張の
ラベルファイルと同じ形式**であり、そちらは `xml:lang="ja"`・role `…/label` の日本語ラベルを
実際に持っている(`instance.labels_from_zip` が既に読んでいる)。
**したがって「要素ごとの日本語の標準ラベルが含まれているか」の答えは「含まれている」。**

**ただし標準タクソノミのラベルファイルは書類の ZIP に入っていない**(ZIP には会社拡張の
`_lab.xml` 20〜32 KB だけ。1 社目では 249 要素のうち 8 件しか引けない)。
使うには `disclosure.edinet-fsa.go.jp` からの**ダウンロードが要る。**

## 2. ダウンロードせずに同じことができる ― 書類自身のインライン XBRL

**書類の財務諸表は iXBRL(インライン XBRL)である。** 表の 1 行の中に

- 日本語の勘定科目名(`<td>` のテキスト)
- その行の数値に付いた要素名(`<ix:nonFraction name="jppfs_cor:Assets">`)

が**同じ `<tr>` の中に並んでいる。** だから **要素 ↔ 日本語の勘定科目名の対が、
順番の推測ではなく表の構造から**取れる(1 社目で ix のある行 373、取れた名前 226)。

**この方法を先に試す。** 理由は 3 つ。

1. **ダウンロードが要らない**(費用 0 円・許可も要らない)。
2. **会社自身が自分の計算書で使った言葉**なので、同じ書類の本文(MD&A)の言い回しと合いやすい。
3. **標準タクソノミに無い会社拡張の要素も同時に引ける。**

**標準タクソノミのラベルは、この方法で足りなかったときの次の手**として残す
(そのときはダウンロードの許可を人間に求める。URL は §1 のとおり、`jppfs`・`jpcrp` の
`_lab.xml` 2 本)。

### 取れることを先に確かめた(診断。直す前の状態の観測)

| 語 | 1 社目 | 2 社目 | 3 社目 | 既存の語彙 |
|---|---|---|---|---|
| 資産合計 | `Assets` | `Assets` | `Assets` | 在る |
| 負債合計 | `Liabilities` | `Liabilities` | `Liabilities` | 在る |
| **売上原価** | **`CostOfSales`** | **`CostOfSales`** | `CostOfSales`+1 | **無い** |
| **短期借入金** | (無し) | **`ShortTermLoansPayable`** | **`ShortTermLoansPayable`** | **無い** |
| **利益剰余金** | **`RetainedEarnings`** | **`RetainedEarnings`** | **`RetainedEarnings`** | **無い** |
| **退職給付に係る資産** | **`NetDefinedBenefitAsset`** | (無し) | (無し) | 在るが**別名**を指していた |
| **退職給付に係る負債** | **`NetDefinedBenefitLiability`** | **`NetDefinedBenefitLiability`** | **`NetDefinedBenefitLiability`** | 在るが**別名** |

| 受注高 / 受注残高 | **(無し)** | (無し) | (無し) | 在るが書類に無い |

**前に見つけた語彙の穴のうち 4 つが埋まり、2 つ(流動資産・固定資産)は埋まらない見込み**
(計算書では見出しの行で、その行に数値が付いていないため)。
**受注高・受注残高は引けない = 「元データに無い」の裏取りになっている。**

## 3. 当て所(新しいフラグ `label_vocabulary`、既定 `False`)

| | 中身 |

### 4.5 指示 3 ― 同じ文の 2 つの主張が同じ相手を指していないかの検査

> 同じ文の中の 2 件以上の主張が、**同じ pointer の組**(順序を無視した集合)に結ばれていたら
> 1 件の衝突として数える。`T007`/`T008` と `T021`/`T022` がこの型であった
> (直し 6 で解消済み)。

| | 予測 |
|---|---|
| `P10`(直し 6 入り)での衝突 | **0 〜 4 件**(合計)。`T007/T008`・`T021/T022` は直し 6 で消えている |

## 5. 先に書いておく限界

- **ラベルの語彙は書類ごとに違う。** 書類に出てこない勘定科目は引けない。
  **だから「語彙の漏れ」が 0 になることはない。**
- **会社が自分の表で使った言葉**なので、**会社によって同じ概念が違う言葉になる。**
  3 書類で測った数が、未使用の書類でそのまま出るとは限らない。
- **これは語彙を増やす変更である。** CLAUDE.md の区分では記述的知識(Kind 1)にあたり、
  **既定 `False` のフラグに留める。** `P11` を既定にするかは人間が決める。
- 流動資産・固定資産のような**見出しの行**は、この方法では引けない。
  標準タクソノミのラベル(§1)ならば引ける見込みがあるが、**ダウンロードの許可が要る。**

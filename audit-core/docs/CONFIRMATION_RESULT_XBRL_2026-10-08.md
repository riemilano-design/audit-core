## 3. 人間の 3 つの読みを元データで確かめた ― すべて当たり。1 つは原因が 2 つに分かれた

### (a) 「結び付けの誤りは既定値に落ちた結果かもしれない」 → **当たり。ただし資産と負債で原因が違う**

| 要素 | `Prior2YearInstant` | 括弧内の前期の差を計算できるか |
|---|---|---|
| `jppfs_cor:Assets` | **無** | できない |
| **`jpcrp_cor:TotalAssetsSummaryOfBusinessResults`** | **在**(24,079,430,000) | **できる。Prior1 − Prior2 = 1,475,245,000 ― 本文の「14億7千5百万円」と一致** |
| `jppfs_cor:Liabilities` | **無** | できない |
| 負債の業績概要の要素 | **そもそも存在しない**(`[]`) | **どの要素でも計算できない** |
| `jpcrp_cor:NetAssetsSummaryOfBusinessResults` | **在** | **できる(`N034` が実際に正しく処理している)** |

**資産合計は、正解を出せるデータが同じ書類の中に在るのに、抽出器が 2 期しか持たない要素を選んだために届かなかった**
= **語彙の選び方の問題**。そして **Prior2 が無いときに止まらず、当期の残高への単発照合に落ちている**
= **人間の指摘どおり「止めるべき所で別の値を代用している」。設計の原則に反する。**

**負債合計は原因が違う** ― 業績概要の要素が**存在しない**ので、**どの語彙を選んでも計算できない。**
こちらは「元データに無い」に近い。**同じ 5 件の中で原因が 2 つに分かれる。**

### (b) 「丸め方が主張ごとに違う」 → **当たり。階段になっていた**

`adapters/xbrl/comparators.py:43-46`:

```
round    : |fact - target| <= unit/2
truncate : 0 <= fact - target < unit
abs+...  : same two checks with both sides' sign dropped
Returns one of "round" / "truncate" / "abs+round" / "abs+truncate"
```

**4 つを順に試し、最初に合ったものを返す。** `round` は `±unit/2`、`truncate` は `0..+unit` なので、
**合わせると `−unit/2 .. +unit` ― 許容幅は実質 1.5〜2 倍。**
**人間の読み(どちらかで合えば通す作りなら許容幅が実質 2 倍)は正しい。**
**書類単位で 1 つに決めるべき**という判断にも同意する。**ただし直すのは測定が終わってから。**

### (c) 「目標値の件は、文章の主張には規則が掛かっていないのでは」 → **コードで確認。掛かっていない**

`adapters/xbrl/recipes.py:286` のコメントに **「文章 Claim には掛けない」** と明記され、
`recipes.py:406` の判定は `_build_raw_num_claims` の中にしか無い。
**だから `T031`「拡大を見込みます」は目標・計画の規則を素通りした。**
`N013`(ROE の目標)は数の主張なので規則の対象だが、**窓が数の手前 10 字しか見ないため捕まらなかった**(既報)。
**同じ「目標・見通し」の取り違えが、数の側は窓の狭さで、文字の側は規則の不在で、2 つの別の理由で漏れている。**

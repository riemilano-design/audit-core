### §1-2 どちらが誤接続をしたか。保留で避けた誤接続は何件か

| | A1 | A2 | B |
|---|---|---|---|
| 正解集合での誤接続 | **0** | **0** | **0** |

**Core は同じ行を同定した上で `VALUE_MISMATCH` を出し、接続を拒んだ。**

### §1-3 正解不明が何件残り、結論をどこまで制限するか

## §3 この結果の読み方 ― **正解集合は A に有利な部分集合である**

**正解集合の作り方そのものが、「主張の文を読めば参照先が分かる」件を選んでいる**
(G-独立-2 科目名が文に出る・G-独立-3 親か会計名が文に出る・G-独立-4 列が文に出る)。
**これは一般 LLM の得意な形である。**

- **Core に有利な偏りは無い**(人間が最も警戒した点)。正解集合は Core の規則を
  1 つも使わずに作った(別名表・6 欄の鍵・親の絞り・接続の規則・値の照合は不使用)。
- **だが A に有利な偏りは在る。**この偏りは**消せない** ―
  参照先を独立に確認する方法が「文に字が在るか」しかないからである。
- **したがって「一般 LLM の方が優れている」と一般化しない。**
  言えるのは「**文から参照先が読み取れる主張では、一般 LLM が 24/24 で Core が 12/24**」である。

> **一般 LLM 単体で同等の正確性・根拠の再現性を実現できる → 現在の Core の差別化は弱い。

**この分岐に当たる。**ただし**「同等」ではなく「正確性では一般 LLM が上、
偽の確認の検出では Core が上」**である。

「一般 LLM に渡す証拠レイヤー」の方が筋が良いことを示している**が、

## 2. 型 1(数字の置換)― 定義を独立に固定する

### 2-1. 現場の定義を変える(いちばん大事な決め)

**`lib/sites.py` の `t1_sites`(= `data_bearing_sites`)をそのまま使わない。**

既定は「トークンの値が参照一覧に在る」ことを現場の条件にしている。これを使うと、**3 書類の現場は 3 / 48 / 8 = 59 件で、
うち 29 件は単位を持たない数**である。中身を 1 件ずつ読んだ結果(実測):

```
「第2　事業の状況　4　経営者による財政状態…」     の 4 = 節番号
「（注）1　金額は仕入価格によっており…」           の 1 = 注番号
「第5　経理の状況　1　連結財務諸表等」             の 1 = 節番号
「2.最近2連結会計年度の主な相手先別の販売実績」     の 2 = 項番号
「1.0」「△5.0」                                 = 表の断片
```

**これらは主張ではない。** ここに誤りを混ぜても誤りにならないので、**分母が嘘になる**
(人間が一度捕まえた型 ―「第2回」の 2 を「第2局」にして誤りとして数えた件と同じ)。
さらに `％` のトークンは 1 件も現場にならない ― 本文の `5.8` は XBRL の `pure` 値 `0.058` と一致しないためである。
**つまり既定の定義では、型 1 は金額だけになり、率が同語反復になる。**

**固定する定義:**

> **型 1 の現場 = 原本の P7 + Core の判定で `GROUNDED` な「数の主張」。**
> 値が参照一覧に在ることは**現場の条件にしない**(その条件は**置換値の側**に掛ける)。

この定義での母数(**既に測ってある数。予測に数えない**):

| 書類 | 数の主張 | うち GROUNDED | 単位の内訳 | form の内訳 |
|---|---|---|---|---|
| `S100Z4Q1` | 60 | **50** | 円 44・% 6 | 直接 31・派生 19 |
| `S100Z4B6` | 91 | **46** | 千円 33・% 13 | 直接 29・派生 17 |
| `S100YMFV` | 88 | **53** | 円 26・百万円 13・% 12・ポイント 2 | 直接 33・派生 20 |
| **合計** | **239** | **149** | 金額 116・% 31・ポイント 2 | 直接 93・派生 56 |

### 2-2. 置換値の距離を層で固定する(人間の決定 (ウ))

**許容は読めば決まる**(実測):

| 主張の種類 | 許容 | 原文で変えられる最小の幅 |
|---|---|---|
| 金額(千円) | **500 円**(`0.5 × claim_scale`、`vocabulary.py:118-127`) | 1 千円 = **1,000 円** |
| 金額(百万円) | 500,000 円 | 1 百万円 = 1,000,000 円 |
| 1 株当たり(円、小数 2 桁) | 0.005 円 | 0.01 円 |
| **割合(％・ポイント)** | **0.15 ポイント**(`recipes.py:364`) | **0.1 ポイント** |

**既定の `build_t1` は距離を決めていない** ― `mult=2, delta=1` から順に試して**最初に見つかった値**(= 元の値 +2)を返す。
これでは率が「混ぜる側の選び方」を測る。**層を先に固定する:**

| 層 | 置換の作り方 | 分母 |
|---|---|---|
| **(a) 許容のすぐ外** | 許容を**ちょうど超える最小の幅**(金額なら 1 単位、割合なら +0.2 ポイント) | **入れる** |
| **(b) 1 桁だけ違う** | 数字 1 文字だけを別の数字に替える(例 129,331 → 129,431) | **入れる** |
| **(c) 桁違い** | ×10(例 129,331 → 1,293,310) | **入れる** |
| **(a') 許容の内側** | 許容を**超えない**幅(割合の ±0.1 ポイントなど) | **入れない。別の箱** |

**(a') は「Core の見逃し」ではない。** 契約が「0.15 ポイントまでは同じ」と決めている範囲である
(人間の決定 (ア))。**分母に入れると、細かく混ぜるほど検出率が下がる指標になる**
([[metric-must-not-fall-when-component-works]] の型)。**件数と中身だけを別の箱で報告する。**

**置換値は、桁を掛けた値で参照一覧に在ってはならない。** 在れば型 5(偶然一致)になり、型 5 は凍結中である。
在る値しか作れない現場は**使わず、件数を記録する。**

### 2-3. 混ぜ方・検出・分母(型 2 から引き継ぐ部分と、引き継がない部分)

**引き継ぐ:**
- **1 つの ZIP に誤りは 1 件だけ**(帰属を曖昧にしない)。
- 混ぜるのは MD&A の textblock の HTML の中だけ。**HTML の中で「数字 + 単位」が一意に見つかること**を条件にする
  (**型 2 より厳しく効く** ― 型 1 は数字を書き換えるので、同じ数字が 2 回出ると**別の出現を壊す**危険がある)。
- **検出 = 混ぜた後の主張が `GROUNDED` ではない。**
- **その位置に主張が 1 件も作られなかった場合は「止めなかった」**(分母に入る)。
- 検出率は **条件付き**(混ぜる前に辿れていた主張に限る)と **定義どおり**(拾われなかった現場も分母)の 2 つを、
  **Clopper-Pearson(正確法)の幅つき**で並べる。
- **不変条件: 混ぜた後の Claim 総数が原本と同じで、GROUNDED がちょうど 1 件だけ減る。**
- 外した件数を 3 つの理由(場所を特定できない / 混ぜる前から辿れていない / 拾われなかった)で数える。

**引き継がない:**
- 現場の定義(§2-1)。型 2 は「単位に兄弟がある数」、型 1 は「GROUNDED な数の主張」である。
- **層ごとの率を主とし、合計は「層の混ぜ方で動く数」と断る。**

## 3. 型 3(原文に無い数)― 「前」が無いので別の形で固定する

### 3-1. 型 2・型 1 から引き継がないもの

**型 3 は文を挿入する。混ぜる前にその主張は存在しない。**

- **③「混ぜる前から辿れていない」は定義しない**(「前」が無い)。
- **②「対応が曖昧」も起きない**(挿入する文は自分で書く)。
- **条件付きの率は定義しない**(「混ぜる前に辿れていた主張」が無い)。**率は 1 つだけである。**

### 3-2. 固定する定義

> **型 3 の分母 = 挿入した文の数。**
> **見出しの数 = 「主張にならなかった件数」**(= 止めなかった)。
> **Core の判定(`POINTER_NOT_FOUND` / `UNVERIFIABLE` / `VALUE_MISMATCH`)は内訳として添えるだけ。**

理由: 存在しない主語について書いた文は**どの事実にも結びつかない**ので、主張になれば必ず非 GROUNDED になる。
**Core 側の率は同語反復である。** 危険なのは逆側 ―
**挿入した偽の文が主張にならず、照合も警告も走らないまま黙って通ること**である。

**上限は 1 書類 6 件である。** `lib/sites.py` の `ABSENT_TEMPLATES["xbrl"]` は 6 主語しかなく、
`build_t3` は 1 件ごとに別の主語と別の値を使う(同じ偽文を 2 回入れると 1 つのことを 2 回試すだけになる)。
**実測の現場 118 / 135 / 136 は「挿入位置 × 雛形」の数であり、混ぜられる件数ではない。**

**不変条件(型 2・型 1 とは別):**

> **混ぜた後の Claim 総数が原本 +1(挿入した文が複数の主張になるなら +k)で、
> かつ他の主張の状態が 1 件も変わらないこと。**

挿入が文の切り方を壊すと他の主張まで動く(括弧内の句点で文を切る既知の癖がある)。**ここは必ず測る。**

### 3-4. 型 3 の読み方を先に固定する

- **止めなかったが 0 件だった場合** = 「分解層は、存在しない主語の文でも主張として拾い、Core が結び付け先なしとして止めた」。
  **これは覆いの試験であり、値の照合の試験ではない。** 結果文書にそう書く。
- **止めなかったが出た場合** = **「偽の文が、照合も警告も走らずに通る穴が実在する」。** 件数と、拾えなかった主語を全部書く。

## 4. 3 つの型を 1 つの表に並べるときの決まり

| 守ること | 理由 |
|---|---|
| **3 つの率を同じ列に並べない。** 型ごとに分母の定義が違う(型 2 は現場、型 1 は GROUNDED な主張、型 3 は挿入した文) | 分母が違う率を並べると、出どころの違いが消える([[compare-rates-need-same-base]]) |
| **型 1 は層ごとの率を主とする。** 合計は「層の混ぜ方で動く数」と断る | 距離を決めるのは混ぜる側であり Core ではない |
| **型 3 の見出しは「主張にならなかった件数」。** Core の判定は内訳 | Core 側は同語反復 |
| **(a') は別の箱。** 「契約が通すと決めている範囲」と書き、検出率の分母に入れない | 細かく混ぜるほど率が下がる指標にしない |
| **見出しに「開発に使った 3 書類」を必ず付ける** | 未使用の書類での値ではない |
| **型 5 は凍結のまま。件数も報告しない** | 道具の不備で未測定 |
| **将棋側は測らない** | 冊子の Claim を Core へ渡す経路が無い(`adapters/shogi/recipes.py:128`) |

## 5. 3 役と範囲

- 計器の実装は**実装担当**。`audit-core/fixtures/xbrl/` に置く(`measure/` は `adapters` を import してはいけない)。
- **独立監査の GO の後、司令塔が 1 回だけ測る。**
- `audit-core/core/py` と `audit-core/adapters` を **1 行も触らない。** 触る必要が出たら止めて人間へ。
- **既存の計器(`tamper_unit.py` / `run_detection_t2.py`)と段 4 の結果は変えない。** 型 1・型 3 は別の入口として足す。
- **費用 0 円。**

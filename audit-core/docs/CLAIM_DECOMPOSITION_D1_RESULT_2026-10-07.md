## 2. D1-8 が外れた意味

Golden が動かなかったのは、**新しい門がどこからも呼ばれていないから**である。
司令塔は「門を足したから記録の面が変わる」と考えたが、足したのは門ではなく**まだ繋がっていない部品**だった。
監査が指摘した「schema が門から呼ばれていない」と、Golden の rc=0 は、**同じ事実を別の計器が独立に指している。**

## 3. 司令塔自身の誤り 2 件(記録に残す)

**誤-1. 正規化を掛けたことを言わずに「完全一致」と報告した。**
照合スクリプトは両辺に `replace(/\s+/g,"")` を掛けていた(両辺に掛けたこと自体は規則どおり)。
しかし**掛けたと書かなかった**。生の文字列では交わり 0 で、計画 §8 の D1-5 が
「0 件なら作成者が実装を見ている疑い」と警告していた不一致を、その正規化が消した。
さらにその正規化は repo のどこにもコミットされておらず、**一回限りの手の実測であって門ではなかった**。
→ 直し (3) で、`gold_01` を実際に読む試験として委託済みの門に固定した。

**誤-2. 封じた 12 欄のうち D1-8 を測らずに監査へ回した。**
監査が「12 欄中 1 欄の実測が引き渡し資料に存在しない」と指摘して初めて測った。
同じ型(書く直前に測り直さない)を繰り返している。

## 4. 独立監査が見つけたもの

1. **schema が門から呼ばれていない。** `loadClaimDecompositionSchema` は試験からしか呼ばれず、
   `form` / `subject` / `value` / `modifiers` / `evidence_pointer` はどの経路でも検査されていなかった。
2. **schema の `form` enum が §11 決-1 と矛盾していた。** 2 語のままで、正本の 4 語に更新されていなかった。
   `gold_01` を通すと 3 件(`derived_value`)が落ちる状態 ― **使ったら正解集合を落とす** schema だった。
3. **被覆の「完全一致」は未公開の正規化を経ていた**(上記 誤-1)。
4. (軽微)`gold_01.json` の原文に禁止語(「有利」「不利」)が含まれる。顧客向け出力ではなく分解層の試験材料であり
   直ちに違反ではないが、D-2 以降で同種の材料を増やすときの参考として記録する。

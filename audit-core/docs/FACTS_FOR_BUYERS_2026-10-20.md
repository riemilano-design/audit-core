## §0 この文書の読み方

- **何であるか**: Audit Core(文の中の数や主張を、原資料の値と照合して一致・値違い・参照先なし・判定不能の 4 状態で返す検証の道具)について、**測った数の一覧**。
- 各行に、記録の path と key(`〔…〕` の印)・再現のコマンド・門の file を付けた。数は文書の字からでなく、記録(`fixtures/**/*.json` など)から写した。
- 印は機械が読む。`python3 measure/facts_check_2026-10-20.py --check` が全部の印を記録と突き合わせて 1 行ずつ OK / NG を返し、門 `tests/measure/test_facts_for_buyers.py` が同じ照合を試験として走らせる。
- 並べ方: §1 に負けた数・外れた予測・0 件・落ちた数を**先頭**に。§2 に領域別の数(勝ちも負けも)。§3 に未解決の穴の今日の状態。§4 に封と結果の対の成績。§5 に記録の無い数(別表)。§6 に資産の数。§7 に再現。
- **何でないか**: 検証の能力を言い切る文書ではない。一般 LLM との優劣を言う文書でもない(§1 の先頭は、一般 LLM が当てた行で Core が保留した行)。材料は少なく、分母が小さい行が多い。
- QWED との関係は「計算 対 出所」とだけ書く。QWED が見るのは値の計算で、こちらが見るのは値の出どころ(どの fact か)。
- 門が縛るのは、数の欄と印の 1 対 1 と、印と記録の一致である。結論の言い回し(例: 「半分」)は門の外にある。
- 「0 件」と書いた行は、先に記録の key の取り違えを疑い、数えた対象と分母を同じ行に書いた。測っていない数は書かない。

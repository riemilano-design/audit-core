### §3-3 標本の型と、S-8 が割れたこと

標本は A の VALUE_MISMATCH 1,898 行から封 §0-2 の 7 の規則で引いた 120 行で、84 本にまたがる。司令塔(AI の席)が 1 行ずつ、文・span・結んだ先・値を書いた紙(scratchpad。追跡していない)で読んだ。**人は読んでいない。盲検ではない**(封の予測を知ったうえで付けた)。【門なし】

- **割れた所**: 封の (イ) の字は「内訳・一部分・文の中で計算した率や差を、**全体の fact と比べた**」。司令塔は読むあいだ、(イ) を次の 2 つの形にも付けていた。型を付け終えてから (イ) の 21 行を読み直し、細目を補足の記録に残した(型の記録は変えていない)。
  - イ1 字のとおり: 5 行。
  - イ2 向きが逆(全体・合計の数や率を、同じ文に原因として出た内訳の要素の fact と比べた): 13 行。部分と全体の取り違えではあるが、封の字の向きではない。
  - イ3 内訳の数を、となりの内訳や別の表の要素の fact と比べた: 3 行。全体は出てこない。
- **3 通りの数**: 型の記録のまま 79 行(65.8%)= 幅の中。イ1 と イ2 まで(部分と全体の取り違え)なら 76 行(63.3%)= 幅の外。イ1 だけ(封の字のとおり)なら 63 行(52.5%)= 幅の外。(ア) 58 にも封の字より広く読んだ行が含まれる(§3-4。行数は細目に残していない)ので、63 は封の字のとおりの下限ではない。

### §3-4 封に無い決め(実装の席・独立監査・司令塔)

実装の席が封の字を 1 通りに読んだ所(script と封の門 `ea3b036c` に在る。結果を見る前):

1. 包み直しで iXBRL を入れる順は、元の ZIP の member 名の順。
2. 「file 名」は member 名の最後の `/` より後。新しい名前がぶつかったら止める(起きた数 0)。
3. 様式の種類はサマリーの file 名の 8 字。1 本に 2 種類以上在れば止める(起きた数 0)。
4. 「claim が 0 の本」「GROUNDED が 0 の本」「VALUE_MISMATCH が 1 以上の本」の分母は切れた本。

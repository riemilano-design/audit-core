### 1-1. 機構は 2 つ重なっている(どちらも接続部分 `adapters/xbrl` にある)

**(1) 主語が取れない数の主張が、どの JPY の事実でもよいとして総当たりする。**
`recipes.py:209`(`_direct_value_claim`)は、主語が結び付かなかった場合に
**全 JPY 事実**から値の合う候補を探し、ヒットした要素名が 1 系統なら
`reason="value_only(no subject)"` のまま **GROUNDED** にする。7 件はすべて `subject=None` だった。

**(2) 値の一致の判定が、片側に 1 単位ぶん広い。**
`comparators.py:_match_value` / `vocabulary.py:match_value` は

```
round    : |事実 − 主張| <= 単位/2
truncate : 0 <= 事実 − 主張 < 単位        ← 片側にまるまる 1 単位
abs+...  : 上の 2 つを、両辺の符号を外して もう一度
```

を順に試し、**最初に当たった経路で「一致」とする。** つまり実効の許容は
**−単位/2 〜 +単位**(百万円なら −500,000 〜 +999,999 円)で、**さらに符号違いも通る。**
これは本文が百万円未満を切り捨てて書く慣行への対応であり、**規約として在るもの**だが、
**片側に 1 単位ぶん広く、符号も問わない**ため、偶然一致の窓が大きい。

7 件の内訳(司令塔が `match_value` を直接呼んで経路を取った):
**丸めの経路 3 件(うち符号を外した経路 2 件)・切り捨ての経路 4 件。**
(独立監査は「丸め 2・切り捨て 5」と報告した。差は `44百万円` の件を
どちらに数えるかで、司令塔は `match_value` の戻り値そのものを採った。**件数の合計は 7 で一致している。**)

### 1-2. 混入実験の中だけの話ではない ― 原本に 11 件ある

**混ぜていない原本で測った: GROUNDED な数の主張 149 件のうち 11 件(7.4%)が `subject=None`**
(`S100Z4Q1` 1・`S100Z4B6` 5・`S100YMFV` 5。id は N042 / N052・N065・N073・N080・N081 / N035・N039・N049・N053・N055)。
司令塔と独立監査が別々に再現した。

**言えることと、まだ言えないことを分ける**(人間の指示 2026-10-08):

- **確実に言えること**: **`subject=None` のまま GROUNDED になっている数の主張が 11 件存在する。**
- **混入実験で言えること**: **挿入した架空の主張 17 件のうち 7 件が、その経路によって GROUNDED になった。**
- **まだ言えないこと**: **11 件すべてが誤った束縛だったとは言わない。** 1 件ずつ読んで確かめていない。

**この 2 つは別の数として残す。** 誤停止の基準線(正しい文 91 件のうち 19 件が止まった)と
60 件の人の確認は、**この経路がある状態のパイプラインを測っていた。**

### 1-3. これは Core の欠陥ではない。接続部分の欠陥である

**Core(`audit_core.verify_all`・comparators)は、渡された契約(pointer・comparator・params)どおりに照合しているだけ**である。
**「主語の無い主張をどの事実にでも当ててよい」という判断と、「片側に 1 単位広い許容」という規約は、
どちらも `adapters/xbrl`(`recipes.py` / `comparators.py` / `vocabulary.py`)に在る。**
独立監査も同じ結論に達した。

**直すには `adapters/xbrl` を変える必要がある。** これは判定結果・閾値を変える「判断的知識」なので、
**人間の決定が要る。この封では直していない**(司令塔・実装担当・監査のいずれも 1 行も触っていない。
束ねた sha `950ebc91…0cda` 不変)。

| | `S100Z4Q1` | `S100Z4B6` | `S100YMFV` | 合計 |

**主張になった 17 件の判定: GROUNDED 7・UNVERIFIABLE 5・VALUE_MISMATCH 3・POINTER_NOT_FOUND 2。**

### 3-0. 型 3 は 2 段に分けて記録する(人間の決定 2026-10-08)

**封じた F-2(「主張にならなかった件数」)は変えない。予測は当たりのまま残す。**
そのうえで、**今回見つかった欠陥を別の測定軸として追加する。**

```
型 3(挿入した偽の文 18 件)
│
├─ 主張にならなかった ............ 0 件   ← 覆いの穴(既存の測定・封じた F-2)
│
└─ 主張になった .................. 17 件
     │
     ├─ PNF / UNVERIFIABLE / VALUE_MISMATCH ... 10 件(止まった)
     │
     └─ **GROUNDED ................ 7 件**   ← **追加測定。本当に危険な層**
```

| 軸 | 数 | 意味 |
|---|---|---|
| **既存**: 偽の文が主張にならなかった件数 | **0 / 18** | 分解の覆いに穴は無かった |
| **追加**: 偽の文が主張になった後、偽のまま GROUNDED になった件数 | **7 / 17(41%)** | **束縛が偽文を「事実」にした** |

**F-2 の当たりは取り消さない。** 正しい記録は
**「F-2 は予測上ヒットした。しかし別の測定軸から、偽の主張が GROUNDED になるという重大な穴が発見された」**である。

**「主張にならなければ安全」という見出しだけでは足りなかった。**
実際には **「主張になった偽文を、束縛が誤って事実にしてしまう」**という、より危険な層が在った。
**この層は、今回の計器を入れたから見えた。**

### 3-1. 不変条件の 1 件(`S100YMFV` 位置 1655)

生の出力は `invariant_total_ok=False` / `other_claims_unchanged=False` だが、
**独立監査が全件の総当たりで「挿入した 1 件を除くと残り 140 件が内容・順序とも完全に一致する」ことを確認した。**
つまり**他の主張は動いていない。** 生の出力が False になったのは、
挿入した主張の同定が値の衝突で空になり、計器が「どれを除いて比べるべきか」を決められなかったためで、
**こちら側の限界である。両方書く。**

## 5. 限界(結果文書に必ず書くこととして独立監査が挙げたもの)

1. **直していない。** §1 の欠陥の修正には `adapters/xbrl` の変更が必要である。
   **人間は (ア)「主語の無い数の主張は束縛しない(`UNVERIFIABLE` にする)」を採ると決めた**(2026-10-08)。
   **ただし順番は「監査完了 → 現状値を固定 → 修正方針を新たに封印 → 実装」であり、この文書は「現状値の固定」である。**
   **ここに書いた数はすべて「直す前の数」である。**
   (イ)符号の一致を要求する案は**不採用** ― 7 件は止まるが、**符号まで一致する無関係な事実があれば通り、
   「主語が無い」という根本の条件が残る。** (ウ)限界として放置する案も**不採用** ―
   営業資料以前に、**Core へ渡す束縛の品質基準として許容できない**(人間の判断)。
2. **`S100Z4Q1` は 50 件のうち 42 件が「混ぜられない書き方」で落ちた。** 漢数字混じりの金額が多い書類では
   型 1 をほとんど混ぜられない。**書類の書き方で母数が大きく変わる。**
3. **測ったのは開発に使った 3 書類である。** 未使用の書類での値ではない。
4. **型 1 の合計の率(94.3%)は層の混ぜ方で動く。** 層ごとの率を読むこと。
5. **(a') の 17/17 は「契約が通すと決めている範囲」であり、見逃しではない。** 検出率の分母に入れていない。
6. **`main()` の段は単体試験の外にある。** 独立監査の変異 M11 ―
   **抽選の種から書類名を外すと、見出しの数が 7/17(41%)から 8/17(47%)に静かに動き、41 本の試験は全部緑のまま**だった
   (**実物のコードは正しく `種 + ":" + 書類名` を使っており、この欠陥は実在しない**)。
   **この計器に今後手を入れるとき、回帰を捕まえる力が弱い。** 2 回目の監査が段 4 で差し戻したのと同じ型である。
7. 独立監査の変異 11 本のうち 6 本が赤、2 本(M3・M5)は実物では到達しない等価変異、
   3 本(M6・M10・M11)が 6 の構造的な穴を指している。
8. **型 5 は凍結のまま。** 期間・母集団の入れ替え 344 件は人が作るもので未測定。将棋側は経路が無く未測定。
9. 試験の本数: `python3 -m unittest discover -s tests -t .` で **490 本 OK**、
   `python3 -m pytest -q` で **586 passed**。差 96 本は `measure/tests/`(96 本)を pytest が拾うため
   (490 + 96 = 586、skip・xfail は 0)。**本数には使ったコマンドを添える。**

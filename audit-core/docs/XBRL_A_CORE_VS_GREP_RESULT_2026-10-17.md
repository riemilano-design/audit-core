# 第 3 層 解釈(**ここから先は解釈である**)

## §3-1 言えること

- **値が一致する fact を返すだけの検索は、参照先を 1 件も当てられなかった**(0/64)。
  **口を開いた 17 件は全部、値の持ち主を根拠として採っていた。**
- **Core は、値が合わないことを検出して止めながら、本来の参照先を 71.9% で名指した。**
  **これは単純な検索には構造的にできない**(止めるという状態が無く、
  値の持ち主以外を名指す手段が無い)。
- **検索を強くすると誤りを通す方向に悪くなる**(D″)。
  **「買い手が grep を少し強くすれば代替できる」という筋は、この標本では支持されない。**

## §3-2 言えないこと(**人間の指摘をそのまま置く**)

1. **これは Core の照合機能の切り分けであって、
   LLM + Core という製品全体の優位性の証明ではない。**
2. **Core 単体の差が小さくても大きくても、LLM との相互補完は別の実験**である。
   今回 Core 単体で差が出たことは、**組み合わせを試す根拠を強める**が、
   **組み合わせの性能を測ったわけではない。**
3. **使用済みの 8 書類である。**未使用データでの再現性は測っていない。
4. **T5 の正解は「改変前の文で値が一意に当たった主張」に偏る。**
   さらに **正解そのものが誤りうる** ― `Core-P` の 18 件の食い違いのうち、
   私が目で見た 3 件は**正解側が怪しい**(文の主題が `純資産合計` の行で、
   正解は `totalchangesofitemsduringtheperiod`、Core は `netassets`)。
   **数は厳しいまま置き、食い違った対を記録に全部残した**(1 件ずつ読める)。
5. **人工の誤りである。**実際の書類で起きる誤りではない。
6. **D′・D″ には改変後の値を構成から直接渡した**(文から数を拾う手間を与えていない)。
   **値検索に有利な側に倒してある。**
7. **既存製品との比較・売却価値は測れない。**

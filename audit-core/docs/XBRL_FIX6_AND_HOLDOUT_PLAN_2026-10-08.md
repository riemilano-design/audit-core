## 1. 6 つ目の直し ― 括弧内の前期の方向語

### 直すこと

文字の主張(向きの語)が**丸括弧の中にあり、その括弧が「前連結会計年度は」を含む**とき、
当期と前期の対ではなく**前期と前々期の対**に結ぶ。数の主張の側には同じ扱いが既にある
(`_direct_value_claim` の `prev_year_phrase`)。**その文字版が無いのが `T008`・`T022` の誤りの機構である。**

### 当て所

`recipes.py: _build_raw_text_claims` の主語ありの平の枝(`elif subj:`)。新しいフラグ
**`text_prior_year_paren`(既定 `False`)**。括弧の判定は**文字の窓ではなく括弧の深さ**で行う
(「前連結会計年度は」+ 金額で 16 字になり、数の側の窓 15 字では届かないため)。
前期・前々期の対が引けないときの理由は、**数の側と同じ名前 `no_element(no prior2 for prior-year diff)`**
を使う(同じ原因なので登録簿は 29 のまま増やさない)。

適用するのは**平の枝だけ**。CF 流量項目の枝(当期 1 本)と「支出」系の枝には掛けない
― 開発 3 書類にその形の実例が 0 件で、**測れないものを作らない**ため。これは限界として書く。

## 2. 未使用の書類での測り方(人間の指示 4)

**2026-10-08 の追加の申し送りにより、これは EDINET の API キーが入るまで保留である。**
キーの取得は人が行う。キーが入ったら、**セッション A の取得の道具
`audit-core/measure/fetch_material.py`** で「接続部分の開発に使っていない書類」を取る。
**キーの値には触れず、環境変数 `EDINET_API_KEY` から読む形**で呼ぶ(値を文書・ログ・
コミットに書かない。既存の `adapters/xbrl/edinet.py: fetch` も環境変数の**名前**しか持たない)。

### 手順(1 コマンドで回せるようにしておく)

```
# 1) 人がキーを環境に入れる(値はセッションに渡さない)
#    export EDINET_API_KEY=...
# 2) セッション A の道具で、接続部分の開発に使っていない書類を取る
python3 audit-core/measure/fetch_material.py …        # 置き場は ~/.cache/audit-core/edinet/<docID>.zip
# 3) P7 と P8 の両方を 1 回の実行で測る
python3 fixtures/xbrl/measure_xbrl_fix5_2026-10-08.py --doc <docID> --out fixtures/xbrl
```

**開発に使っていない書類の条件**: `S100Z4Q1`・`S100Z4B6`・`S100YMFV` のどれでもないこと。
この 3 件は接続部分(`adapters/xbrl`)の設計・語彙・境界を決めるのに使った。

計測 script は **`base`(= `P7`)と `all`(= `P8`)を同じ 1 回の実行で両方回す**ので、
`P7` と `P8` の両方で測るという指示はこのままで満たされる(途中の 1 つずつの構成も同時に出る)。
**`fix6` のフラグを足したら、構成の表に `fix6_prior_paren` と `all6` を加える**(下記 §3)。

### 出すもの(開発に使った書類と同じ形)

1. `P7` と `P8` の **主張の総数・止まった件数・率(分母を 2 通り)**
2. **項目ごと**(1a/1b/2/3/4/5/6 を 1 つずつ + 全部)の件数
3. **新しく止まるようになったもの・新しく通るようになったもの・主張でなくなったものを全件列挙**
4. **決まった丸め方と、その証拠(R と T)**
5. **誤停止(直す前は `GROUNDED` で、直した後に止まったもの)を全件、原文つきで**

### holdout に対する予測(開発 3 書類の外に出る予測。**書類が届く前に封じる**)

| 欄 | 予測 | 根拠(開発 3 書類の値) |
|---|---|---|
| 直し 5 が落とす主張 | **総数の 5 〜 25%** | 6/91 = 6.6%・28/133 = 21%・27/140 = 19% |
| 止まった率の下がり方 | **−5 〜 −15 ポイント** | −6.9・−11.0・−13.5 |
| **新しく止まるようになったもの(`GROUNDED` → 停止)** | **0 〜 2 件** | 1・0・0 |
| 新しく通るようになったもの | **0 〜 4 件** | 3・0・2 |
| **誤停止(正しい主張を止めた件数)** | **0 件** | 0・0・0(1b を狭めた後) |
| 決まった丸め方 | `truncate` か `round` のどちらか、**証拠 R = 0** | R=0/T=19・R=0/T=0・R=0/T=21 |
| 直し 6 の対象(括弧内の前期の方向語) | **0 〜 3 件** | 3・0・0 |
| 直し 3 が捕まえる主張 | **0 〜 4 件** | 2・2・0 |
| 直し 4 が直す主張 | **0 〜 3 件** | 3(うち state 2)・0・3(うち state 2) |
| 直し 1a が動かす行 | **0 〜 6 件** | 6・0・3 |

**外れたらその旨を書く。幅を外した欄は「開発 3 書類が狭すぎた」証拠として扱う。**
**とくに「誤停止 0 件」が外れたら、それは設計の欠陥であり、直してから測り直す**(1b で一度やったのと同じ扱い)。

### 1 書類では決まらないこと(先に書く)

holdout **1 書類で出る数は、依然として 1 標本である。** 止まった率の幅は 100 件前後で ±8 ポイント程度あり、
**「効果の本当の値」は 1 書類では ±1 桁の精度しか出ない。** 必要なのは書類の本数であって、
1 書類を holdout にしたことで値が確定するわけではない ― これは holdout を測る前に書いておく。

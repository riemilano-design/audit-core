# 封: engine の inline XBRL の読み取りが「自己閉じの空の欄」を次の fact まで読む欠陥は、過去の便の数にどれだけ効いたか(便 NR)― 2026-11-17

便 PS(結果 `docs/XBRL_PLAN_SOURCE_RESULT_2026-11-17.md`。commit 8795b49c)の監査で見つかった engine の読み取りの欠陥について、**engine を直す前に**、過去の便の数への効きを `measure/` だけで数える封。取得 0・0 USD・engine(`core/`・`adapters/`)は 0 行・LLM の席を呼ばない・新しい読み 0。script も記録もまだ無い。この封の後に engine を直すかどうかは、この便の数を人間に報告した後の別の封で決める。

## §0 欠陥(分かっていること)

`adapters/xbrl/instance.py` の inline XBRL の経路(ZIP の `XBRL/PublicDoc/` に `.xbrl` が無く `.htm` だけが在るとき)は、`<ix:nonFraction 属性>中身</ix:nonFraction>` の形を正規表現で拾う。属性の並びの最後が `/` の**自己閉じの tag**(値が空の欄。`xsi:nil="true"` を持つ)も始まりの tag と読むので、次の fact の終わりの tag までを 1 つの fact として拾う。作り物の例:

```
<ix:nonFraction name="ex:A" contextRef="Prior" unitRef="JPY" scale="6" xsi:nil="true"/> … <ix:nonFraction name="ex:A" contextRef="Current" unitRef="JPY" scale="6">120</ix:nonFraction>
```

本当は「Prior の ex:A は空・Current の ex:A は 120 百万」。engine は「**Prior の ex:A が 120 百万**」という fact を 1 つ作り(以下 **作られた fact**)、「Current の ex:A」は読まない(以下 **消えた fact**)。

司令塔がこの封を書く前に見た数: 便 PS の記録に在る数(TSS の 400 本で、短信の本体の自己閉じ 5,588 個・192 本、サマリー 4,418 個・202 本)と、手元の cache の ZIP の入れ物の数(下の §1)。**判定(行の state)が変わる数は 1 つも見ていない。**

## §1 対象と分母

1. **入れ物の棚卸し。** `~/.cache/audit-core/` の下の ZIP を全部開き、engine の `load_instance` がどちらの経路を通るか(`.xbrl` の経路/`.htm` の経路/どちらの file も `XBRL/PublicDoc/` に無い)を folder ごとに数える。司令塔が封の前に数えた値: `edinet` 281・`edinet-demo-cabocia` 3・`edinet-fresh-2026-10-21` 40・`edinet-prior-2026-11-02` 94 は全部 `.xbrl` の経路。`tanshin-self-2026-11-14` 400 と `tanshin-2026-11-09` 17 と `sheet` 10 は、そのままではどちらの file も無い(便の script が包み直して engine に渡す)。script はこの数を数え直し、違えば止まる。
2. **主の対象は便 TSS の 400 本**(母集団の表 `fixtures/xbrl/tanshin_self/population_2026-11-14.json`・記録 `fixtures/xbrl/tanshin_self/states_2026-11-14.json`)。TSS の script の `cut`・`wrap` を呼んで包み、engine に渡した形そのもの(`.htm` の経路)で数える。分母は、切り出せた本と、その行の全部(P33E)。
3. **便 2026-11-09 の短信(`fixtures/xbrl/tanshin/states_2026-11-09.json`)** は、その script が engine に渡す ZIP がどちらの経路を通るかを数えるだけ(`.htm` の経路の本が在れば、その本の自己閉じの数も)。判定の数え直しはしない。
4. **除外(測らない、と書く)**: TSS の注入の便(1b)・near の記録・型の読みの記録・英文短信の側(`sales/`。別のセッション)・EDINET の便(`.xbrl` の経路だけを通る、を 1 の数で示すにとどめる)。

## §2 数え方

### §2-1 正しい読み(measure/ の中の独立の読み)

engine を呼ばずに、包んだ ZIP の `.htm` を自分で読む。規則は 1 つ: **属性の並びが `/` で終わる `<ix:nonFraction …/>` は「空の欄」で、fact を作らない。** それ以外の `<ix:nonFraction 属性>中身</ix:nonFraction>` は engine と同じ式で値にする(tag を消す・`,` を消す・`-?\d+(\.\d+)?` に合えば `float × 10^scale`・`sign="-"` なら負)。この独立の読みの fact の列(要素名・context・値の多重集合)が、**§2-2 の直した入力を engine に渡した結果の fact の列と同じこと**を script が本ごとに確かめる(違えば止まる。違いが出たら、それは自己閉じ以外の読み取りの差なので、数を出さずに報告する)。

### §2-2 直した入力

TSS の `wrap` が包んだ ZIP の `XBRL/PublicDoc/` の下の `.htm` の字から、正規表現 `<ix:nonFraction[^>]*/>` に当たる所を全部消す。ほかは 1 byte も変えない。当たる例: 上の §0 の 1 つ目の tag。当たらない例: `<ix:nonFraction name="ex:A" …>120</ix:nonFraction>`(`/>` で終わらない)。**engine は変えない。変えるのは渡す入力だけ。**

### §2-3 fact の差(本ごと・全体)

「そのまま」と「直した入力」で `load_instance` の fact の列(要素名・context・単位・decimals・値)を多重集合として比べる。

- **作られた fact** = そのままに在って直した入力に無い fact。
- **消えた fact** = 直した入力に在ってそのままに無い fact。
- 自己閉じの数・自己閉じを 1 つ以上持つ本の数・作られた fact の数・消えた fact の数・どちらかが 1 つ以上の本の数。
- 作られた fact のうち、**context が違うだけで同じ要素名の fact が消えた fact の側に在るもの**(上の例の形 = 期の取り違え)の数。

### §2-4 判定の差(主の数)

400 本を「そのまま」と「直した入力」で、TSS と同じ呼び方(`profile_rows`・P33E)に通す。「そのまま」の行が TSS の記録の行と本ごとに全部同じことを先に確かめる(違えば止まる)。行の対応は (本の #, 文の番号, 位置)。claim は文から作るので、行の集合は 2 つで同じはず(違えば止まって報告)。

- state の移り変わりの表(そのまま × 直した入力。全部の state の組)。
- **state が変わった行の数**と、変わった行を持つ本の数。
- state は同じで **reason だけ変わった行**の数(`RUN.safe_reason` を通した字で)。
- TSS の結果の文書が外に言っている頭の数(台帳の TSS の行が持つ数のうち states の記録から出るもの)を、直した入力で数え直した値。どの数を数え直すかは、script が台帳の行でなく TSS の記録の集計の鍵を全部並べて、鍵ごとに「そのまま・直した入力・差」を出す。
- 「結べて値が合った」state の行のうち、**そのままでは合い、直した入力では合わなくなった行**(作られた fact に頼っていた一致)の数。逆(直した入力でだけ合う行)の数。

### §2-5 記録に持たないもの

文・値・要素名・context の字・会社名・証券コード・docID。本は # で指す。

## §4 限界(先に書く)

1. 数えるのは states(判定)の差だけ。型の読み(AI の席 1 席)・注入・near は数え直さない。
2. 「直した入力」は司令塔が決めた 1 つの直し方(自己閉じを消す)で、engine の直しそのものではない。engine の直しの封は別に書き、そこで同じ数が出ることを確かめる。
3. `.htm` の経路には、ほかの読み取りの欠陥(入れ子・`ix:continuation`・負の表記の format)が在るかもしれない。この便は自己閉じだけを見る。
4. state が変わらなくても、engine が選んだ fact が変わっているかもしれない。reason の字の差でしか見えない。
5. 英文短信の側の数への効きは測らない(別のセッションに知らせる)。

# 封: 便をまたいだ集計 AT ― 「値が違う」と「結べたが別のもの」の行のうち、数の身元の 5 つの属性の取り違えに写る行の割合を、既に在る型の読みの記録だけで数える ― 取得 0・0 USD・engine は 0 行・新しい読み 0 ― 2026-11-17

人間の問い(2026-11-16):「これまでの全てのテストをふまえて、あらゆる文書に対応できる仕組みへの共通点やヒントは見つけられない?」。司令塔は「偽の結びと偽の警報の多くは、数の身元(項目・期・範囲・単位・1 株あたりか)の取り違えに見える」と答え、それを**測っていない見立て**と断ったうえで、既に在る記録だけで数える便を案に出した。人間の言葉(同日)「寝るから君に任せる進めて」の下で、司令塔がこの便を封じる。

この便は**新しい材料を読まない。新しい型も付けない。** 過去の 3 つの便(監査報告書の KAM・有報の 3 つの節 YS・短信の概況の文 TSS)で AI の席が付けた型の字を、この封の表(§2)で属性に写して数えるだけ。

この便で言えるようになること(結果が出たあと):「3 つの便それぞれで、『値が違う』と言った行(読んだもの)のうち、この封の写し方で 5 つの属性の取り違えに写る行の割合」と「属性の外に落ちた行の型の内訳」。**言えないこと**: 属性を engine に入れたら警報が減ること(測っていない)・型の読みの正しさ(AI の席 1 席・盲検でない・人は読んでいない)・誤りを通す率・3 つの便の外の文書での割合。

## §2 写しの表(型の字 → 属性。この封で固定する)

属性は 5 つ: **項目**(何の数か。定義を含む)・**期**・**範囲**(部分か全体か、連結か単体か)・**単位**(単位・丸めの桁)・**1 株あたり**(1 株あたりの数か総額か)。

### §2-1 「値が違う」の行(V)

| 便 | 型・細目 | 写す先 | 理由(字) |
|---|---|---|---|
| KAM・YS | ア | 範囲 | 一部分の数を全体の fact と比べた |
| KAM・YS | ウ | 範囲 | 連結と単体の取り違え |
| KAM・YS | エ | 期 | 期の取り違え |
| KAM・YS | オ | 項目 | 定義の違い |
| KAM・YS | カ | 単位 | 丸め・単位(細目が無いので全部を内に写す。§5) |
| KAM・YS | イ | **外(見積り・計画)** | 実績の数でない。5 つの属性に無い |
| KAM・YS | キ | **外(符号)** | 5 つの属性に無い |
| KAM・YS | ケ | **外(分けられない)** | |

| TSS | ア | 範囲 | セグメント等の数を全社の fact と比べた |

- 当たる例: KAM の V の行で型が ウ → 範囲。TSS の標本の行で型が イ・細目が イ3 → 項目。

### §2-2 「結べた」の行(G。KAM と YS だけ)

- a → 合う(偽の結びでない)。b → 「違うもの」の字で写す: 項目 → 項目、範囲 → 範囲、側 → 範囲、期 → 期。c → 外(分けられない)。
- **b は語彙の作りで全部が属性の内に入る**(b の字が「項目・範囲・側・期のどれかが違う」)。だから G の側では「属性で説明できる割合」は**反証できない**。G で数えるのは、b の属性ごとの内訳と、(b + c) に対する c の割合だけ。

## §3 数えるもの(分母を字で書く)

1. **V の率(便ごと。主)**: 分子 = §2-1 で属性の内に写った行。分母 = その便の V の読んだ行 − ク の行。KAM は V 連結と V 単体を足した全部の行(標本でない)。YS は 3 つの節の全部の行。TSS は標本 120(母 1898)。
2. **V の率の 2 本目**: 分母に ク を入れた率(ク は外として)。
3. **内訳**: 便ごとに、属性ごとの行の数・外の理由ごとの行の数。KAM は連結・単体別、YS は節別も。
4. **並べるだけ**: TSS の近い行の型(あ・い・う・え・お)の数。率に入れない。
5. **G**: KAM(連結は標本 60 / 母 136、単体は全部)と YS(節別)で、a・b・c の数、b の属性ごとの数、c /(b + c)。
6. **3 つの便を足した数は主にしない。** 引き方が違う(全部の行と標本)。参考として行の単純な合計の率を 1 行だけ書き、「母集団の率ではない」と添える。
7. 本の数: 便ごとに、V の属性の内の行を持つ本の数と、いちばん多い 1 本が持つ行の数(片寄りを見る)。

記録は `fixtures/xbrl/attr_tally/tally_2026-11-17.json` の 1 つ。行は持たず数だけ(本の # も書かない)。script は `measure/xbrl_attr_tally_2026-11-17.py`。

## §5 限界(結果の文書にも写す)

1. 型は**AI の席 1 席(司令塔)が付けた**。盲検でなく、人は読んでいない。この便はその字を数え直すだけで、型の正しさは 1 つも確かめない。
2. 写しは**あと知恵**。YS と TSS の集計を見たあとに書いた。たとえば「見積り・計画」を 6 つ目の属性と呼べば率は上がり、KAM・YS の カ を外に写せば下がる。結果の文書には、外の理由ごとの数を必ず並べる。
3. 語彙が便で違う。TSS は細目で割ったが KAM・YS には細目が無い。同じ字(カ・オ)が同じ中身とは限らない。
4. 行が少ない(YS の V は 18 行、KAM の V は 37 行)。1〜2 行で率が数ポイント動く。
5. 「属性の取り違えに写る」は「属性を条件に入れれば止まる」ではない。engine は既に期と側の一部を見ている。属性を足したときに正しい結びがどれだけ減るかは測っていない。
6. G の側は反証できない作り(§2-2)。
7. 3 つの便は有報・監査報告書・短信で、上場会社の開示だけ。「あらゆる文書」の根拠にはならない。

## 2. どう取るか ― `--pick 5`(同じ窓・同じ種)

`fetch_material.py` は `random.Random("<種>|edinet-pick|<from>|<to>").sample(rows, k)` で選ぶ。
**`rows` の並びは `(日付, docID)` で決まっており、k を変えても選ばれる index の列は前方一致する。**
これは実装の細部に頼る話なので**推測せず実測した**(候補 183 件・この種の文字列):

```
k=1 -> [31]
k=2 -> [31, 152]
k=4 -> [31, 152, 119, 3]
k=5 -> [31, 152, 119, 3, 34]
前方一致: True
```

**index 31 がすでに取った `S100Z37J`** である(`--pick 1` で取れたものがこれ)。
だから**同じ窓・同じ種で `--pick 5`** を回せば、

- 1 件目 = `S100Z37J`(**再取得。sha が `d8337184477d6554…` と一致することの照合になる**)
- **2〜5 件目 = 新しい 4 件**

が取れる。**窓も種も変えない**ので、選び方は最初と同じ 1 つの封に従っている。

### なぜ `ADAPTER_USED` に `S100Z37J` を足して `--pick 4` にしないのか

それが本来の直し方である(道具の規約は「`ADAPTER_USED` は選ばない」)。
**だが `fetch_material.py` は本線の作業ツリー(`/Users/midoriko/Desktop/sgogi-coach`)に在り、
このブランチには存在しない。** 共有の木をこの席から書き換えるのは、
並行する席の作業を壊す型の事故なので**しない。**

**本線の担当へ申し送り:** `audit-core/measure/fetch_material.py` の
`ADAPTER_USED = {"S100Z4Q1", "S100Z4B6", "S100YMFV"}` に `"S100Z37J"` を足すこと。
足すと候補が 182 件になり index の対応が変わるので、**足すのは今回の取得の後**にする。

### 取得が封と合っているかの確かめ方(出力を見るだけで分かる)

1. `candidates: 183` であること。**183 でなければ index の対応が変わる**(EDINET に遅れて
   提出が足された等)。その場合は 1 件目が `S100Z37J` にならないので、出力で分かる。
2. `fetched S100Z37J` が **1 件目**に出て、**sha256 が `d8337184477d6554` で始まる**こと。
3. 残りの 4 件が `S100Z4Q1`・`S100Z4B6`・`S100YMFV`・`S100Z37J` のどれでもないこと。

## 3. **4 件の使い分けを、取る前に決める**(ここが封の本体)

**種が返す順**(`--pick 5` の 2 件目から 5 件目、= index `152`・`119`・`3`・`34` の順)で、

| 種の順 | index | 役割 |
|---|---|---|
| 1 番目 | **152** | **直しの効果を測る 2 件のうちの 1 件** |
| 2 番目 | **119** | **直しの効果を測る 2 件のうちの 1 件** |
| 3 番目 | **3** | **取り置き。資料用の最終の数字まで中身を見ない・測らない** |
| 4 番目 | **34** | **取り置き。同じ** |

**この割り当ては手で選んでいない。** 私が知っているのは index の数だけで、
**どの index がどの会社かは知らない**(候補の一覧は 183 件のうち先頭 40 件しか印字されていない)。

### 取り置きの 2 件に対してやらないこと(字で書く)

- ZIP を開かない・`load_instance` を呼ばない・MD&A を読まない
- 計測 script を回さない(`measure_xbrl_fix5_<docID>.json` を作らない)
- 主張の数・止まった件数・語彙の数を**1 つも**見ない
- **記録するのは docID・社名・期末・バイト数・sha256 だけ**

**「資料用の最終の数字」とは、`P13`(または主語の規則を直した版)を正本として外に出すときの数**である。
そのときに初めてこの 2 件を測る。**それより前に 1 回でも測ったら、取り置きの意味は消える** ―
消えたらそう書いて、取り置きではなく開発用に移す。

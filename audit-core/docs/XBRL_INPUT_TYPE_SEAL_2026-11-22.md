### 型(第 0 版。書類ごとに JSON 1 つ)

- **書類の決め**: 提出者の識別子(字)と識別子の scheme(字)・当期の始まりの日・当期の終わりの日・提出日。
  - 当期の終わりの日 = 文脈の `id` が `CurrentYearInstant` で始まる定義の時点の日。当期の始まりの日 = `id` が `CurrentYearDuration` で始まる定義の始まりの日。提出日 = `id` が `FilingDateInstant` で始まる定義の時点の日。それぞれ 1 通りに決まらなければ、その書類は「断った」(理由を書く)。
- **型の行**(1 行 = 1 つの数か 1 つの文。鍵 = 種類・科目コード・期間・対象・次元の組。同じ鍵の fact は 1 行にまとめる):
  1. 種類: `数` か `文`。
  2. 科目コード: 対応表のコード(字)。
  3. 期間: 時点なら日 1 つ。期間なら始まりの日と終わりの日。
  4. 対象: `個別` か `既定`。その fact の文脈が軸 `jppfs_cor:ConsolidatedOrNonConsolidatedAxis` に member `jppfs_cor:NonConsolidatedMember` を持てば `個別`、その軸を持たなければ `既定`。
  5. 次元: (軸のコード, member のコード) の組の集まり(4. の軸を除く。軸のコードの昇順)。
  6. 値(`数` だけ): `無い`(空の fact)か、符号つきの本当の大きさの 10 進の字(表示の字の数 × 10 の `scale` 乗。`sign` が `-` なら頭に `-`。**負の印つきの 0 は `-0` と書く**)。
  7. 単位(`数` だけ): `通貨:XXX`(measure が `iso4217:XXX` 1 つ)・`株`(`xbrli:shares` 1 つ)・`純数`(`xbrli:pure` 1 つ)・`通貨:XXX÷株`(分子 `iso4217:XXX` 1 つ・分母 `xbrli:shares` 1 つ)の 4 つの形。
  8. 表示の位(`数` で値が在る行だけ): 整数(`scale`。属性が無ければ 0)。
  9. 精度(`数` で値が在る行だけ): 整数(`decimals`)。
- **対応表**(書類ごとに JSON 1 つ。型とは別の file): 科目コード → 要素の名・軸のコード → 軸の名・member のコード → member の名。コードは、書類に現れた名を種類(科目・軸・member)ごとに字の昇順に並べた番号から作る字(`K0001`・`A0001`・`M0001` の形)。**対応表は答えから作る 1 対 1 の表で、この便では作る手間も正しさも測らない。**
- **持ち込み**(型ではない。元から写すだけ): `.htm` ごとの素の本文(便 XB0 の `strip_text`)・表 F の全部の行の `kind`・`self`・`start`・`end`・`parent`・対象の fact ごとの「型の行の番号」(**どの置き場がどの数かは答えから取る**)・表 H の `pos`・`before`・`sections`・`references`・`resources` の中の `ref` の entry・`hidden` の行の `kind`・`self`・`text`・脚注の行の全部・文の fact の、`name` と `contextRef` 以外の属性の全部(持ち込みの属性)・数の fact の、`name`・`contextRef`・`unitRef`・`decimals`・`scale`・`sign`・`format`・`xsi:nil` 以外の属性の全部(持ち込みの属性)・提出者別タクソノミの表(便 XT0・便 XP0 のとおり)。
  - **持ち込みに入れないもの**(門で見る): 型に入った fact の `name`・`contextRef`・`unitRef`・`decimals`・`scale`・`sign`・数の fact の `format`・`xsi:nil`、文脈の定義、単位の定義。
- **型の外**(型に入らない fact。理由を付けて、その fact の `attrs` の全部と、その fact が指す文脈・単位の定義を元から写す。1 つの fact に理由が 2 つ以上在れば重ねて数える):
  - (a) 期間が期の表に無い(下の「期の名」の規則で名が作れない)。
  - (b) 文脈の entity が書類の決めと違う。
  - (c) 4. の軸に上の member 以外の member が在る・同じ軸が 1 つの文脈に 2 回在る。
  - (d) 単位が 4 つの形のどれでもない。
  - (e) 数の fact の `format` が `ixt:numdotdecimal` でない(空の fact は `format` を持たないのが形)・空でない数の fact に `decimals` が無い・`decimals` か `scale` が整数の字でない。
  - (f) 表示の字が「数字と `,` と `.` だけ」でなく、値を作れない。
  - (g) 同じ鍵の数の fact の間で、値・単位・表示の位・精度のどれかが違う(その鍵の fact の全部を型の外にする)。
  - (h) 空の fact が `name`・`contextRef`・`unitRef`・`xsi:nil` と持ち込みの属性のほかの属性を持つ・`xsi:nil` が `true` でない。
  - (i) 便 XB0 の関数が読めない文脈の形は、便 XB0 のとおり書類ごと「断った」になる(型の外ではなく断りとして数える)。

### 型から作る命令の規則

- **`name`**: 対応表で科目コードを引いた名。
- **数の fact の `unitRef`・`decimals`・`scale`・`sign`・`format`・`xsi:nil`**: 値が `無い` なら `xsi:nil` を `true` にし、`decimals`・`scale`・`sign`・`format` を付けない。値が在れば `decimals` = 精度・`scale` = 表示の位・`format` = `ixt:numdotdecimal`・値の字が `-` で始まれば `sign` = `-`(始まらなければ付けない)。`unitRef` は単位の `id`。
- **単位の `id` と定義**: `通貨:XXX` → `id` は `XXX`・`株` → `shares`・`純数` → `pure`・`通貨:XXX÷株` → `XXXPerShares`。定義は形のとおり。書類の型の行に現れた単位だけを、`id` の字の昇順に作る。
- **期の名**: 時点の日が当期の終わりの日なら `CurrentYear`・提出日なら `FilingDate`・当期の終わりの日の N 年前の日(N は 1 以上)なら `Prior<N>Year`。期間は、始まりと終わりが当期の始まり・終わりなら `CurrentYear`・両方がその N 年前の日なら `Prior<N>Year`。「N 年前の日」= 年から N を引いた同じ月・同じ日。元の日がその月の末日なら、引いた先の月の末日。当期の終わりの日と提出日が同じ日なら `CurrentYear` を先に当てる。どれにも当たらなければ名は作れない(型の外 (a))。
- **文脈の `id`**: 期の名 + (`Instant` か `Duration`)+ member ごとに `_` + member の字。member の並びは、`個別` の member が先、次に次元の組を軸の名の字の昇順。member の字は、接頭辞が `_cor` で終わる名なら局所名、そうでなければ接頭辞と局所名を区切りの字なしで続けた字。
- **文脈の定義**: entity は書類の決め・期間は型の行・member は `scenario` の中の `explicitMember` で、並びは軸の名の字の昇順(`個別` の軸も同じ並びの中に入れる)。member が無ければ `scenario` を付けない。書類の型の行に現れた(期間・対象・次元)の組ごとに 1 つ、`id` の字の昇順に作る。作った `id` が 2 つの違う組で同じになったら、その書類は「断った」。
- **`resources` の並び**: 持ち込みの `ref` の entry(元の並び)→ 作った文脈 → 型の外の文脈(元の並び。作った `id` と同じ `id` で中身が同じなら足さない。中身が違えば「断った」)→ 作った単位 → 型の外の単位(同じ扱い)。
- **型の外の fact** は、`attrs` を型の外の file に書いたとおりに付ける。持ち込みの属性は書いたとおりに付ける。

### 比べ方

- **比べ方 1(属性)**: 型に入った fact について、作った `attrs` と元の `attrs` を比べる。`contextRef` と `unitRef` は字でなく、それぞれの側の定義の中身(期間・entity・member の組の集まり/measure)で比べる。ほかの属性は名と値の組として同じか。書類の全部の対象の fact で同じなら「属性が意味として同じ」。別に、`contextRef` の字も全部同じ書類を「文脈の名も同じ」と数える。
- **比べ方 2(道具)**: 作った表 F と表 H で便 XP0 の folder を作り、便 XP0 の組む命令で包みを組み、道具 P に掛ける。fact の一覧の列は便 XB0 の `FACT_COLS`。**行から `contextRef` の列を除き、`unitRef` の列はそれぞれの側の包みの単位の定義の measure の字に置き換え(両側に同じ手を掛ける)、行を並べ替えた集まりが元の包みと同じなら「fact が意味として同じ」。** 相手の元の包みもこの便で道具に掛ける(便 XB0 と同じく `.xbrl` を落とした包み)。「鳴り方が同じ」は便 XP0 と同じ数え方。包みは 2 回組み、2 回が同じかを見る(道具は 1 回)。
- **混ぜ物**(型が出力を決めていることの確かめ。1 本につき 1 つ。道具に掛ける): 型の `数` の行のうち、対象が `既定`・次元が空・値が在り・対象を `個別` に変えた鍵が型に無い、最初の行(型の行の番号の昇順)の対象を `個別` に変えて作り直し、組んで道具に掛ける。**その行を指す置き場の fact の行だけが変わり(軸と member の列が 1 組増える)、ほかの行が 1 つも変わらない**なら「混ぜ物が効いた」。そういう行が無い書類は「混ぜ物を作れなかった」。
- **表示の字の検査**(型の値と本文の字の突き合わせ。型に入った空でない数の fact ごと): 値の大きさ ÷ 10 の(表示の位)乗を、小数点より後ろ(精度 + 表示の位)桁(0 より小さければ 0 桁)・3 桁ごとの `,` つきで書いた字が、本文の fact の中の字(タグを除く)と同じか。

- **先に自分の欠陥を疑う場合**: 型の外の fact が 0(62 本の全部で)・型に入った fact が対象の fact の 90% 未満・属性が意味として同じなのに道具の fact が違う書類が在る・混ぜ物を作れなかった書類が 6 本以上・断った書類が 6 本以上・型から作る命令が元の `attrs` や元の定義を読める形になっている(門で見る)・値が `-0` の行が 0(理由を 1 件ずつ読むまで「無い」と書かない)。

## §5 門

- 封の門: 封の字の決め(§1)と script の定数が同じ・封 → script → 記録の commit の順・作り物の書類で規則を 1 つずつ確かめる(型の外の理由 (a)〜(h) のそれぞれ・同じ鍵の fact のまとめ・空の fact・`-0`・期の名の N 年前と月の末日・member の並び・提出者別の member の字・単位の 4 つの形・`resources` の並び・`id` の重なりの断り・比べ方 2 の正規化・混ぜ物・表示の字の検査)・**型から作る命令に渡す folder の持ち込みに、入れないものが無い**・型の値を 1 つ変えると作った属性か定義が変わる(欄ごとに)・記録に禁止のものが無い。変異で赤を確かめる(掃く形で)。
- 結果の門: 結果の文書の数を記録と字で照らす・当たり外れを封の字の境と記録から決め直す。

## §6 読み方の決め(結果を見る前に)

- この便の数は「答えから作った型と対応表を、それだけを読む命令に渡すと、XBRL の側が意味として元に戻るか」と「第 0 版の型に入らない fact は何か」で、**「会社が型を埋めれば XBRL が作れる」とは読まない。** 型も対応表も答えから作っている。会社がこの型で情報を用意できるか・対応表を作れるか・埋めた中身が正しいかは測っていない。
- 持ち込み(素の本文・fact の置き場・どの置き場がどの数か・文の中身・脚注・提出者別タクソノミの表)はこの便では作っていない。
- 対象の `既定` は「個別の印が無い」という意味で、連結とは限らない。
- 道具が読む fact が元と同じでも、EDINET の本物の検査に通ることは言えない(便 XV0 の限界のまま)。
- **「XBRL を作れる」「専用の道具が要らない」「どんな資料も作れる」「誤りが無くなる」は、この便からは言えない。**
- 次の便の候補(別の封が先。人間に示す): XM0-1 が当たりなら (i) 型の外の理由のうち fact がいちばん多いものを型の拡張で入れる第 1 版(0 USD) (ii) 型から本文の表示の字と表も作る(持ち込みを減らす。0 USD) (iii) 前の年の対応表を今年に持ち越せる割合を数える(0 USD) (iv) 答えを見ない席が、XBRL でない資料から型を埋める(有料。別の封と、払う前の知らせが先)。XM0-1 が外れなら、違った所の型を読む(読むのは開発の 5 本だけ)のが先で、(i)〜(iv) は示さない。

## §7 限界(結果の文書の頭に書く)

- 便 XB0・便 XT0・便 XP0・便 XV0 の限界の全部(67 本は無作為でない・有報だけ・道具 P は本家の版でない・`.xbrl` を落とした包み・script は前の便の script を経て engine の module を間接に読み込む)。
- 型・対応表・持ち込み・型の外は、どれも答え(受理済みの XBRL)から作った。型の外の fact は元から写すので、その fact が元と同じになるのは当たり前。
- 型の欄と規則(期の名の 3 つの型・単位の 4 つの形・`format` の 1 通り・個別の軸と member)は開発の 5 本を見て決めた。
- 比べ方 2 は `contextRef` の字を見ず、`unitRef` は measure に置き換えて比べる。字まで同じかは別の数で書く。
- 混ぜ物は 1 本につき 1 つ・対象の欄だけ。ほかの欄を変えた確かめは封の門の作り物だけ。
- 文の fact は、型が持つのは科目・期間・対象・次元だけで、文の中身と書式の属性は持ち込み。

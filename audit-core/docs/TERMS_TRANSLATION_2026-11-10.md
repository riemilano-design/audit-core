# 独自の語の対訳 ― 買い手の技術者が最初に読む 1 枚(2026-11-10)

この repo の文書は日本語で、作業の中で決めた短い語(封・門・変異・台帳など)を使っている。下の表は、その語を一般のソフトウェア開発・研究の手続きの語に置き換えたもの。**新しい測定はしていない。** 置き換えの語は「同じ役目をする一般の語」であって、一般の語が含む要件(たとえば外部の登録機関への事前登録)を全部満たすとは言わない。満たしていない点は右の欄に書いた。

入口は 3 つだけ: (1) 測った数は台帳 [FACTS_FOR_BUYERS_2026-10-20.md](FACTS_FOR_BUYERS_2026-10-20.md)、(2) 英語の短い抜粋は [../README.en.md](../README.en.md)、(3) 手元で回すのは `sh run_tests.sh`(全部)と `python3 -m pytest -q tests/measure`(門だけ)。

## 手続きの語

| この repo の語 | 一般の語 | 何をしているか | 一般の語と違う点 |
|---|---|---|---|

| 門(`tests/measure/*`) | 回帰試験・文書と記録の整合の試験(regression test / consistency gate) | 文書の表と数が記録(`fixtures/**/*.json`)と一字違わないか、封より前に実装が無いか、engine が宣言なしに変わっていないかを pytest で見る | 「門」と呼ぶのは、壊すと赤になることを変異で確かめたものだけ |

## engine の語

| この repo の語 | 一般の語 | 何をしているか |
|---|---|---|
| claim | 照合の単位 | 文の中の 1 つの数(または主張)と、それを結ぶ参照先 |
| 名指す | 参照先の提示 | 値が違うときに、どの fact と比べたかを返す |
| profile(P27・P33E など) | 設定の束(feature-flag set) | 規則の旗の組。既定は P27。外部の文には推奨の profile を明示して使う |
| 旗 | feature flag | 規則ごとに真偽で入る。偽なら既存の出力は byte で変わらないことを門が見る |
| 留め・宣言された遷移 | ハッシュの固定・承認済みの変更 | engine の file の `sha256` を門が留め、変えるときは封に書いた値への遷移だけを許す |
| 注入 | fault injection | 正しい文の数を 1 か所だけ書き換えて、engine が止めるかを見る |
| 覆い | テストの収集範囲(coverage of collection) | どの試験 file が標準のコマンドで収集されるかの記録(行の覆いではない) |

## 4 つの判定(engine が claim ごとに返す state)

判定条件は engine の字(`core/py/audit_core/verify.py` の `verify`)に合わせて書いた。注意点の数は台帳と結果の文書の記録から写した(門は縛らない)。

| 項目 | GROUNDED | VALUE_MISMATCH | POINTER_NOT_FOUND | UNVERIFIABLE |
|---|---|---|---|---|
| 日本語 | 根拠あり | 値の不一致 | 参照先なし | 判定不能 |
| 定義 | 文の数が、元資料の fact で裏付けられている | 参照先の fact は見つかったが、値が合わない | 文の数に対応する fact が元資料に見つからない | 照合の前に、照らせない理由が決まった |
| 判定条件 | 参照先の fact を全部引け、契約に書いた比べ方(丸め・単位の帯)で一致した | 参照先の fact を全部引けたが、比べ方で一致しなかった | 参照先を 1 つでも引けなかった、または参照先が 1 つも無かった、または規則が「見つからない」理由を返した | 規則が登録済みの「照らせない」理由(主語が無い・計画の数など)を返した |
| 注意点 | 値と出所が合ったことだけを言い、文の主張全体が正しいとは言わない。参照先は規則が選ぶので、別の要素の値が偶然同じなら誤って根拠ありになる(値が偶然一致する誤りの注入で P30E が通した率 12 / 535 = 2.2%) 【門なし】 | 文の誤りとは限らない。人が書いた決算短信の概況では、値の不一致 110 行のうち 71 行がセグメント・内訳などの数を全社や別の要素の fact と比べた行だった(LLM の席が全行を読んだ型分けで、記録に欄は無い) 【門なし】 | 文の誤りとは限らない。元資料に無い数(計画・目標など)もここに入る | 正誤は言わない。照らせなかったことだけを言う |

## 注入の語(engine に誤りを見せて測るとき)

| 項目 | 通した | 止めた |
|---|---|---|
| 英語 | false pass | caught |
| 定義 | 1 か所だけ書き換えた誤りの数を、engine が根拠あり(GROUNDED)と返した | 書き換えた誤りの数を、engine が根拠あり以外で返した |
| 判定条件 | 注入の後の文で、書き換えた位置の claim の state が GROUNDED | 同じ位置の claim の state が VALUE_MISMATCH・POINTER_NOT_FOUND・UNVERIFIABLE のどれか(対応が付かない行は通した・止めたのどちらにも数えない。率の分母に含めるかは結果の文書ごとに書いた) |
| 注意点 | 率は注入の型と材料ごとに違い、型を混ぜた 1 つの率にはしない。分母は結果の文書ごとに書いた | 止めたことは、誤りの場所や正しい値を示したことと同じではない。元の値の fact を名指した行は「名指して」と別に数える(例: 規則 T の表の期の入れ替えで P33E が止めた 361 行は全部前期の fact を名指した) 【門なし】 |

## この 1 枚で言えないこと

1. 上の置き換えは役目の対応で、各一般語の規格(登録機関・第三者の審査・道具による変異の網羅)に合うとは言わない。違う点は表の右の欄に書いた。
2. 「門で縛っている」と言えるのは、台帳の印と結果の文書の表の範囲だけ。散文の言い回しは門の外にある。

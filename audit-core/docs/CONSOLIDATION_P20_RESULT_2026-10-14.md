## 0. 一行で

**4 つの合格線はすべて通った。** 連結が在る 6 書類では 1 行も動かず(C-1 = 0)、連結が無い 2 書類で 231 行のうち 150 行(64.9%)が根拠に結びついた。8 書類全体の一致判定率は **41.8% → 58.2%**。

## 1. 直した場所(置き場所を 1 度間違えた)

最初は `resolve.make_resolver`(pointer を引く所)に落とし込みを入れた。**C-1 は 0 になったが C-2 も 0 だった。** 止まっているのは pointer を引く前で、`recipes.py` が `I.facts_for` → `I.ctx_ok` → `I.plain_context` を通して `reason="no_element"` を決めていた。

直しは `adapters/xbrl/instance.py` の**枠の判定**へ移した。

- `consolidated_element_count(facts)` ― 素の期間の枠に在る財務の要素の種類数。**日本基準 `jppfs_cor` と IFRS `jpigp_cor` の両方**を数える。
- `with_nonconsolidated_fallback(contexts, facts, enabled)` ― **書類ごとに 1 度だけ**呼ぶ。旗が偽か、連結の要素が 1 種でも在れば**同じ辞書をそのまま返す**(振る舞いが 1 行も変わらないことが型で保証される)。
- `DocumentContexts(dict)` ― 決定を属性 1 つで持つ入れ物。**context の id も中身も書き換えない。**
- `plain_context` ― 落とし込みが決まっている書類でだけ、**単体の member だけ**を持つ枠を素として扱う。

呼ぶのは `recipes.build_raw_claims` の `load_instance` の直後、**1 か所だけ**。語彙の組み立て(`_label_subjects`・`_flow_items_by_base`)も素の枠で足切りするので、**その前**でなければ旗は半分しか効かない(試験 `WiringTest.test_the_decision_comes_before_the_vocabulary_is_built` がこの順序を留める)。

### 1-1. 別名を張らなかった理由(人間の指示に直結)

`CurrentYearInstant_NonConsolidatedMember` を `CurrentYearInstant` の別名にする実装は**退けた**。それをやると pointer が名乗る枠(連結)と値の出どころ(単体)がずれ、人間が警告した「**違う対象の数値を正しい根拠として扱う**」そのものになる。

実測で確かめた: 連結が無い 2 書類で一致と言った行の `xbrl:` pointer は、**全件が実在する `..._NonConsolidatedMember` を名乗っている**(素の枠を名乗った件数 0)。

### 1-2. 自分で踏んだ欠陥(2 件)

| # | 欠陥 | どう見つけたか |
|---|---|---|
| 1 | 置き場所が `resolve` で、止める判定より下流だった | C-2 = 0 を「効かない」で済ませず、`reason` を 1 件読んだ |
| 2 | member を**裸の局所名**で比べていた。実物は `jppfs_cor:NonConsolidatedMember` と接頭辞つきなので **1 件も当たらず**、「旗が効かない」と読み違えた | 記録「『0 件』を根拠にする前に、その 0 が自分の欠陥でないかを確かめる」を適用し、実物の context の member を印字した |

### 3-2. 分母の書き方(**揃っているかを機械で確かめた**)

対にするのは **id ではなく中身の鍵**(`kind` / `form` / `subject` / `value` / `unit` / `word` / `span`)。id は規則で動くので使えない。

- **行の数は 918 で P16・P20 ともまったく同じ**(書類ごとにも同じ)。P20 は主張を増やしていない。
- **鍵が重なって潰れた行が 15 件在る**(S100YZ4E 5・S100YUHC 5・S100YXGH 5)。だから封に書いた「連結なし 2 書類は 236 主張」に対し、ここでの分母は **231**(5 件が同じ鍵に潰れた)。**分母が 5 小さいことを隠さない。**
- **連結なし 2 書類では、鍵が片方にしか無い行が 15 件在った**(6 + 9)。中身を読むと**同じ主張で `form` が `direct_value` → `derived_value` に変わった**もの(当期と前期の 2 つの fact が引けるようになり、差の式になった)。`form` を外した鍵で対を作り直すと**片方にしか無い行は 0 件**になる。
- **連結が在る 6 書類では、片方にしか無い行も 0 件、形を外した鍵で状態が変わった行も 0 件。** だから C-1 の 0 は「対が作れなかったから 0」ではない。

2. **58.2% は一致判定率であって正答率ではない。** 人間の指摘(2026-10-14)どおり、この区別は崩さない。

5. **C-1 の 0 の一部は作りによるもの**である。連結の門(`consolidated_element_count != 0`)が在る限り、連結が在る書類では落とし込みが起きない。C-1 が測っているのは「**その門が正しく分類しているか**」で、6 書類(117〜157 要素)で誤分類が無かったということ。**門そのものを外したら何が起きるか**は変異 `P20-M4` で測る(次節)。
6. **誤りを通す率(false pass)は P20 では測っていない。** P16 の 6.2% / P18 の 1.2% と同じ測り方を P20 に当てるのは次の工程。

### 5-3. 退化値を自分で探して出たもの(**既存の緩さ 1 件。P20 由来ではない**)

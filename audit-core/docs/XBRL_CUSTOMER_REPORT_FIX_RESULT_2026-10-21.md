## 十 限界

- 判定の効き目は変わらない。「違う」が正しい文に出る率は、報告の形では減らない(丸めた差・増減要因の語・区分の取り違えは engine の側)。
- 文の数の読み取りの崩れ(`2兆3,471億円` が `3,471億円` になる等)は engine(extract)の側で、報告では直せない。
- `no_same_value` が名指した当期の値は `verify_document` の出力に欄が無く、報告には出さない(変わらず)。
- 語の主張の単位を書類の単位に落とした行は、文から読み取っていない(上の語の表の二行目)。
- 表題の「書類の種類」は書類の題名 `jpcrp_cor:DocumentTitleCoverPage`(「有価証券報告書」)で、無ければ DEI の `DocumentTypeDEI`(「第三号様式」のような様式名)に落とす。期末日は DEI の `CurrentPeriodEndDateDEI`(無ければ `CurrentFiscalYearEndDateDEI`)をそのまま出す。
- 率の文の末尾の零(`12.0%`)は claim の値(浮動小数)に残らないので、率の出典の値の桁は文より一つ少ないことがある(件数は測っていない)。
- 抜粋は、末尾が数で終わる抜粋のその数と、先頭が小数点で始まる数だけを落とす。先頭が桁の途中で切れた数(`2026年` の先頭が切れた `26年`)は見分けられず落とさない。この切れ目の処理は「対象外」「判断しない」の抜粋だけで、「違う」「要確認」の抜粋は engine の出したまま。
- 括弧(丸める前の値)と `△` の凡例は、司令塔が承認した一行を「違う」と「一致」の節の説明に置いた(「出典の値は文の桁に丸めた数。括弧は丸める前の値。△ は負の数(財務諸表の書き方)」)。
- 「一致」の節の主表示は、四捨五入と切り捨てのうち文の値と同じになる方を選ぶ(司令塔の判断 2026-10-21)。切り捨てを選ぶ行は、括弧の生の値が四捨五入では別の数になる行である。どちらにしても文の桁より細かい差は括弧に出る。
- 報告の日本語の字が客に伝わるかは門で縛れない。縛るのは節の割り当て・件数・単位・名簿・指紋の置き場・バイト列の同一だけである。
- module の変異の実測は、実装席が手で走らせた一回限りの手の実測で、門では縛れない。毎回縛るのは `tests/adapters/xbrl/test_report_customer.py` の golden・名簿・単位・桁・符号・抜粋・指紋・表題で、これらは壊した標本で赤くなることを同じ試験の中で確かめている。

- 封 §0 の数は試作の席の数え方で、この測定の「前」の値が再現した(名前のまま出た行・本文の hex・金額の claim の数。上の表と門 `test_6`)。例外は単位の食い違いの前の値: 封の千四百八十は`805千円` を漢数字形と読む誤読を含んでいて、直した読み取りで測り直すと二十一行(違う三・要確認七・一致十一)多い(上の単位の表の『単位の食い違い 前』)。独立に数えた前の値は別の数え方(c13a746 の本文の列の字)である。
- 封 R2-3 の注記のとおり、英字の正規表現に当たる行は会社のラベル自体の英字の行で、直接数えると零である(上のラベルの表)。
- 封 §1-8 は書類の種類を DEI から取ると書く。実物の `DocumentTypeDEI` は様式名(「第三号様式」)で、書類の題名ではない。封は直さず、書類の種類は題名の意味に読む(司令塔の判断 2026-10-21)。
- 封 §1-1 の「名簿に在る file 名だけを読む」ため、名簿の README の取り方は `curl -sS -O` でなく `curl -sS -o`(名前を指定)で書いた。儀式の門 `test_xbrl_ritual_result.py` は README の `curl -sS -O` の行がちょうど二本であることを縛っている。

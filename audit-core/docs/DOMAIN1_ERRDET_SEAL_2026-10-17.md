# 誤り検出の封 ― **LLM の根拠を機械が検証すると、LLM 単体にできない品質保証ができるか**

2026-10-17。**誤りの生成より先・測定より先・LLM の生成より先に commit する。**
人間の決定(2026-10-17)に従う。

> この実験を進めることには賛成です。**ただし、検証器の価値を証明するための実験であって、
> Core の優位性を証明するための実験ではありません。**
>
> **大事なのは、Core が LLM より優れていると証明することではありません。
> LLM が出した根拠を機械が検証することで、LLM 単体ではできない品質保証が
> 実現するかを確かめることです。**
>
> **① LLM に何を見せるかを固定する。**同じ誤り入り報告文と同じ根拠情報を、
> LLM 単体と LLM + Core に与える。**入力差を封印記録に残します。**
> **② 比較対象を 3 方式に明確化する。**A LLM 単体 / B 現行 Core 単体 /
> C LLM の回答を Core が検証。**主たる比較は A 対 C。B は参考群。**
> **A と C の差がなければ、機械検証を加える価値が今回の条件では確認できません。**
> **③ 誤りを検出できたことと、誤りの場所を特定できたことを分ける。**
> 「誤りを検出」「正しい根拠を提示」「誤りの種類を特定」を別々に採点する。
> **偽警報と、判断不能に倒す保留も分ける。**
>
> **落とし穴**: 人工的な誤りを検出できても、実際の文書で起きる誤りを検出できるとは
> 限らない。**原資料との照合だけで機械的に検出できる誤りと、文脈の理解が必要な誤りを
> 分ける必要がある。**
>
> 僕からの指示は、**実験の封印を先に行い、Core 単体の測定から始める。
> ただし、A 対 C の比較条件と採点基準も同時に封印しておく**、です。
>
> なお、**費用上限の 2 ドルは現時点では見込みであって、保証値ではありません。**

**この実験は Core の優位性を測るものではない。**測るのは
**「LLM の回答を機械が検証すると、見落としと偽警報がどう動くか」**だけである。
**Core 単体(B)は参考群**であり、**B が勝っても製品の結論にしない。**

### §1-1 1 件だけ変える ― **変種は誤りの数だけ作る**

**変わったら、束ねた変種を LLM 側に使わない。**

## §2 誤りの作り方 ― **規則を字で固定する(実行前)**

### §2-1 対象の選び方(**私が選ばない**)

1. 報告文の文を番号の昇順に並べる。
2. 各文の**「正解集合に在る主張のうち id が最小のもの」**を対象の候補にする。
3. **文 17 は使わない。**`R035`(「補正予算額は**マイナス**48,327,000円」)が在り、
   **これは §2-4 の罠**だからである。同じ文に誤りを足すと罠と干渉する。
4. 残る候補は **8 文・8 件**である。

### §2-2 誤りの型 ― **2 群 × 2 型。各型 2 件。合計 8 件**

| 群 | 記号 | 作り方 | 検出に要るもの |
|---|---|---|---|
| **群 I**<br>**原資料との照合だけで機械的に検出できる** | **I-1 桁の入れ替え** | 十進表記の**2 桁目と 3 桁目**を入れ替える(同じ数字なら次の組へ) | **値が原資料に無い**ので照合だけで足りる |
| | **I-2 末尾 1 桁の差** | 末尾の桁に **+1**(9 なら −1) | 同じ |
| **群 II**<br>**文脈の理解が必要** | **II-1 列の取り違え** | **同じ行の別の列**の値に差し替える。列の候補の順は `支出済額 → 予算現額 → 不用額 → 補正予算額`(自分の列を除く、最初に在るもの) | **値は原資料に在る。**文の列の字と食い違うことに気づく必要がある |
| | **II-2 別の科目の値** | **同じ会計・同じ階層・同じ列の別の行**の値に差し替える(抜粋の並び順で最初のもの) | **値は原資料に在る。**行が違うことに気づく必要がある |

**作った値は次を満たさなければならない(満たさなければその型はその文では作れない)。**

- **群 I**: その値が**抜粋の 176 セルに 0 件**かつ**索引 4,209 行に 0 件**
  (在ったら型の規則の次の候補へ。I-1 は次の桁の組、I-2 は +2・+3…+9)
- **群 II**: その値が**抜粋に在る**こと。かつ**正しい参照先の値と違う**こと
- **どの型でも**: **同じ文の中に既に出ている数と一致しない**こと
- **表記**: カンマ区切り + `円`。**桁数は変えない**(I-1・I-2 は桁数が変わらない)

### §2-3 型と文の割り当て(**材料が決める。私が決めない**)

1. 各型について、**その型が作れる文**を数える。
2. 型を**「作れる文の数」の昇順**に並べる(同数なら `I-1 → I-2 → II-1 → II-2` の順)。
3. 各型に**2 文**を割り当てる ―
   **① Core が結べた主張の文のうち番号が最小のもの、② 結べなかった主張の文のうち
   番号が最小のもの。**どちらも「まだ使っていない文」に限る。
4. **層化に Core の結果(結べた / 結べなかった)を使う。正解ラベルには使っていない。**
   理由は、この実験の仮説が「**Core 単体の検出は結べた件に閉じる**」であり、
   **そこで層を分けないと仮説を測れない**からである。**開示する。**
5. **8 件そろわなければ「そろわなかった」と書く。規則を緩めない。**

### §2-4 **偽警報の罠(植えない。既に材料に在る)**

`R035` は「補正予算額は**マイナス**48,327,000円」である。**報告文は正しい。**
`extract_claims` が符号を落とすので、**素朴な照合では「原資料に無い数」に見える**
(2026-10-17 に実測。`fixtures/sheet/poc_sign_defect_2026-10-17.json`)。

**これは「報告文の抽出時点で符号が落ちている」型であり、文書の誤りではない。**
**だから検出率の分母に入れない。偽警報の側で別に数える。**

**単位の書き換え(千円単位など)の罠は作らない。**正しい文書を書き換えることになり、
**誤りの検出率の分母にも偽警報の分母にも入れ方が決まらない**からである。
**罠は `R035` の 1 件だけで測る。**

## §3 採点基準 ― **検出 / 保留 / 見落としを分け、さらに 3 段に分ける**

### §3-1 1 件の答えは 3 つのどれか(**互いに排他**)

| 記号 | 中身 | Core | LLM |
|---|---|---|---|
| **検出** | **「原資料と一致しない」と言えた** | 値の食い違いを検出 | 「根拠なし」または不一致の申告 |
| **保留** | **「どれを指すか決められない」** | 一意でない / 手がかりが 2 つ以上 | 「判定不能」 |
| **見落とし** | **「確認済み」として参照先と値を出した** | 1 行に特定して値も一致 | 6 欄を答えた |

**保留は検出ではない。**保留を検出に数えると「全部保留する道具」が最高点を取る。

### §3-2 誤りの 1 件につき、**3 つを別々に採点する**(人間の指示 ③)

| 記号 | 中身 |
|---|---|
| **検出-1 誤りだと言えたか** | §3-1 の **検出** だったか(保留・見落としは別に数える) |
| **検出-2 正しい根拠を提示できたか** | 方式が示した参照先が、**正解ラベルの行**(改変前の正しい行)と一致するか。参照先を出さなかった場合は**「提示なし」** |
| **検出-3 誤りの種類を特定できたか** | 固定語彙での申告が正解ラベルの型と一致するか。語彙は `値が原資料に無い / 列の取り違え / 別の科目の値 / 親階層の取り違え / 単位・符号の表記 / 不明` |

**Core の検出-3 は内部の状態から機械で写像する**(値の食い違い → `値が原資料に無い`)。
**LLM の検出-3 は答えの欄として申告させる**(§5-2 で問いに 1 欄足す)。

### §3-3 無改変の主張での採点(**偽警報と保留を分ける**)

| 記号 | 中身 | 分母 |
|---|---|---|
| **偽警報** | **正しい主張を「原資料と一致しない」と言った** | **無改変の主張**(束ねた変種で 35 − 8 = **27 件**。`R035` は除いて別記) |
| **保留(無改変)** | 正しい主張を「判断不能」に倒した | 同じ |
| **確認済み(無改変)** | 正しい主張を確認した | 同じ |
| **罠(`R035`)** | **文書は正しいのに「一致しない」と言ったか** | **1 件。別記する** |

### §3-4 合否の閾値(**Core 単体。結果を見る前に決める**)

| 記号 | 閾値 | 不合格の意味 |
|---|---|---|
| **E-1** | **見落とし = 0 件**(8 件の誤りすべて) | **誤りを「確認済み」として通した。検証器として失格** |
| **E-2** | **偽警報 ≦ 1 件**(無改変 27 件。罠は除く) | 正しい主張を止めすぎる |
| **E-3** | **結べた 4 件の誤りは 4 件すべて検出** | 結べているのに検出できない |
| **E-4** | **結べなかった 4 件では検出 0・保留 4** | ここが **Core 単体の天井**。**天井が在ることを失敗とは書かない**(仮説どおり) |

**E-1〜E-3 のどれかを満たさなければ「不合格」と書く。**
**E-4 は予測であって合否ではない**(外れたら外れとして書く)。

## §5 A 対 C の条件(**同時に封じる。実行は Core 単体の結果を人間が見た後**)

### §5-1 3 方式(**主比較は A 対 C。B は参考群**)

| 方式 | 中身 |
|---|---|
| **A** | **LLM 単体。**答えをそのまま採点する |
| **B** | **現行 Core 単体**(§3・§4 で測るもの)。**参考群。製品の結論にしない** |
| **C** | **LLM の回答を Core が検証する。**LLM の答えを入力とし、**機械の検証結果だけを出力にする** |

**入力差はゼロである。** C は A と**同じ 1 回の生成**を使い、**その出力に検証を当てるだけ**である。
だから「A に有利 / C に有利な入力」が原理的に作れない。
**これは人間の指示 ①(LLM に何を見せるかを固定する)の最も強い形である。**

### §5-2 LLM に見せるもの(**字で固定する**)

| | |
|---|---|
| 渡すもの | **束ねた変種の報告文**(誤り 8 件)+ **抜粋 76 行**(= 原資料の行) |
| **渡さないもの** | **Core の候補一覧・Core の状態・正解ラベル・誤りの件数・誤りの型の割り当て** |
| 問い | **段 11 の問いに「不一致の種類」の 1 欄を足したもの**(§3-2 の固定語彙)。足す字は `measure/sheet_errdet_question_2026-10-17.py` が生成し、**段 11 の問いが接頭であることを機械で確かめる** |
| 席 | **seat1 `model=sonnet`(順そのまま)/ seat2 `model=haiku`(逆順)**。**各 1 回。やり直しなし** |

**「根拠情報」を「抜粋(原資料の行)」と読んだ。Core の候補一覧は渡さない。**
理由は 2 つ。(1) **方式 C(2026-10-17)で、Core の証拠を足しても答えが 1 件も
変わらないことを実測した。**(2) 渡すと「証拠の注入」という別の変数が混ざり、
**検証器の価値を切り分けられない。**
**人間の意図が「Core の候補も渡す」であれば、LLM 側の実行前に差し替える**
(封は入力条件を字で固定しているので、その 1 行を差し替えれば済む)。

**問いに「不一致の種類」を足すことは、席に「誤りが在る」と教えることになる。**
**これは交絡である。**だから**偽警報は同じ文書の無改変 27 件で測る**
(別の対照を生成しない ― 費用のため)。**この交絡を結果の文に書く。**

### §5-3 C の検証規則(**先に字で固定する。結果を見てから変えない**)

LLM が出した 6 欄を**原資料の行に引き当てる**。引き当ては
`sheet_poc_ab_score_2026-10-17.py` の `resolve()` ではなく、
**`sheet_poc_m3_addendum_2026-10-17.py` の `reach()`(M-3′)を使う。**
理由: **同じ行が決算書と明細の両方に在り値が同じ場合、M-3 の「一意のセル」定義は
原資料の構成を方式の欠点として数えてしまう**(2026-10-17 に実測。A で 28/35 が
これで落ちた)。**M-3 の数も併記する。**

| 検証の結果 | C の出力 |
|---|---|
| 当たる行が無い | **確認できない(参照先が無い)** |
| 当たった行の値が揺れる | **確認できない(値が一意でない)** |
| **当たった行の値が主張の金額と一致しない** | **原資料と一致しない** |
| 一致する | **確認済み** |

**C の出力はこの 4 値だけである。LLM の断定をそのまま顧客に出さない。**
**C の検出 = 「原資料と一致しない」。C の保留 = 「確認できない」2 種。
C の見落とし = 誤りなのに「確認済み」。**

### §5-4 A 対 C で比べること(**同じ分母で**)

**検出 / 保留 / 見落とし**(§3-1)、**検出-1 / 検出-2 / 検出-3**(§3-2)、
**偽警報 / 保留(無改変)**(§3-3)を、**A と C で同じ分母で並べる。**

| 記号 | **C が A を上回ったと書ける条件** |
|---|---|
| **G-1** | **見落としが減る**(誤り 8 件のうち「確認済み」が減る) |
| **G-2** | **偽警報が増えない**(無改変 27 件) |
| **G-3** | **G-1 と G-2 の両方**を満たすこと |

**G-3 を満たさなければ「上回った」と書かない。**
**「A と C の差がなければ、機械検証を加える価値が今回の条件では確認できない」**と書く
(人間の字)。**C が優れても、別の誤り種類や別資料で再現するかは別問題**と書く。

### §5-5 費用

- **Core 単体(§3・§4)は 0 USD。**
- **LLM 側は 2 席 1 回ずつ。見込み 2 USD ― これは見込みであって保証値ではない**(人間の字)。
  **上限は実測で 4 USD。**実測トークンを記録し、**段 11 と同じ式**で上限を出す
  (sonnet 15 / haiku 5 USD/1M。**全部が出力だと仮定した上限**)。
- **超えそうなら実行前に止める。超えたら打ち切って途中までを記録する。**

## §6 失敗条件

| 条件 | 判定 |
|---|---|
| **結果を見てから誤りの生成規則・採点基準・閾値を変えた** | **失敗** |

| **変えた 1 件以外の値が動いた** | **その変種は無効** |
| **束ねた変種と 1 件ずつの結果が食い違った** | **束ねた変種を LLM 側に使わない**(記録に書く) |
| LLM の生成をやり直した | **失敗** |
| 実測の上限が 4 USD を超えた | **打ち切り** |
| **人工の誤りでの成功を、顧客価値や販売可能性の証明として書いた** | **失敗**(人間の指示) |

## §7 示せないこと(**先に書く**)

1. **人工的な誤りを検出できても、実際の文書で起きる誤りを検出できるとは限らない**(人間の字)。
   **だから群 I と群 II を分けた。**それでも**実際の誤りの分布は測っていない。**
2. **1 文書・1 報告文・8 件の誤り・1 回。**汎用的な性能は主張しない。
3. **誤りは正解集合の 24 件にしか植えていない。**
   別枠 11 件は**何が誤りかを定義できない**ので、**そこでの検出能力は測れない。**
4. **層化に Core の結果を使った**(§2-3 の 4)。**正解ラベルには使っていない。**
5. **問いに「不一致の種類」を足すことは、席に誤りの存在を教える**(§5-2)。**交絡である。**
6. **`R035` 型(抽出の符号落ち)は私の欠陥であって文書の誤りではない。**
   **これを「検出できた」と書かない。**
7. **2 席の一致を証拠に数えない**(CLAUDE.md 8(2))。
8. **顧客が買うかは測れない。**この実験は**検証器の価値**を測るものであり、
   **Core の優位性を証明するものではない**(人間の字)。

### 2-5. 訂正と確認(2026-10-15)― **分母が同じではない。** 比較可能性を機械で確かめた

人間の指摘(2026-10-14)「**P16 と P18 の分母・誤りの種類・評価条件が比較可能であることが前提です**」に答えるため、3 点を機械で確かめた。道具は `measure/false_pass_compare_2026-10-15.py`(試験 21 本)。

**まず訂正**: §2-3 で「P18 4/340」と書いたが、**P18 が実際に変えたのは 406 回**である。誤りを当てる対象は「その規則セットで**一致と言った**数の主張」なので、一致と言う数が増える P18 では対象の行も増える。

| | 行(3 書類の合計) | 変えた回数(× 2 通り) | 通した |
|---|---|---|---|
| P16 | 170 | 340 | 21 |
| P18 | **203** | **406** | 4 |

**確かめた 3 点**

1. **分母**: **P16 の 170 行は P18 の 203 行の部分集合**(3 書類すべてで成立。機械で確認)。だから共通の 170 行(340 回)で比べられる。
2. **誤りの種類**: 共通の全行で、**同じ id に同じ字の変え方が当たっている**(変え方は claim の id で決まり、規則セットに依存しない)。機械で 1 行ずつ照合。
3. **評価条件**: 両方とも `batch=1`(1 回の検証で 1 件だけ変える)。同じ 3 書類・同じ土台の文章。

**揃えた分母での比較**

| | 分母 340(共通の 170 行 × 2 通り) | P18 で新たに一致と言うようになった 33 行(66 回) |
|---|---|---|
| P16 | **21 / 340 = 6.2%** | ― |
| P18 | **4 / 340 = 1.2%** | **0 件** |

**読み**: P18 は「一致」と言う行を 170 → 203 に増やしながら、**増えた 33 行では誤りを 1 件も通していない**。つまり 6.2% → 1.2% は、止める件数を増やして稼いだ数ではない。これが人間の言う「正しい一致を保ちながら誤った一致を減らす」の機械で確かめられる形である。

**実物で守りが発火することを確かめた**(正常な入力では発火しない守りは測れない)。手元に在る過去の測定の出力 4 本に当てたところ、**揃っている 1 本だけを受け入れ、3 本を名前つきで拒否した**。

| 件 | 中身 |

**ここで直し方を変えた。** 1 か所ずつ塞ぐのを 3 回やって 4 件目が出た以上、塞ぎ方が間違っている。**報告の形を先に 1 回で検査する**関数(`check_shape`)を置き、欄の欠落・重複・空・型違いを全部そこで落とす。以降の計算は形が整っていることを前提にできる。入口も 1 本にまとめた(`analyze`)。

試験も 1 件ずつ足すのをやめ、**崩し方を表にして網羅する**(`DegenerateInputTest`)。表は **20 通り**の崩し方を持ち、それぞれについて (a) 拒否すること と (b) **CLI ごと当てても例外を投げないこと** を両方当てる。試験は 21 本。

**独立監査の 3 回目も REVISE ― 8 件目が出た。** 監査は前の版に在った検査が 1 つも落ちていないことを照合し、2 回目の 4 件が直っていることを再現し、**自分で変異 18 本**を当てて 16 本赤・2 本は到達しない沈黙(実害なしを実行で確認)と報告した。そのうえで 8 件目を実測した。

| 件 | 中身 |
|---|---|
| 8 | **同じ `(書類, 規則セット, 変え方)` の run が 2 回在る入力** ― `index` が辞書に詰めるので後勝ちで**黙って上書き**し、上書きされた側の結果が消える。監査の再現では真の run だけなら 0/4 の所が **1/4 = 25%** に化けた。`check_shape` は 1 件の run の中の `id` の重複は見ていたが、**run そのものの重複は一度も見ていなかった** |

これも「黙って嘘の率を出す」型である。**公表した数は影響を受けていない**(監査が本番の出力を検査して重複 0 件を確認)。run の層の重複の検査を足し、監査が再現した場面をそのまま試験にし、その検査を外す変異が赤くなることを確かめた。あわせて「報告が list でない」「run が辞書でない」の 2 形も表に足した(監査の任意の推奨)。試験 21 本。

**この道具で出た欠陥は 8 件、全部が退化値である。** 実物の入力では 1 件も発火せず、数は一度も動いていない。**それでも止めてよかった**と言える理由は 8 件目で、これは「測定の出力を手で連結する」という、この project が実際に 4 回やった操作で起きる。**実物の数は変わらない。**

**道具にした理由**: この比較を手で 1 回やると、同じ型の誤り(「一回限りの手の実測は門ではない」)を繰り返す。道具は、崩れている入力では**率を並べずに崩れている所を印字する**。試験 21 本のうち **14 本**は、崩れた入力を**本当に落とすか**を当てている(個別に 10 本 + 表で 20 通りを一度に当てる 2 本 + 自己比較 1 本 + run の重複 1 本)。崩し方の一覧は `DegenerateInputTest._broken` にある。

## 4. 正直に書く点

1. **訓練 2 書類の 79.7% は訓練の数**。P17 の規則はこの 2 書類の失敗を読んで作ったので、未使用の書類で同じ数が出る保証は無い。設計に使っていない S100Z4Q1 では +1(146 → 147)しか動いていない ― その書類にセグメントの文も「により」の文も少ないからで、「効かない」ではなく「測れていない」。**未使用の書類で測るまで、相手に 79.7% を言わない。**
2. A の 1 回目は 16 書類で GROUNDED を 71 件失った。予測(0〜3)を大きく外し、棄却条件どおり外した。A'(2 回目)は従来の段落内の引き継ぎを消していて 3 件失った(実装が計画の字より狭かった誤り)。A''(3 回目)で 0。**3 回目で当たったのは、2 回外れたからであって、最初から当てたのではない。**
3. 誤りを通す率の「0」は **% について**で、全体では 1/203。残る 1 件の型(書かれた最小の桁の中)は engine では消せない。
4. 誤りを通す率は 3 書類・2 種類の変え方で測ったもの。単位のずれ(千円 ↔ 百万円)・原文に無い数・値が偶然一致して参照先が違う型は、2026-10-08 の道具(`measure/inject.py`)の測定(30/30 検出)があるが P17/P18 では測り直していない。

5. **測る道具の欠陥を 3 つ出した。** 順番で変え方を割り振った版・1 行に 1 通りだけ当てた版・25 件まとめて変えた版。どれも**出力を見ても分からない**型で、数の読み違いに直結した(§2-3・計画 §8・§9)。道具に試験 12 本を付けた(`tests/adapters/xbrl/test_false_pass_tool.py`)。**数を出す道具は、engine と同じだけ留める。**

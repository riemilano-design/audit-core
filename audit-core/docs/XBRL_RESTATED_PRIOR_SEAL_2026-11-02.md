# 封: 出所のずれの名指し ― 「翌期の有報の前期欄の値」(文2)はどれだけ起き、engine が止めた数のうちどれだけを「翌期の前期欄」と名指せるか ― 2026-11-02

2026-11-02。人間の指示「まかせるから進めて」(2026-11-02。「数を、どの書類・どの要素・どの期・どの単位・どの区分の fact かに結びつけ、出所のずれを止める」を突き詰める、の 2 番目の便)。
EDINET DB(Cabocia 株式会社)が 2026-10-27 と 2026-11-02 に書面で説明したとおり、同社の API が返した 2 項目(ソニーグループの営業利益・減価償却費)の値は**元の有報の数ではなく、翌期の有報で前期の値として開示された数**で、出典の doc_id だけが元の有報を指していた。同社が横断して確かめたところ同じ形は他にもあり、同社は応答に「出所の書類」と「当期・前期のどちらの欄か」を加える直しを公開する。engine はこの 2 項目を VALUE_MISMATCH で止めたが、「どこから来た値か」は言えていない。台帳 H-14 はこの型(段 1 の札 `文2`)を「この標本では起きえず未測定」としている(段 1・段 2 の 20 社は最新の有報で、翌期の有報が無いため)。
本便は 2 段。**段 1**: 手元の有報 97 書類について、同じ会社の**前年の**有報を EDINET から取り、(前年の有報の当期欄)と(手元の有報の前期欄)を要素ごとに突き合わせ、値が違う割合(文2 が起きうる基礎率)を測る。**段 2**: 前年の有報の文の数を「翌期の前期欄の値」に差し替えた注入を作り、engine(P27。変えない)が止めるか、止めた行を measure 側の規則 R が「翌期の有報の前期欄の fact と一致」と名指せるか、無改変の止めた行を誤って名指さないかを測る。**engine(`core/`・`adapters/`)は本便では 1 行も変えない。** 名指しを engine の profile(既定にしない)に入れるかは、本便の結果を見て人間が決める(別の封)。

## §1 段 1 ― 前年の有報を取り、要素ごとに突き合わせる(字で固定)

1. 97 書類の ZIP の sha256 を記録と照らす。各 ZIP の DEI から EDINET コードと当期の末日を読む。読めない書類は数えて除く。
2. 会社ごとに、当期の末日の 1 年前の日 E′ を求め、E′ + 60 日 〜 E′ + 110 日の各日の `documents.json`(type=2)を引き、`edinetCode` が同じ・`ordinanceCode` 010・`docTypeCode` 120(有価証券報告書。訂正と四半期は除く)の書類を**前年の有報**とする。2 つ以上あれば提出日が最も遅い 1 つ。無ければ「前年なし」と数える(新規上場・決算期変更など)。
3. 前年の有報の ZIP を取り、sha256 を記録。手元の書類を **next**、前年の有報を **prev** と呼ぶ。
4. 組ごとに、要素の突き合わせ: prev の**当期の枠**(`CurrentYear*`。member なし)の数値の fact と、next の**前期の枠**(`Prior1Year*`。member なし)の数値の fact を、(要素名, 期の型 Duration/Instant, 単位)で結ぶ。結べた要素ごとに **同じ / 違う / 片方に無い** を数える。「同じ」は値が等しいこと(engine の帯ではなく等号。開示の数そのものを比べる)。「違う」は値が異なること。
5. 違う要素について、差の大きさ(|next − prev| / |prev|)の分布と、要素名の上位(どの要素が違いやすいか)を記録する。
6. 固定の確認: E01777 の組で、営業利益と減価償却費及び償却費の要素(IFRS。`jpigp_cor` の要素名は記録に書く)が「違う」に入るか。

出力: `fixtures/xbrl/prior_pairs_2026-11-02.json`(組の一覧・docID・sha256・要素ごとの数・分布。会社名は書かない。docID は材料の名として記録に残す ― 手元の 97 の docID は既に `regress97` の記録に在る)。

## §2 段 2 ― 注入と名指しの規則 R(字で固定)

1. 対象は段 1 で組が出来た会社の **prev**(前年の有報)。prev の経営分析の文を P27(既定)で判定し、GROUNDED の claim のうち、engine の pointer の要素が段 1 で「違う」に入った要素で、pointer の枠が当期(`CurrentYear*`)の行を **注入の site** とする。
2. site ごとに、文の数を **next の前期欄の値**(同じ要素・`Prior1Year*`・member なし)を文の単位と桁に丸めた字に差し替え、1 site 1 文書で P27 を走らせる(`verify_document(zip, "P27", text)`)。差し替えた claim の state を記録する。丸めの結果が元の字と同じになる site は「差が桁の中」として除き、数を記録する。
3. 規則 R(measure 側。engine は変えない): engine が止めた claim(state が GROUNDED でない)について、engine の pointer の要素(pointer が無ければ claim の subject から engine と同じ語彙で引いた要素。引けなければ R は何も言わない)を next の前期欄で引き、文の数と next の fact を **engine と同じ帯**(`comparators` の照合。文書の丸めは `vocabulary.decide_rounding`)で比べる。帯の中なら「翌期の有報 <next の docID> の前期欄と一致」と名指す。
4. 数えるもの: 注入した site の数、engine が止めた数(止めた割合)、止めた行のうち R が名指した数(名指しの割合)、名指しの要素が注入した要素と同じ数。
5. 対照(偽の名指し): prev の**無改変**の文を P27 で判定して止まった行(VALUE_MISMATCH・UNVERIFIABLE・POINTER_NOT_FOUND)に R を当て、名指した数と割合。無改変の文の数は prev 自身の数なので、R が名指すのは偽(翌期の前期欄が偶然同じ値のときだけ正しくない名指しではないが、出所は prev 自身)。
6. 固定の確認(F-10): E01777 の 2025 年 3 月期の有報の文に、書面の 2 つの値(営業利益 1 兆 2,766 億円の桁、減価償却費及び償却費 1,125,588 百万円)を文の単位で注入し、engine が止め、R が 2026 年 3 月期の有報の前期欄を名指すか。文に該当の数の site が無ければ「site なし」と記録し判定しない。

出力: `fixtures/xbrl/restated_naming_2026-11-02.json`。

## §4 言えないこと

- 97 社は 2026 年提出の有報に偏り、業種・規模の代表ではない。前年の有報が無い会社(新規上場など)は測れない。
- 「違う」は開示の修正再表示・表示の組替え・会計方針の変更・誤りを区別しない(段 1 では理由を読まない)。
- 注入は「翌期の前期欄の値をそのまま書く」1 型で、DB の値の実際の出方(四捨五入・単位・表示)ではない。
- R は measure 側の規則で、engine には入っていない。engine の profile に入れるときは別の封(既定にしない)。
- 名指しは「翌期の前期欄と一致」までで、なぜ翌期で値が変わったかは言わない。
- EDINET からの取得は人間の鍵のある席で行い、cloud の席では行わない。取得の回数と bytes は記録に書く。費用 0 USD。

## §5 作法

- 封を先に commit(この文書) → 段 1 の script `measure/xbrl_prior_pairs_2026-11-02.py`(DEI の読み取り・API の日付一覧・ZIP の取得・要素の突き合わせ。作り物の backend で dry run できる形) → 段 1 の記録 → 段 2 の script `measure/xbrl_restated_naming_2026-11-02.py`(注入・P27・R・対照) → 段 2 の記録 → 結果 `docs/XBRL_RESTATED_PRIOR_RESULT_2026-11-02.md` → 門 `tests/measure/test_xbrl_restated_prior.py`(記録が無い席では skip。作り物の backend で段 1 の突き合わせと R を確かめる) → 独立監査 GO → path 指定で commit。
- 記録・文書・門に会社名を書かない。docID は材料の名としてだけ書く(手元の 97 は既に記録に在る。新しく取る前年の有報と E01777 の 2 書類も同じ扱い)。鍵の値・応答の中の会社名は記録に入れない。
- 覆い・台帳・README の本数は同じ便で揃える。台帳には L・P の行と、H-14 の状態の更新(測れたら「測った」に)。

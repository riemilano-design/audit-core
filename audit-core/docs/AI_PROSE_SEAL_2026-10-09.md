## 0. なぜ測るのか ― 実証と売り文句の間の未接続

| | 経路 |
|---|---|
| **今までの実証** | 人間が書いた MD&A → XBRL → Evidence Verification |
| **営業資料の売り文句** | **AI が生成した文** → Evidence Verification |

**この 2 つの間は一度も実測していない。** 測定の輪の中に LLM が入ったことがない
(資料 p9 は自分でそう書いている)。代用は型3(偽の主張の混入)だけである。

**問い:「AI 幻覚検出の話として本当に成立するのか」。**
いちばん重要な数は **「AI が作った誤った主張を GROUNDED にしてしまう件数」**。
**0 なら強い。1 件でも出たら、資料の「幻覚を捕まえる」は結果を踏まえて慎重に直す。**

## 1. この封が答えないこと(先に書く)

- **一般化しない。** 書類 1 件・LLM 1 社・1 回の生成である。
- **S100Z4Q1 は接続部の開発に使った書類。** 絶対値は買い手が見る数ではない。
  この実験が見るのは**同じ証拠・同じ profile・同じコードの上での、人間の文と AI の文の対**である。
- **LLM 間の差を測らない。** 1 社だけ回す(§2.2)。
- **封A/B とは混ぜない。** `4f9bd14` の予測は 1 文字も変えない。後段で `tol_of`・344 件・型5・
  Golden と実行経路の不一致・自動門が比べていない 4 欄をまとめて潰す(人間の裁定どおり、今回は触らない)。

## 2. 方法(実行前に固定する)

### 2.1 書類と証拠
- 書類 **`S100Z4Q1`**(人間の文の実験と同じ対象)。キャッシュに在る ZIP を使う。EDINET は呼ばない。
- **証拠は一切変えない。** AI の文は、元の ZIP の MD&A の textBlock だけを差し替えた**複製**に入れる。
  これにより **接続部(`adapters/`)も核(`core/`)も 1 行も変えずに**、人間の文と同じ経路
  (`recipes.build_raw_claims(zb, profile)`)がそのまま走る。ZIP 書き換えの前例は `fixtures/xbrl/tamper_unit.py`。
- 人間の文: `measure/material/xbrl/S100Z4Q1.original.txt`、**5,192 字**、sha256 先頭 `4e9dd890aae77f28`。

### 2.2 LLM
- **1 社だけ回す。**複数の鍵が在る場合の選び方を**今決めておく: 使える provider のうち名前の辞書順で最初**
  (claude < gemini < gpt)。**結果を見てから選び直さない。良い方を採らない。**
- 器は既存の `scripts/playtest/lib/llmClient.ts` 系と同じ扱いで、**費用上限を env から読む**。上限 **1.00 USD**。
  予想は 1 回の生成で 0.1 USD 未満。**上限が発火したら止めて人間へ返す。**
- 鍵は env のみ。値は見ない・写さない・記録しない。

### 2.3 指示文と fact の差し込み(両方固定)
- 指示文: **`fixtures/xbrl/ai_prose_prompt_2026-10-09.txt`**、sha256
  **`eeca4a1474f427538ff76ce536a84ab6c1e9a245fd5b8a8a73df916dd58b23d4`**。
- `{FACTS}` に差し込む規則(**これも固定**):元の ZIP の instance から、
  **member を持たない素の context の fact を全件**、`(要素名, context id)` の昇順で、
  **ラベル・値・単位・期間**の 4 欄で表にする。選別・間引き・並べ替えをしない。
  差し込んだ後の本文の sha256 を結果に記録する。
- **人間の MD&A を見せない。機械の門で確かめる**(§2.5 の門③)。
- **検証されることを知らせない。**「正確に」「幻覚を避けて」とも書かない(普通の依頼を再現する)。

### 2.4 実行の順序 ― **真偽の札は engine の判定より先に付ける**

7186ffc の失敗を踏まえ、**結果を見てから判定を動かせない形にする。**

1. 生成を 1 回だけ回す → AI の本文を**コミット**(sha256 を記録)。
2. **`build_raw_claims` だけ**を走らせ、**判定の付いていない**主張の一覧
   (id・文・数・単位)を作る。**ここで verify は走らせない。**
3. **独立監査が、engine の判定を見ないまま**、主張 1 件ずつに
   **真 / 偽 / 判定不能**の札を付ける(根拠は XBRL の fact)。**この札をコミットする。**
4. **その後で** verify を走らせ、札と判定を突き合わせる。
5. 司令塔は 3 の札を**見てから** 2 をやり直さない。各測定は 1 回だけ。

### 2.5 機械の門(破れたら実験は無効。やり直しは人間の判断)
- 門①: 複製 ZIP の **fact と context が元と完全一致**(`load_instance` の出力で照合)。差が 1 件でもあれば止まる。
- 門②: 差し替えたのは MD&A の textBlock **1 つだけ**(他の textBlock も一致)。
- 門③: **指示文の全文に、人間の MD&A の 20 字以上の部分列が 1 つも含まれない。**
- 門④: profile は **P7**、**人間の文と AI の文を同じ実行で**回す(片方だけ別の日に測らない)。
- 門⑤: 上限 1.00 USD。発火したら止める。

## 3. 測るもの

人間の文(P7・同じ実行)と AI の文の対で、次を数える。

| | 欄 |
|---|---|
| 1 | Claim として拾えた数(数の主張・文字の主張の別) |
| 2 | Binding できた数(`subject != None`) |
| 3 | GROUNDED |
| 4 | **誤って GROUNDED になった数** |
| 5 | UNVERIFIABLE |
| 6 | VALUE_MISMATCH |
| 7 | POINTER_NOT_FOUND |

そして §2.4 の札と組んで、**この 2×2 を出す**(営業で意味を持つのはこの表である):

| | engine が GROUNDED | engine が止めた |
|---|---|---|
| **主張が真** | 正しい通過 | **誤停止** |
| **主張が偽** | **誤った通過(幻覚の見逃し)** | **正しい停止** |

「幻覚を捕まえる」が意味するのは **正しい停止 ÷ 偽の主張の総数**。
**分母(偽の主張が何件あったか)を札で独立に数えなければ、VM や PNF の件数は何も言わない。**

### 土台(人間の文・P6・束縛修正後。P7 は実行時に測る)
**91 行 = 数 60 / 文字 31。GROUNDED 71(数 49 / 文字 22)・VM 5・PNF 7・UNVERIFIABLE 8。**
(営業資料の「72 件」は束縛修正で **71** になっている。資料側の直しが要る ― 本実験とは別件。)

## 4. 予測(1 つの表。外れは外れとして残す)

| # | 予測 | 当たりの条件 | 外れの条件 |
|---|---|---|---|
| **AI-1** | AI の文は人間の文より**数の主張が密**になる | 1,000 字あたりの数の主張が **13 件以上**(人間は 60/5,192 = **11.6**) | 11.6 未満 |
| **AI-2** | AI の文は**束縛率が高い**(定型の勘定科目名で書くため) | AI の束縛率 − 人間の束縛率 **≥ +5 点** | +5 点未満(同じ・下回るを含む) |
| **AI-3** | 束縛できた数の主張のうち GROUNDED の割合は AI の方が**高い**(照合相手そのものを要約しているため) | AI ≥ 人間 | AI < 人間 |
| **AI-4** | **誤って GROUNDED が 1 件以上出る** | **1〜6 件** | **0 件**(= 営業には良い結果)、または **7 件以上** |
| **AI-4m** | AI-4 の**経路**は、総当たり探索(`recipes.py:212`)か符号を落とす枝(`abs`) | 誤った通過の **1 件以上**がその 2 経路のどちらかを通っている | 誤った通過が出たのに **全件が別経路** → **件数は当たり・経路は外れ**(別に記録) |
| **AI-5** | AI の文には**偽の主張が含まれる** | 札で**偽が 2〜12 件** | **0 件**(→ AI-6/AI-7 は評価不能になる。それも今ここに書いておく)、または 13 件以上 |
| **AI-6** | 偽の主張を**全部は止められない** | 正しい停止 ÷ 偽の主張 が **0.5 以上 1.0 未満** | 0.5 未満、または **1.0**(全部止めた) |
| **AI-7** | **誤停止は AI の文の方が少ない**(人間の文の最大の停止原因 `no_subject` を、定型の書き方が避けるため) | AI の誤停止率 < 人間の誤停止率 | AI ≥ 人間 |

**AI-4 が 0 件なら、それは予測の外れであり、同時に製品にとって最も良い結果である。**
**外れを隠さず、売り文句の根拠として使う。**

### 観測するが予測しないもの(封A/B と混ぜないため)
- AI の文の GROUNDED が、残差の帯 (0.5, 1) に何件入るか。**封A の予測ではない。背景観測としてだけ残す。**
- 札が「判定不能」になった主張の件数と理由の型。
- AI が作った数のうち、XBRL に同じ値の fact が**偶然**存在した件数。

## §0 根拠(封の前の下調べ 2026-10-21、司令塔の席の手元の数。正本でない。scratchpad/rounding/report.md)

- いまの帯(P22 まで): 金額は書類ごとに切り捨て/四捨五入を engine が決める(`decide_rounding`)が、切り捨ては **符号つき**(負の値で「絶対値が 1 桁大きい文」を通す)。率は ±0.15 pt 固定の両側。fact の `decimals` は帯に使っていない(`tol_of` は呼び出し元なし)。P19 の旗 `truncate_on_magnitude`(切り捨てを絶対値で)と P18 の旗 `pct_tolerance_from_decimals`(率の帯を書かれた桁の半分に)は P20〜P22 に積まれていない。
- 儀式(同梱 1 書類、P21 の記録)の通した 17: 率 12 は生の値を 1 桁に四捨五入すると文の値になり注入後にはならない(±0.1 の注入が ±0.15 の帯の中)。金額 4 のうち N237・N277(負の値 △22・△780)は符号つきの切り捨てで通した、N125・N199 は前期へ移った(P22 で止まる)。N096 は 0 → 00 の退化値。
- 同梱書類に端数処理の方針の記述は無い。67 書類でも字の方針は 5 書類(切り捨て 4・四捨五入 1)しか取れず、取れない書類を四捨五入に倒すと金額 339 行(7.9%)が落ちる = **字の方針は使わない**。engine の書類ごとの判定を残す。
- fact の decimals が文の桁より粗い行は 67 書類 2,512 行・儀式 221 行で 0 = decimals で帯を広げる場面は無い。
- **封の門の実装席の発見(2026-10-21、commit 前に封を直した)**: 下調べの V3 は「書類ごとの丸め方の判定を P22 のまま固定し、切り捨ての帯だけ絶対値にし、率の帯を書かれた桁の半分」の monkeypatch で、既存の旗 2 つとは別物。P19 の `truncate_on_magnitude` は `decide_rounding` の判定の軸も変え、67 書類のうち 3 書類(S100YZ7E・S100Z38F・S100Z48T)で切り捨て → 四捨五入に反転して金額 55 行が落ちる。P18 の `pct_tolerance_from_decimals` の帯は 1 桁で ±0.06(0.5·10^-d + 0.01、recipes.py 182〜191 行)で ±0.05 ではない。本物の旗で実測: 旗 2 つ = 儀式 通した 2 / 240(N069・N096)、67 書類の代価 63(金額 55・％ 7・ポイント 1)。率の旗だけ = 儀式 4 / 240(N069・N096・N237・N277)、代価 8(％ 7・ポイント 1)、VALUE_MISMATCH 1,410 → 1,418。**司令塔の判断: 率の旗は既存のまま積み、切り捨ては「照合の帯だけ絶対値で片側」の新しい旗にする(判定は P22 のまま)= 下調べの V3 の形。**

## §3 限界

- 率の帯(1 桁で ±0.06)は、提出者が表示の桁の金額から率を出した型(下調べで 7 行)を落とす。これは代価として残す。差が 0.05〜0.06 の注入は通る(儀式の N069)。
- 退化値(0 → 00)は注入道具の欠陥で、帯では止まらない。
- P19 の `truncate_on_magnitude`(判定の軸も変える旗)は積まない。積むと 3 書類で金額 55 行が落ちる(§0)。
- 字の端数処理の方針は使わない(取れる書類が 5 / 67)。
- 前々期の値への置き換えは P23 でも通る(P22 の限界のまま)。

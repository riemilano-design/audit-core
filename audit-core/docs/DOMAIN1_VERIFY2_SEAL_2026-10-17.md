# 検証層の直しの封 ― **申告を消さない。そして「grep で足りるか」を同じ便で測る**

2026-10-17。**直しの実装より先・測定より先に commit する。**
人間の決定(2026-10-17)に従う。

> 私は、今回提案された **(1) 検証層の設計修正を先に行い、その後に
> (2) 別資料で再現性を確認する** という順序に賛成です。
>
> **ただし、単に検証器を修正して 8 件検出できるようにするだけでは不十分です。**
> 次の条件を先に固定する必要があります。
>
> * **LLM が申告した誤りを、検証器が勝手に消さない。**
> * **「誤りの存在」「誤りの種類」「本来の参照先」を別々に採点する。**
> * **検出・見落とし・偽警報・保留を独立して集計する。**
> * **同じ材料での修正結果と、未使用の別資料での結果を分けて報告する。**
>
> そして、売却判断に直結するのはその次です。**同じデータで、LLM 単体・既存製品・
> LLM + Core を比較し、Core を追加することで何が改善するのかを示すこと。**
> それが確認できなければ、買い手にとっては**自社で既存技術を組み合わせる方が
> 合理的**かもしれません。
>
> **現時点で Core が既存方式より優れていると主張できないことは明確です。**

---

## §0 **先に書く ― この便の数のほとんどは算術で決まる**

**同じ材料(2026-10-17 の 8 件の人工誤り・凍結した席の答え)を使う。**
**席の答えは commit `1ab6a79` で凍結済みで、1 文字も変わらない。**

**だから「申告を消さない」規則にすれば、検出の数が席の検出数まで戻るのは
規則から算術的に決まる。これは性能の証拠ではない。**

| この便で**算術で決まる**もの | この便で**測る**もの |
|---|---|
| **軸 1 の検出数**(席の検出を消さないので席の数に戻る) | **軸 3 本来の参照先**を何件出せるか |
| 無改変 26 件の偽警報(席も検証器も 0 件だった) | **「誤りが在る」を足し算にした代価** ― **罠での偽警報** |
| 軸 2 の種類(席の申告をそのまま使う) | **Core の機械部分が、素朴な値一致照合(grep)を超えるか** |

**だからこの便の結果に「性能」という語を使わない。**
書けるのは「**設計が通ったこと**」と「**代価**」と「**grep との差**」だけである。
**性能は未使用の別資料((2))でしか測れない**(人間の条件 4)。

---

## §1 直す規則 ― **消さない。足す**

**変えるのは合成の規則 1 か所だけ。**engine・索引・別名表・親の規則・6 欄の鍵・
正解ラベル・誤りの材料・席の答えは**1 文字も変えない。**

### §1-1 軸 1 **誤りの存在**(3 値)

| 席の答え | **C′ の軸 1** |
|---|---|
| `根拠なし` | **誤りが在る**(席の申告。検証器は上書きしない) |
| 6 欄 + 種類が `不明` 以外 | **誤りが在る**(席の申告。**検証器は上書きしない**) |
| `判定不能` | **判定できない** |
| 6 欄 + 種類が `不明` | **検証器が決める** ― 値が合わない ⇒ **誤りが在る** / 行が無い・一意でない ⇒ **判定できない** / 一致 ⇒ **確認済み** |

**席が何か言ったときは消さない。席が黙っているときだけ検証器が決める。**
**検証器が独自に見つけた不一致は足す(論理和)。**

### §1-2 軸 2 **誤りの種類**(固定語彙 6 語。**別に採点する**)

- **席の申告をそのまま使う。**
- 席が `不明` で、**検証器が不一致を見つけた**ときだけ `値が原資料に無い` を入れる。
- **検証器は `列の取り違え` などを言えない**(2026-10-17 に実測。Core 単体 2/8)。
  **言えないものを言ったことにしない。**

### §1-3 軸 3 **本来の参照先**(**別に採点する**)

- **Core の鍵が 1 通りに決まった場合だけ、その行を出す**
  (`GROUNDED` でも `VALUE_MISMATCH` でも鍵は 1 通り)。
- 決まらなければ **「無し(候補 N 通り)」**。
- **席が出した住所は「誤った値の出どころ」として別の欄に残す。**
  **2 つを同じ指標で採点しない**(2026-10-17 の私の指標の穴)。

## §2 独立して集計するもの(人間の条件 3)

**4 つを別々に数える。足し合わせた 1 つの数にしない。**

**軸 2・軸 3 は誤り 8 件を分母に、別の表で出す。**

## §3 並べる 5 方式(**既存製品は手元で測れない。代わりに grep を置く**)

| 記号 | 中身 | 費用 |
|---|---|---|
| **A** | **LLM 単体**(凍結した席の答えそのまま) | 0 |
| **B** | **Core 単体**(参考群。凍結) | 0 |
| **C′** | **LLM + Core。§1 の新しい合成**(申告を消さない) | 0 |
| **D** | **LLM + 素朴な値一致照合。席の申告を使わない** ― 金額が抜粋の値のセルに 0 件なら誤り / 1 件なら確認済み / 2 件以上なら判定できない | 0 |
| **D′** | **LLM + 素朴な値一致照合。席の申告を残す**(§1-1 と同じ合成を grep に当てる) | 0 |

**主比較は 2 つ。**

1. **C′ 対 A** ― **Core を足して何が増えるか**(人間の字)。
2. **C′ 対 D′** ― **Core の機械部分(6 欄の鍵・別名表・親の規則)が、
   grep を超えるか。**

**D・D′ は「買い手が自社で安価に組める方式」の代わりである。**
**既存製品(Google・NVIDIA・商用の照合製品)はライセンスと接続の都合で
手元で測れない。だから「既存製品と比べた」とは書かない。**
**書けるのは「素朴な値一致照合と比べた」だけである。**

## §4 限界

- 直すのは自己閉じの読み方だけ。`.htm` の経路のほかの読み取り(入れ子・継続・負の表記の format・属性の値の中の `>`)は見ていない。
- 効きを数えたのは TSS の states だけ。型の読み・注入(1b)・near・第 2 便・便 PS のサマリーの数は、直した engine で取り直していない。それらの記録は直す前の engine の数のまま残る(門は「記録の指紋 = 記録を作った時の engine・今の engine はそこから宣言された遷移 1 つだけ離れている」で留めた)。
- 旗なしなので、`.htm` の経路は全部の profile で fact が変わる。元に戻す道は commit を戻すことだけ。
- 空白の入った自己閉じ(`/ >`)は、直した式でも始まりと読む。手元の TSS の `.htm` に在るかは記録に無い(監査の席が 0 個と数えた。記録なし)。
- この直しで「短信の概況の文を engine が正しく結べる」とは言えない。変わるのは行の 1% に満たない。英文短信の側(`sales/`)は `load_instance` を呼ばないことを grep で見ただけで、数は測らない。
- 新しい封の門は、script の中の止める守り(母集団・sha256 の照合・件数の比べ・出力の拒否・`--check` の比べ など)の変異を、script の sha256 の門でしか赤にしない(数を作る配線は赤にする)。
- `--check` の全数の作り直し(材料の本を作り直す重い走らせ直し)を監査で走らせたかは確かめていない。
- 直す前の「そのまま」の行は TSS の記録と便 NR の記録を字で読んだもので、engine を戻して作り直していない。NRE-4 と NRE-5 の「直す前」だけは旧い engine の blob・式の写しで走らせた。

# 確かめる席への頼み(便 UM4)

封: `docs/UNIVERSAL_FILL_VERIFY_SEAL_2026-11-24.md` §1-2・§1-3。この紙と folder 1 つだけを席に渡す。司令塔は、頼みの頭に「folder の path」だけを足す。この紙のほかの文書(封・前の便の文書・記憶の file)は、席に渡さない・席は読まない。

## 頼むこと

別の人が、ある会社の素材から、銀行向けの説明資料に使う数の表を作りました。あなたは、その表の数を 1 行ずつ素材に当てて、根拠を確かめる役です。表を作った人のやり方・理由は渡されません。

- 渡された folder の中だけを読み、その中にだけ書く。folder の外の file・この repo の file・記憶の file は開かない。python の標準 library は使ってよい。確かめ方は自由。
- folder に在るもの: この紙・`指定.json`(当期の始まり・終わり)・`definition_A.json`(項目の id・名・単位・期・範囲)・`素材/`(架空の中小企業の経理の担当が、会計ソフトとその周りの道具から抜き出した file 一式。作り物)・`確かめる表.json`(`{"行": [{"id", "状態", "数値"}, ...]}`。`状態` は `在る`・`無い`・`分からない`)・`出どころの書き方.md`(出どころの形。**1-4 と 1-5 の節だけ**を読む。`file` は `素材/` の下の相対 path で書く)。
- `取り方` が `計算` の項目(表に在っても)は確かめない。確かめるのは `取り方` が `素材`・`素材の和` の項目の全部。

## 出すもの(folder の直下に、この名で)

`根拠の表.json` ― `{"行": [ {...}, ... ]}`。確かめる項目の全部について 1 行ずつ。1 行の欄:

- `id`
- `見立て` ― 次のどれか 1 つ。
  - 表の `状態` が `在る` の行:
    - `合う` ― その数が、その項目(名・期・単位・範囲)の数として素材から出せる
    - `合わない` ― 素材から出せるその項目の数は、表の数と違う
    - `見つからない` ― その数の根拠を素材の中に見つけられない
    - `決めが要る` ― 項目の読みが 2 通り以上在り、読みによって数が変わる。どれを採るかを決める人が要る
  - 表の `状態` が `無い`・`分からない` の行:
    - `無いで合う` ― その項目の数は、素材からは出せない
    - `在るはず` ― その項目の数は、素材から出せる
    - `決めが要る` ― 上と同じ
- `出どころ` ― `合う` の行には必ず。表の数を素材から出す道を、`出どころの書き方.md` の 1-4 の形(`素材`・`素材の和`・`表の行の和` のどれか)で書く。機械がこの出どころから数を計算し直し、表の数と比べる。ほかの見立ての行は `null`。
- `別の道` ― `合う` の行で、**別の file** からも同じ数が出せる時だけ、同じ形で書く。無ければ `null`。
- `正しいと見る数値` ― `合わない`・`在るはず` の行だけ。本当の大きさの整数の字。ほかは `null`。
- `正しいと見る数値の出どころ` ― `合わない`・`在るはず` の行だけ。上と同じ形。ほかは `null`。
- `注` ― 自分の言葉で短く(なぜそう見立てたか)。

**数が素材のどこかに在ることと、その数がその項目の数であることは別です。**項目の名・期・単位・範囲に合う数かを見て見立ててください。決められない時に `合う` と書かない。

終わったら、出した file の名だけを短く報告してください(数や中身は報告に書かない)。

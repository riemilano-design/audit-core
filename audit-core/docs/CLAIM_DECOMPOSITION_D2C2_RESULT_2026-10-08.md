# D-2c-2 の結果 ― gold-02 は別の型だった。ずれは 5 つの型に分かれる

2026-10-08。封じた予測は [CLAIM_DECOMPOSITION_D2C2_PLAN_2026-10-08.md](CLAIM_DECOMPOSITION_D2C2_PLAN_2026-10-08.md) §3
(M-1〜M-5)。**予測は書き換えていない。費用 0 円。**

## 1. いちばん大事なこと ― 実測の span は「行の境界」にぴったり揃っている

```
行の開始:   [0, 35, 36, 76, 110, 143, 171, 210, 252, 287, ...]
実測 span: [(0,34), (36,75), (76,109), (110,142), (143,170), (171,209), (210,251), (252,286)]
```

**gold-02 では、実測の span 8 件すべてが行(=文)の境界と一致している。** ずれているのは**正解の側**で、
正解は 2 か所で**文より狭く**取っている。

| # | 正解 | 実測 | 型 |
|---|---|---|---|
| 1 | **[0, 8]**「今回の 20 局」 | **[0, 34]**「今回の 20 局について、時間の使い方と指し手の内訳をまとめました。」 | **粒度**(正解は句、実測は文。開始は同じ) |
| 2 | **[36, 61]**「序盤で 1 手に 30 秒以上かけた場面は 7 回」<br>**[62, 74]**「中盤では 11 回でした」 | **[36, 75]** × 2 件(value 7 と 11) | **まとめ方**(正解は 1 文を 2 claim に割る。実測は 1 span を値ごとに 2 件) |

**gold-04 の「定数 −4 の数え違い」とは、まったく別の型である。**
gold-02 の実測は 1 文字もずれていない ― **噛み合っていないのは「claim の span は文か句か」という決め方**である。

## 2. 新しく見つかった 2 つの型

### 型 4: 母集団の昇格(gold-04 と gold-02 の**両方**で出た)
```
原文: 「後手が同じ場所へ 2 回続けて駒を動かした局は、20 局のうち 4 局です。」
正解: 1 件(aggregate, value 4)  ― 20 局は母集団
実測: 2 件(direct_value value 20 + aggregate value 4)
```
**D-2c-1 で gold-04 に見つけた型が、gold-02 にも在った。1 本の偶然ではない。**
`CLAIM_CONTRACT_SPEC_v0.2.md` の修飾 `population` に当たる数を、LLM は独立した Claim として出している。

### 型 5: span が合っても form と value が外れる(精度の落ち)
```
原文: 「駒を取る手は、指し手全体の 15.0 % を占めます。」
正解: aggregate / value 15.0
実測: direct_value / value 15     ← span は [143,170] で完全一致
```
**span が合った 6 件の中にも、form と value が外れているものがある。**
`15.0` を `15` と読み、`aggregate`(全体に対する割合)を `direct_value`(そのまま書いてある数)と見た。
**これは「form 12/37」の一部を説明する** ― span を直しても form は直らない。

### ただし 5 つのうち 2 つは、予測になっていなかった(自己評価)
**M-1 と M-3 は、封じる前に手元にあった数から決まっていた。**
- M-1: gold-02 は span 交わり 6/9 だと**既に知っていた**。定数ずれなら 0/9 になるので、
  「別の型」はその時点で確定していた。**外れようがない。**
- M-3: 外れた span が `(0,8)・(36,61)・(62,74)` だと**既に知っていた**(D-2b の結果 §2 に書いてある)。
  長さ 8・25・12 は引き算で出る。**測る前に答えが出ていた。**

**本当に外れうる粒度で書けていたのは M-2・M-4・M-5 の 3 つだけ。** 3/3 当たりである。
「5/5 当たり」と書いて済ませると、予測の力を過大に見せる。**粗い欄を当たりに数えない。**

## 4. ずれの 5 つの型(ここまでの観察の総まとめ)

| 型 | 中身 | 見つかった本 | 直し方の向き |
|---|---|---|---|
| 1 | **位置の数え違い** ― 長さは正しく、定数でずれる(−4) | gold-04 | **LLM に位置を数えさせない。本文を返させて照合する** |
| 2 | **粒度** ― 正解は句、実測は文 | gold-02 | **仕様の決め(人間)。「claim の span は文か句か」** |
| 3 | **まとめ方** ― 正解は 1 文を 2 claim に割る、実測は 1 span を値ごとに複数 | gold-02 | 同上(型 2 と同じ決めの裏表) |
| 4 | **母集団の昇格** ― `20 局のうち 4 局` の 20 を独立 Claim に | gold-04・**gold-02** | 指示文 + schema(修飾 `population` を使わせる) |
| 5 | **精度の落ち** ― span は合うが form と value が外れる(`15.0`→`15`、`aggregate`→`direct_value`) | gold-02 | 指示文(form の決め方) |

**型 2 と型 3 は、D-2a で「span の粒度」を 2 通りに読める形で書いた前科と同じ場所である。**
あのとき「数のある文を 1 claim として」と書き、2 通りに読めると自分で記録した。
**その曖昧さが、いま実測として現れている。**

## 5. 次に何をするか(人間の判断)

### 順位が変わった ― いちばん上は「人間が決めること」になった

> **「claim の span は文か句か」を人間が決める。**

**これを決めないと、正解集合と実測が噛み合わない。** そして**これは LLM の誤りではない。**
- 実測は gold-02 で 8/8 が行の境界に揃っている ― **機械として一貫している。**
- 正解集合は独立の 3 人が書いたもので、**2 か所で文より狭く取っている。**
- **どちらが正しいかは、将来この Claim を何に使うかで決まる**(証拠へのポインタを付ける単位)。**仕様の決めであって、測定では決まらない。**

**費用 0 円で、決めれば型 2 と型 3 が同時に消える。** 直す対象が正解集合側か指示文側かも、この決めで決まる。

### 決めた後の順番(司令塔の推し)

| 順 | やること | 費用 |
|---|---|---|
| 1 | **粒度を決める**(人間)。決まったら、どちらの側を直すかが決まる | 0 円 |
| 2 | **過剰生成 26 を 5 つの型で割る照合器** ― **箱がもう決まった**(型 1〜5) | 0 円 |
| 3 | **位置を数えさせず本文を返させる**(型 1 が丸ごと消える) | 0 円で作れる・測るのに実 run 1 回 |
| 4 | **母集団の昇格と form の決め方を指示文 + schema に書く**(型 4・5) | 同上。3 と束ねて実 run 1 回 |

**3 と 4 は束ねて 1 回で測る。** 別々に測ると実 run が 2 回になる。
**2 を先にやる理由**: 割ってから直すと、直した後に「どの型が減ったか」が数で言える。
割らずに直すと、合計が動いただけで**どの型に効いたか分からない。**

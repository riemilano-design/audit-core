[CORE_CONNECTION_C2_PLAN_2026-10-06.md](CORE_CONNECTION_C2_PLAN_2026-10-06.md)(封 `82a1ab0`)§8 の 4 点に、人間が同日に答えた。本文は変えない。

| § | 問い | 決定 | 添えられた条件 |
|---|---|---|---|
| 8.1 | 範囲 = H-9 の並走再現 | **YES** | これ以上広げない。将棋の全分析の Core 化まで入れると C-1g との実験の目的が混ざる |
| 8.2 | `h9_reference.ts` を audit-core の中に置く | **YES** | **監査専用・参照専用として隔離**する。Core が TS に依存するのではなく、TS の既存 H-9 → 参照 ↔ 比較 ← Python Adapter → Core という**独立したオラクル**として使う |
| 8.3 | 1 回目の出力に観測の値を書く | **YES** | 照合に要る値(対局の数・群の名前・Claim の value・pointer・state)は出す。自然言語の文は出さない |
| 8.4 | 反証の観測 108 件を数える | **YES** | 「108 件を Core に検証させる」のではなく、**今回の入力母集団に含めた観測の Claim として数え、packetRef が無いので UNVERIFIABLE になる**扱いを保つ。母集団を都合よく削らないため |

**人間が C-2 で証明できると認めた範囲**(これより広く読まない):

1. 将棋側の既存 H-9 の意味(観測 → packetRef → canonical 一致 → 結果)を Adapter で取り出せる。
2. Core の既存 `verify_all` で同じ結果を再現できる。
3. Core を将棋固有に変えなくてよい。

213/213 の一致を「Core の汎用性の証明」と読まない(本文 §7 の但し書きのとおり)。

**人間が一番見たい点**: 予測 P-11「修飾が 321 件とも空」。XBRL では population・time_range・normalization が実際に出たのに、将棋の H-9 の断面では要らない。同じ Claim の構造で、Adapter が返す意味の濃さが違っても処理できるかを見る。**ただし「修飾は将棋では不要」と一般化しない** ― 言えるのは「H-9 という狭い断面では空だった」まで。

**順序**: C-1g(実装 → 凍結時点で 3 書類を 1 回 → ID 照合 → 監査 → コミット → 結果文書)を完了させてから C-2 に入る。崩さない。

# 別資料での再現性の封 ― **grep で代替できる範囲が、別の資料でも同じかを測る**

2026-10-17。**取得より先・材料を作るより先・生成より先に commit する。**
人間の決定(2026-10-17)に従う。

> 私の判断は、**(2) の別資料での再現性検証に進むべき**です。
> **ただし、目的は Core の優位性を証明することではなく、今回見えた
> 「grep で代替できる範囲」と「Core でしか出せていない情報」の差が、
> 別資料でも残るかを確認することです。**
>
> **(2) を実施する際の条件**
> * **採点基準と予測を、生成前に封印してコミットする。**
> * **比較の中心は C′ 対 D′ とし、検出数だけでなく、本来の参照先の正確性を測る。**
> * **別資料を使い、今回の人工誤りへの調整と、別資料でも通用する能力を区別する。**
> * **予算は上限 3 USD を目安とし、超過が必要なら実行前に再判断する。**
> * **結果が悪くても、基準を変更して救済しない。**
>
> なお、**Google や NVIDIA などの既存製品に対する比較は、この試験では実証できません。**
>
> これは**売却価値を高く見せるための試験ではなく、買い手が安価に代替できる範囲を
> 絞り込み、あなたの Core に対価を払う合理性が残るかを判断するための試験**です。

**測るのは差の再現である。**
**「Core が優れている」と書くための封ではない。**

## §3 採点基準(**生成前に封印する**。人間の条件 1)

**2026-10-17 の `verify2` と同じ**。**1 文字も変えない。**

| 軸 | 中身 |
|---|---|
| **軸 1 誤りの存在** | 誤りが在る / 確認済み / 判定できない(**排他**) |
| **軸 2 誤りの種類** | 固定語彙 6 語。**席の申告。検証器は言えないものを言わない** |
| **軸 3 本来の参照先** | **Core の鍵が 1 通りのときだけ出す。正解ラベルの行と一致するかを測る** |

**集計は独立に 4 つ**(検出 / 見落とし / 保留 / 偽警報)。**罠は別記。**

### §3-1 **比較の中心は C′ 対 D′**(人間の条件 2)

| 記号 | 中身 |
|---|---|
| **A** | 席そのまま |
| **B** | Core 単体(参考群) |
| **C′** | 席 + Core(**申告を消さない**) |
| **D** | 席 + 素朴な値一致照合(**申告を使わない**) |
| **D′** | 席 + 素朴な値一致照合(**申告を残す**) |

**主比較は C′ 対 D′。**
**検出数だけで結論しない。軸 3(本来の参照先)の正確性を必ず並べる**(人間の条件 2)。

### §3-2 **「今回の材料への調整」と「別資料でも通用する能力」を分ける**(人間の条件 3)

**2026-10-17 に私が決めた所を 1 つずつ挙げ、別資料で同じ数が出るかを対応表で書く。**

| 記号 | 2026-10-17 に私が決めた所 | 別資料で確かめること |
|---|---|---|
| **K-1** | 合成の規則(**席の申告を消さない**) | **別資料でも D → D′ で検出が増えるか** |
| **K-2** | 列の表層形の表(`予算現額 / 予算現在額 / 計` 等) | **別資料の報告文でこの表が当たるか。当たらなければ正解集合が減る** |
| **K-3** | 誤りの型と割り当て規則 | **別資料で 8 件そろうか** |
| **K-4** | 検証器の到達定義(**M-3′**) | **別資料でも M-3 と M-3′ で数が変わるか** |
| **K-5** | 罠(`R035` = 文面の「マイナス」) | **別資料に同じ形が在るか。無ければ「無かった」と書く** |

**K-1〜K-5 のどれかが別資料で崩れたら、それは「今回の材料への調整だった」ことの
証拠である。隠さずそう書く。**

## §5 費用(**上限 3 USD を目安。超えるなら実行前に止める**。人間の条件 4)

| 生成 | 見込みの上限(全部が出力だと仮定) |
|---|---|
| 報告文 1 本(`sonnet`) | **1.24 USD**(段 11 の実測 82,529 トークンから) |
| seat1(`sonnet`) | **1.52 USD**(誤り検出の実測 101,111 トークンから) |
| seat2(`haiku`) | **0.35 USD**(実測 70,493 トークンから) |

**3.11 USD は人間の目安 3 USD を超える。だから生成の前に止めて人間に再判断を求める。**
**0 USD の工程(取得・構造の確認・抜粋・索引・下見の費用)を先に済ませ、
そこで実測に近い数を出して報告する。**

**人間が選べる形を 2 つ用意する**(どちらを採るかは人間が決める)。

| 記号 | 形 | 見込みの上限 |
|---|---|---|
| **費-1** | 段 11 と同じ構え(報告文 `sonnet` + 2 席) | **3.11 USD** |

**走らせたら実測トークンを記録し、同じ式で上限を出す。超えたら打ち切る。**

| 条件 | 判定 |

## §7 示せないこと(**先に書く**)

1. **同じ発行者・同じ構成の別年度である。**
   **別の自治体・別の様式での再現性は測っていない。**
2. **人工の誤りである。**実際の文書で起きる誤りの分布は測っていない。
3. **既存製品(Google・NVIDIA・商用の照合製品)は測れない。**
   比べるのは**素朴な値一致照合(grep)**だけである。
4. **誤りを示唆する問いの下での席の答えである。**
5. **軸 3 の件数が顧客にとってどれだけの値打ちかは測っていない。**
6. **報告文は LLM が 1 回書いたものである。**実際の自治体の報告文ではない。
7. **売却可能性は測れない。**
   この封は「**買い手が安価に代替できる範囲を絞り込む**」ためのものである。

## §8 手順

1. **この封を commit する。**(取得より先)
2. 取得(5 file。**一度だけ**。失敗は失敗として記録)。**commit する。**
3. **構造の確認**(parse が通るか。**費用 0**)。**落ちたら止めて書く。**
4. 抜粋・索引・下見の費用を出す(**費用 0**)。**commit する。**
5. **人間に報告し、費-1 / 費-2 のどちらで走らせるかの判断を得る。**
6. 生成(報告文 1 本 → 誤りを植える → 席)。**やり直しなし。**
7. 採点(5 方式 × 3 軸)。**別の文書に結果を書く。**同じ材料の表に混ぜない。

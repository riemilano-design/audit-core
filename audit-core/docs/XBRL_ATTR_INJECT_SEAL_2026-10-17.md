# 封 ― **単位・期間・次元の注入試験。穴が実際に誤通過を生むかを測る**

2026-10-17。人間の指示(優先順位 02「正しい参照先の属性を 1 つずつ変え、Core が誤って
検査通過にするかを測る。**対照群を置き、結果を見る前に予測を封印する**」)。

**この封は実測より先に commit する**(順序は門で確かめる)。
**engine は 1 行も変えない。規則を増やさない。0 USD・席は呼ばない。**

---

## §0 目的

棚卸し(`docs/XBRL_VERIFY_INVENTORY_2026-10-17.md`)で、
`verify` は **実在と値しか見ない**ことを人工の探りで示した。
**この封が足すのは「実材料の上で、その穴が何件の誤通過を生むか」である。**

**穴の存在を示すだけでは足りない**(人間の指示: 単位・期間・次元の穴が
**実際に何件の誤通過を生むかは分からない。だからこそ、まず測る**)。

---

## §1 二部構成

### 第 1 部 ― **属性を 1 つだけ変えた fact を注入する**(人工)

基準は **contract v1 で検査通過した 24 行**
(`fixtures/xbrl/cd8/contract_v1_2026-10-17.json` の `**B′ の最終判定**` = `検査通過`)。

各行について、**正しい参照先と同じ値を持つ fact を、属性 1 つだけ変えて instance に足し**、
**その新しい key を参照先として** contract v1 の入口に渡す。

| 枝 | 変えるもの | 期待(封の時点では**予測**) |
|---|---|---|
| **対照** | 何も変えない(元の参照先) | `GROUNDED`。**ここが GROUNDED でない行は無効にする** |
| **単位** | `unit` を `JPY` → `USD` | ? |
| **期間** | context を `CurrentYear*` → `Prior1Year*`(新しい枠) | ? |
| **次元** | context に `_TestMember` を足す(新しい枠) | ? |

**変えるのは注入した fact の属性 1 つだけで、値は変えない。**
**主張(値・単位・種類)も変えない。**
**`GROUNDED` が返れば「誤って検査通過にした」= 穴が発火した**と数える。

### 第 2 部 ― **注入しない実材料での露出**

**注入せずに**、24 行それぞれの参照先について、
**同じ値(±許容)を持つ兄弟 fact** が instance に何件あるかを、3 つに分けて数える。

| | 数えるもの |
|---|---|
| **別の期間** | 同じ要素名・**別の期間の枠**・同じ値 |
| **別の次元** | 同じ要素名・**次元が違う枠**・同じ値 |
| **別の単位** | 同じ要素名・**単位が違う**・同じ値 |

**これが「値の照合では捕まらない取り違え」が実データに何件あるかの代理指標である。**

## §3 予測(**実測より先に固定する。結果を見てから変えない**)

| 記号 | 予測 | 外れる条件 |
|---|---|---|
| **Q-1** | 対照 = **24/24 が `GROUNDED`** | 1 行でも違えば外れ(その行は無効にする) |
| **Q-2** | **単位**注入 → **24/24 が誤って検査通過** | 1 行でも止まれば外れ |
| **Q-3** | **期間**注入 → **24/24 が誤って検査通過** | 1 行でも止まれば外れ |
| **Q-4** | **次元**注入 → **24/24 が誤って検査通過** | 1 行でも止まれば外れ |
| **Q-5** | 第 2 部「別の期間に同じ値」= **1 行以上** | 0 行なら外れ |
| **Q-6** | 第 2 部「別の次元に同じ値」= **1 行以上** | 0 行なら外れ |
| **Q-7** | 第 2 部「別の単位に同じ値」= **0 行** | 1 行でも在れば外れ |
| **Q-8** | 注入で `POINTER_NOT_FOUND` や `実証不能` になる行 = **0 行** | 1 行でも出たら外れ |

**Q-2〜Q-4 は「穴が在る」という予測である。**当たっても**新しい発見ではない**
(棚卸しで人工の 1 件ずつでは既に示した)。**この封の新しい数は第 2 部(Q-5〜Q-7)である。**

## §4 この封で測れないこと(先に書く)

1. **人工の注入は「穴の存在」を示すが、「実務で何件起きるか」ではない。**
   第 2 部がその代理指標だが、**LLM が実際に期間や次元を間違える頻度ではない。**
2. **誤通過の件数は、注入を作った私の手で決まる。**だから第 1 部の数を
   「危険度」として引用しない。**危険度は第 2 部の露出で語る。**
3. **24 行は contract v1 が通した行である。**通らなかった行の穴は測らない。
4. **同じ 8 書類である。**

## §5 判定基準

- **第 1 部で誤通過が 1 件でも出れば、穴は実在する**(直すかどうかは別の判断)。
- **第 2 部の件数が修正の優先度を決める材料になる。**
  **0 件でも「放置してよい」とは書かない**(人間の指示: 今回問題がなかったから
  放置するのではなく、別途確かめる)。
- **「第 1 層を直すべき」と書かない。**この封は**測るだけ**で、
  直すかどうかは結果を見て人間が決める。

- **席を呼ばない。**0 USD。
- **注入した fact を repo に残さない**(instance の fact 一覧を記憶の中で足すだけ)。

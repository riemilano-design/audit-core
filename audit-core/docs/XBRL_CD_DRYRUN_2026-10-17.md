# 第 3 層 解釈(**ここから先は解釈である**)

## §3-1 いま分かったのは「設計のままでは買えない」ということ

**金額の問題と、標本の問題が同時に出た。**

- 15 USD は目安の 5〜6 倍。
- **その 15 USD で測れる軸3 の標本は小さい**(参考書類では T5 の合計が 64 件、
  書類あたり 0〜29 件)。
- **費用の 87% は fact の一覧**で、これは**どの腕にも必要な共通の入力**である
  (削ると D′ の検索対象も狭まり、**比較対象を弱く見せることになる**)。

## §3-2 人間に決めて頂くこと(**私は決めない**)

| | 中身 | 費用 | 失うもの |
|---|---|---|---|
| **(ア)** | **先に 0 USD で「Core 単体 対 D′・D″」だけを測る**(席を呼ばない)。使用済みの書類で、参照先の特定率と誤認定率を機械だけで比べる | **0 USD** | 「LLM + grep 対 LLM + Core」ではない。未使用データの主張もできない |
| **(イ)** | **書類を 1〜2 件に減らして封のまま回す** | 1.8 〜 4.6 USD | 軸3 の標本が 0〜29 件。**0 件の書類を引く可能性が在る** |
| **(ウ)** | **T5 が作れる書類に限る**(封じた並びの先頭から T5 ≥ k の書類を取る規則を**先に**書く) | 取得 0 USD + 生成分 | 標本が「T5 が作れる書類」に偏る。**そう書いて報告する必要が在る** |
| **(エ)** | **8 書類のまま 15〜18 USD を使う** | 14.67 〜 18.47 USD | 目安の 5〜6 倍 |

**併せて `EDINET_API_KEY` を渡して頂く必要が在る**(新しい 8 件はまだ取れない)。

**私は (ア) → 結果を見て (ウ) を推す。**理由は 2 つ。

1. **(ア) は 0 USD で「Core は D″ に何を足しているか」の有無が分かる。**
   そこで差が 0 なら、**15 USD を使う理由が消える**(買い手の問いに答えが出る)。
2. **(ウ) は「軸3 を測れる標本」を先に確保できる。**(イ) は 0 件を引く賭けである。

**ただし (ア) は未使用データの主張にはならない。**
**「代替できる範囲」の切り分けには使えるが、「別の書類でも通用する」とは言えない。**

## §4 示せないこと

1. **構造は使用済みの書類で測った。**新しい 8 件の本文・`refs` の件数は違いうる。
2. **注入していない。**site の数は「作れる機会」であって注入の結果ではない
   (記憶 `opportunity-in-material-does-not-mean-it-fires`)。

4. **T5 の正解は、改変前の文で値が一意に当たった ref である。**

### §5-4 **削って効くのはどれか(数で比べた)**

## 2. REVISE の理由 ― `identified` の 1 件が型 5 の条件を満たしていない

監査は依頼書 (b)(`identified` が 0→1 に動いた 1 件を 1 件ずつ読む)で、**`S100Z4B6` の 1 件が
型 5 の条件を満たしていない**ことを見つけた。司令塔が独立に再現した実測:

```
S100Z4B6  identified = 1
  トークン: 「50,000」 unit='千円'  (= 5千万円)
  原文の行: 「…短期貸付による支出50,000千円などによるものであります。」
  結ばれた参照: OtherCL@Prior1YearInstant_NonConsolidatedMember
                 value = 50000  unit = '円'  label = 'OtherCL'(その他の流動負債)
```

**桁が 1000 倍違う。** 原文の 5千万円が、前期・非連結の「その他の流動負債 50,000 **円**」に結ばれている。
原因は `lib/sites.py` の `_matches()` / `_value_index()` が、**千円・百万円・億円という接尾辞の倍率を
一切掛けずに、原文の数字リテラルと XBRL の生の値(素の円)を直接比べている**こと。
`_unit_compatible` は両方 `money` 族なので通る。

型 5 は「**真の参照が正しく特定されたうえで**、別の事実の値が偶然一致する」型である。
ここでは真の特定そのものが誤りなので、**この 1 件は型 5 ではない。件数が嘘になっていた。**

もう 1 件(`S100YMFV`)は正当だった:

```
S100YMFV  identified = 1
  トークン: 「69.64」 unit='円'  原文「1株当たり当期純利益は69.64円」
  結ばれた参照: BasicEarningsLossPerShareSummaryOfBusinessResults@CurrentYearDuration
                 value = 69.64  unit = '円'   ← 真の参照として正しい
```

### この欠陥の大きさ(司令塔が独立に測った ― 隅の事例ではない)

| 書類 | 千円/百万円/億円 を持つ量のトークン | 生の値で参照と一致 | **桁を掛けて参照と一致** |
|---|---|---|---|
| `S100Z4Q1` | 2 | 2 | 0 |
| `S100Z4B6` | **61** | **1** | **29** |
| `S100YMFV` | 51 | 1 | 1 |

**`S100Z4B6` では、正しく結べる 29 件を落として、誤って結んだ 1 件だけを採っていた。**
(`S100YMFV` が 1 件しか増えないのは、この書類が本文で百万円に丸めて書くため、桁を掛けても
XBRL の生の値と**厳密一致しない**から。丸めの許容は別の話で、ここでは測っていない。)

`data_bearing` を入口に持つ **型 1 も同じ土台の上にある。** `S100Z4B6` の `data_bearing` 20 件は、
金額のトークン 61 件のうち生の値が偶然一致した 1 件を含み、桁を掛ければ一致する 29 件を含まない。
**型 1 の現場一覧(3/20/8)も、この欠陥の上に建っている。**

### 監査が併せて見つけた潜在の欠陥(今回の数には実害なし)

`prepare_material.py` の `"円" if (unit or "").upper().startswith("JPY") else ...` は、
実在する `unitRef="JPYPerShares"` も「円」に丸める。司令塔が 3 書類の ZIP を独立に展開して確認:

| 書類 | `JPY` | `JPYPerShares` | `pure` | `shares` |
|---|---|---|---|---|
| `S100Z4Q1` | 716 | **41** | 139 | 52 |
| `S100Z4B6` | 967 | **40** | 161 | 50 |
| `S100YMFV` | 840 | **41** | 130 | 67 |

`unit_family('円') == unit_family('千円') == 'money'` なので、**「1 株当たりの金額」と「総額」が
同じ族として比較可能になっている。** 今回の 2 件は自己整合していた(`S100YMFV` の件は真の参照・
借用候補とも 1 株当たり指標)ので**実害は出ていない**が、別の書類ではいつでも再発しうる。
これは依頼書が探せと指示した「単位の族の表の抜け」そのものである。

## 3. 適用した帰結

### 決定 1 ― 型 5 は「道具の不備で未測定」として凍結する(XBRL・将棋の両方)

人間の事前のしきい値(1 書類 5 件以上)を当てる前に、**件数そのものが信頼できない**ことが分かった。

- 直した後の `t5` は 0 / 1 / 1。
- そのうち `S100Z4B6` の 1 件は**型 5 ではない**(§2)。有効な候補は `S100YMFV` の 1 件のみ。
- どちらの数え方でも 5 件に届かないので、**決定 (b)(型 5 は将棋だけで測る)の維持は変わらない。**
- さらに 3 回目の REVISE により、**型 5 は将棋でも「道具の不備で未測定」として凍結する。**
  型 5 は `identified_sites` を入口に持ち、`identified_sites` は参照一覧に頼るからである。

**書くべき文言:** 「型 5(値が偶然一致して参照先が違う)は、機械で作る道具に金額の桁を揃える処理が
無いため、件数が信頼できない。有価証券報告書・将棋のどちらでも**未測定**とする。
人の盲検確認で観測された型 5 の例は 3 件(T008・T022・T031、通った文字の主張 22 件のうち)あり、
これは別の経路(人が読んだ結果)で得た数であって、混入実験の検出率とは混ぜない。」

### 決定 2 ― 実 run は参照一覧に頼らない型だけで行う = **型 2(単位のずれ)のみ**

追加 2 の依存表(監査が間接依存まで検算済み)により、参照一覧に頼らないのは **`t2_sites` だけ**である。

| 型 | 入口 | 参照一覧への依存 | 実 run |
|---|---|---|---|
| 型 1(数字の置換) | `data_bearing_sites` | **有**(値の一致で現場を選ぶ) | **除外** |
| 型 2(単位のずれ) | `t2_sites` | **無**(226–252 で `refs` 未使用) | **採用** |
| 型 3(原文に無い数) | `t3_sites` + `build_t3` の `_ref_values` | **有**(入れる値が参照に無いことを確かめる) | **除外** |
| 型 5(偶然一致) | `identified_sites` | **有** | **除外・凍結** |
| 期間・母集団の入れ替え | `human_sites` | ― | 人が作る(344 件・未測定のまま) |

**これは実験の幅を大きく狭める。** 混入実験で測れるのは「単位のずれを止められるか」だけになり、
検出率は**単一の型についての数**になる。事前に決まっていた帰結なのでそのまま適用するが、
**この狭まりは結果文書の見出しに書く。**

現場の件数(帯は無く実測): 型 2 は `S100Z4Q1` 11 / `S100Z4B6` 77 / `S100YMFV` 87。
`inject.py` の `TYPES_BY_KIND["xbrl"]` は既に `["T2_UNIT", "T3_ABSENT"]` なので、
**実 run では `--types T2_UNIT` で型 3 も外す。**

### 測った事実 ― 将棋の冊子はこの欠陥に当たらない(が、凍結は維持する)

自分の記憶「0 件に理由を付けるときは自分の道具の欠陥を先に潰す」に従い、
将棋側も推測せず測った。

```
c5_round5_booklet.md: 数のトークン 242 → 量 149
  単位の分布: None 93・局 19・秒 16・手 13・局面 5・分 3
  千円/百万円/億円 を持つトークン: 0 件
```

**金額の桁を持つ単位は 0 件なので、§2 の欠陥は将棋側では発火しえない。**
それでも型 5 を将棋でも凍結するのは、`identified_sites` のもう一方の経路
(単位を持たないトークン 93 件が、ラベル語の裏取りだけで同定される)を今回測っていないからである。
**測っていないものを採用しない。** 人間が将棋側の型 1・型 3・型 5 を生かすと決めるなら、
その経路を先に測る段が 1 つ要る。

## 4. 直さないと決めたもの(と、その理由)

**金額の桁を揃える処理は、今は作らない。**

1. 直しても人間のしきい値(1 書類 5 件以上)に届く見込みが薄い。`S100Z4B6` で桁を掛けて一致するのは
   29 件だが、そこから「ラベルが違う・値が違う・桁比 10 倍以内」の借用候補が在る件だけが型 5 になる。
   `S100YMFV` は丸めのため 1 件しか増えない。**増える保証が無い。**
2. 桁の変換は、`adapters/xbrl` を使わない独立実装であるこの階層の設計方針そのものに関わる。
   `adapters/xbrl/instance.py` から借りれば**測定が循環する**(測る対象と測る道具が同じコードになる)ので
   借りられない。
3. 人間が事前に代替路を決めている。**追加の実装と監査の往復を増やさず、代替路を採る。**

監査も独立に同じ結論を推した(「追加の実装・監査往復のコストに対して合理的」)。

**ただし、これは「直せない」ではなく「今は直さない」である。** 必要な直しは記録しておく:

1. トークンの単位が千円・百万円・億円のとき、倍率(×1,000 / ×1,000,000 / ×100,000,000)を掛けてから
   参照の値と比べる。比較側で単位の族と桁の両方を見る。
2. `JPYPerShares` を `JPY` と別の族にする(「1 株当たり」と「総額」を混ぜない)。
3. 本文が丸めて書く場合(百万円)の許容を、書類単位で 1 つ決める。
4. 1〜3 を入れたら、`identified` / `t5` / `data_bearing` / `t1` を**全部再測定**する
   (今回の 3/20/8・0/1/1・3/20/8 は、この直しの前の数として残す)。

## 3. この回でいちばん重要な発見 ― 指標が弱い

**(a) span 一致は、単独で読むと何も意味しない。**
句点で切って 1 文 1 claim を出すだけの規則で **32/37(86 %)** 取れる。
D-2b で LLM の span 一致が 90 % でも、それは情報を持たない。

**規律(D-2b への申し送り)**: span 一致を単独で引用しない。
必ず `actualOnly`(過剰生成)と `expectedOnly`(見落とし)を併記する。

**(b) uncovered は、貪欲な戦略の前では常に 0 になる。**
照合器は正しい(監査が独立に確認)。基準線は「ASCII 数字を含む文には必ず claim を作る」ので、
自身の uncovered は構造的に必ず空になる。

**含意(D-2b への申し送り)**: **LLM が同じ貪欲戦略を取れば、D-2b の uncovered もほぼ 0 に落ちる。**
uncovered が測るのは「claim を作らなかった(見逃した)数字入りの文」であって、
「作った claim の中身が正しいか」ではない。**value / form 一致と必ずセットで読む。**

**(c) したがって、実力が出るのは value(8/37 = 22 %)・form(3/37 = 8 %)である。**
`derived_value` 0/9・`aggregate` 0/17・`threshold` 0/3 ― 素朴な規則は**導出値・集計・閾値を 1 件も当てられない。**
これが D-2b で LLM が超えるべき下限である。

## 4. 監査が独立に見つけたもの

監査は司令塔の 7 本とは別に **14 本**の変異を当て、**10 本赤・3 本黙り**。
黙った 3 本(`span` 側の `.sort()` 除去 2 系統・`spanKey` の区切り文字除去)は、
**記録した数値(1 回目・2 回目とも)を汚染していない**ことを個別に確認済み
(並び順だけの問題 / カンマ区切りは数字に現れないため単射性が保たれる)。
D-2a の M3(採点結果が実際に壊れていた)とは質が違うため、REVISE にはしていない。

**推奨 2 件(D-2b の前に足す)**
- 入力の順序を乱して `span.*` / `uncovered.*` が文書化された昇順で返ることを確かめる試験
- `spanKey` の区切り文字が数字を分離する役割を明示する試験(`[1,23]` と `[12,3]` を別に扱う)

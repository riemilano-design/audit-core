### 2.1 外れ 4 件は 2 つの根しかない

**根 1(A2・A3)― 依存を表に書いて、そこで止めた。**

計画 §2 の依存表に、私は自分で「(f) I-2 の kind 免除 → 依存するもの: **同じ Golden の面**」と書いた。(e) については同じ依存から**設計を変えた**(版を記録自身の `schemaVersion` で解決する)。**(f) については表に書いて完了扱いにし、Golden を rc=0 と予測した。**

工程 v3 (4) は依存を**見つける**力はあったが、見つけた後に止まる穴があった。依存の列挙と、依存から出る予測は別の作業である。表を埋めると「確かめた」気持ちになるが、表は材料で、予測が結論である。

**→ 工程の直し(第 3 版 (5))を `docs/AGENT_PROTOCOL.md` に足した。** 依存の表は**行ごとに「この依存から出る予測」の欄を持つ。欄の無い行は未完了**である。設計変更で依存を消した行は「消した」と書く。封じる前に、表の行数と依存由来の予測の欄の数が合っているかを数える。

**根 2(A4・A8)― 集合は当たり、件数が外れた。これは工程 v3 (2) が効いた実例である。**

A4 で予測したのは t1〜t9 の**識別子の集合**であり、9 件の挙動はすべて実装された。外れたのは「新しい `it()` が 9 本」という**件数**で、実際は t8 が既存の試験への assertion 追加になったため 8 本だった。A8 の 1 件のずれも同じ原因である。

もし件数だけで予測していたら「2387 と 2386 で 1 件外れた」で終わっていた。集合で予測したので、**どの要素がどう実現されたか**まで分かり、「仕様としては全部在る・数え方が違う」と言い切れる。**工程 v3 (2) の「件数ではなく識別子の集合で予測する」は、この封で初めて役に立った。**

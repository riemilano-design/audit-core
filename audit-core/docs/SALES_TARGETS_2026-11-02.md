## §1 Cabocia 株式会社(いちばん近い相手。商談はまだ無い)

検索で分かったこと(出典: 同社の「トレーサビリティとデータ品質」のページの検索要約、ASCII・テレビ東京のプレス記事の検索要約、企業情報サイト):

- 主力は **EDINET DB**: 上場企業の有報の XBRL を構造化し、Web・API・MCP で出す財務データの基盤。財務の数値は「決定論的に parse し、抽出・名寄せ・集計のどこにも LLM を使わない」と自分で書いている。各データ点に docID を持たせて EDINET の原本まで辿れる設計。
- **AI 要約(ai_summary)は 2026-08-06 に提供を終了**した、と同社のページにある。理由は「自由記述の LLM 出力では幻覚をゼロにできず、社内の検証で、財務の表に無い数値を本文が断定する例を確認した」こと。API では 2026-11-19 まで凍結した値を deprecated として返す。
- 残る AI の利用は補助の欄(有報の要約・決算説明会・事業タグ・決算説明資料からの数値抽出)で、専用の表に分離。LLM 出力は **原文との突合(grep_verify)で、原文に無い数値は破棄**する、とブログにある。
- 他の事業: AI 活用支援(導入設計・運用・研修)、EC 分析 AI(Amazon・楽天・Shopify・Yahoo!ショッピング)。これが「XBRL 以外の領域」。
- 本社は東京都港区。共同代表の名が記事にある。

**読み**: 同社は「数値は LLM に触らせない」「LLM の文は原文突合」まで自力で来ている。Audit Core が足すのは、その先の 2 つ。(a) 文の数が**どの fact か**を指すこと(字の存在だけでは、別の期・別の要素・別の単位の同じ数字を通す。台帳の D-01 の注入の保留がこれに当たる)。(b) 期・単位・次元の違いで**止める**こと。同社が止めた AI 要約を、claim ごとの判定つきで**戻せる**かどうかが、相手にとっての価値。

**EC 分析 AI への展開**: 出所が構造化された売上の表なら engine の形(文の数 → 出所の値 → 帯で比べる)は同じだが、XBRL の adapter は使えない。新しい adapter と材料が要る。先に有報で足場を作ってから。

**言うこと**: 相手の 3 本(AI の文)が届いたら、封 → 記録 → 結果の形で claim ごとの判定を返す。無償で 1 本、有償の PoC で残り。同社の grep_verify と Audit Core の判定を**同じ文で並べる**表が、いちばん短い説明になる。

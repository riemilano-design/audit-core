## §1 中身(`report_customer.py` だけ)

1. **ラベルの読み方**: `fixtures/xbrl/taxonomy_labels_sha256.txt` に `jpigp_2025-11-01_lab.xml`(2,593,515 バイト、sha256 `d45c95cc634202973557f5ed935d747ba25e751b7386c5269fe3e7bdb2c82d09`、取得元 `http://disclosure.edinet-fsa.go.jp/taxonomy/jpigp/2025-11-01/label/jpigp_2025-11-01_lab.xml`、人間の許可 2026-10-21「取って良い」)を足し、`TAXONOMY_LABELS_README.md` に取り方を 1 行。module は**名簿に在る file 名だけ**を読み、sha256 が合わない file は使わない(使わなかったことを provenance に書く)。名簿に無い file は folder に在っても読まない。jpigp の file は実装の便で標準の folder に戻す。
2. **(a) 単位**: 文の値は span の中で claim の値と同じ金額の字をそのまま出し、出典の値は同じ単位・同じ書き方に直す。語の主張は span の中でいちばん近い金額の字の単位、無ければ書類で最も多い単位。同じ金額の字が無い行は claim の単位のまま出し、読み取れない行として数える。
3. **桁**: 出典の値は文の書いた桁に丸めた字を先に、丸める前の値を括弧で後に(例「61 百万円(61.274)」)。
4. **符号**: 出典の値が負なら「△」で書く(日本の財務諸表の書き方)。符号の判定は変えない。
5. **(c) 英字**: 要素・区分の字は、名簿の標準ラベル(jpcrp・jppfs・jpigp)と書類の ZIP の `XBRL/PublicDoc/*_lab.xml`(書類自身のラベル)から引く。CLI に `--zip`。
6. **(d)** 「違う」の意味の欄に「文の誤りか、当てた出典の誤りかは決めない」。
7. **(e) 指紋**: sha256・engine の指紋・profile・道具・ラベルの sha256 は本文から外し、同じ名前の `.provenance.json`(本文の sha256 を含む、key を並べ時刻なし)に出す。本文の末尾は「…は同じ名前の `.provenance.json`(機械用)に置いた。」の 1 行だけ。本文と json のどちらも同じ入力から同じバイト列。
8. **表題**: `--zip` があれば書類の DEI(提出者名・書類の種類・当期の期末日)から「<提出者名> <書類の種類>(<期末日>)の数の点検」。無ければ今の字。
9. **抜粋**: 対象外・判断しないの抜粋は数の字の途中で切らない(切るなら数の前か後)。

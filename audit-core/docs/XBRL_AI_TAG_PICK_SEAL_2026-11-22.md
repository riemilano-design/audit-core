## §2 規則

### §2-1 席に送る行と、席に渡す字

- **行の順**: 書類の順(file 名の順)→ 書類の中の file の順(便 XG1 の `doc_texts` の返す組を昇順に並べた順)→ file の中の行の順(便 XG1 の `file_rows` の返す順)。
- **送る行(本番)**:
  - 類 A の行: 本番の 62 本の類 A の行を上の順に並べ、0 から数えた番号が 8 で割り切れる行(2603 行のうち 326 行)。
  - 類 W の行: 本番の 62 本の全部(68 行)。
  - 合わせて 394 行。違えば止める。
- **送る行(試し)**: 開発の 5 本の類 A の行を上の順に並べた頭の 5 行。
- 類 U(候補が 1 つで答えと同じ)と類 N(候補が無い)には送らない。
- **渡す字**:
  - **見出し** = 便 XG1 の `file_rows` がその行に付けた見出し。無ければ `(なし)`。
  - **前の行** = 同じ file の中でその行より前に在る行(`file_rows` の返す全部の行。類を問わない。見出しをまたいでよい)の字(便 XG1 と同じ `_row_label` → `norm_label`)のうち、空でないものの**後ろから 12 個**を、上から順に ` / ` でつなぐ。1 つも無ければ `(なし)`。
  - **この行** = その行の字(同じ読み。便 XG1 の T)。
  - **候補** = 段 3 の候補の要素の名(便 XG1 の返す字のまま)を並べ、1 から番号を振って 1 行に 1 つ(`1. 名`)。**主の席には昇順・副の席には降順**で並べる。
- 値・期・単位・後ろの行・ほかの file の字・要素のラベルは渡さない。
- 1 行につき席ごとに 1 回の呼び出し。

### §2-2 指示文(字で留める。system は無し = user の 1 message。封の門が照らす)

`{HEADING}`・`{PREV}`・`{ROW}`・`{CANDS}` を §2-1 の字で置き換える。ほかは 1 字も変えない。

```

表の見出し: {HEADING}
この行より前の行(上から順): {PREV}
この行: {ROW}
候補:
{CANDS}

答えは 1 行だけ、「答え: 3」の形で候補の番号を書いてください。候補の中に正しい要素が無いと考えるとき、または渡した字だけでは 1 つに決められないときは「答え: 0」と書いてください。説明は書かないでください。
```

### §2-3 答えの読み方

- 返った text(type が text の block をつないだ字)を NFKC にかけ、`答え` の後ろの `:` に続く最初の整数を読む(間の空白は落とす)。`答え` が 2 つ以上在れば最初の 1 つ。整数が 0 以上・候補の数以下のときだけ答えとする。
- 読めない・範囲の外・text が 0 字・stop_reason が `end_turn` でないときは、同じ指示文でもう 1 回だけ呼ぶ。それでも読めなければ、その席のその行は **答えなし**。
- 答えを司令塔が手で直さない。席の text を読んで規則を足さない。
- 番号は、その席に渡した並びで要素の名に戻す。席どうしは要素の名で比べる。

### §2-4 行ごとの席の札と、通す規則

- **席の札**(行ごと・席ごと): 「正」= 選んだ要素が書類の要素(便 XG1 の E)と同じ・「誤」= 別の候補を選んだ・「0」= 答えが 0・「答えなし」。類 W の行には「正」は無い(候補の中に答えが無い)。
- **通す規則 P1(主の席だけ)**: 主の席が 1 以上の番号を答えた行を通す。ほかは止める。
- **通す規則 P2(2 席の一致)**: 主の席と副の席がどちらも 1 以上の番号を答え、要素の名が同じ行を通す。ほかは止める(0・答えなし・食い違い)。
- 「止める」は「人が見る行に回す」の意味で、この便では数えるだけ。

### §2-5 数えるもの

1. 類 A(326 行)・類 W(68 行)のそれぞれで、席ごとの札の数(正・誤・0・答えなし)。
2. 類 A・類 W のそれぞれで、P1・P2 の、通した行の数・通した行のうち誤の数(**誤って通した数**)・止めた行の数・止めた行のうち主の席が正だった数(止めすぎ)。
3. 類 A で、主の席が誤の行のうち P2 が止めた数。
4. 類 A を、候補の数の帯(2・3〜6・7 以上)と計算書の種類(貸借・損益・キャッシュフロー・種類なし)に分けた、1〜3 の数。
5. 並べる 2 行(類 A): **何もしなかったら** = 「でたらめに 1 つ選ぶ」の期待の正の数(行ごとの 1 ÷ 候補の数の和)と、「昇順の頭の候補を選ぶ」の正の数。**完璧に動いたら** = P2 が 326 行を全部通して誤 0・類 W の 68 行を全部止める。
6. 呼び出しの記録: 席ごとの回数・やり直しの回数・答えなしの数・入力と出力の token の合計・USD(§3 の単価で)・返った block の type の並びの種類・stop_reason の種類。試しの 10 回は別に書く。

### §2-6 記録に書かないもの

行の字・見出しの字・前の行の字・要素の名・値・会社名・証券コード・EDINET コード・docID・file の名・席の返した text そのもの。行ごとに書くのは、書類の番号(file 名の順)・類・候補の数・計算書の種類・席ごとの札・その行の指示文の sha256・呼び出しの数だけ。指示文の型(§2-2 の字)と §2-2 の例は記録に書いてよい。送った文と返った text は、追跡しない置き場(`~/.cache/audit-core/ai_tag_pick_2026-11-22/`)にだけ置く。

## §3 席・回数・上限・下見・試し(字で留める)

- **席**: 主の席 = `claude-sonnet-5-5`・副の席 = `claude-haiku-5-5`。
- **呼び出しの形**: `max_tokens` 100・`temperature` の欄は送らない(便 LX の実測: 送ると HTTP 400)・思考の指定は主の席 `{"type": "between_tools"}`・副の席 `{"type": "disabled"}`(便 LX と同じ字)。API の版・やり直し(429 と 5xx に最大 2 回)は便 LX と同じ字。
- **回数**: 本番 394 行 × 2 席 = 788 回・試し 5 行 × 2 席 = 10 回。§2-3 のやり直しは 1 行 1 席につき 1 回まで。
- **上限**: 5 USD(この便の全部。試し・やり直し・中断した呼び出しを含む)。走らせる前の見積り(入力の字数 × 1.0 を token とみなし、出力は `max_tokens` の全部。単価は入力 5 USD・出力 25 USD / 100 万 token の保守的な字。試しの 10 回 + 本番の 788 回で。やり直しは見積りに入れない)が上限を超えたら 1 回も呼ばずに止まる。走っている間も、使った額(返った usage で。返らなかった呼び出しは見積りの額で)が上限に届いたら止まる。
- **鍵**: 環境変数 `ANTHROPIC_API_KEY` だけから読む。値は印字・記録・例外の文に通さない(記録は書く前と書いた後に検査する)。走らせるのは司令塔だけ。
- **下見(0 USD)**: `--dry-run` は鍵を読まず通信せず、本番と同じ関数で全部の指示文を組み、行の数・指示文の字数の合計・見積りの額・配線の確認を出す。作り物の transport(返事は実物の API の返事の形)で、答えの読み方・やり直し・上限で止まることを本番と同じ道で通す。
- **試し(有料。上限の内)**: 全部の前に、試しの 5 行を 2 席に 1 回ずつ(10 回)だけ呼び、HTTP の状態・stop_reason・返った block の type・text の字数・答えが読めたかを見る。**見るのはその形だけ。答えの中身で指示文を直さない。** 形が悪い(text が 0 字・思考の block が `max_tokens` を食う・HTTP 400)ときに直してよいのは思考の指定と `max_tokens` だけで、直したら日付つきの別の file に書いてから本番を走らせる。指示文(§2-2)は直さない。試しの答えは本番の数に入れない。
- **送り先**: Anthropic の API だけ。送るのは公開されている開示書類の表の行の字と、公開されている標準の要素の名。

## §4 分母

- 類 A は 2603 行のうち 8 行に 1 行(326 行)。率は 1 行で 0.3 ポイント動く。帯に分けるとさらに小さい。
- 類 W は 68 行の全部。うち候補が 1 つの行が 56 行。
- **送る行は答えを使って選んでいる**(類 A = 候補の中に答えが在る・類 W = 無い)。実際に紙を書く場面では、行が類 A か類 W かは分からない。本番の 62 本での比は 2603 対 68 で、この便の 326 対 68 は類 W を多く取っている。**2 つの類を足した率は書かない。**
- 類 U(12444 行)・類 N(387 行)は送らない。「全部の行のうちどれだけ正しく書けるか」はこの便では測らない。

## §6 限界(結果の文書の頭に書く)

- 行の字は提出済みの書類の字。**AI や人がこれから書く紙の字ではない。** 候補は便 XG1 の絞りの結果で、絞りが答えを落とした行は類 W に入っている。
- 「正」は「提出済みの書類の要素と同じ」の意味。書類の要素が正しいことは確かめていない。
- 送る行は答えを使って選んだ(§4)。8 行に 1 行。有報だけ・67 本は無作為でない。
- 指示文は司令塔が書いた。盲検でない。別の指示文・別の渡す字なら数は変わる。
- 席と司令塔は同じ系統の model。2 つの席も同じ系統で、一致には系統の癖の一致が混ざる。
- 席の答えは呼ぶたびに変わりうる。数は 1 回の呼び出しの記録で、繰り返しの幅は測らない。model の版が変われば同じ数は出ない。
- 測るのは要素の選びだけ。文脈(期・連結か単体か・member)・単位・符号・表の外の fact・文章の fact・提出者別タクソノミの要素を新しく作る判断は測らない。
- engine は変えていない。

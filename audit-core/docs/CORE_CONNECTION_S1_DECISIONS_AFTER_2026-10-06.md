# S-1 の後の人間の決定(2026-10-06)

> 出典: [S-1 の結果](CORE_CONNECTION_S1_RESULT_2026-10-06.md) §6 の 3 つの問いと、[C-1h の結果](CORE_CONNECTION_C1H_RESULT_2026-10-06.md) §4 の「一致」の定義。人間が決め、司令塔の付け足し 4 点を「進めて」で採用した。

| # | 問い | 決定 | 条件・付け足し |
|---|---|---|---|
| 1 | Golden の期待値 `docs/golden_master/c5_expectation.json` を S-1 の新しい現状(H-9 NG 8)で書き直すか | **GO** | 旧 Golden → S-1 の 1 回目 → 差の記録 → 人間承認 → 新 Golden の順。1 回目と差の一覧(`s1_first_run_diff.txt`・`s1_first_run_compare.json`)は消さない。`--write` は 1 回だけ。`note` に「NG 8 を現状として固定した。判定ではなく記録」の 1 行を足す(後から rc=0 を読む人が NG 8 件を緑と誤読しないため) |
| 2 | S-2 = E-3・I-4(本番の門)にも packet を渡すか | **GO。予測が先** | S-2 の価値は H-9 の再現ではなく「Core 化した検証の結果が最終出口までどう伝播するか」。予測は 2 層: 仮説 ID 単位(NG 8 件が E-3 で封筒ごと落ちるのか行ごとか、I-4 で統合の入力から何件消えるか)と顧客の出口の単位(g8 の冊子の sha が何冊変わるか、本編のどのページか)。本番の門に触るので監査 GO 無しに承認しない |
| 3 | 20 件の元(席が `names` の配列を「A+B+C」に潰す 18・数の差 2)を席の指示文で直すか | **GO。原因を個別に確かめてから予測** | 18 件: まず**潰したのが席か、席に渡した seat_input の描画か**を 1 件読んで分岐を決める(描画なら指示文を直しても直らない)。表示だけの問題か、後段の Claim の束縛を壊す情報損失かを区別する(C-2 では形の名前に関する主張の束縛が切れて VALUE_MISMATCH になっている)。2 件: 原文と packet を 1 件ずつ並べて原因を分類 → 予測 → 実装 |
| 4 | 3 社目の期待値を作る条件「一致」の定義 | **(i) 集合の完全一致を維持** | 「予測外を人間が説明できたから採用」を許すと予測の評価基準が後から緩む。予測 → 実測 → 差 → 人間の原因説明までは残すが、「説明できたから当たり」にはしない。**帰結(司令塔が先に書き、人間が異論なし)**: 規則は段ごとに適用されるので、次に 3 社目が「予測 0 件・実測 0 件」で止まる段が来れば空集合同士の一致として期待値を作れる。その期待値は「現状の固定」で「予測の当たり」ではなく、T028 の外れは C-1h の結果に残る |

**共通の線**: Core は触らない(S-1 でも動いたのは Golden の配線だけで、Core 側に要求は出ていない)。

**順序**: S-1 閉じ(済み `c2708ed`/`97af3b8`)→ Golden 更新 → 18+2 件の原因読み(読むだけ)と S-2 の予測を並行 → S-2 の封 → 実装。

**人間の読み(記録)**: S-1 の最大の成果は 213/213 より「Core で見つかった 21 件が、実際の将棋の Golden Master にも同じ観測単位で現れた」こと(Adapter の抽象化が机上でなかった)。H-11 の外れは「観測の値に名前がある」と「文に名前が出る」の混同という**予測の意味定義の誤り**が露出したもので、次の予測の材料になる。

# 封 ― **最小の検証規則(contract v1)。LLM が渡し、Core が規則で照合する**

2026-10-17。人間の決定(「次は contract の設計に進む。いきなり 24 件すべてや
リンクベースではなく、**最小の検証規則から**」)。

**この封は実装・実測より先に commit する**(順序は門で確かめる)。
**0 USD・席は呼ばない**(凍結した答えを使う)。

---

## §0 作るもの(人間が指定した 4 点そのまま)

1. **LLM から Core へ、主張・参照先・必要な参照先の本数を渡す。**
2. **主張の種類ごとに比較規則を定義する。**
3. **規則が無い場合は、引き続き「実証不能」とする。**
4. **同じ条件で A / B / C を再比較し、検証可能な範囲が増えたか、
   誤通過や誤拒否が増えていないかを測る。**

---

## §1 入口の形(**新しい部品はここだけ**)

新しい file を 1 つ足す ― `adapters/xbrl/verify_external.py`。

```
要求 = {"種類": <主張の種類>, "値": <数>, "単位": <字>,
        "参照先": [<xbrl の key>, ...]}
応答 = {"state": GROUNDED | VALUE_MISMATCH | POINTER_NOT_FOUND | UNPROVABLE,
        "規則": <使った規則の名>, "未検査属性": [単位, 期間, 次元, 重複],
        "reason": <規則が無い等の理由>}
```

**比較の算術は 1 つも新しく書かない。**`audit_core` に**登録済みの comparator**
(`equals_within`・`diff(a-b) equals_within`・`pct_change(cur,prior)`)と
`vocabulary.UNIT_SCALE` をそのまま使う。
**新しいのは「外から来た主張と参照先から Recipe を組む」入口だけである。**

**既存の経路を 1 行も変えない** ― `recipes.py`・`verify_document.py`・
`resolve.py`・`comparators.py`・`core/py/audit_core/*` は**触らない**(sha を門で固定)。

---

## §2 規則の表(v1。**これだけ**)

| 主張の種類 | 必要な参照先 | 使う comparator | 条件 |
|---|---|---|---|
| **単一の値(金額)** | **1 本** | `equals_within` | 単位が `UNIT_SCALE` に在る金額(千円・百万円・億円・兆円・円) |
| **差分** | **2 本** | `diff(a-b) equals_within` | 同上 |
| **変化率** | **2 本** | `pct_change(cur,prior)` | 単位が率(`%`・`％`) |
| 上のどれでもない | ― | ― | **規則が無い → `実証不能`** |

**`%` の単一の値に規則は与えない**(率は 2 本要る)。**`実証不能` のままにする。**
**規則を増やさない。**増やすなら別の封。

---

## §3 測るもの(**役割を替える実験と同じ 4 軸 + 覆い**)

| 記号 | 測るもの | 分母 |
|---|---|---|
| **R-1** | 誤った参照先を「検査通過」にした件 | 検査通過になった行 / 注入の行 |
| **R-2** | **正しい主張を「不一致」にした件** | 無改変の行 |
| **R-3** | 実証不能の件数と内訳 | 全 192 行 |
| **R-4** | 最終判定の正確性(A 対 B 対 **B′**) | 注入 64 と 無改変 128 を別々に |
| **R-5** | **検証を試みられた行(覆い)** | 席が参照先を名指した 85 行 |
| **R-6** | 2 本要る規則の発火 | その規則を使った行 |

**合成規則は役割実験の封(`docs/XBRL_ROLE_SWAP_SEAL_2026-10-17.md` §1)と同じ字を使う。**
**判定の対応表を変えない**(変えると A との比較が別物になる)。
`POINTER_NOT_FOUND` は引き続き `実証不能` に写すが、**件数を別に数えて記録する。**

## §4 封の前に数えた分母(**開示する。結果ではない**)

席が名指した 85 行の単位。

| 単位 | 行 | v1 の規則 |
|---|---|---|
| 千円 | 37 | **単一の値(金額)** |
| 百万円 | 31 | **単一の値(金額)** |
| ％ | 17 | **無し(実証不能)** |

**だから「検証を試みられる行」は最大 68 である**(85 − ％ 17)。

**凍結した席の答えは参照先を 1 本しか持たない。**
**したがって 2 本要る規則(差分・変化率)はこの材料では 1 件も発火しない。**
**実装はするが、発火は人工の試験でのみ確かめる**(§6 の予測 P-6)。

---

## §5 この封で**測れないこと**(先に書く)

**B′ は検出も偽警報も動かせない。**理由は材料の構成である。

- 席が参照先を名指した 85 行の判定は **`確認済み` 41(無改変)・`誤りが在る` 44** で、
  **`判定できない` は 0 行**である。
- 合成規則は **`誤りが在る` を上書きしない**。
- **よって注入の検出(51/64)と偽警報(2/128)は、定義上 A と同じになる。**

**動きうるのは 3 つだけ** ― **検査通過の件数(覆い)**・**R-2(誤拒否)**・**R-1(誤通過)**。
**この実験は「覆いと誤拒否の交換」を測るものである。**精度の改善は測れない。

## §6 予測(**実装より先に固定する。結果を見てから変えない**)

| 記号 | 予測 | 外れる条件 |
|---|---|---|
| **P-1** | 検証を試みられた行 = **68**(千円 37 + 百万円 31) | 違えば外れ |
| **P-2** | R-1(注入が検査通過)= **0 件** | 1 件でも出たら外れ |
| **P-3** | **R-2(無改変で不一致)は 0 件から増える。1〜15 件** | 0 件、または 16 件以上なら外れ |
| **P-4** | 検査通過は **10 行から増える**(= 覆いが増える) | 10 行以下なら外れ |
| **P-5** | 検出 = **51(A・B と同じ)**、偽警報 = **2(同じ)** | 違えば外れ |
| **P-6** | 2 本要る規則の発火 = **0 件**(実物)。**人工の試験では発火する** | 実物で 1 件でも発火したら外れ / 人工で発火しなければ外れ |
| **P-7** | 実証不能は **129 行から減る** | 減らなければ外れ |
| **P-8** | `POINTER_NOT_FOUND` が **1 件以上**出る(席が実在しない key を名指した行) | 0 件なら外れ |

**P-5 は「同じ」の予測である。**当たっても**上回ったとは書かない。**

## §7 判定基準

- **B′ が B より良いと書けるのは、覆いが増え、かつ R-1 と R-2 が増えないときだけ。**
- **R-2 が増えたら、それは代価である。**「覆いが増えた」とだけ書かない。
  **両方を同じ表に並べる。**
- **R-1 が 1 件でも出たら、覆いが増えても「進める」と書かない。**
- **検出・偽警報が A と同じであることを、改善の根拠にしない**(§5)。

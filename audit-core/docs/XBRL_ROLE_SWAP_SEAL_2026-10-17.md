# 封 ― **役割を替える実験(A / B / C)。現行 Core のまま、直さずに測る**

2026-10-17。人間の決定(「先に役割を変えた実験をやる。単位・期間・次元の修正も、
contract の拡張も、リンクベース取得も、その前にはやらない」)。

**この封は実測より先に commit する**(順序は門で確かめる)。
**engine は 1 行も変えない。0 USD・席は呼ばない**(席の答えは凍結済みを使う)。

---

## §0 この実験が答える問い

> **現行 Core を実証担当に置くだけで、LLM 単独より信頼性が上がるのか。
> それとも追加修正が不可欠なのか。**

**「とにかく動かす」ではない。**上回らなかったときに、
**何が原因だったか**(未検査属性か / contract 不足か / 意味的裏づけか)を
分けて記録することが目的の半分である。

---

## §1 3 つの腕

| 腕 | 中身 |
|---|---|
| **A** | **LLM 単独。**凍結した席の答え(`判定` と `参照先`)をそのまま |
| **B** | **LLM が特定し、現行 Core が実証する。**席の `参照先` を Core の recipe に差し替えて `audit_core.verify` を呼ぶ。**席の申告は上書きしない**(併記する) |
| **C** | **正解データによる独立監査。**封じた注入記録(`true_ref_key` 等)で A と B を採点する |

**B の合成規則(先に字で固定する)**

| 席の判定 | Core の結果 | **B の最終判定** |
|---|---|---|
| `確認済み` | 検査を通過(`GROUNDED`) | **検査通過** |
| `確認済み` | `VALUE_MISMATCH` | **不一致** |
| `確認済み` | 検証できない | **実証不能** |
| `誤りが在る` | 何であれ | **誤りが在る**(席の申告を残す。Core の結果は併記) |
| `判定できない` | 何であれ | **実証不能** |
| 参照先を名指していない | ― | **実証不能** |

## §2 人間が指定した 3 つの固定条件

1. **`GROUNDED` の意味を限定する。**出力の語は **「検査通過」**とし、
   **「正しい」とは書かない。**各行に**未検査属性**を明示する ―
   **単位・期間・次元(連結区分)・重複の 4 つ**
   (根拠は `docs/XBRL_VERIFY_INVENTORY_2026-10-17.md` §2)。
2. **contract が無い行を隠さない。****実証不能として残す。**
   **実験を成立させるために contract を足さない。**別集計で件数を出す。
3. **差分・率の主張(参照先が 2 本要る行)を別集計にする。**
   1 本で検証できる主張と混ぜない。

---

## §3 測るもの(**分母を字で書く**)

| 記号 | 測るもの | 分母 |
|---|---|---|
| **R-1** | **誤った参照先を「検査通過」にした件** | (a) 検査通過になった行 / (b) 注入の行 |
| **R-2** | **正しい主張を「不一致」にした件**(誤拒否) | **無改変の行**(主張は真。だから不一致は誤り) |
| **R-3** | **実証不能**の件数と内訳 | 全 192 行。内訳は「名指さない / contract が無い / 主張が無い / 2 本要る」 |
| **R-4** | **最終判定の正確性(A 対 B)** | 注入 64 行(検出)と 無改変 128 行(偽警報)を**別々に** |
| **R-5** | 検査通過の覆い | **無改変で席が `確認済み` と言った行** |
| **R-6** | 差分・率の行(別集計) | その行だけ |
| **R-7** | contract が無い行(別集計) | その行だけ |

**R-4 の正しさの定義(先に固定)**: 注入の行は `誤りが在る` が正しく、
無改変の行は `確認済み`(B では **検査通過**)が正しい。
**`実証不能` はどちらでも「正しい」に数えない。**安全側だが、当たりでもない。

## §5 この材料では測れないこと(**先に書く**)

**A の危険な誤通過は 0 件である**(注入 64 行で `確認済み` と言った行は 0。
`fixtures/xbrl/cd8/score_2026-10-17.json` の A の見逃し 0/64)。
**したがって「B が危険な誤通過を減らす」ことはこの材料では示せない。**
示せるのは **B が誤通過を増やさないこと**と、**B が何を実証不能に落とすか**である。

## §6 予測(**測る前に固定する。結果を見てから変えない**)

| 記号 | 予測 | 外れる条件 |
|---|---|---|
| **P-1** | R-1 = **0 件**(検査通過になった行に注入の行は 1 つも無い) | 1 件でも注入の行が検査通過になったら外れ |
| **P-2** | R-2 = **0 件**(無改変の行で不一致になる行は無い) | 1 件でも出たら外れ |
| **P-3** | B の検出(注入 64 行)= **51 件。A と同じ** | 52 件以上でも 50 件以下でも外れ |
| **P-4** | B の偽警報(無改変 128 行)= **2 件。A と同じ** | 違えば外れ |
| **P-5** | B の実証不能 = **150 行**(名指さない 107 + 名指したが検証できない 43) | 違えば外れ |
| **P-6** | 検査通過 = **10 行**。**すべて無改変** | 違えば外れ |
| **P-7** | R-5 の覆い = **10 / 41**(無改変で席が `確認済み` と言った行) | 違えば外れ |
| **P-8** | 差分・率の 7 行と contract が無い 24 行は**全部 実証不能** | 1 件でも別の判定になったら外れ |

**予測が全部当たっても「B が A を上回った」とは書かない。**
P-3・P-4 は「**同じ**」の予測である ― **同じなら上回っていない。**

## §7 判定基準(**人間が定めた 4 軸をそのまま使う**)

1. **誤った参照先を実証済みとして通した割合**(R-1)
2. **正しい参照先を誤って拒否した割合**(R-2)
3. **実証不能として適切に止めた割合**(R-3)
4. **LLM 単独と比べた最終判定の正確性の差**(R-4)

- **B が A を上回る**と書けるのは、**R-4 の検出が増えるか、偽警報が減るか**のどちらかが
  起きたときだけである。**等しいなら上回っていない。**
- **危険な誤通過(R-1)が増えたら、他が良くても「継続」と書かない。**
- 上回らなかったときは、**原因を 3 つに分けて数える** ―
  **未検査属性(単位・期間・次元)** / **contract 不足** / **意味的裏づけの不足**。

## §8 やらないこと

- **engine を直さない**(単位・期間・次元・contract・リンクベース、どれも触らない)。
- **正解データで調整しない。**合成規則・分母・予測はこの封で固定済み。
- **実験を成立させるために contract を足さない**(§2 の 2)。
- **席を呼ばない。**0 USD。
- **新しい指標を足さない。**判定は §7 の 4 軸。

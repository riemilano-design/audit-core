# 封: 期間・単位の保留規則((d) と同じ型)― **判定仕様と予測だけ。実装はしない**

2026-10-19。(d)(`docs/XBRL_DIM_HOLD_SEAL_2026-10-17.md` → `docs/XBRL_DIM_HOLD_RESULT_2026-10-17.md`)と
同じ型で、**属性注入で 100% 通った残り 2 つの穴(期間・単位)**に保留規則を当てる。
属性注入の結果(`docs/XBRL_ATTR_INJECT_RESULT_2026-10-17.md`): 単位 24/24・期間(注入)18/18 が誤って通過。
実データの露出は期間 0/24・単位 0/24。

**engine(`core/`・`adapters/`)は変更しない。**規則は `measure/` に置く。**0 USD・席は呼ばない。**
**目的は精度の向上ではない。**危険な通過は既に 0/24(contract v1)。
**測るのは「注入した穴を通さなくなるか」と「正しい参照先を何件保留にするか(代価)」だけ**である。

## §1 規則は 2 つ(**互いに独立。1 つの欄に混ぜない**)

### §1-1 規則 P ― 同額の期間兄弟が在れば保留

参照先 1 本の主張について、**(1)〜(5) をすべて満たす**とき発火する。

1. contract v1 の比較器の結果が **`GROUNDED`**
2. 渡された参照先が instance の fact **ちょうど 1 件** `f` に解ける
3. 別の fact `g` が同じ instance に在り **`g.name == f.name`**
4. **`dim_of(g.context) == dim_of(f.context)` かつ `g.context != f.context`**
   ― 次元の部分が同じで枠が違う = **期間の部分だけが違う**。`dim_of` は (d) の
   `measure/xbrl_dim_hold_rule_2026-10-17.py` の関数を**そのまま import**する
5. **`g.unit == f.unit`** かつ **`abs(g.value - f.value) <= tol`**。`tol` は (d) と同じ
   `tol_of(単位)` = `UNIT_SCALE[単位]`(新しい閾値を作らない)

**発火したら `UNPROVABLE`、`held=True`、理由 `ambiguous_period:<件数>`。**
(状態名は (d) と同じ食い違い: 封の語は `UNVERIFIABLE`、Core の既存の名は `UNPROVABLE`。新しい名を作らない。)

### §1-2 規則 U ― 主張の単位の種類と fact の単位の種類が違えば保留

1. contract v1 の比較器の結果が **`GROUNDED`**
2. 渡された参照先が fact ちょうど 1 件 `f` に解ける
3. **主張の単位の種類** `claim_class(単位)`:
   `百万円 / 千円 / 億円 / 兆円 / 円` → `JPY`、`% / ％` → `pure`、それ以外・`None` → **`None`(判定しない)**
4. **fact の単位の種類** `fact_class(f.unit)`: `JPY` → `JPY`、`pure` → `pure`、
   **それ以外は字のまま**(`shares`・`JPYPerShares`・`USD` …)、`None` → `None`
5. **両方が `None` でなく、かつ違う**とき発火

**発火したら `UNPROVABLE`、`held=True`、理由 `unit_class_mismatch:<claim_class>/<fact_class>`。**

**U は兄弟を数えない。**渡された fact 自身の単位を見る(属性注入の「単位」の枝は
**注入した USD の fact を指させて通した**ので、兄弟ではなく参照先そのものの属性で止める)。

### §1-3 合成 ― (d) → P → U の順に当て、**どれかが発火したら `UNPROVABLE`**

- 3 つの規則は**それぞれ v1 の応答に独立に当て、発火を別々に記録する**。
- 最終状態は「3 つのうち 1 つでも発火 → `UNPROVABLE`」。理由は発火した規則の理由を `;` で連結(順は d, P, U)。
- **`GROUNDED` 以外の状態は 1 文字も変えない。参照先を増やさない・選び直さない**((d) 封 §3-2 と同じ)。

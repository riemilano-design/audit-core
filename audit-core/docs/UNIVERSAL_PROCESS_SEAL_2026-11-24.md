# 封: 便 UM3 ― 便 UM2 と同じ素材を、型も検査も持たない普通の AI の席に資料まで作らせ、作る過程を便 UM2 の過程と並べる

- この文書は封。実装・席の走り・記録・門はまだ無い。engine(`core/`・`adapters/`)は 0 行。便 UM2 の封・script・記録・結果の文書も 0 行。
- 出どころ: 人間の言葉(2026-11-24)。「同一素材を普通のAIエージェントに処理させ、その作成過程をAudit Core利用時の過程と比較することで、資料生成における判断・処理方法・失敗原因を発見し、Audit Coreの改善に繋がる知見を得る」「主目的は性能の勝敗ではなく、普通のAIエージェントの作成過程から、資料生成の効率化・精度向上・取りこぼし防止に繋がる具体的なヒントを発見すること」「条件・記録方法を事前に封印し、結果を見て評価基準を変更しない」。便の名(UM3)も人間の言葉。
- **7 段のどこに当たる便か**: どの段も作らない。便 UM2 が作った 1〜7 段(B)の横に、段に分けない席(A)を置き、行ごとの結果と、作る過程の数を並べる。出るのは、次に 1〜7 段のどこを直すかの手がかり。
- **費用**: API は呼ばない(0 USD)。席は全部この PC の Claude Code の subagent。鍵は使わない。
- 結果を見てからこの封も予測も書き換えない。補足は日付つきの追記か結果の文書に書く。

### 1-3 席の数と回

### 1-4 行ごとの照合(答えを知っている側)

- 正解は便 UM2 の `正解/正解.json`(素材を作った席が書いたもの。0 字)。id と正解の鍵の対応は便 UM2 の集計 script の対応を写す。素材の行は 1 社 1 期 30(a01〜a30)。1 期目 240(4 社 × 2 回 × 30)・2 期目 240。

## §3 読み方の決め(結果を見る前に)

- **勝ち負けの文は書かない。** A の「同じ」が B の「通す」より多くても、「型も検査も要らない」とは書かない ― A の「違う」「無いのに在る」は、A の中では止まらずに資料へ出る数で、B の「止める」とは別の量。2 つを必ず同じ表に並べる: A が出して正しかった行・A が出して違った行(誰も止めていない)・B が止めた行(そのうち席の答えは正しかった行)・B が通して違った行。
- UM3-A3・UM3-A6 が当たったら、その数を結果の文書の頭に書く(A の負け)。UM3-A2・UM3-A5 が当たったら、それも頭に書く(B の負け ― 止めすぎて、普通の席が出せる数を資料に出せていない)。
- 揺れ(UM3-A7)は 2 回だけの数。「A は安定している/いない」とは書かず、違った行の数だけを書く。
- 過程の数(§1-5)は、同じ種類の AI の席の、この 4 社での数。「速い」「安い」とは書かない(時間と費用は測る量に入れていない。秒は並べるだけ)。
- **言えないこと**: 「実物の会計の素材で」「普通の AI で足りる」「Audit Core の方が正しい」「人の確かめが要らない」「別の種類の AI でも同じ」「手がかりで良くなる」(手がかりは確かめていない)。

## §4 限界

- 素材は便 UM2 の作り物の 4 社・2 期。正解は素材を作った席が書いたもので、独立に確かめていない。素材を作った席・B の席・A の席は同じ種類の AI で、「ありそうな形」の考えを共有する。
- A の席は repo の文脈を持ち、頼みの紙も司令塔が書いた(値の表・自信・作業の記録を書かせる)。何も言われない席の振る舞いではない。値の表を書かせること自体が、席の作り方を変えうる。
- 過程の数は、会話の記録に残った道具の呼び出しだけ。席が頭の中で決めたこと(採る・捨てるの理由)は記録に無く、席の申告と司令塔の読みでしか見えない。
- B の過程で数えられるのは 1 期目の席だけ。B の 2 期目は script で、A の 2 期目(席)とは作りが違う。同じ物差しでは並べられない所は、並べずにそう書く。
- 1 社 1 期につき 2 回。揺れの大きさは言えない。
- 資料の質(銀行の人に伝わるか)は測らない。
- 司令塔は便 UM2 の結果を知って予測を書いた(§0)。

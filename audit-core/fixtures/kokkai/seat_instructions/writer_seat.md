# 要約を書く席への指示文(そのまま。`<会議の JSON>`・`<出力の道>`・`<issueID>` だけが回ごとに違う)

あなたは「会議録の要約を書く席」です。他の席や記録は見ないでください(この指示と、下の JSON ファイルだけが材料です)。

## 材料
`<会議の JSON>`
国立国会図書館の国会会議録検索システム API の応答。`meetingRecord[0].speechRecord` が発言の配列で、各発言に `speechOrder`(発言番号、整数)・`speaker`(発言者名)・`speakerPosition`・`speech`(発言本文)があります。発言 0 は会議録情報(出席者一覧など)で発言ではありません。本文は約 6 万字なので、python で読んで要点を把握してください(全文を一度に表示しなくてよい)。

## 書くもの
この会議の内容を、読む人に伝わる要約として **20〜40 文** で書き、1 文を 1 件の claim として次の JSON に落としてください。

出力ファイル(これ 1 つだけ作る): `<出力の道>`

```json
{
  "issueID": "<issueID>",
  "written_by": "AI の席(要約)",
  "claims": [
    {
      "id": "K-001",
      "text": "要約の 1 文(日本語。誰が何を述べたか)",
      "speech_order": 12,
      "speaker": "発言者名",
      "quote": "発言本文からの逐語の引用(60 字以内。省略や言い換えをしない。無ければ省く)",
      "number": {"text": "文に書いた数の表記(例: 三百億円)", "value": 30000000000, "unit": "円"}
    }
  ]
}
```

規則:
- `speech_order` は、その文の根拠になる発言の `speechOrder` を 1 つだけ書く。`speaker` はその発言の `speaker` をそのまま写す(敬称・役職を付けない)。
- `quote` は発言本文に**そのままの字で**在る部分を切り出す(改行や全角空白はまたがない)。全部の文に要らないが、**8 文以上**に付ける。
- `number` は、文に数の主張があるときに付ける。`text` は文に書いた表記、`value` は円・人・％などの単位での値(「三百億円」なら 30000000000、「一五％」なら 15、「八年」なら 8)、`unit` は 円・人・％・年・日・回・か月・件 などの単位の文字。**8 文以上**に付ける。数は発言本文に出る数を使い、自分で計算した数(合計・差など)は使わない。
- 文の中身は会議録に書かれていることだけ。評価や推測は書かない。
- 内容の偏りを避け、複数の発言者・複数の話題を取り上げる。

できたら、件数(全体・quote つき・number つき)と、使った発言番号の一覧だけを報告してください。ファイルの中身は報告に貼らなくてよい。

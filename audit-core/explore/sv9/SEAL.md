# 封 ― 便 SV9: 日付の列が在る表は、行ごとの期を機械が日付から決めると、正しい道が照合で止まらなくなるか(2026-11-24)

軽い型(CLAUDE.md 作法 7)。commit は 2 回(この封 → 結果)。台帳・門・変異の掃きは作らない。監査は結果の前に 1 回。engine は 0 行(照合は explore の script で、SV0 の `tally.py` は変えず、その上に差し替えの層を置く)。費用は 0 USD・席は 0。数は外に出さない。人間は 2026-11-24 に「見えた課題を解決して」と言った。SV5・SV7 で見えた課題「仕訳を月で足した正しい答えが、仕訳の札が年の期間なので S3 で止まる」を扱う。

## 0. 問い

保存の席の札は列・行ごとに期を 1 つしか書けず、仕訳帳のような「行ごとに日付が違う表」は年の期間の札になる。機械が保存の時に表の日付の列を見つけ、その行の升の期を「その日 1 日の期間」に細かくし(札の期の中に収まる時だけ)、照合は「足し合わせの升が全部、項目の期(月次ならその月)の中に在る」なら期が合うとすれば、

1. SV5(元の file を見た席の 1 社)と SV7(貯めた行だけの席の 1 社)で S3 に止まった正しい月次 24 行は通るか。
2. そのかわり、違う行や罠・ずらしを通す数は増えないか。

## 1. 材料

- 席は使わない。SV0・SV1・SV4・SV5・SV7 の答え・札・素材をそのまま使う。
- 比べる群(どれも同じ答えに、旧い照合 S1〜S7 と新しい照合 S1〜S7 を当てる):
  - A: SV1 の答え(9〜11 社、貯めた行だけ)
  - B: SV5 の元の file を見た席の答え(12〜14 社)
  - C: SV5 の貯めた行だけの席の答え(12〜14 社)
  - D: SV7 の貯めた行だけの席の答え(15〜17 社)

## 2. 新しい照合(SV0 の照合からの差分だけ)

- 日付の列: 表の 2 行目より下で、空でない升の 8 割以上が日付(`YYYY/M/D`・`YYYY-M-D`・`YYYY年M月D日`)として読める列。左から最初の 1 列だけを使う。
- 升の期: 札で決めた期が `期間` で、その行の日付の列の日がその中に在る時だけ、期を「その日からその日までの期間」に替える。それ以外は札のまま。
- 期が合うの決め: 足し合わせ(升が 2 つ以上)の時、月次の項目は、どの升の期もその月の中に在れば合う(SV0 は月ちょうどの期間だけを合うとした)。そのほかの項目の決めは SV0 のまま。

## 4. 言えないこと・次の候補

- 新しい照合は、足し合わせの升が月の中に在ることしか見ない。**月の行を全部足したか(足し漏れ)は見ない**。足し漏れの答えは S1 で値が合わなければ止まるが、席が足し漏れた和を値として書けば通る。
- 日付の列の見つけ方は 1 通り。
- 次の候補(結果がどうであれ、この中からだけ): (i) 新しい照合で SV7 の 1 本の流れを数え直し、SV8 の聞く印と合わせる。(ii) 足し漏れを見る照合(その月の行を全部足した和と比べる)。(iii) 実物の公開データで通す(費用の見積もりから)。(iv) やめる。

# 封 ― 便 TR2: XBRL でない経路の確定の台帳(AI は候補だけ・人が確定・様式が変わったら止める)(2026-11-25)

軽い型(CLAUDE.md 作法 7)。commit は 2 回(この封 → 結果)。監査は結果の前に 1 回で、報告は `AUDIT.md`。engine 0 行・費用 0 USD(席はこの PC の subagent)・通信なし。素材は作り物で、数は外に出さない。人間は 2026-11-25 に、TR2 の封へ進むこと・翌期の変異(列の挿入・行の並べ替え・シート名の変更・見出しの字の微修正)をすべて止めて人に確定し直させることを証明すること・台帳は「1 項目 = 1 セル」と「並べて書いた行の合算」を初めから許し、元の行は全部「使う/使わない」を人が決める形(司令塔の案)で進めることを決め、「任せる進めて」と言った。同じ日に、点検レポートの要確認を「要修正・精査」と「軽量確認」に分けること、検査の限界を注記することも決めた(§6)。

最終の仕組みの部品: 段 2〜4(材料の定義 → 素材の読み込み → 共通の形)。XBRL の無い素材でも、照合の基準を AI の取り出しでなく、**人が確定した台帳で機械が元の升から読む**形(パターン A)にする。

## 0. 問い

1. AI の席が会計ソフトの書き出しから台帳の候補(項目 ← 行と列、符号つきの足し算、全部の行の使う/使わない)を出し、人の代わりの席が画面で確定すると、正しい値を読む台帳になるか。
2. 確定した台帳で、翌期の同じ様式の file は止めずに正しく読み、様式の変わった file は全部止めて、どこが変わったかを人に示せるか。
3. 座標だけを覚える素朴な読み方なら、様式の変わった file で黙って違う値を読む数はいくつか(止める仕組みが要る訳の大きさ)。

## 1. 材料の定義と素材(`build_tr2.py`。AI を使わない・乱数は社の番号で固定)

- 材料の定義(段 2): [材料定義_TR2.md](材料定義_TR2.md)。15 の項目と期(売上高 当期・前期、営業利益 当期・前期、経常利益 当期、当期純利益 当期、減価償却費 当期、現金及び預金 当期末、流動資産合計 当期末、資産合計 当期末、短期借入金 当期末、長期借入金 当期末、負債合計 当期末、純資産合計 当期末・前期末)と、それぞれの足し方の定め。
- 素材: 作り物の会社 6 社(番号 51〜56)の「会計ソフトの書き出し」の xlsx(期 1)。1 社 2〜4 枚のシート(貸借の表・損益の表・ほかに製造原価の表や部門別の表)。社ごとに次を変える:
  - シートの名(例: 貸借対照表 / BS / 残高試算表)。
  - 表の頭の行(題・会社名・単位の行の数)。
  - 列の並び(当期が先か前期が先か・科目の番号の列の有無)。
  - 単位(円か千円)。
  - 区分の行と小計の行の有無。
  - 複数の科目に分かれる項目(預金の種類・銀行ごとの借入金・製品と商品の売上・販管費と製造原価の減価償却費)。
  - 紛れの行(1 年以内返済予定の長期借入金・部門別の表の売上高)。
  - 6 社のうち 2 社は、損益の表に利益の行(営業利益・経常利益)が無く、符号つきの足し算でしか出せない。
- 正解: build が素材と同時に書く(`正解/値.json`: 項目と期ごとの円の値。期 1・期 2・変異のそれぞれ)。正解の台帳の形は書かない(正しさは読んだ値で決める。同じ値を出す別の足し方も正しい)。
- 期 2(翌期の同じ様式): 値だけを変えた file(前期の列は期 1 の当期の値)。
- 変異(期 2 から 1 つずつ。7 種 × 6 社 = 42): ① 列の挿入(使う表の値の列の間に「前期比」の列)② 行の並べ替え(使う表の隣り合う 2 行の入れ替え)③ シート名の変更(使う表)④ 行の見出しの微修正(使う行の字を 1 か所変える。例: 「(A銀行)」→「 A銀行」)⑤ 列の見出しの微修正(「当期末」→「当期末残高」の形)⑥ 科目の追加(借入金か預金の新しい科目の行を足す。値は 0 でない)⑦ 単位の変更(円 ↔ 千円。値も合わせて直す)。変異の file の正解は期 2 の値(⑥ は足した科目を定義のとおり含めた値)。

## 2. 台帳の形(機械が決める)と、読む規則(`ledger_tr2.py`。AI を使わない)

- 台帳 = 提案と確定で決まる部分 + 機械が期 1 の file から作る指紋。
  - 決める部分: 項目と期ごとの成分の並び(シートの名・行の見出しの字・同じ字の何番目か・列の見出しの字・符号 +1/−1)と、シートごとの単位の倍率。使うシートのデータの行は、全部、どれかの項目の成分か「使わない」のどちらかに決める。
  - 指紋(機械): シートの名の集まり。使うシートごとに、列の見出しの行より上の行の字・列の見出しの並び・データの行の見出しの並び(順を含む)。
- 読む規則(この順で、1 つでも当たれば読まずに止める):
  - S1 シートの名の集まりが指紋と違う。
  - S2 使うシートの頭の行・列の見出しの並び・行の見出しの並びが指紋と違う。
  - S3 どの項目にも「使わない」にも決まっていない行が在る。
  - S4 成分の升が空か数でない。
- 止めた時は、人に確定し直してもらう依頼(顧客向け)を出す。変わった所(シート・行か列・前の字・今の字)を並べる。読めた時は、項目と期ごとの円の値と、成分ごとの元の升(シート・行の見出し・列の見出し・値)を出す。
- 比べ(素朴な読み方): 同じ確定の台帳を、期 1 の file の升の位置(シートの名・行の番号・列の番号)だけに直し、止めずに読む。シートが無い時は読めない(黙って違う値は読まない)と数える。

## 3. 席(1 社 2 席・合わせて 12)

- 提案の席(1 社 1 席): 紙 [BRIEF_PROPOSE_TR2.md](BRIEF_PROPOSE_TR2.md)。期 1 の xlsx を読む用に機械が書いた CSV(シートごと・升の字のまま)と材料の定義を渡し、台帳の候補を JSON で返させる。正解は見せない。
- 確定の画面(機械): 1 社 1 枚の HTML。項目ごとに成分の升の字と値・足した値、シートごとの全部の行(使う行は印・使わない行の一覧)。**機械が 1 社 1 か所、候補に誤りを入れる**(選び方: 成分が 2 つ以上の最初の項目の最後の成分を落とす。無ければ最初の項目の列をもう一方の期の列に替える)。入れたことは席に知らせない。

- やり直しは「形が読めない」時と利用の上限で止まった時だけ。

## 4. 数える(`tally_tr2.py`。記録は数だけ)

- 提案の台帳(誤りを入れる前)で期 1 を読んだ値: 項目と期 90 のうち正解と同じ数。
- 確定の台帳で期 1・期 2 を読んだ値: 90 × 2 のうち正解と同じ数。読めずに止めた数。
- 入れた誤り 6 のうち、確定の席が直した数(確定の台帳でその項目の期 1 の値が正解と同じ)。
- 期 2(同じ様式)で止めた社の数。
- 変異 42 のうち止めた数(種類ごと)。止めた依頼に、変異を入れた所(シートと、行か列の字)が出ている数。
- 素朴な読み方: 変異 42 のうち、止まらず読み終え、どれかの値が正解と違った数(黙った誤り)。
- 確定の台帳が 1 か所でも正解と違う値を出す社では、変異の数え方は同じで、値の正しさは別に数える。

## 6. TR1 の点検レポートの直し(人間の決め 2026-11-25。予測は置かない機械の直し)

- `report_tr1_v2.py`: TR1 の `check_A` の出力と基準 A から、点検レポートを作り直す。engine は変えない。区分は次のとおり。
  - 要修正・精査: 照合で一致しない・元が無い。
  - 軽量確認: engine の保留。「数は照合先と一致。同じ額が別の枠にも在る」と書き、照合先の一次ソースと、同じ額の在る枠の名を並べる。
  - 人の判断が必要・確認済み・点検していない数: TR1 のとおり。
- 「この点検の限界」の注記に次の 2 つを書く:
  - 元の値との差が資料の 1 桁未満の数は、照合が通る。資料の桁より細かい誤りは見ない。
  - 円の単位の金額は照合していない。
- 数える: 軽量確認の行で同じ額の在る枠の名を欠くもの(0 であるべき)。要修正・精査と軽量確認の数(TR1 の要確認 111 の内訳の写し)。

## 7. 言えないこと

- 素材は機械の作り物で、本物の会計ソフトの書き出しではない(本物を借りるのは人間の決め)。様式の癖は司令塔が選んだ範囲だけ。
- 確定は人の代わりの席(subagent)。本物の人の手間と正しさは測らない。
- 止めた後に、確定し直して読み直す流れは、この便では測らない。
- 素材の値は機械が決めたので、席が素材の意味を取り違える形は、本物より少ないかもしれない。

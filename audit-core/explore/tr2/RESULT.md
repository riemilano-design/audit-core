## 3. 読み(結果の後に司令塔が見た。記録の外の読み)

- **様式の変化は、どの種類も読む前に止まり、人に確定し直しを頼む形になった。** 依頼には、シート・変わったもの(列の見出し・行の見出し・シートの名・頭の行・未決の行)・確定した時の字・今回の字が並ぶ。科目の追加は「行の見出しの並び」と「未決の行」の両方で止まった。
- **止める仕組みが無いと、変化の半分近く(20 / 42)で、黙って違う値を読む。** 列の挿入・行の並べ替え・単位の変更は 6 社とも黙った誤りになった。科目の追加は、2 社では黙った誤り(5 項目が違う値)。ほかの 4 社は、行が 1 つずれて値の無い区分の行に当たった 1 項目が読めず、残りのうち 4 項目は黙って違う値だった。見出しの字の微修正は、素朴な読み方でも値は合った(升の位置が変わらないため)。それでも台帳は止める。人が字の変わった理由を確かめるまで読まない、という作りのため。
- **TR2-7 の外れは、止める仕組みの要る訳を小さくしない。** 封の数え方は「止まらず読み終え、どれかが違う」なので、1 項目でも読めない変異は 20 に入れていない。科目の追加の 4 社(1 項目が読めず 4 項目が黙って違う)を入れて数えれば 24 / 42 になる(結果を見てからの数え方なので、判定は外れのまま)。黙った誤りの数は、素材の行の並びで変わる。
- **AI の提案は、この素材では全部正しかった(90 / 90)。** 利益の行の無い 2 社でも、符号つきの足し算(1 項目で最大 15 の升)を正しく組んだ。1 年以内返済予定の長期借入金は 6 社とも使わない行にし、部門別のシートが在る 2 社は、そのシートを使わないシートにした。
- **確定の席は、画面に入れた誤り 6 を全部直し、ほかは直さなかった。** 入れた誤りは、成分が 2 つ以上の項目から 1 つを落としたもの(定期預金・商品売上高・売上値引・雑費・製造原価の減価償却費)。席は「前期では足している」「定義では製造原価のものも足す」と、画面の中の手がかりで見つけた。
- **TR1 の点検レポートは、要確認 111 を要修正・精査 66 と軽量確認 45 に分けた。** 軽量確認の行には、一致した照合先(要素・期・範囲・値・精度)と、同じ額の在る枠(例: 当期・単体・株主資本等変動計算書の利益剰余金の列)を並べた。「この点検の限界」の注記には 3 つを書いた。1 桁未満の差が通ること、円の単位は照合しないこと、XBRL と帳簿の一致は見ないこと。

## 4. 言えないこと

- 素材は機械の作り物で、見出しも値も整っている。本物の会計ソフトの書き出し(結合した升・空白の揺れ・期の途中の科目の改廃)では、提案の正しさも止めすぎも変わりうる。
- 止めすぎは、同じ様式の翌期 1 回(6 社)でしか測っていない。本物では、資料に関係の無い科目が 1 行増えても止まる(全部の行を決める作りのため)。止める回数が多すぎないかは測っていない。
- 確定は人の代わりの席。入れた誤りは「成分を 1 つ落とす」形だけ。
- 止めた後に確定し直して読み直す流れは測っていない。依頼の見せ方の質も測っていない。科目の追加では、ずれた行の見出しが全部並び、依頼の行は 6 社で 94 になる。「依頼に変わった所が出ている 42 / 42」は、変異の字が依頼のどこかに在れば数える緩い数え方。
- 提案の席のうち 3 席(第 53・54・55 社)は、作業用の script を、渡した folder の外の作業場所(repo の外)に置いた(司令塔が作業場所の file の時刻から確かめた)。どの席も、読んだのは渡した folder の中だけと報告したが、席が開いた file は確かめていない。
- 「この点検の限界」の注記は、封 §6 の 2 つに、3 つ目(XBRL と帳簿の一致は見ない)を足した。3 つ目は測った数でなく、注記の足し(監査の指摘で、封との違いとしてここに書いた)。
- 素材を作る python は、openpyxl が user の場所に在るため `-I` でなく `-E` で走らせた(読むのは機械の作った file だけ)。

# 札を付ける席への指示(便 XC7)

あなたは有価証券報告書の inline XBRL を作る席です。渡す画面(markdown の file)には、今年の報告書の表と、前の年の同じ会社の表(升ごとに XBRL の札つき)が並んでいます。今年の表のうち `〔★M番号〕` の印の付いた升に、XBRL の数の fact の札を付けてください。

## 札の形

印ごとに、次の 6 つを答えます(前の年の表の札と同じ書き方)。

- `name`: 要素の名(例 `jpcrp_cor:NetSalesSummaryOfBusinessResults`)。前の年の表に在る要素を使うのが基本。
- `contextRef`: 文脈の id。今年の表の列や表の前の字が示す期(当期・前期・何年前)から決める。前の年の札の文脈を 1 年ずらした物と同じ形になる(前の年の `CurrentYearDuration` は今年の `Prior1YearDuration`、前の年の `Prior1YearInstant` は今年の `Prior2YearInstant`。今年の列は `CurrentYear…`)。画面の頭に、この画面で使われている id の一覧が在る。
- `unitRef`: 単位の id(画面の頭の一覧から)。
- `decimals`: 桁(例 `-3`・`0`・`2`)。
- `scale`: 倍率(千円なら `3`、百万円なら `6`、円・株・% の時の扱いは前の年の札に合わせる)。無ければ書かない。
- `sign`: 負の数を「△」などで表す升で、前の年の札に `sign=-` が在る形なら `-`。無ければ書かない。

## 付けない時

次の升は札を付けず `null` と答えます。
- 数でない升(年月・回次・名・見出しの字など)。
- 前の年に同じ意味の札が無く、要素を確かめようがない升。
- 今年の表と前の年の表で「表の前の字」(表の題・注記の名)が違う意味の表の升(例: 今年は注記の表なのに前の年は貸借対照表)。注記の表の数は、本表と同じ要素でも札が付かないことが多い。
- 前の年の同じ行の札の文脈に、提出者が独自に作ったメンバー(id の中に `-asr_E` や `-000` のような提出者のコードが入っている物。役員の名など)が付いている升。標準のメンバー(`_CapitalStockMember`・`_NonConsolidatedMember`・`_Row1Member` のような、コードの入らない物)は札を付けてよい。
- 迷う升。**誤った札は、付けないより悪い**(付けない升は後で別の席が見る)。

## 答えの出し方

指定された答えの file に、JSON だけを書いてください。印の全部を鍵にします。

```json
{"M1": {"name": "...", "contextRef": "...", "unitRef": "...", "decimals": "...", "scale": "...", "sign": "-"}, "M2": null}
```

- 画面の file と、この指示の file 以外を読まないでください。repo の file・git・網には触らないでください。
- 答えの file 以外に何も書かないでください。報告には、答えた印の数と null の数だけを書いてください。会社の名・人の名・数の値を報告に書かないでください。

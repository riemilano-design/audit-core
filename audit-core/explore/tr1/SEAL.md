# 封 ― 便 TR1: 点検の基準を生の XBRL に替える(パターン A)・確認済みに一次ソースを出す・増減額の拾い方を直す(2026-11-25)

軽い型(CLAUDE.md 作法 7)。commit は 2 回(この封 → 結果)。監査は結果の前に 1 回で、報告は `AUDIT.md`(内部監査レポートの形)。engine 0 行(`adapters/xbrl/instance.py` の `load_instance` と `verify_external.py` の `verify_external`、`vocabulary.py` の表を読むだけで使う)・費用 0 USD・通信なし・鍵なし。数は外に出さない。人間は 2026-11-25 に「次の便では、パターン A への移行(生の XBRL からの直接基準化)…へ即座に修正すべき」と言い、司令塔が便を TR1(XBRL の経路)と TR2(XBRL でない経路の確定の台帳)に分ける案を出し、人間は「進めて」と言った。

最終の仕組みの部品: 7 → 5 の照合の**基準**。TR0 では基準(facts)が AI の席の取り出した材料だった(パターン B)。この便で、XBRL が在る資料の基準を、AI の触れない生の XBRL から engine の読み方で直接作る(パターン A)。

## 0. 問い

1. 点検の基準を生の XBRL にすると、AI の取り出しが誤り、資料もその誤りのまま書かれた時に、点検はそれを止めるか(基準 B は素通りさせるか)。
2. 増減額・増減率の拾い方を直すと、まだ見ていない資料で言い過ぎが減るか。
3. 確認済みの数のすべてに、一次ソース(XBRL の要素・期と範囲・値・精度)を出せるか。

## 1. 基準 A の作り方(`build_tr1.py`。AI を使わない)

- 会社: RD2 の 11 社(番号 31〜41)。元の有報の zip は RD2 と同じ手元の cache から、sha256 で結ぶ(`fixtures/xbrl/tanshin/fetched_2026-11-09.json` の `#` 7〜17)。zip は信頼しない data として読むだけ。
- facts: zip を `load_instance` で読んだ fact を**全部そのまま**使う(engine の保留の規則が兄弟を見るため)。
- 項目と要素の対応: engine の表 `vocabulary.PROFILES["P33E"].subjects` の、その字の最初の行の要素の並び(先に在る要素を使う)。表に無い 2 項目だけ、この封で固定して足す: 流動資産合計 → `CurrentAssets`、短期借入金 → `ShortTermLoansPayable`。字の対応: 売上高・営業利益・経常利益・当期純利益(連結は `親会社株主に帰属する当期純利益` の行)・減価償却費・現金及び預金・資産合計・長期借入金・負債合計・純資産(純資産合計)・従業員数(期末の従業員数)。
- 期と範囲の枠: 当期 `CurrentYearDuration`・前期 `Prior1YearDuration`・当期末 `CurrentYearInstant`・前期末 `Prior1YearInstant`。範囲は AQ0 の A1 で人の代わりの席が選んだもの(人の決め)。単体なら枠に `_NonConsolidatedMember` を付ける。従業員数は、単体の社で枠そのものに値が在ればそれを使う(RD0 と同じ)。
- 要素が見つからない項目は、基準 A に無い項目として「点検していない数」に回す(AI で埋めない)。

## 2. 誤った取り出しを入れた材料と、新しい資料(書く席)

- 材料: TR0 の材料(RD2 の答え + AQ0 の選び)から、1 社 2 項目の値を、取り出しの誤りの形に替える。選び方(乱数なし):
  - 封 §0 の数える 16 項目の順で、金額の項目のうち、RD2 の正解の folder の `他の読み.json` に、資料の桁(百万円)で違う値の読み(単体か前期)が在る最初の 2 項目。値をその読みに替える。
  - 2 つに満たなければ、残りは次の金額の項目の値を 1000 で割った値にする(千円の表を円と読んだ誤りの形)。
- 書く席は 1 社 1 席(11 席)。紙は TR0 と同じ [../tr0/BRIEF_WRITE_TR0.md](../tr0/BRIEF_WRITE_TR0.md)。席には誤りを入れたことを知らせない。
- やり直しは「形が読めない」時と利用の上限で止まった時だけ。

## 3. 点検(`check_tr1.py`)

- 数を拾う規則は TR0 の `check_tr0.py` に、次を足す(結果を見る前にここで決める):
  - 「前期の X から Y 増加/減少/増/減」「前期末の X から Y …」: Y は増減額、Y の直後の括弧の中の ％ は増減率。符号は同じ節の「増」「減」「拡大」「縮小」の字で決める。
  - 「前期比」などの増減の字の後の括弧の中の ％ も増減率とする。
  - 「営業損益」「経常損益」「当期純損益」「親会社株主に帰属する当期純損益」を項目の字に足す。「X の損失」は負の値、「X の利益」は正の値とする。
  - 「損失額が Y 拡大/縮小」の Y は増減額で、損失の拡大は負の増減とする。
- 基準 A: §1 の facts。照合は `verify_external`(金額 1 つ・増減額・増減率)。人数は facts の値と同じかをこの script で見る。
- 基準 B: TR0 と同じ作り方の facts(誤りを入れた材料から)。拾い方は基準 A と同じ。
- 区分: 確認済み(照合が一致)・要確認(一致しない・元が無い・保留)・点検していない(項目に結べない・増減でない率・円の単位・基準 A に要素が無い)。基準 A では「人の判断が必要」は範囲を人が決めていない時だけ。
- 点検レポート(顧客向け。基準 A)の直し: 確認済みの行に一次ソース(要素の名・期と範囲の字・値・開示の精度)を出す。要確認の元の数を、元の精度の単位と資料の単位の両方で出す。資料の数が増減額と同じ時は「増減額の可能性」を添える。表と文の確認済みを分けて並べる。題の会社の番号を 1 回にする。
- 誤りを入れた資料: TR0 の (a)〜(d) を、基準 A で確認済みになった数から同じ選び方で入れ、基準 A で点検する。
- TR0 の資料(誤りを入れる前の 11 枚。見たことのある資料)も、基準 A と新しい拾い方で点検し直す。

## 4. 数える(`tally_tr1.py`。記録は数だけ)

- 取り出しの誤りから来た数: 新しい資料の照合した数のうち、誤りを入れた項目と期を参照するもの。基準 A と B それぞれで要確認になった数。
- 言い過ぎ: 新しい資料で、基準 A で要確認になった数のうち、誤りを入れた項目を参照せず、資料の数が材料の値(と、そこからの増減額・増減率)と資料の桁で同じもの。
- TR0 の資料を基準 A で点検し直した時の要確認の数。
- 新しい資料で、基準 A で照合した増減率の数・拾った数のうち照合した数。
- 基準 A の確認済みの行のうち、一次ソース(要素の名と枠)を欠くもの。
- 誤りを入れた資料: 入れた誤りのうち基準 A で要確認になった数。

## 6. 言えないこと

- 基準 A は「提出された XBRL と合う」ことを見る。XBRL そのものが会社の帳簿と合うかは見ない。
- 項目と要素の対応は engine の表(と 2 行の足し)で決まる。表に無い書き方の項目(例: 売上高でなく事業収益の要素で出す社)は点検していない数になり、点検できる数は B より減りうる。
- 取り出しの誤りは機械で入れた 3 つの形だけ。AI の席が自然に起こす誤りの形と同じとは限らない。
- 拾い方の直しは TR0 の 23 件を見てから決めた。TR1-3(見た資料)は割り引き、TR1-2(まだ見ていない資料)で測る。
- 範囲(連結か単体か)は AQ0 で人の代わりの席が決めたもの(人の決めの形。中身は subagent)。

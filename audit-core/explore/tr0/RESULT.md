## 3. 読み(結果の後に司令塔が見た。記録の外の読み)

- **点検は、入れた誤りを全部見つけ、点検レポートを読んだ人(の代わりの席)も全部を直すべき数として挙げた。** 1 桁の違い・当期と前期の入れ替え・文の中の 1 桁の違い・単位の書き間違い(百万円 → 千円)の 4 種で、どれも要確認になった。確認済みの数を直すべきに挙げた席は 0 で、確認済みの区分は読む人に信じられていた。
- **ただし、誤りの無い資料でも 23 の要確認が出た。これは点検の言い過ぎ(拾い方の欠陥)。** 書く席は「前期の X 百万円から Y 百万円(Z%)減少しました」の形で書いた。この便の拾い方は増減額を「前期比」「前年同期比」などの字で見分けるので、「前期の X から Y 減少」の Y を当期の値として照合し、合わないとした。第 36 社の「営業損益は X 百万円の損失」の形の書き方も、項目に結べなかった。
  - 封の TR0-1 の数え方は、拾った読みのまま材料と比べるので、この読み違いを言い過ぎと数えなかった。字の上では 0 で当たりだが、本当の言い過ぎは 23(11 社のうち 8 社で 2〜3 ずつ)。**予測の中身としては外れと読むのが正しい。**
  - 書く席が自分で入れた数の誤りは、照合した 301 の中には見つからなかった(要確認 23 は全部が拾い方の読み違いだったため)。
- **読む席が「分かりにくかった所」に書いたことは、点検レポートの次の直しにそのまま使える。**
  - 言い過ぎの要確認が在った 8 席のうち 7 席が、言い過ぎの要確認について「数は増減額に見えるが、レポートは当期の値と合わないとだけ言う」と書いた。読む人は言い過ぎに気づいたが、レポートだけでは誤りか読み違いかを決められなかった。
  - 元の数の単位が読みにくい: 単位の書き間違いを入れた行で、元の数を資料の(間違った)単位で、桁の多い数のまま出していた。元の資料の単位と資料の単位が並ぶ所で、どちらが正か分かりにくい。
  - 見出しの重なり: 点検した資料の名に会社の番号が 2 回出る(資料の見出しの字と、レポートの字)。
  - 確認済みの表に同じ項目が 2 回ずつ並ぶ(表と文の 2 か所)理由が書かれていない。
  - 点検していない率(増減率に見えるもの)を「増減でない率」と書いていた。拾い方が増減率と見分けられなかったための字で、訳が中身と合わない。
- **人の判断が必要 1**: 第 34 社の従業員数(AQ0 の画面で「わからない」だった項目)。第 34 社の読む席は「人が決めること」にこれを挙げた。作る前の確認で決まらなかった項目が、作った後の点検レポートまで持ち越されて人に届いた。

## 4. 言えないこと

- 書く席・読む席は subagent。本物の顧客が読んで分かるか、直す手間は測っていない。
- 資料は短い「決算の概要」1 種。数を拾う規則はこの便の script で、書き方の型が変わると拾い違える(§3 の 23)。
- 材料の値そのものの正しさは RD2・AQ0 による(この便は資料が材料と合うかを見た)。
- 入れた誤りは機械の 4 種だけで、確認済みの数から選んだ。
- **増減率の照合(engine の期間の対)は、一度も働かなかった。** 資料の中の率は、どれも「増減でない率」として点検していない数(38)の側へ落ちた(拾い方が「前期比」などの字の無い率を増減率と見分けられないため)。照合した 301 は、金額 1 つの照合 292 と増減額の照合 9。
- 数を拾う規則は、封 §3 の字と少し違う。封は「数の前の括弧の中に前期が在れば前期」としたが、実装は「項目の字から数までの間に前期・前年が在れば前期」。増減の字(前期末比・前期末から・前期に比べ など)も封の列挙より多い。出た資料で、この違いが区分を変えた所は見つけていない。
- 「人の判断が必要」の説明の字は、未決の項目すべてに「元の資料の中で候補が食い違い」と同じ字を出す。未決の訳が候補の食い違いでない時には言い過ぎになりうる(今回は 1 件で、AQ0 の画面で列の見出しが読めず決まらなかった項目)。
- 材料を作る script は正解の値を読まない。当期の始まりと終わりの日だけを、RD2 の正解の folder の期の file から読む(監査の指摘で script の説明の字を直した)。

## 0. 問い

SV0 では、埋める席は元の file を見て答えた。保存の時に共通の形で貯めておく方式が商品として成り立つには、**作る時は元の file を開かず、貯めた行だけで項目を埋められる**必要がある。貯めた行だけを見せると、元の file を見せた SV0 より、正しく埋まる行は減るか。誤りは増えるか。

## 1. 材料と席

- 素材と札は SV0 のものを**そのまま使う**(3 社・`期1/` の file・保存の席の `札.json`。作り直さない)。正解・罠も SV0 のもの。
- 貯めた行(機械で作る。席ではない): `扱い` が `貯める` の file の、数として読める升 1 つを 1 行にする。数の読み方は SV0 の照合の S1 と同じ。1 行の欄は次だけ。
  - `番号`(行の通し番号。file の名・升の位置は見せない。番号と升の対応は司令塔だけが持つ)
  - `表`(file の名から拡張子を除いたもの。保存の時に表の名は残るので見せる)
  - `行の見出し`(同じ行の、数でない字の升を左から ` / ` でつないだもの)
  - `列の見出し`(同じ列の、その升より上にある数でない字の升のうち、下から 2 つまでを上から ` / ` でつないだもの)
  - `値`(升の数。表示のまま。千円の表なら千円の数)
  - 札から決めた `期`・`単位`・`性質`・`範囲`(既定 → 列の例外 → 行の例外 の順。SV0 の照合と同じ決め方)
- 埋める席: 1 社 1 席。[BRIEF_FILL.md](BRIEF_FILL.md) と、その社の `貯め.csv` と、当期の日付だけを見る。元の file・札・正解は見ない。**3 社とも当期の始まりと終わりの日を字で渡す**(SV0 では 1 社だけ仕訳の日付から決めさせた。それをそろえる)。
- 席は合わせて 3。やり直しは「形が読めない(json が壊れている・項目が足りない)」時だけ 1 回。中身を理由にやり直さない。
- 行: 1 社 31 項目、3 社で 93 行。項目は SV0 と同じ。

## 2. 照合と集計

- 席の答えの `番号` を升に戻し、**SV0 の照合(`../sv0/tally.py` の判定 S1〜S7)をそのまま当てる**。読めない `番号` は S1。
- 「正しい行」「違う行」「無いと答えた」「決めの行」の数え方は SV0 と同じ。M-罠・M-ずらしも SV0 の script のまま数えるが、予測は置かない(札が同じなので、新しいことは言えない)。

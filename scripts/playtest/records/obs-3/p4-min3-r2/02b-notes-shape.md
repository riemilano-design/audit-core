## 仮説 001(止まる段)

### 1. 観測した事実
- `obs.vocab.shapeStatus`(`recognition byGroup[group].statusCounts.shape.{self,opponent}.{none,forming,completed,matched}`)
  - 自分側: `none` 22558 / `forming` 5360 / `completed` 0 / `matched` 0
  - 相手側: `none` 15549 / `forming` 5208 / `completed` 33 / `matched` 0
  - いずれも**延べ**(局面 × 形のレコードの行。18 局 594 局面 × 形 82 種)。**局数ではない**。

### 2. そこからの推論
- 自分側は「途中の段(`forming`)」の行が 5360 あり、途中までは何度も数えられている。一方で最後の段(`completed`)の行が 1 つも無い。
- 同じ数え方・同じ 18 局で、相手側には `completed` が 33 ある。したがって「この数え方では誰も `completed` にならない」という道具側の説明は、少なくともこの組では取りにくい(自分側 47 種・相手側 35 種と分母が違うので、33 と 0 の差の大きさ自体は根拠にしない)。
- 読めるのは「どこまで進んでどこで止まるか」であって、「どの形を目指していたか」ではない。名前は写しに無い。

### 3. 仮説
`02b-H-shape-001.json` の `statement` と同じ(ここには繰り返さない)。

### 4. 不確実性
- `completed` 0 は「本人が最後まで囲えていない」ことと同じではない。判定の側(必要駒の置き方・`completed` の条件)が厳しいために 0 になっている筋がありうる。今の写しにはその切り分けに使える項目が無い。
- 延べの件数は形の種類数に比例して増えるので、自分側と相手側の数をそのまま比べられない。001 は「自分側の中で `forming` があって `completed` が無い」という形の読みに留めた。
- `completed` が 0 のまま推移しても、「止まる段が同じ」ことの証拠にはならない(それは 002 の担当)。

## 仮説 002(止まる位置がそろっているか)

### 1. 観測した事実
- `obs.vocab.shapeMissingSummary`(`recognition byGroup[group].{shapeMissingTotal,selfClosestOneAwayGames}`)
  - `selfClosestOneAwayGames` = 13(**局数**。自分側の「最も近づいた形」の欠けがちょうど 1 枚だった局の数)
  - `shapeMissingTotal` = 31804(欠けたマス・駒の**延べ**。`forming` の局面だけ)
- `obs.eval.game`(`games[].{no,total,result,ending,events}`): 局は `no` 1〜18 の 18 局。

### 2. そこからの推論
- 13 は局数、18 も局数なので、この 2 つだけは同じ分母で並べられる(P-89 に触れないよう、延べの 31804 や 5360 とは同じ文に置かない)。
- 18 局のうち 13 局で「あと 1 枚」まで到達している。止まる位置が局ごとに散らばっているなら、ちょうど 1 枚欠けで止まる局がこれほど揃う必要はない、と読める。
- ただし「同じ 1 枚か」は写しからは言えない(どの駒かは渡されていない)。002 は「同じ 1 枚」ではなく「同じ最後の 1 枚の手前」という段の話に留めた。

### 3. 仮説
`02b-H-shape-002.json` の `statement` と同じ。

### 4. 不確実性
- 「最も近づいた形」は局ごとに別の形かもしれない。別の形で 1 枚欠けが 13 局ぶん起きているだけなら、「同じところで止まる」とは言えない。これを分けるには、形の id ごとの内訳(写しに無い)が要る。
- 残り 5 局が何枚欠けだったかは写しに無い(`selfClosestOneAwayGames` の外側の内訳が無い)。
- 18 局は分母として小さい。予測の `alsoRequires` に「次の組も 20 局以上」「同じ組の `forming` の延べが 1000 以上」を置いた。

## 仮説 003(数え直すと減る・見分けがついていない)

### 1. 観測した事実
- `obs.vocab.shapeMovedRequiredSummary`(`recognition byGroup[group].shapeMovedRequiredCompleteTotal`、`recognition movedRequiredZeroShapeCounts.{self,opponent}`)
  - `completeTotal` = 9(**延べ**。初期位置でない必要駒だけで数え直して到達率が満ちた数。**「形が完成した局の数」ではない** ― P-90)
  - `zeroCount` = 自分側 0 / 相手側 0(数え直せない形は無い)
- `obs.vocab.exposure`(`recognition byGroup[group].exposure["D''"]...`)の `shape.self`: `named` 0 / `hedged` 657 / `hidden` 4703。相手側は `named` 0 / `hedged` 1109 / `hidden` 4132。

### 2. そこからの推論
- `zeroCount` が自分側・相手側とも 0 なので、「数え直しが効かない形があったから 9 で止まった」という説明は取りにくい。数え直しの手続き自体は全部の形に当たっている。
- 一方で数え直しは初期配置の駒を分母から外すため、外した駒が後で動いた局も「そろっていた」に入る(P-90)。したがって 9 は上限寄りの数で、これを「完成」と読み替えてはいけない。
- `named` 0・`hedged` 657・`hidden` 4703 は、そろっている側を断定して出せた場面が無く、大半が伏せられていることを示す。つまり「どの段まで進んだか」を外から見分けられている場面自体が少ない。
- ここから、001・002 の読み(段で止まる・同じ手前で止まる)を強く確かめるには、今の観測の粒度が足りない、という弱い読みを別に立てた。

### 3. 仮説
`02b-H-shape-003.json` の `statement` と同じ。

### 4. 不確実性
- 003 は本人の指し方ではなく、測り方の側の話に寄っている。次の 20 局で露出の規則(`D''`)や判定の条件が変われば、`named` の数は本人が変わらなくても動く。予測はその前提の上に置いた数である。
- `hedged` 657 と `hidden` 4703 は延べなので、局ごとにどれだけ偏っているかは分からない。
- 9 の中身(どの形・どの局か)は写しに無い。9 が同じ形に集まっているのか散っているのかで読みは変わる。

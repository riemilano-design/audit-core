# 将棋教育データの作り方

このスキルは、単にスキーマに通るデータを作るだけでなく、[CLAUDE.md](../../../CLAUDE.md) の最重要コンセプト(「定跡を覚えさせる」のではなく「考え方を身につけさせる」)に沿った**質**のデータを作るための手順です。

## 作成前に確認すること

1. [docs/DATA_MODEL.md](../../../docs/DATA_MODEL.md) を読み、対象の型(shapes/openings/intents/explanations)がパイプラインのどの段階に対応するかを把握する
2. 既存データ(`data/examples/` および `data/shapes/` 等)を確認し、`id` の命名規則(`^[a-z0-9_]+$`)と `family` / `parent_shape_id` の関係に矛盾しないようにする
3. 一度に作るのは数件まで([CLAUDE.md](../../../CLAUDE.md) ルール4番)

## 品質チェックリスト(スキーマだけでは検証できない観点)

- **「なぜ」が書かれているか**: `characteristics` や `reason` が、単なる事実描写(「玉が2二にある」)ではなく、初心者にとっての意味(「なぜこの形が良いのか/なぜこの手なのか」)を説明しているか
- **専門用語のフォロー**: 説明文の中で将棋用語(囲い、棒銀、など)を使う場合、`glossary_terms` にそのキーを含めたか、または文中で簡単に言い換えているか
- **断定しすぎていないか**: `confidence_level` が `low`/`medium` の内容を、言い切りの文体で書いていないか。「〜が多いです」「〜しやすいです」のような控えめな表現を使う
- **目的→手→理由の順序**: `explanations` を作る場合、`purpose`(目的)が先、`reason`(理由)がその目的を裏付ける構成になっているか。手順や事実の羅列になっていないか
- **出典があるか**: `source` が空でないか。「一般的な知識」で済ませず、可能な範囲で具体的な参照元を書く

## スキーマ準拠の確認

Node.js環境が整っていれば `node scripts/validate-data.mjs` を実行してスキーマ違反・ID参照切れを確認する。整っていない場合は、`data/schemas/<type>.schema.json` の `required` フィールドを目視で確認する。

## 完了後

作成したデータは `main` に直接コミットせず、ユーザー(人間)に将棋知識としての正しさのレビューを依頼すること。[docs/ROLES.md](../../../docs/ROLES.md) を参照。
